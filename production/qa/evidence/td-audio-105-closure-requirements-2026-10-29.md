## 二、三条真实缺口(逐条给「怎么算清」)

### 缺口 A —— `mono_enabled` 不在混音器里

| 项 | 内容 |
|---|---|
| 现状 | 注册表 `AudioSettingsRegistry:103` 有 `MonoParameter` 条目;`MixerRegistry:52` 有常量;但 `.mixer` 的 `m_ExposedParameters` **不含它** |
| 后果 | 玩家在设置里改 mono **不产生任何声学变化**(参数写不进混音器) |
| 修法 | 混音器资产加 `mono_enabled` 暴露参数 + 一条实际的 mono 处理链(单声道下混) |
| 判定 | `.mixer` 解析出的暴露参数集**含 `mono_enabled`**,且「开 / 关」两态**实测有可闻差异** |
| 归属 | **混音器资产拓扑批**(与 `OQ-44-2` 同族;`TD-audio-106` 结案块已留此项) |
| ⚠️ | **不能靠改注册表清** —— 注册表早就对,断的是资产侧 |

### 缺口 B —— `subtitle_text` 没有出向通道

| 项 | 内容 |
|---|---|
| 现状 | 事件表 5 行带文本;codec 读出并存在 `AudioEventRow`;但**全库无消费者** |
| 后果 | 44 侧「有文本」与「送到 42」之间断链 —— `AC-44-15` `[A]` 的**双投递**只成立一半 |
| 修法 | 44 在 cue 发射点把 `subtitle_text` 经一个**只入不出**的出向口交给 42(ADR-013 的两栈边界;44 仍不持状态) |
| 判定 | 发一条语声 cue ⇒ 42 侧收到对应文本(**端到端夹具**,不是「字段存在」) |
| 归属 | **42 + 44 接线轮** |
| ⚠️ | 这一半**与 49 无关** —— 它只要求「文本送到」,不要求「呈现规格」 |

### 缺口 C —— 42 侧无字幕控件

| 项 | 内容 |
|---|---|
| 现状 | 42 元件库有 `Label` 文本组件,但**无专供字幕的控件** |
| 后果 | 即便缺口 B 修好,玩家屏幕上**仍看不到字幕** |
| 修法 | 归 **49(P2)** 的「四钩子具体要求」 |
| 判定 | 屏幕上有字幕且符合 49 的呈现规格 |
| 归属 | **49(P2)** —— `OQ-42-8` 已于 2026-10-06 裁定「42 只留接口,具体要求归 49」 |
| ⚠️ | **这不是 42 的欠账** —— 42 交付的恰是它该交付的那一半 |

### 缺口 D —— 13 的「可见对应物」达成面

| 项 | 内容 |
|---|---|
| 现状 | `AC-13-F1` 的 13 侧只判**结构前提**(cue 语义是独立枚举 id / 呼吸层默认在);夹具自陈达成面 BLOCKED-BY 42 |
| 修法 | 42 的冗余通道把「咳嗽 / 呻吟 / 呼吸」映射到**非色相可辨**的可见物(形状 / 明度 / 姿态) |
| 判定 | 三类 cue 各有一个**默认可见**且**非色相**的对应物 |
| 归属 | **42**(13 已交付它该交付的一半) |
