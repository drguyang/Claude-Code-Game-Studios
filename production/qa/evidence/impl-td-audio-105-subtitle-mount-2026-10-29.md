## 三、A —— 字幕挂载与自动收尾

### 3.1 为什么必须有自动收尾

字幕的 `Show` 是**「替换当前行」**语义,`Hide` 只由调用方触发。此前生产侧**从不调 `Hide`**
⇒ 第一条咳嗽的台词会**永远停在屏幕上**。而 42 **不判时机**(`E-12b` 逐字)⇒
「停多久」只能由**上游发射点**记账。

### 3.2 实现

| 件 | 内容 |
|---|---|
| `PatientCueDriver._subtitleHideAtTick` | `long`,`-1` = 无待收尾字幕 |
| `PatientCueDriver.SubtitleHoldTicksDefault` | **60 tick = 3.0 s @ 20 Hz**(`TICK_SECONDS = 0.05`)—— **P0 占位值**,呈现规格归 49(P2) |
| ctor `subtitleHoldTicks` | 可注入;**`<= 0` 构造期抛出**(0/负数 = 「立刻收起」,比常驻更糟) |
| `DeliverVisualChannels(...)` | `Show` 后记 `_subtitleHideAtTick = tick + hold` |
| `TickSubtitleHold(tick)` | `OnTickEdge` 末尾;**整数 tick 比较**,不读墙钟 |
| `StopAll()` | 一并 `Hide()` + 清账(场景卸载 / 读档前不留残行) |
| `BootRoot` 6.0 段 | `SubtitleLineView` 与 `PatientCueMarkView` 同批挂到 UI 根 |

### 3.3 一个必须写下来的夹具教训

首版 `test_subtitle_hidesAfterHoldTicks` **红了**,但它**不是实现的问题**:

```
DIAG emit=2 shown=2 hide=0 hold=60 hideAt=82 hideAt2=1060
```

咳嗽**每 ~40 tick 再发一次**,每次 `Show` 都把停留窗**从头算**(新字幕替换旧字幕)。
于是「末 tick + 61」那一刻**刚好吃到新一次咳嗽**,`hideAt` 被推到 1060 ⇒ 永远测不到收起。

⇒ 修法 = **先让病人离场再推进**(不再有新字幕,窗才是确定的)。
⚠️ 由此得到一条**诚实结论**:「连续咳嗽期间字幕一直刷新」是**正确行为**(新 cue 替换旧字幕),
但它让「到点收起」这条判据**只能在没有新 cue 的窗口里测**。

### 7.1 本轮抓到的**夹具缺陷**(两处,均如实登记)

**① 首版 `test_subtitle_hidesAfterHoldTicks` 红的是夹具,不是实现。**
诊断实测:`emit=2 shown=2 hide=0 hold=60 hideAt=82`;推到 tick 1000 时 `hideAt=1060`。
根因 = 咳嗽**每 ~40 tick 再发一次**,每次 `Show` 都把停留窗**从头算**(新字幕替换旧字幕),
我选的「末 tick + 61」那一刻**刚好吃到新一次咳嗽**。⇒ 修法 = **先让病人离场再推进**。

**② S3 首轮假存活 = 基线取样太晚。**
原夹具把 `before = subtitle.HideCount` 取在**循环之后**;而「立刻收起」这个变异在**循环内**
就已经收起了一次 ⇒ `before=1 / after=1` ⇒ `Is.EqualTo` 相等 ⇒ 假存活(诊断实测坐实)。
⇒ 修法 = **基线改成绝对量 `Is.Zero`**(停留窗覆盖整个循环,循环全程就不该有任何一次收起)。

> ⚠️ **可复用的记法**:「**不该发生 X**」类断言,**基线不能取「当前值」,只能取绝对量** ——
> 否则变异只要发生在取样点之前,就被基线一起吸收。同族:前置必须断言「**该发生的确实发生了**」
> (本文件两条夹具均加了 `Shown.Count > 0` 前置,否则「未收起」是空真)。
