## 2. 为什么此前记「无载体」是错的

`critical_paths.json` #1 的原 reason:

> 启动序(Boot → Addressables 预载)需真启动;headless 无载体

**前半句成立**:EditMode 里预检必然判死 —— `pipeline_gate_test.cs:1243` 已把它钉成判据
(`TryPreload()` 在 EditMode 必须返回 `false`)。

**后半句不成立**:PlayMode 有真 catalog(BootRoot 的 PlayMode 夹具一直靠它跑启动序),
`Addressables.InitializeAsync` + `data-core` 预载**真跑得起来**。
⇒ 「headless 无载体」是把**EditMode 的结论**外推到了**PlayMode**,而没实测后者。

## 3. 判据设计(两处防假绿的取舍)

### 3.1 主判据:A

```
真 InitializeAsync(autoReleaseHandle:false) → await → 非 Failed → Release
  → TryPreload() == true
  → IsPreloaded == true · LastPreloadDiagnostic == "missing=[]"
  → 【内容断言①】反射读 AddressablesDataProvider._items,必须**非 null**
  → 【内容断言②】Provider.Load<ItemDataSet>() 行集非空 · ConfigVersion != 0
```

**为什么必须有 ①**:`EnsureItems()` 是**惰性**的(`AddressablesDataProvider.cs:532`)——
`Preload()` 改成空实现时,`Load<ItemDataSet>()` 仍会自己补装 ⇒ **② 对「预载真的跑过」零判别力**。
这条是读源码时抓到的,不是猜的;证伪 M1 就是照它设计的。

### 3.2 反例:B(装载抛)

```
TryPreloadGated(precheck: true, factory: null, load: throw)
  → 返回 false(不得吞成 true)
  → IsPreloaded 仍 false(无半预载态)
  → Provider **抛 InvalidOperationException**,不得返回 null
```

⚠️ 这条**不是重复件**:EditMode 的 `pipeline_gate_test` 钉的是「预检 false ⇒ 短路」与
「预检 true ⇒ 装载恰一次」,**`catch` 分支零覆盖**。
(「预检 false ⇒ 短路」本件**不复制** —— 一个 AC 允许多条载体,但不该把别人的载体抄一遍。)

`TryPreloadGated` 是 `internal` 且 Presentation 未对测试装配开 IVT ⇒ 走反射(与
`pipeline_gate_test.cs:1266` 同法)。

## 5. 工具改动:`run_smoke.py` 支持多份结果件

`#1` 的载体是 **PlayMode** 件,其余 `test` 条多在 **EditMode** —— 单份 `--results` 装不下两面,
而「分两次跑、各自数 PASS」会让「自动 PASS 数」失去意义(每次都少一半)。
⇒ `--results` 改 `nargs="+"`,多份**合并**成一个判定面(同名测试以**后给**者为准)。

向后兼容实测:单份 `--results unity/Logs/s21-2-full-em.xml` 输出仍为
`自动 PASS 11 · 无名 8`(与改动前逐字一致)。
