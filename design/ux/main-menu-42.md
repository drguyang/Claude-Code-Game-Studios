## 1. 类型声明与闭集边界

**本屏不是 `ModalId` 成员,也不得成为其一。**

- `ModalId` 闭集(`AC-42-F1` 八员)描述的是「**世界里**摊开的模态」——
  它的每一次开合都以「世界已在跑」为前提(规则七的门、`BlocksPlay`、tick 冻结面全部据此)。
- 主菜单出现在**世界装载之前**:此时没有 tick、没有病人、没有可被「挡住」的世界。
  ⇒ 把主菜单塞进闭集会让「`BlocksPlay` ⇒ 冻结世界」这条读法失去前提(冻结一个不存在的东西),
  也会让 4 的 `IModalGateState` 在启动期读到「有模态摊开」。
- **它是场景级屏**:`MainMenu` 场景(ADR-023 §① 的第二个场景)里的 42 UI 根。
  42 的职责不变 —— **只渲染、只发意图,不持游戏状态**(ADR-013 §9 C3)。

⚠️ **本 spec 不新增任何判定**:「有没有可继续的存档」「继续到哪一份」全归 7a / 7b;
本屏只负责「可发现地给出这一个入口」。

## 2. Purpose & Player Need

玩家双击图标之后的第一秒问的是同一句话:**「我上次那局还在吗?」**

**这个屏存在的理由**

- 7b 把「继续诊治」列为存档位的**两条正式入口之一**(另一条是暂停壳)。
  没有主菜单,这条入口在生产上**根本不存在** —— 7b:189 写了两支,落地的只有一支。
- 游戏**不能**一启动就把玩家丢进世界:那样「继续」这个语义无处表达,玩家失去对进度的掌控入口。

**什么会变糟(若本屏缺失或做错)**

- 启动即入世界 ⇒ 玩家**没有机会选择**「继续」;7b 的正式入口断一支。
- 若主菜单做成现代 UI(标题 + 按钮组 + 版本号):直接破拟物铁律(世界之外也该是「一张纸」)。

**玩家目标**:启动后**一眼看到「继续诊治」**,按一下就回到诊治。

**游戏目标**:把 7b 的第二条正式入口补上,并让「启动」这件事**不打断拟物。**

## 3. Player Context on Arrival

| 问题 | 答案 |
|---|---|
| 刚才在做什么 | 刚启动游戏(或刚从桌面切回);**没有任何世界态** |
| 情绪状态 | 低唤醒;期待「快速回到上次」或「我刚买的,看看能干什么」 |
| 认知负荷 | 最低 —— 本屏**不得**要求任何理解成本 |
| 已有什么信息 | 知道自己打开了游戏;不知道有没有存档 |
| 最可能想做什么 | ① 继续上次的诊治(主诉求) |
| 最怕什么 | 按下去把进度覆盖掉 / 一堆看不懂的选项 |

**情绪设计目标**:安静、确定。**不制造第二层选择**(与暂停壳同一条铁律)。

## 4. Navigation Position

```text
[Boot(常驻:相机 / AudioListener / tick 驱动)]
        │  additive 装载
        ▼
[MainMenu 场景]  ←─ 本 spec
        │  「继续诊治」(无存档时文案 = 「开始诊治」)
        ▼
[World 场景(additive)]  ← ✅ 2026-11-01 用户裁定(原 OQ-MM-1):**直接进世界**,取最近存档
```

- **入口唯一**:游戏启动(无其它入口;不提供返主菜单的路径 —— 见 OQ-MM-3)。
- **出口唯一**:「继续诊治」一行。**本屏不提供设置 / 退出 / 制作名单**
  (P0 口径与暂停壳同一条:**只放一行**,见 §14 OQ-MM-5)。
- **出口去向(已裁)**:装载 `World` 并按最近存档继续;无存档时同一行改文案「开始诊治」并开新局。
  ⚠️ **`save-slots-7b.md:51` 的「尚未入世界,册 = 首屏」自本裁起作废** —— 该处须就地加注(原文不删)。
- ⚠️ **装载方式**:`MainMenu` 与 `World` 都是 **additive**(ADR-023 §①:`永不用 LoadSceneMode.Single`)。
  本屏不得自己切场景 —— 它只发意图,装载归装配层。

## 5. Layout Specification

**最小形态 = 一张纸、一行**(没有世界时);**有世界时 = 一张纸 + N+2 行**(ADR-040 D9)。

```text
没有世界(首次启动)                    有世界(N 个)
┌──────────────────────────┐          ┌──────────────────────────┐
│  开始诊治                 │  ← 开新局  │  继续诊治                 │  ← 最近游玩的世界,开屏落焦
└──────────────────────────┘          │  第 3 局                  │  ← 其余世界(按最后游玩降序)
                                      │  第 1 局                  │
                                      │  新起一局                 │
                                      │  删一局                   │  ← 末行(ADR-040 D6)
                                      └──────────────────────────┘

删除态(按「删一局」之后;只用 Submit 一路输入,不新增动作 / 不新增模态屏):
┌──────────────────────────┐
│  删除 第 3 局              │  ← 第一次按 = 选目标
│  删除 第 1 局              │
│  返回                      │
└──────────────────────────┘
```

**二次确认的形态**:选中某一行后,该行文案变「**再按一次确认 · 第 N 局**」;
**在同一个世界上再按一次**才真删。按别的世界 = 换目标(重新进入待确认),不删任何东西。
⚠️ 两次都必须落在**同一个世界**上 —— 这是「二次确认」的本体,不是「按两次任意键」。

⚠️ **「第 N 局」里的 N 是**世界序号**(目录名后缀),**不是**游玩时长 / 日期** ——
存档摘要(`OQ-MM-6`)仍未裁,本屏**不得**自造日期文案(那需要 7a 的槽位元数据源)。

| 项 | 规格 | 判据来源 |
|---|---|---|
| 容器 | 模态**之外**的全屏层:纸面水平居中、纵向居中 | 与暂停壳同族的「纸压在世界/暗底上」 |
| 行高 | ≥ `--skeuo-shared-row-height`(44 px 下限) | AB-3(焦点落点高半) |
| 行样式 | `.ruled`(与暂停壳/脉案行同一声明块) | `SkeuoPaper.uss` |
| 列宽 | `--skeuo-shared-modal-width`(480 px @1680),水平居中 | 暂停壳 2026-10-31 走查缺陷驱动补填的同一条 |
| 文字 | 「继续诊治」/「开始诊治」/「新起一局」由 42 直接写(常量,非数据驱动);**其余世界行**的文字由装配层给(`MainMenuWorldView.Label`),42 不拼 | 42 呈现职责 + ADR-013 §9 C3 |
| 文案切换 | 有存档 ⇒「继续诊治」;无存档 ⇒「开始诊治」 | ✅ 2026-11-01 用户裁定(原 OQ-MM-2) |
| 背景 | 世界尚未装载 ⇒ 纸面下是**纯色底**(不是游戏画面) | 见 §6「无世界态」 |

⚠️ **本节刻意留白**:纸纹浓淡 / 字号 / 是否有标题栏 —— **未定**,归美术轮。
本 spec 只钉**结构与可达性**。⇒ 走查时不得以「不好看」判不通过,也不得以「看着还行」判通过。

✅ **底色已于 2026-11-01 裁定(补轮)**:**复用调色板既有 token `--skeuo-implement-bg`(`#6B4423`)**,
**不新增任何字面色值**。落地形态 = **42 侧全屏背板**(`.menu-backdrop`,绝对定位铺满场景级屏容器,
绘制在纸面之前,`pickingMode = Ignore`),**不动相机** —— 菜单期启动序第 5 步的相机还没建出来,
此时渲染的是场景里预摆的占位相机(改它要么改不到,要么在关屏后留下一台被改过清屏色的相机)。
⇒ 美术轮改 token 时背板**自动跟随**;本行只钉「纯色、不透明、铺满」这三条属性。

## 6. States & Variants

| 态 | 触发 | 呈现 |
|---|---|---|
| **有存档** | 启动期查得可继续存档 | 纯色底 + 居中纸面 + 一行「继续诊治」 |
| **无存档** | 启动期查无存档(含查询失败 ⇒ 保守取此态) | 同左,文案 = 「开始诊治」 |
| **多个世界**(2026-11-04) | 启动期查得 ≥1 个**有档**的世界 | 每世界一行(第一行「继续诊治」,其余「第 N 局」)+ 「新起一局」+ 「删一局」;**行数 = 世界数 + 2** |
| **删除态** | 按了「删一局」 | 每世界一行「删除 第 N 局」+ 末行「返回」;选中后该行变「再按一次确认 · 第 N 局」 |
| 行焦点 | 开屏即落焦 / 方向键(单行 ⇒ 无位移;多行 ⇒ 逐行移动) | 焦点环(与暂停壳同一 overlay 载体) |
| **行重建后的焦点** | 每次形态切换(进删除态 / 进待确认 / 装配层回推列表)都会**重建行** | **焦点必须落回某一行**:进删除态 ⇒ 第一个世界;待确认 ⇒ 同一个世界;回推列表 ⇒ 首行。⚠️ 2026-11-04 实测:首版重建后焦点悬空 ⇒ 手柄/键盘玩家按开「删一局」后**一步也走不了** |
| 行按下 | `Submit` / `Click` | 见 §7 |

**显式声明不存在的态**(防实现期自行发明):无「加载中」· 无「不可用行」· 无多页 · 无错误态。

> ✅ **「无存档」已裁(2026-11-01 用户)**:该行**仍可用、仍获焦**,只把文案换成「开始诊治」,
> 激活后进世界开新局 ⇒ **不引入禁用态**,也就不碰 7b 规则三的「禁只靠变暗」(根本不需要色通道)。
> ⚠️ **查询失败按「无存档」处理**(保守:开新局不会覆盖任何东西;反过来选「继续」则可能把空档当档读)。

## 7. Interaction Map

| # | 输入 | 上下文 | 结果 |
|---|---|---|---|
| 1 | `Submit` / `Enter` / 手柄南键 | 焦点在该行 | 发「进世界」意图;有存档 ⇒ 继续最近档,无存档 ⇒ 开新局 |
| 2 | 指针点击该行 | 同上 | 与 1 **同一出口**(`Activate()`),不得各写一份 |
| 3 | 方向键 / 左摇杆 | 单行 | **无位移**(只有一个落点);不得逃到屏外(焦点单栈) |

**实现纪律**:键盘/手柄/指针三条路径必须汇到**同一个** `Activate()`;
与暂停壳 `Activate(int)` 同款(两条路径各写一份判定 = 将来必然分叉)。

**模式库对应**(`design/ux/interaction-patterns.md`):**P-01 单栈焦点门**(焦点不逃出本屏)·
**P-04 双导航等价**(手柄 Submit 与指针 Click 同一出口)。

## 8. Events Fired

**零三流事件。零 sim 参与。**

| 触发 | 下游 | 性质 |
|---|---|---|
| 「继续诊治」 | 装配层的场景 / 载入意图 | **不是** `SimEvent`;场景装载归 ADR-023 |
| 开屏 / 离屏 | 42 自身容器 | 纯呈现 |

**理由**:主菜单出现时**世界尚未装载** ⇒ 没有 `ITickProvider`、没有 `IEventSink` 可用;
写任何事件都要求 sim 先于世界存在,与 ADR-023 的装载序矛盾。

## 9. Transitions & Animations

**零动画**(与暂停壳同一口径):出现 / 离屏 / 进入世界皆瞬时。
理由同上:**此阶段没有 tick、没有世界时钟**;引入转场就等于给启动期发明一套时间基准。
⇒ 登记为**未定**(OQ-MM-4),实现轮不得自行发明。

## 10. Data Requirements

**一个布尔,零 DTO**。

| 数据 | 用途 | 来源 / 所有者 | 更新频率 | null / 失败处理 |
|---|---|---|---|---|
| `hasContinueSave` | 决定文案「继续诊治」/「开始诊治」 | **7a 存档服务**(存档目录扫描结果,经装配层注入);**不归 UI** | 启动期一次(开屏前定值,屏内不变) | 查询失败 ⇒ **取 false**(按无存档处理,见 §6) |

⇒ 「显示上次游玩时间 / 病人数」一类**不在本 spec 面内**(OQ-MM-6 登记为后续轮候选);
本屏**不读**存档内容,只读「有没有」。

⚠️ **所有者纪律**:UI 只消费这个布尔,**不得**自己去扫存档目录(那会让 42 反向依赖 7a,并造出第二份「什么算可继续」的判据)。

## 11. Accessibility

| 要求 | 本屏的落法 |
|---|---|
| **键盘可达**(L-1) | `Enter` / `Space` 激活;焦点必须有落点(开屏即落该行) |
| **手柄可达**(L-2) | 南键激活;焦点必须有落点 |
| **焦点可见** | 焦点环 overlay(与暂停壳共用同一载体契约 `AC-42-G4`) |
| **非色-only** | 本屏无状态色;焦点靠**环的存在**表达 |
| **文本对比度** | 行标签与纸面底色 **≥ 4.5:1**(WCAG AA):**要求成立,色值未定** —— 归美术轮;判定 = 走查取色 |
| 文本缩放 | ⚠️ 未定 —— 归无障碍轮 |
