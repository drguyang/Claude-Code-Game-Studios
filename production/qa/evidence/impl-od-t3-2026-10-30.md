## 三、9 侧:`PeakDrugLoad`

`Sim/ProgressionEvaluator.cs` 新增:

```
PeakDrugLoad(t) = max_p  Σ_{i : 处置_idᵢ = p}  |drug_potencyᵢ| × Decay(t − tickᵢ, half_lifeᵢ)
```

- **纯函数**(事件流的函数)⇒ 不进 F1、不进 `trend`、不进存档,属派生态。
- **不进 `Progress` 的理由**:F1 的药物项是治疗项且带对称 clamp(校验 15「超限 = 饱和截断」);
  过量若要「有毒」就得让超出部分反向抬 `Progress` —— 两种语义纠缠在同一个单值上,
  `trend` 符号反转那类问题复发。这正是 `TD-sim-02` 自写的「不得与 `Progress` 单值纠缠」。
- **取绝对值**:药效符号随数据走,但「体内积了多少药」与方向无关。
- **与 F1 的两道门无关**:`polarity = causal` / `∈ treatable_by` 只管药效;吃错药照样在体内积着。
- **输出**:`Sim.Contracts/VitalsDto.cs` 的第 5 个字段 `Fix PeakDrugLoad`(默认参 ⇒ 25 个既有构造点无需改)。
- **接线**:`Gameplay.Boot/DiseaseVitalsService.cs` 的 `GetVitals` 全整数域求值后填入。

## 四、53 侧:定档 + 结算 + 数据

| 件 | 内容 |
|---|---|
| `Sim.Contracts/OverdoseEvaluator.cs`(新) | 定档纯函数:`load ≥ threshold[i]` ⇒ 档 = i(**闭区间下界**,同 F2 的 `position ≥ appear_at`);未达最低档 ⇒ `NoOverdose = -1`(与禁忌侧同款负数哨兵理由:档 0 是合法档) |
| `Sim/Consequences/OverdoseSettler.cs`(新) | 游标式结算器。**刻意不并入 `ContraindicationSettler`** —— 前者的驱动是「一条用药事件」(离散),后者是「一个 tick 的体内药量」(连续累积);合并会把两种游标语义塞进同一个 `Step`,出错无法归因。 |
| `53_cost_table.json` | `harm_kind_enabled` += `overdose`;`bands.overdose = 2`;新根键 `overdose_band_thresholds = ["1","3/2"]`;新行 2 条(档 0·1 → `INJ_DRUG_HARM`,severity 3·4) |
| `CostTable53.RejectHarmKind` | 撤销 `Overdose` 拒收分支(原文保留在 remarks 里) |
| `CostTableBinder` | 撤销「`harm_kind_enabled` 含 `overdose` 即拒」;新增 `ReadOverdoseThresholds`(严格递增 / 档数一致 / 启用联动四条拒收) |
| cooked 布局 | **尾段式**追加 `threshold_count: i32` + 逐项 `i64`(不动逐行布局 —— 行内插字段会让旧产物解出错位数据,静默) |

**只升不降**:`PeakDrugLoad` 会随半衰期衰减,但已造成的伤害不可逆 ⇒ 按病人记「已发出的最高档」,
只在新档**严格高于**它时再发。

**一处实现期自查修掉的缺陷**:`BandOfInjury` 初版只按 `injury_id` 反查档位,而真实表里
**过量两档都指向 `INJ_DRUG_HARM`** ⇒ 重建 `_highestBand` 时会取到最大档(1),
导致「已发档 0」被读成「已发档 1」⇒ 真正的档 1 永远发不出来(**漏伤害**)。改为
`(injury_id, severity_band)` 双键 + **首个匹配即返回**(歧义取最小档 —— 最坏是多一次查表,不会漏)。

## 九、残留(如实登记)

1. **未做实际游玩验证** —— 「反复灌同类药会中毒」在真实游玩中是否可撞见,取决于
   `drug_potency` / `half_life` 与档位线(`1` / `3/2`,约两剂 / 三剂)的关系。
   本件只证**判据链能跑通**,不证**玩家会撞到**。归 playtest。
2. **「槽」分组未实现** —— P1a 的 12 药物槽落地后,`ComputePeakDrugLoad` 的分组键应换成槽;
   载荷**不需要改**(槽不是载荷字段,是 12 侧的容器)。
3. **`OverdoseSettler` 每 tick 只查「本 tick 有过用药事件」的病人** —— 若某病人的药量越过档线
   而本 tick 恰好没有新的用药事件,不会结算。⚠️ 这在当前模型下**不可能发生**
   (`PeakDrugLoad` 只在用药那一刻达到局部最大,之后只衰减),但没有夹具枚举这一点;
   若将来引入「药量随其它事件上升」的机制,须重审此假设。
4. **档位线 `1` / `3/2` 是本轮取的数值**(非推导)—— 与 `single_dose_max = 1/2` 配套;
   改它只动 `53_cost_table.json` + 重烘,不动代码。
