## Overview

**44 音频系统是表现层的一条「语义 cue → 声音」通道,与 42 拟物 UI 同构 ——
只触发 / 只渲染,永不持有游戏状态(ADR-018,✅ Accepted,本 GDD 的权威件)。**

它的技术面:**上游系统在表现层发出语义 cue**(13 的咳嗽呻吟 · 37 的结案纸页 ·
52 的预告线索 · 8 的听诊层 / 9 的呼吸语义),44 只把 cue 变成声音 ——
经由 **`AudioCueDto`**(无 `disease_id`,整数语义,受 `PresentationDtoGuard` 递归扫描)。
音频事件表走 **ADR-014 烘焙管线**(玩家构建零 JSON 解析器);混音拓扑为
`Master / Music / Ambience / Voice / SFX / Stethoscope / UICue` 七条总线 + 行为驱动的快照清单。

它的玩家侧:**你是**先听见后看见**的那个人**。玩家可以在隔壁房间听见病人呼吸变坏、
听诊器里听见细湿啰音(吸气象、断续、撕 velcro 那种)——**而系统永不叮一声告诉你「他转危了」**。
「无提示音」铁律由白名单断言机械化(AC-44-09 BLOCKING),让「判断为骨」在听觉侧成立:
**听见变化是你的本事,不是系统的通知。**

> **职责边界(一句话)**:44 不订阅 sim 真值、不写三流、不进 sim 程序集;
> 它消费的是**表现层语义 cue**,不是**游戏状态**。任何「我需要知道病种才能选素材」的需求,
> 语义解析都在上游完成,44 只收结果 cue id。

## Player Fantasy

**「门后的人还在喘气。」** —— 玩家可以在**看不到病人**的情况下,仅凭声音判断他是否转危。
这是无血条设计(支柱一「判断为骨,手感为肉」)在**听觉侧**的兑现:
`diagnosis-system.md:171` 转引的 9 的幻想「世界不为你暂停」,唯一不依赖 UI 的外显方式就是声音。

**玩家应该是那个「听见了什么」的人,不是那个「收到了通知」的人。**

- **听诊器里的世界**:低技能 ≠ 把啰音静音 —— 低技能 = 更高的接触噪声底、
  更窄的通带、更少的频段细节(摩擦声、衣料声、病人自己的呼吸声混进来)。这正是真实的实习医生体验
  (`diagnosis-system.md:1588-1591`)。**你的耳朵不会说谎,但你的耳朵也提醒你:「你没练过听」。**
- **变体库混合的病人语声**:病人是**人**,不是音效机 —— 男 / 女 × 强 / 中 / 弱 × 数种句尾,
  按 (病种语义, 精度档, 强度) 选变体并交叉淡化。**禁**把已录语声做五项参数调制
  (音高 / 气声 / 语速 / 断句 / 共鸣)—— 那是「变声器」,不是「病人说话」。
- **世界声是线索,不是警报**:狗吠 / 马蹄 / 锣声 / 鸟群惊飞(52 预告线索)是**可以听出来的前兆**,
  不是「红色感叹号的声音版」。玩家学到的不是「叮 = 危险」,而是「今晚的鸟在乱飞」。

**参考锚**:英灵神殿的**风声 / 门吱呀**—— 世界有声音,但从不替你说话;
《双城》式的拟物声(笔尖走路、翻纸)让「翻开脉案」本身有触感。
**要避免**:任何「成就达成」式 stinger、任何「转危报警」式 ducking、任何「玩家做对了就播对音」的素材切换。

## Detailed Design

### Core Rules

**规则一 · 44 与 42 同构 —— 只触发 / 只渲染,永不持有游戏状态(ADR-018 §一)。**
44 不读 sim 真值、不写三流、不进 sim 程序集(门 A 不受影响)。
**数据入口只有 `AudioCueDto`**(2026-09-18 修正:原写「`AudioCueDto` + `VitalsDto`」——
`VitalsDto` 全文无任何消费者 / 公式 / AC 引用,是一处**绕开 AC-44-09 白名单的旁路**
(可直接由体征驱动呼吸声,不经上游 cue 语义)。**已删除**;ADR-018 §一 表同批同步。
44 的**唯一**输入是上游语义 cue,输出只有 `AudioMixer`。)

**规则二 · 音频触发源必须来自「行为反馈白名单」,不得来自「状态播报」(ADR-018 §六)。**

| 类别 | 例 | 归属 |
|------|-----|------|
| 玩家自身动作 | 笔尖走路 / 落笔 / 翻纸 / 器物放置 / 脚步 | 42 / 44 |
| 玩家主动的检查动作 | 听诊器接触声 / 摩擦声 / 衣料声 | 44(听诊层) |
| 玩家可感知的世界声 | 狗吠 / 马蹄 / 锣声 / 鸟群惊飞 / 哭喊 / 钟声 | 52 → 44 |
| 持续生理声(非状态播报) | 呼吸层的**连续**变化(平稳→急促→停顿) | 9 语义 → 13 触发 → 44 |
| **战斗乐层(连续织体)= 第 5 类**(2026-09-17,25 的 V4/V7 回填) | 遭遇期乐层的**缓变**(淡入淡出,**无边界拍**) | **表现层音频观察者订阅遭遇态 → 44**(27 永不点歌);护栏 **G1 禁帧对齐 / G2 去标注盲测 / G3 本地设备侧触发** 全文见 **ADR-018 §六「音乐层例外」条** —— 无护栏则例外不成立,黑名单四禁对本类原文适用 |

黑名单(禁止 —— 状态播报):任何 sting / jingle / 提示音宣告状态变化;
用 ducking 报状态;用素材切换报状态;用音频表达本来该由玩家读数得出的结论。

> **⚠️ 2026-09-18 修订(首轮评审阻断 2;原机械化**不可执行**)** —— 原文 AC-44-09 只断言
> 「每个 CueId ∈ 白名单类别」,但**事件表 schema 里根本没有类别字段**
> (ADR-018 §Key Interfaces 的示例行 = `{cue, assets, tier_params, loop, bus}`),
> 且 schema 本体被推迟到 `OQ-44-4` —— **BLOCKING 门骑在一个 Open Question 上,无载体**。
> 更糟:**只查内容不查时机**。反例:13 恰在病人跨过危险阈值的那个 tick 发一条咳嗽 cue ——
> 咳嗽在合法类别里、断言全绿,但**那条咳嗽就是警报**。52 的档位表
> (威胁=狗吠 / 灾难=锣声)同理 —— 它是「状态枚举 → 声音」的映射穿了件拟物外衣。

**机械化(AC-44-09,BLOCKING)**:音频事件表 schema **必须携带两个字段**,
`OQ-44-4` 由 Open Question **升格为本 GDD 的定型小节**(见 §Event Table Schema):

| 字段 | 类型 | 作用 |
|------|------|------|
| `whitelist_category` | enum(5 类) | 内容侧:cue ∈ 上表五类之一(**含第 5 类战斗乐层**) |
| `trigger_source` | 闭枚举 | **时机侧**:见 §Event Table Schema 的合法 / 禁止集 |

**双重负向夹具(缺一不可)**:
① 注入一条 `whitelist_category: Sting` 的行 → 断言**必须失败**;
② 注入一条**类别合法**(如 `PlayerAction`)但 `trigger_source: VitalsCrossed` 的行
→ 断言**必须同样失败**(这是堵住「阈值时刻的咳嗽」的那一半)。
`OQ-44-4` 未落盘前置 **NOT-RUN 守卫**,不得放行(见 §Event Table Schema)。

> **⚠️ 2026-09-18(25 二轮 E3,用户裁定 [甲],详见 `combat-and-weapon-lines.md` §6.3/§6.4/旋钮表)**:
> 战斗音频的触发 = **事件类别**(onset 到达 / 挥空 / `EncounterEnded`),
> **任何音频参数(音量 / 音色 / 声像)不得读 `magnitude`** —— 与 ADR-018 §六 无提示音铁律同向:
> 听觉侧不允许出现「伤害数字」的第二载体。昏迷后静默的触发源 = `EncounterEnded`,不设「昏迷瞬间」专用 cue。

**规则三 · 快照由行为驱动,绝不用来播报状态(ADR-018 §三)。**
`StethoscopeFocus` 是玩家**自己**拿起听诊器触发的;`Paused` 是暂停。
快照切换**不**用于「病人转危 ⇒ 压低环境以突出心跳」。

> **⚠️ 2026-09-18 修订(首轮评审阻断,`DialogueFocus` 自相矛盾)** —— 原 `DialogueFocus`
> 触发源 = 「病人语声播放」。而病人语声(呻吟 / 咳嗽)由 13 依病情发出 ⇒ **病情恶化 = 呻吟更频
> = 混音器自动压低环境音** —— 这**正是**本条禁止的「转危 ⇒ duck 环境」,只是绕过了 cue 层
> 走快照层,AC-44-09 的白名单抓不到。ADR-018 §三 原文「行为 / 场景状态」措辞把病情
> (一种「场景状态」)也包了进去,使 AC-44-C1 不可证伪。
> **修订**:铁律判据收窄为 **「无 *非拟物* 触发源」** ——
> **拟物**的让位(世界因一个**你能定位的声音**而让位)合法;**非拟物**的 ducking(混音器替你
> 给这一刻打分)非法。据此:`DialogueFocus` 仅限**玩家主动发起**的对话(玩家点选病人交谈),
> **病人自发呻吟 / 咳嗽不触发**该快照(它们走 Voice 总线,不压环境)。
> **AC-44-C1 同步改写**为「无任何快照由**非拟物**的状态变化触发」。

**规则四 · 呼吸分两层渲染,精度档 = 通带与噪声底,不是静音开关(ADR-018 §四 需求①)。**
基础气流层 + 附加音层(细湿啰音等)。**低技能 ≠ 静音,低技能 = 更吵的接触噪声、更窄的通带。**
**AC-44-01(BLOCKING)**:三档下附加音层**始终非零**;断言无「档位 ⇒ 静音」路径。
**AC-44-08**:附加音层**不得**实现为连续水声(细湿啰音 = 吸气末、断续、细密的爆裂音,咳嗽后不消失)。

**规则五 · 语声走「变体库混合」,不是「参数调制」(ADR-018 §四 需求②)。**
男 / 女 × 强 / 中 / 弱 × 数种句尾;按 (病种语义, 精度档, 强度) 选变体并交叉淡化。
**禁**对已录语声做音高 / 气声 / 语速 / 断句 / 共鸣五项独立调制。

**规则六 · 接触噪声 / 信噪比是暴露参数(ADR-018 §四 需求③)。**
`Stethoscope` 总线暴露接触噪声底与信噪比,由精度档驱动。
`READ_FLOOR_MIN > 0` 在音频侧有对应实现:背景噪声永不为零,但也不毁掉信号。

**规则七 · 听诊音精度 = 本机玩家自己的技能档(2026-09-18 用户裁定 D-A,重开 2026-09-14 裁决)。**

> **⚠️ 原裁决已作废**:原写「联机下统一取**主机**技能」,**理由**是「单 `AudioListener` 每设备
> 只有一条混音总线(结构性约束)」—— 该理由**为假**,三个专家独立证伪:
> 钉死的 `audio.md:256-266` 只说「**同一时刻只有一个 `AudioListener` 处于活动状态**」
> (= 一个空间化参考点),**从未说「每设备一条总线」**。而联机是 **1-4 名玩家各自一台机器、
> 各自一个 Unity 实例、各自一套完整 `AudioMixer`**(`game-concept.md:27`)——
> 「四人共用一条总线」只在 **split-screen** 下成立,本作**没有** split-screen。
> ⇒ 每人按自己技能设档 **零同步成本**。
> **设计后果(裁定 D-A 的决定性理据)**:原裁决会让**非主机玩家的听诊保真度冻结在主机档**,
> 听觉侧的技能成长**永不发生** —— 与 `game-concept.md:124`「你认得出」及本 GDD
> §Player Fantasy 的「**你的耳朵提醒你:你没练过听**」直接冲突;
> 还会制造**反向激励**(新手当主机拖低全队保真度;老手当主机则新手可跳过学习)。

**裁决**:`SetTier(TierSource.Local)` —— 每台设备按**本机玩家自己**的技能档渲染听诊音。
技能档(一个只读整数)**由 sim 同步到表现层**;脉案字体量**早已**各自分叉(铁律⑤),
其数据路径**本就存在**(客户端已必须读本地技能值显字)—— 听觉侧复用同一条路径。
**边界**:分叉的是音**与**字,统一的是**事实**(病情由主机唯一执行,ADR-005 不变)。
**若日后支持 split-screen**,则「单总线」约束在该形态下**真实成立**,须**另开 ADR** 登记例外,
不得以本 GDD 修补。
远端实体的空间化复用 ADR-001 §一之二的 **`IPositionalChannel`**(per-`ActorId` latest-value 表,
2026-09-18 自 `IReplayPipe` 拆出),44 **只读取声源锚点、不自建位置通道、不新增 QoS 通道、不做语音通道**。

**规则八 · 44 不拥有音频素材的语义选择权。**
若「需要病种才能选素材」—— 那是上游(8 / 13)的责任,上游解析成 cue id,44 只收结果。
`AudioCueDto` 无 `disease_id`,`PresentationDtoGuard` 递归扫描覆盖。

**规则九 · 关键音频的视觉替代 = 引用 13 已交付之物 + 显式 P0 非目标(无障碍,ADR-018 §八;2026-09-18 裁定 D-C)。**

> **⚠️ 原条文是标语不是规格**:原文「关键音频必须有视觉替代」**未命名任何通道、未指派任何系统**,
> 且本 GDD §UI Requirements 明写 **44 零玩家可见 UI** ⇒ 44 **物理上无法自己渲染**替代物。
> 更根本:幻想的定义恰恰是「**看不到**病人,仅凭声音」—— 拟物视觉信号(呼吸幅度等)**需要视线**、
> **不能穿墙**,因此**没有任何视觉替代能重建那条跨房间通道** —— 那条通道**就是**论点本身。
> 而最自然的替代(面色 / 口唇发绀)是**纯颜色通道**(WCAG 1.4.1),色觉盲玩家读不出
> 「发绀 vs 苍白」—— **替代物自身不可及**。另:病人语声**无字幕 AC**(WCAG 1.2.2)。

**裁决(三条具名项 —— 承 13 的 `AC-13-F1/F2/F3` 先例)**:
1. **视觉替代 = 直接引用 `AC-13-F1`**(咳嗽 / 呻吟 / 呼吸三类 cue 均有**默认可见**对应物:
   姿态 / 面色 / 呼吸幅度;**由 13 拥有,44 不新造组件**)。
2. **显式 P0 非目标**:「**隔墙听觉检测在 P0 无视觉等价物**」—— 聋哑玩家在 P0 失去本设计的主张。
   这是**诚实登记的代价**,不是靠「双通道冗余」一句话糊过去(与 13 的 AC-13-F3 同形)。
3. **44 自己的非视觉义务**:mono 选项 · 各总线独立音量 · **病人语声字幕**(WCAG 1.2.2)。

**证据类型 = ADVISORY**(不可自动化 —— 承 `patient-ai.md:1152`「硬标 BLOCKING 只会被绕过」)。

### States and Transitions

**44 是表现层,状态是「混音 / 播放」状态,不是游戏状态。** 分两层:

**① 总线与快照层(ADR-018 §三):**

| Snapshot | 用途 | 触发(必须由行为驱动) | 回退 |
|----------|------|----------------------|------|
| `Default` | 常规游玩 | 默认 | — |
| `StethoscopeFocus` | 听诊聚焦(**只压 Ambience / Music 电平**;~~抬 Stethoscope~~ —— 2026-09-25 二轮 F7=甲:快照**不拥有** Stethoscope 组参数,「贴耳抬升 / bus 路由」归**贴耳切换脚本动作**,见下纪律) | **玩家主动**进入听诊动作 | 玩家离开听诊动作 |
| `DialogueFocus` | 语声优先(压 Ambience / Music) | **玩家主动发起**的对话(点选病人交谈)—— **病人自发呻吟 / 咳嗽不触发**(2026-09-18 修订,见规则三) | 对话结束 |
| `Paused` | 全总线衰减 | 暂停 | 恢复 |
| `VRComfort` | VR 模式(见 ADR-018 §七) | **P1b** | — |

> **快照 / 脚本参数归属分离(2026-09-18 增补)** —— Unity 快照会**插值它存储的全部参数**:
> `DialogueFocus → Default` 回退会把 `Stethoscope` 组的档位滤波 / 噪声底参数**一并拉回**
> 快照存储值,**静默覆盖脚本控制**。两个控制面从未分离 —— 这是实现期必踩的坑。
> **纪律**:快照**只拥有** Ambience / Music / Master 的音量;
> `Tier` / 接触噪声底等参数**不入任何快照**,**只由脚本驱动**。
>
> **⚠️ 2026-09-25 二轮补(F7=甲 / 玩家滑块双写半边)** —— 同一坑型还有**玩家面**:
> 玩家经设置壳调的总线音量与快照的 A/M/Master 音量是**同一 mixer 参数**时,进出听诊/暂停
> 一次快照就把玩家值**静默打回**,且 OQ-SS-5=甲 的 store 只在写入时推送、不自愈 ⇒ 耳感漂移、
> store 与耳感分叉。**结构性要求(mixer 资产纪律)**:每总线拆**两级组** ——
> 「快照 duck 组」(快照捕获)+ 「玩家音量组」(滑块直写),**快照参数集 ∩ 玩家 exposed 集 = ∅**


### F-44.1 精度档 → 通带与噪声底(听诊层)

The tier-to-filter mapping formula is defined as:

`filter_params = TierMap[Tier]`(表驱动,无运算)

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| Tier | T | byte | 0 低 / 1 中 / 2 高 | **设备级**:由 `SetTier(TierSource.Local)` 设定,来自本机玩家自己的技能档(2026-09-18 裁定 D-A);**不再是 `AudioCueDto` 字段**(见下注) |
| TierMap | — | table | — | 每档一行 **定型列集(6 列,2026-09-25 二轮 S1+Y1 回刷 —— 原 4 列/`gain` 量纲表已废)**:`{ passband_center_hz, passband_width_hz, noise_floor_db, contact_noise_floor_db, band_detail_count, signal_db }`(量纲 Hz / dB / 计数);数值**待调**(用户调,见 §Tuning Knobs)。**`signal_db` 为第 6 列(F-44.2 第三输入的唯一出处 —— 原「派生量、非列」写法使 AC-44-05 断言对象悬空,已废)** |

**Output Range:** 每档一组 { 通带范围, 噪声底 dB, **接触噪声底 dB**, 频段细节, **信号基准 dB** }。
**约束:三档的附加音层始终非零**(AC-44-01);差异必须**可辨**且**非静音型**(AC-44-02)。
**Example:** 低档 = 窄通带 + 高噪声底 + 少频段细节(摩擦声 / 衣料声混进来);高档 = 宽通带 + 低噪声底 + 全细节。

> **⚠️ 2026-09-18 修订(列集自相矛盾 / 悬空符号 —— 三处旧口径不一致)**:
> 原文有**三个名字指同一样东西、两个引用指向不存在的列**:
> ① F-44.1 的列集 = { 通带中心 / 通带宽 / 噪声底 gain / 频段细节数 };
> ② F-44.2 说 `SIGNAL_GAIN`「由 TierMap 驱动」—— **第四列幻影**;
> ③ F-44.5 用 `TierMap[Tier].breathLayer` —— **该列不存在**。
> **定型列集(唯一出处;2026-09-25 二轮扩 5→6 列)**:`TierMap[T] = { passband_center_hz,
> passband_width_hz, noise_floor_db, contact_noise_floor_db, band_detail_count, signal_db }`。
> **`signal_db` = F-44.2 的 `SIGNAL_dB` 输入**(原「派生量、非 TierMap 列」写法使 AC-44-05
> 「三量由 TierMap 驱动」的断言对象悬空 —— 二轮 Y1 阻断,已改列)。渲染侧附加层增益另见
> F-44.6 `gain_scale`(cue 级,**合成规则见 F-44.2 末注**)。`breathLayer` **删除**
> —— F-44.5 改写为 `Loop(cue, TierMap[T])`。
> **「频段细节数」给出的是计数 n,须同时给出 n 个频段的中心频率与内容**
> (细湿啰音 > 1 kHz,基础气流 < 500 Hz —— **须钉住这个数量级**,否则「细密爆裂音」无法落地)。
> **量纲钉死**:`passband_*` 单位 **Hz**;`noise_floor_db` / `contact_noise_floor_db` 单位 **dB**(见 F-44.2)。
> **`Tier` 从 DTO 移除的理由**:一个 `AudioMixer` 组是**全局共享**的,逐 cue 带 `Tier`
> 会让同 cell 内不同档的声源**互相踩滤波**;档位本质是**设备级**状态。若确需逐源滤波,
> 用**逐源** `AudioLowPassFilter` / `AudioHighPassFilter` 组件,不用共享组。
> **所有滤波 / 噪声底变化须 ramp ≥ 50 ms**(AC-44-04 现仅写「crossfade」,此处补齐为**硬下界**),
> 否则切换产生爆音 / 相位抵消。

> **设计来源**:`diagnosis-system.md:1588-1591` ——「低技能 ≠ 把啰音静音;低技能 = 更高的接触噪声底、
> 更窄的通带、更少的频段细节。这正是真实的实习医生体验。」

### F-44.2 接触噪声底 / 信噪比(暴露参数)

`SNR_dB = SIGNAL_dB − 10·log10( 10^(NOISE_FLOOR_dB/10) + 10^(CONTACT_NOISE_dB/10) )` —— 以 `Stethoscope` 总线增益实现

> **⚠️ 2026-09-18 修订(量纲破裂 —— 原公式 `SIGNAL_GAIN / (NOISE_FLOOR + CONTACT_NOISE_floor)` 已作废)**:
> 原式三个变量都声明为 **dB**,而 **dB 是对数量 —— dB 除以 dB 求 SNR 无意义**,
> 两个噪声源在 dB 域也**不能相加**。具体退化:NOISE=+30、CONTACT=−30 ⇒ **除零**;
> 两者同为负时比值是「看起来像正数的巧合」(如 −6/−85=0.071);
> 且原文的例子「低档 SNR ≈ 1:1(= 0 dB)」**根本取不到**。
> 另:**dB 越接近 0 越响** ⇒ 原文「噪声永不为零」用 dB 写是**反的**(静音 = −∞ dB)。
> **修正式**:把两个噪声源**先线性化再相加**,信号与合并噪声**相减**得 SNR(dB);
> 区间钳位 **−24 … +24 dB**。`SIGNAL_dB` **直取 TierMap 第 6 列 `signal_db`**(2026-09-25 二轮 Y1;原「由 band_detail_count 与素材派生」无式可算,已废);
> `NOISE_FLOOR_dB` / `CONTACT_NOISE_dB` = `TierMap.noise_floor_db` / `TierMap.contact_noise_floor_db`。
> **「噪声永不为零」的 dB 侧正确表述**:`noise_floor_db` 有一个**有限下界**
> (即 `READ_FLOOR_MIN > 0` 映射为「噪声线性幅度 > 0」),**不是**「dB 值 ≠ 0」(dB=0 是最响)。

**Variables:**

| Variable | Symbol | Type | Range | Description |
|----------|--------|------|-------|-------------|
| 信号 | SIGNAL_dB | float(dB) | 待调 | **= `TierMap[T].signal_db`**(直取第 6 列,2026-09-25 二轮 Y1;非派生) |
| 噪声底 | NOISE_FLOOR_dB | float(dB) | 待调(有限下界) | 背景噪声 |
| 接触噪声底 | CONTACT_NOISE_dB | float(dB) | 待调 | 听诊器摩擦 / 衣料声;随 Tier 变化(= `TierMap.contact_noise_floor_db`) |

**Output Range:** `SNR_dB` 随精度档上升(高档更高),钳位 **−24 … +24 dB**。
**硬约束:`READ_FLOOR_MIN > 0` 在音频侧有对应实现**(AC-44-06)。
**Example:** 低档 `SNR_dB ≈ −6 dB`(噪声几乎淹没信号);高档 `SNR_dB ≈ +12 dB`(信号清晰可辨)。

> **⚠️ 2026-09-25 二轮补(双增益合成规则 —— Y2 阻断)**:本式是**分析域** ——
> `SNR_dB` 只用 TierMap 三列(`signal_db` / `noise_floor_db` / `contact_noise_floor_db`)计算;
> **F-44.6 的 `gain_scale` 是附加音层 cue 级的渲染乘子,不参与本式、也不改写本式输出**。
> 两域分工:**分析域**(TierMap)= 构建期断言 `ComputeSnrDb(signal_db, noise, contact) ∈ [−24, +24]`
> —— **超界 = 配置拒绝**(TierMap 行非法,不是运行期夹);**渲染域**(gain_scale × 总线发送)
> = 运行期增益,作用于附加音层源,**不得**回写分析值。断言与实听域分离,防「断言绿但实听越界」。

### F-44.6 Intensity(byte 0–255)→ 声学量(2026-09-18 新增)

`Intensity` 在旧稿中**无任何声学映射**:数据契约声明它存在、F-44.3 拿它当选择器,
但**无公式把 0–255 映到增益 / 爆裂音密度 / 交叉淡化参数** —— `Intensity=10` 与 `250`
**听起来一模一样**。本式补齐。

```
u = Intensity / 255            // 归一 [0,1]
gain_scale   = GAIN_MIN  + u × (GAIN_MAX − GAIN_MIN)
density_mult = DENS_MIN  + u × (DENS_MAX − DENS_MIN)   // 附加音层出现密度倍率
bucket       = (u < BUCKET_LOW) ? 弱 : (u < BUCKET_HIGH) ? 中 : 强
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| `GAIN_MIN` / `GAIN_MAX` | float(dB) | 待调 | 强度映射到的增益下限 / 上限 |
| `DENS_MIN` / `DENS_MAX` | float | 待调(≥0) | 附加音层密度倍率下限 / 上限 |

### `trigger_source`(时机侧 —— 闭枚举,堵「阈值时刻的咳嗽」)

> 改数据即可过 CI);② 正文与 AC 措辞**不得**称本字段「堵住」阈值警报,只称「**依赖上游
> 诚实申报 + 负向夹具查谎报形态**」;③ **重开触发条件 3**(评审日志)持续盯防:
> 实现期若出现 false-negative(基于时序的播报绕过),须另加可检代理
> (如上游发射模块 IL 扫描禁引阈值枚举 / 发射时机与阈值事件去相关探针),本条**不得记为已解决**。

1. `whitelist_category` 必填且 ∈ 五类;

5. **`tier_map` 键集与列集**(2026-09-25 二轮):顶层 `tier_map` 必含键 `{"0","1","2"}`,每档

## Edge Cases

> 每条 = 明确条件 + 明确结局。**格式**:`If [condition]: [exact outcome]. [rationale]`。

### 听诊与呼吸层

- **If 玩家低精度档(0)听诊而病人有细湿啰音**:附加音层**非零但更吵**(窄通带 + 高噪声底),啰音**淹没在噪声里但存在**。
  **绝不静音**(AC-44-01)—— 静音 = 玩家以为漏了素材 / 以为病人没病。
- **If 玩家低精度档听诊而病人**无**啰音**:信号 = 基础气流层 + 噪声,无附加音;**
  **不**因为听不出啰音就出现「空洞」—— 那是正常现象(规则四 / F-44.1)。
- **If 档位变化导致通带突变**:交叉淡化 / 平滑过渡,**ramp ≥ 50 ms**(F-44.1 注),禁止「啪」一声切换(爆音 / 相位抵消,AC-44-04)。
- **If 天气层的进入与退出**(2026-09-19,承 5 首轮评审 B-11):同受上条约束 —— 增益变化必须走**对称淡化**,**禁硬切**;淡化的时长参数归 44(**5 不持有**)。⚠️ 淡化 ≠ 提示音:淡化是**连续声床的增益斜坡**,不携带「天气变了」的**离散事件语义**,故不触 AC-44-09 白名单;若淡化被做成**可听辨的 onset 音形**则违 AC-44-09(与 5 侧 AC-5-10 的去标注盲测联合)。
- **If 呼吸层从「急促」过渡到「停顿」**(转危):呼吸循环**连续**变慢 / 变浅,**无突变音效**(AC-44-10)。
  **停顿(昏迷)vs 停止(死亡)**:两者必须**可听辨**—— 停顿有极轻微的背景气流尾,停止完全无声;
  **但绝不**用「叮」宣告是哪个(9 的 AC-21 / ADR-018 §六)。
- **If 呼吸 cue 的循环句柄被上游重复 BeginLoop**:44 检测到同源重复循环,**以最后一次为准**,释放旧句柄;
  不叠加两条呼吸层(防「两层呼吸」bug)。
- **If 上游 EndLoop 传了过期句柄**:44 忽略;循环由唯一持有者收尾,过期句柄不产生播放错误。
- **If 上游 EndLoop 因丢包 / 断线永不到达**(2026-09-18 增补;**2026-09-25 二轮随 ADR-001
  裁决二收口**):循环 cue **必须自评兜底** —— 从最新快照 `Progress` 自行求值是否该结束
  (**P0 架构义务**);重连拉流重建 = P1b 增强(须 45 登记三条前置,不免除自评义务)。
  **不得**出现「呼吸层永不停止」(ADR-001 `ReorderBuffer` 超界丢弃已知可致此)。
- **If 附加音层播放中 13 发来一条咳嗽 cue**(2026-09-18 增补,医学准确性):
  咳嗽 cue **不得**调用 `EndLoop` 停掉呼吸循环 —— 天真实现会「咳嗽 ⇒ 停呼吸 ⇒ 重启」,
  临床上等价于**「啰音被咳掉了」**,**直接违反 AC-44-08**「咳嗽后不消失」。
  咳嗽走独立一次性一次性通道(Voice 总线),呼吸循环继续。
- **If 基础气流层与附加音层各自独立循环**(2026-09-18 增补,相位漂移):
  两层的时钟会漂移 ⇒ 爆裂音漂进**吸气中段** —— 这正是医学上禁止的错误。
  **纪律:附加音层相位锁定到基础循环的周期**,且**窗口必须落在吸气段** ——
  **⚠️ 2026-09-25 二轮 F5 重钉(原 `trigger_phase ∈ [0.6,0.95] × 基础周期` 无相位原点,
  常规读法(0=吸气起点、I:E≈1:2)整段落**呼气** —— 细湿啰音是**吸气末**事件,
  医学反相,且会被 AC-44-08 [A] 固化成构建门,已废)**:
  - **相位原点钉死:`phase 0 = 吸气起点`,周期 = 完整呼吸循环**;
  - **窗口 = 吸气段末 20%**:`adventitious_policy.trigger_phase ∈ [0.8, 1.0] × 吸气段时长`
    (以吸气起点归一;± `jitter` 仍适用,但**不得越出吸气段**);
  - **吸气占比** `INSPIRE_FRACTION`(由 I:E 派生,静息 ≈ 1/3)入 §Tuning Knobs(用户调);
  - **不得**独立自由循环(`clock_ref` 强制,校验规则 8)。

### 语声变体

- **If 变体库缺该 (病种语义 × 精度档) 组合**:回退到最近可用档的变体(高→低),**不静默**;
  编辑期烘焙门拒绝「无任何变体可回退」的 cue。
- **If 强度(Intensity)超出 0–255**:钳位到 0–255(byte 天然钳位);不产生音量突变。
- **If 语声与呼吸层同时播放**:两者走不同总线(Voice vs Stethoscope),**不互压**;
  语声优先仅由 `DialogueFocus` 快照体现,不额外 ducking 呼吸层(规则三)。

### 联机与空间化

- **If 联机下四名玩家技能不同**(2026-09-18 修订,裁定 D-A):**每人按自己技能档**渲染听诊音
  (`SetTier(TierSource.Local)`);脉案字体量亦各自分叉 —— **音与字都分叉,统一的只有事实**。
- **If 远端玩家在音频触发瞬间断线**:44 使用最近一次 `IPositionalChannel` 位置快照;
  断线后 cue 静默过期,不崩溃(表现层降级,非 sim 事件)。
- **If 病人(非玩家)在远端客户端发声**(2026-09-18 增补,**原缺口**):病人 / 受伤实体的
  表现态**锚点发布者已由 ADR-001 §一之二 登记**(9 伤情 / 13 病人 AI 的锚点持有者,**主机侧**);
  44 按 `ActorId` 读表。**无锚点的呻吟 = 无位置的声** —— 这是原稿的**未定义行为**,现由发布者登记封堵。
- **If 上游 cue 在远端客户端如何到达**(2026-09-18 增补,**原缺口 —— 关键**):
  **cue 本身不复制**。各客户端**从本地流副本 + 表现映射自行派生** cue
  (与 ADR-005「客户端持流副本」同构)。**硬前提**:13 的 cue 触发必须是
  **{ 流事件, 版本化烘焙数据 } 的纯函数** —— **禁本地 RNG、禁读表现态位置**,
  否则各客户端会**听到不同的病人**(见 AC-44-D7)。
- **If 同一 `WorldPos Cell` 同时有多个声源**:按**距离归一化** tie-break 混合
  (2026-09-18 修订,裁定 D-B:近者优先,不看类别);不逐帧重排。
  **⚠️ 2026-09-25 二轮 F3 订正**:同格整数锚点距离**恒等** ⇒ 「按距离」在同格内退化 ——
  实际序列 = `priority_class → distance → cell_jitter(ActorId) → CueId`(见优先级公式);
  等距平局由后两键确定性打破,**不逐帧重排**在**生灭时**才重算。
- **If 听者站在病人格上(d = 0)**:权重不除 d(无 `1/d`),直接落到 `cell_jitter` 键 ——
  **最近者不因 d=0 被静音**(F-44.7 多病人混合同一公式覆盖)。
- **If 同格两病人经 `LatticeToWorld` 得同一 float 锚点**:`distance` 相等 ⇒ 由
  `cell_jitter` 分出主次,均**独立 AudioSource 播放**(不合并,ADR-028 ⑤),增益差 =
  `DUCK_DEPTH_DB` 浅层 duck;NaN 路径结构性不存在(零除式已删)。

### 白名单与边界

- **If 某个 CueId 不在白名单类别中**:AC-44-09 断言失败(BLOCKING,EditMode + CI 门)。
  这是构建期拒收,不是运行期告警。
- **If 上游试图传 `disease_id` 进 `AudioCueDto`**:`PresentationDtoGuard` 递归扫描失败(AC-37-15 一致性)。
- **If 玩家暂停游戏**:切 `Paused` 快照(全总线衰减);暂停期间的循环 cue 挂起,恢复后续播。
- **If 玩家进入听诊动作后长时间无任何 cue 更新**:维持 `StethoscopeFocus` 快照(玩家行为驱动,非状态);
  **不设超时**、不自动退出(任何超时阈值若引入,须登记为调参旋钮,不得写死)。

### 素材与管线

- **If 音频素材未烘焙(开发期直接播原文件)**:开发构建允许,但**玩家构建零 JSON 解析器**
  (ADR-014 继承验证)—— 事件表必须走烘焙。
- **If 素材文件缺失**:编辑期烘焙门拒绝;运行期绝不静默播放「空 cue」(缺失 = 构建失败,不是运行期降级)。
- **If 音量 / 总线增益越界**:暴露参数钳位(音量 0–1,dB -80–0);不做「玩家把音量拉爆」的降级处理(那是玩家的选择)。
- **If Addressables 流式加载造成卡顿**(2026-09-18 增补):素材走流式,首次播放某 cue 可能
  因异步加载而**迟发**。**纪律**:高频 cue(呼吸层 / 脚步)在进入对应生态区 / 场景时**预载**;
  一次性 cue 允许极小迟发,但**不得**在听诊中因加载迟发(听诊窗预载)。**具体预载策略归 ADR-014 §五。**

> **无「the system should feel good」条款** —— 全部边界可机械验证(AC-44-01…13 承接)。
> **⚠️ 2026-09-18 修正**:原文断言「全部边界可机械验证」**与事实矛盾** ——
> AC-44-02 / 08 / 10 是**听测**(不可自动化)。正确表述:**机械可验证者 = 断言类**
> (AC-44-01 / 09 / B1–B4 / C1 / D2–D7);**听测者 = 人工证据**(AC-44-02 / 08 / 10 / 11,

### 听觉信息优先级(ADR-018 §六 白名单的播放序)

多声源竞争时的次序(承 sound-bible 模板的 Audio Feedback Priority)。

> **⚠️ 2026-09-18 修订(重心倒置 + 两个冲突的表)** —— 旧稿把**幻想的主通道(持续生理声 / 呼吸)
> 排在 4/5**,低于笔尖刮纸;无**距离感知**(隔门呼吸凭什么压过近旁的环境音?);
> 且边界案例凭空造了**第三个优先级**「关键 cue > 行为反馈 > 环境」,其中的「关键 cue」
> **未定义且不在白名单五类之内** —— 一个未定义的最高档,正是「叮」从后门溜回来的通道。
> **修订:单一出处 + 按距离归一化 tie-break**(用户裁定 D-B)。**删除「关键 cue」措辞。**

**多声源混合规则(唯一出处)**:

- **同一 `Cell` 内**多个声源 → 按**距离** tie-break(**更近者优先**),不看类别。
- **跨类别**时:**玩家自身动作 / 主动检查声**高于**世界声与生理声**(它们是玩家自己发出的、无空间意义的直接反馈)。
- **世界线索 vs 持续生理声**:**没有绝对档位** —— 两**者都是信息通道**(规则二),
  谁更近谁赢。隔一道门的呼吸**必须能压过**远处的狗吠,反之亦然。
- **环境 / 氛围**永远最低(它是底噪,不是信息)。

**排序公式(2026-09-25 二轮 F3 —— 原文只有序、无式,`d=0` / 同格退化不可判)**:

```
rank_key(source) = ( priority_class ASC,          // 上面四条的类序:自身/检查 > 世界≈生理 > 氛围
                     distance ASC,                // 同类内更近者优先
                     cell_jitter(ActorId) ASC,    // 距离也平 ⇒ 确定性第二键(见下)
                     CueId ASC )                  // 终极稳定键
```

- **`distance = 0` / 等距**:不用 `1/d`(除零),直接落到 `cell_jitter` 与 `CueId`;
- **同格多源(整数锚点距离恒等)**:先取 **确定性格内偏移** `cell_jitter =
  SplitMix64(ActorId, Cell) 派生 u16 偏移`(ADR-023 ⑦ / S7 同族,与 `LatticeToWorld` 叠加
  仅作渲染,不回写)—— 同格 N 源由此**可区分**,`AC-44-D8` 的「按距离分别空间化」可断言;
- **重算时机**:`rank_key` **只在声源生灭时重算**(挂起期间不逐帧重排 ⇒ 防增益抖动;
  跨格移动导致的名次变化并入生灭级事件窗,不逐帧)。
- **「赢」的机械语义**:rank 只决定**抢占序与 duck 深度**(高序类压低低序类至
  `DUCK_DEPTH_DB` 旋钮值),**不丢声**;`bus ≠ 优先级类别**(世界语境呼吸走 Ambience
  子通道但**优先级属「持续生理声」类** —— 环境/氛围最低档只管真底噪,
  防「主通道被当底噪压掉」)。

> **理据**:狗吠(52 的预告线索)与呼吸(9 的连续变化)**同为支柱一的信息通道**;
> 用**类别**给它们排序 = 体系性地让 52 压过 9;用**空间**排序才是玩家真实听到的世界。
> 「近的听得清、远的听不清」是物理事实,不需要设计判断 —— 也正因此它**不构成状态播报**。

> **⚠️ 本项目特有条目**:上表**没有**「危险警告」类(那是黑名单)。
> 玩家必须自己从世界线索与生理声**推断**危险,而不是从一条「警告音」被告知。
