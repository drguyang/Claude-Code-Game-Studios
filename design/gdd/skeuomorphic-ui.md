## Summary

42 是全案**唯一被允许画界面的系统**。它交出两样东西:一套**拟物元件库**(纸面 / 卷轴 / 墨迹 / 印章),
和一条**导航动作 → UI 焦点移动**的呈现通道。它**永不持有游戏状态** —— 只读 DTO、只渲染。
没有它,脉案 / 存档位 / 纸质地图 / 教学会各写各的纸,手柄玩家走不完任何一页。

> **Quick reference** — Layer: `Foundation` · Priority: `P0` · Key deps: `3 输入与设备` · `8 诊断与体征揭示`

## Overview

**42 是全案唯一被允许画界面的系统。** 它交出两样东西:

**① 一套拟物元件库。** 纸面 / 卷轴 / 墨迹 / 印章四种元件 + 九宫格切片 + 主题变量,构成
「一本书 / 一张纸 / 一个出诊箱」的视觉语汇。**任何界面都从这套元件拼出来,不各写各的纸** ——
否则每加一页脉案就多一份重复样式,且两页之间必然漂移。

**② 一条焦点呈现通道。** 手柄没有指针,而全案的手持界面**全是纸**。
42 定「导航动作 → UI 焦点移动」这一段:用**官方桥**把输入动作翻成焦点移动事件,
由引擎自己的焦点系统选邻居 —— **42 不重复实现焦点算法**。「同一时刻只有一个界面接收导航」
由**焦点单栈门**保证。

**框架是两栈的**(ADR-013):平面拟物 UI(脉案 / 存档位 / 纸质地图 / 教学)走
**UI Toolkit**(UXML + USS 元件库);世界空间与 VR 走 **UGUI world canvas**(VR 必须 World Space)。
两栈**共用同一个 EventSystem**。

**玩家侧的效果是一句话:你手上是纸和墨,不是 HUD。** 没有血条,没有小地图,
没有进度条,没有「X/5 已查」。状态反馈全部压在**质感、纸声、焦点反馈**上
(声音侧归 44,42 只出触发)。**代价是信息可读性**:一旦把数字都拿掉,
「我到底看懂了没有」这件事必须由**纸面的物理形态**回答 —— 这是本系统真正的技术挑战。

**两条边界(42 最容易越界之处)**:
- **42 不拥有形态** —— 「体征 → 呈现形态」的映射表归 **8 诊断**(那是医学知识,不是渲染知识);
  「病例页该显示什么」归 **37**;42 只负责把它们**画出来**。
- **42 不持有游戏状态** —— 42 是纯渲染器,只读 DTO(`IVitalsQuery → VitalsDto`),
  **零模拟写**。UI 一旦持有第二份真相,事件流就不再是唯一真源。

## Player Fantasy

**核心幻想:你手上拿的是器物,不是仪表盘。**

这个幻想有**两层**,一层是玩家直接感到的,一层是玩家**感觉不到才算成功**的。

### 一、直接层:纸有物性

玩家触到的每一个界面都是**一件东西**,不是一层浮在屏幕上的信息。

| 该感到的 | 由什么产生(42 侧) |
|---------|------------------|
| **纸在手上** | 纸面元件的纹理与边角 · 翻页时页面的物理序列(不是滑动的列表) |
| **墨还没干** | 刚写下的字与写了一阵的字**观感不同**(墨色深浅 / 洇开程度);改写留痕 |
| **这是我的笔迹** | 脉案的病名栏是**玩家指认的**,体征栏是**系统写下的** —— 两者同源同纸、**同一手笔迹**,但**属主不同**(分栏:8 的 UI-8.1「五通道区 + 两栏」) |

> **⚠️ 这一行的边界(2026-09-17 首轮评审补齐)**:全案**零 freehand 输入通道** —— 手柄没有手写板,
> 病名走**拟物病名册翻页指认**(`diagnosis-system.md:345`),体征词的笔迹是 8 定的
> **有限变体族**(每词 3–4 变体 × 3 档浓度,`:1458`)。**42 不采集真实笔迹**,只渲染变体。
> 「我的笔迹」是**视觉归属感**,不是输入方式 —— 数据路径见 §Core Rules 规则十三。
| **旧了的东西有旧的记号** | 页边的**铅笔小勾**(临床病历的物理做法),靠**形状**不靠颜色 —— 色盲可读 |
| **器物有重量** | 出诊箱是**箱子**,不是背包格;纸是**纸**,不是按钮 |

> 承 `game-concept.md:534` 的视觉铁律:**「如果它不能画在一本《脉案》、一张纸质地图
> 或一个出诊箱上,就重新设计。」** 42 是这条铁律在实现层的唯一出口 ——
> 凡 42 画不出「画在纸上」的东西,不是 42 该扩张,而是**那个东西不该存在**。

### 二、间接层:框架的存在感为零

**成功的 42 是玩家从未意识到存在的 42。**

| 玩家不该察觉的 | 如果做对了 |
|---------------|-----------|
| **我在用手柄** | 焦点移动像手指落在纸上一样顺 —— 手柄玩家与键鼠玩家走**同一条**阅读路径,没有「手柄模式」 |
| **界面在做排版** | UI Toolkit 保留模式:只有脏元素重绘。界面**不该有帧率的存在感** |
| **这套界面是「风格」** | 拟物不是皮肤。它是**信息载体** —— 拿掉纸纹,信息就少了一层 |

> **⚠️ 反幻想声明(写在本节,因为它约束后面每一条规则)**:**拟物不得成为装饰。**
> 若某个拟物形态让信息**更难读**、或只是「好看但无信息」,它就该让位。
> 42 的合法性来自**「无血条之后,状态怎么被看见」**,不来自「复古好看」。
> 同理,`game-concept.md:140` 已写明:**无血条 ≠ 无反馈。**

### 三、这一层为什么值得写

MDA 的 **Sensation(感官愉悦)** 在本作是**独立**的一项目标(`game-concept.md:87`),
不是玩法成功的副产品。42 是该项的主要承重件 —— 与 44 音频并列:

- **42 出视觉的质感**,**44 出声音**(`audio-system.md:139`「42 拟物 UI → 笔尖 / 翻纸 / 器物 → UICue 总线」);
- 两者**同构**:只触发 / 只渲染,永不持有状态。

### 四、谁不该感到这个幻想

**敌人有黄铜质读数条**(`game-concept.md:779`:遭遇时出现、脱战淡出、挂在敌人身上),
且**读的是「身体作为机器」**—— 属视觉方向的**黄铜侧**,与主角的**水墨侧**同位不同材。
**主角自己永远无血条。** 42 须同时承载这两种材质,且**不得让它们互相渗透**:
敌人的读数条不得长成一张纸。

#### 规则一 · 两栈分工(三行表,唯一分界线)

| 界面 | 栈 | 档位 |
|------|-----|------|
| **平面拟物 UI** —— 脉案(39)· 存档位(7b)· 设置界面 · 20 的库存容器 · 48 教学 · 43 纸质地图(P1a) | **UI Toolkit**(UXML + USS 元件库) | **P0** |
| **敌人读数条**(挂在敌人身上,一个敌人一条) | **UGUI world canvas** | **P0** |
| **VR 急救 UI**(站定式小游戏) | **UGUI world canvas,必须 World Space** | **P1b**(见规则十二) |

> **⚠️ 四轮就地覆写(本条与 ADR-013 §二 相抵,已裁)**:ADR-013 §二 原文把
> 「VR / **world-space** 的两栈适配」整体推到 P1a。但 `game-concept.md:779` 的「丙」裁决
> (敌人**有**黄铜质读数条,**挂在敌人身上**)在 **P0 就要生效** —— 27 敌人 AI 是 P0,
> 而 P0 的开场遭遇就是兵痞。**原口径 ⇒ P0 的战斗没有状态反馈。**
> **用户裁定(2026-09-16)**:**world-space 栈的最小实现提到 P0** —— 只做「一组世界锚点 → 一张 billboard 面片」
> 这一条路径,**不做**立体渲染、**不做**深度冲突处理、**不做** VR 适配。
> **ADR-013 §二 须同批就地修订为**「**最小实现 P0 · 立体 / XR 适配 P1a**」。
>
> **归属澄清(与 ADR-020 §六 的接缝)**:ADR-013 §一 表里那行「World-space UI(世界空间**体征提示**)」
> 指的是**主角自己的体征世界层呈现**。该面已由 **ADR-020 §六** 判给「8 语义 + **2 摄像机 / shader** 实现」
> —— 主角视野边缘是**水墨渗边**,不是一条 UI 元件。**42 不收这一条。**
> ADR-013 §一 该行须同批订正为「**敌人读数条 / 世界锚点提示**」。

#### 规则二 · 两栈共用同一 EventSystem

- **全案只有一个 `EventSystem`**,两栈共用;UI Toolkit 走 `PanelRaycaster`,UGUI 走 `GraphicRaycaster`
  —— **这是「两条射线通道」,不是「两个事件系统」**。
- **禁**并存 `InputSystemUIInputModule` 与 `StandaloneInputModule`; **禁**双 `EventSystem`。
  (`StandaloneInputModule` 属 Legacy Input Manager,已由 ADR-011 弃用。)
- **z 序是两份,不是一张对照表(2026-09-17 订正)**:`Canvas.sortingOrder`(相机域)与
  `PanelSettings.sortOrder`(**覆盖层域**)分属**两个合成域**,**两个数不可比**。
  42 拥有的是**两张域内序表**:① 覆盖层内(平面 UI 各屏之间谁压谁);② 相机内(读数条与世界几何谁压谁)。
  **各自域内不得撞号**;任一侧调值**必须同批改配置**。
  **⛔ 不存在「调一个数让读数条盖住纸面」这件事** —— UI Toolkit Overlay 面板**恒在全部相机之后**合成,
  这是引擎的结构性事实(**详见 F4 的三层口径**)。旧稿的「z 序须对齐」暗示两数可比,**已删**。

#### 规则三 · 焦点单栈门(同一时刻只有一个界面在收导航)

- 42 维护一个**全局唯一**的「当前活跃栈」状态;**同一时刻仅一栈**消费 ADR-011 的导航意图流。
- **模式切换 ≠ 两门同时开。** 切换走**先关后开**:旧栈的门先关,新栈就绪后再开。
  中间**允许**存在一个**两门皆关的窗口**(玩家按导航键无反应,量级 = 一帧)——
  **这是可接受的;「两门皆开」不可接受**(= 一次按键两次焦点移动)。
  **「原子」的定义 = 对外永不可观测到「两门皆开」**(不是「窗口恒为零」,见 §Formulas F8 的裁定块)。
  窗口内**不得再触发**一次切换(不可重入)。
- **禁**由 3 来判定谁持有焦点:3 **不得**有任何「当前哪一栈持有焦点」的**读取**(`AC-3-C3` BLOCKING)。
  42 自判,3 不知道。

#### 规则四 · 焦点导航呈现侧 = 官方桥,引擎自动移动

- **链条**:导航动作 → 官方桥 → 引擎焦点系统选邻居 → 焦点移动。**42 不实现焦点算法。**
- **禁同键双触发**(三种来源,逐条禁):① 同一控件同时被官方 `Navigate` action 与自建焦点动作绑上;
  ② 双 EventSystem;③ 模块「自动启用 UI 动作」与手写 action asset 同时生效。
  **冻单一来源** —— 只用官方 `Navigate`(承 `adr-011` §三 F1 / 本 ADR §五,已由 `AC-3-C1/C2` 守门)。
- **降级路径(预先写死,不进下一轮争议)**:若 P0 早期 spike 判定引擎焦点质量不达预期,
  降级 = **自实现焦点算法**。此时 `FocusNavigationIntent` 接口**不变**(3 侧零改动),
  只换 42 的实现 —— 两栈边界与元件库契约也**不变**(ADR-013 §Rollback 原文)。
  **装配位置(2026-09-17 补齐 —— 原稿未写,留了一个会让两道门互斥的洞)**:
  降级代码住在 **42 自己的程序集内**,**不新开程序集、不改 `AC-42-A4` 的白名单**。
  理由:自实现焦点算法须读元素几何 ⇒ 须引 UI 呈现 API;而 `A4` 断言「42 是全案唯一
  被允许引用 UI 呈现 API 集的程序集」。**放 42 内 ⇒ 两道门同时成立;放别处 ⇒ 二选一。**
  对外契约面(导出类型)**在降级前后逐条相同**(由 `AC-42-B4` 的收窄口径 + `AC-42-A3a` 守)。
- **P0 焦点载体前置门(承 3 的四轮裁定)**:`AC-3-A1` 在 P0 平面**关掉了**它唯一依赖的
  「官方桥资产同一性」断言(42 尚未成文时无法断言)。**42 的 GDD 必须补上这三问**:
  ① **P0 焦点载体是谁**(答案:UI Toolkit 官方桥那一个 action 实例);
  ② **由谁断言**(答案:42 侧的 EditMode 结构性断言 —— 判据只断**性质**,不引 post-cutoff 符号名);
  ③ **spike 失败降级路径**(答案:上行那段,自实现焦点算法,接口不变)。

#### 规则五 · 拟物元件库(唯一视觉语汇的出口)

- **四种元件**:纸面 / 卷轴 / 墨迹 / 印章。**九宫格切片** + **主题变量**(纸色 / 墨色 / 字号)。
- **界面从元件拼出来,不各写各的纸。** 新增一个界面若需要第五种元件,**先改元件库**,
  再让界面消费 —— **禁**在界面内联样式里手写一份变体。
- **两栈语义对齐**:UGUI 侧(世界锚点 + P1b 的 VR)**同名元件**,观感一致。
- **跨栈例外须审**:若某拟物效果**必须程序化**(UI Toolkit 运行时自定义材质受限,F5),
  该元件**可迁到 UGUI 栈** —— 但**语义仍在同一元件库**。个别元件跨栈是**允许**的,
  静默地各写一套是**禁止**的。

> **⭑ 2026-09-22 注块(元件库构成的三项边界裁定 · 用户裁定 —— 六屏 spec 的扩员请求归并)**
>
> **病因**:六屏 per-screen spec 各自向本库提了扩员请求(OQ-CB-4 / OQ-SB-4 / OQ-SS-4 / OQ-IC-4),
> 却**无一处持有裁决权** —— 与「记号登记表」的旧病同型(形状数 < 语义数),但这次是**档数**:三个

### States and Transitions

42 有**两个**独立的状态机。二者**不得互相推断**。

#### A. 焦点门状态(全局唯一一个「当前活跃栈」)

| 状态 | 进入条件 | 退出条件 | 行为 |
|------|---------|---------|------|
| **平面独占** | 处于平面模式 | 切到 VR 模式 | UI Toolkit 栈消费导航意图;UGUI 栈**不消费**(但仍渲染读数条) |
| **世界空间独占** | 处于 VR 模式 | 退出 VR | UGUI 栈消费;UI Toolkit 栈**不消费、不渲染** |
| **(过渡)两门皆关** | 模式切换的中间态 | 新栈就绪 | **两栈都不消费** —— 玩家按导航键无反应,量级 `0 ≤ W_trans ≤ 1 frame`(F8) |

> **⚠️ 不存在第四个状态「两门皆开」。** 若实现里出现它,即是 `AC-3-C2` 所禁的同键双触发。
> **(过渡)态是合法态,不是异常** —— 它存在的**唯一**理由是让「先关后开」可实现;
> `W_trans = 0`(同帧提交)亦合法。**原子性只禁「皆开」,不禁「皆关」。**
> 过渡态内**不可重入**(切换操作合并 / 去重,见 F8)。

#### B. 呈现根的绑定生命周期(每个界面各有一份)

| 状态 | 进入条件 | 退出条件 | 行为 |
|------|---------|---------|------|
| **未绑定** | 初始 | `Bind(source)` | **不渲染任何数据驱动内容**;元件与布局仍可渲染 |
| **已绑定** | `Bind(source)` | 重绑 / 释放 | 只读 DTO 渲染;**不缓存 DTO 副本**(缓存 = 第二份真相) |
| **重绑中** | 收到新的数据源 | 旧订阅撤除完毕 | **先撤旧订阅,再建新订阅** —— **禁两源同时绑定**(会渲染双份) |

> **边界(承 3 的登记)**:重绑发生时,进行中的拖拽 / 长按**会中止**。
> 这是**设计取舍**(承 `input-system.md` 的同类登记),不是 bug —— 42 不为此保留跨源手势状态。

### F1 · 九宫格切片守恒

九宫格切片公式定义为:

`W_min_req = SL + SR + C_min` · `H_min_req = ST + SB + C_min` · `W_draw = SL + C_target + SR`

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 左 / 右切片宽 | `SL` / `SR` | length | 主题变量,`> 0` | 纸张左 / 右边角不随尺寸拉伸的宽度 |
| 上 / 下切片高 | `ST` / `SB` | length | 主题变量,`> 0` | 上 / 下边角 |
| 内容最小可用区 | `C_min` | length | `> 0` | 内容区**不得小于**的底线(见下注) |
| 目标内容区 | `C_target` | length | `≥ C_min` | 实际要放内容所需的宽 |
| **需求最小宽** | `W_min_req` | length | 由上式导出 | **算出来的**,不是主题声明的 |
| **布局实际最小宽** | `W_min_actual` | length | 主题 / 布局变量 | 该元件在布局里被允许缩到的最小宽 |
| 绘制宽 | `W_draw` | length | `≥ W_min_req` | 元件最终宽 |

**输出范围**:正常玩法下 `C_target ∈ [C_min, W_max_available]`。
**退化行为**:`W_draw < SL + SR + C_min` ⇒ 内容宽为**负** ⇒ 内容被边角吞掉,或纸角被反向挤压成畸变。

**装载期反例断言(核心)**:**`W_min_actual ≥ W_min_req`** —— 即
**主题声明的可缩下限,不得小于切片与内容底线的算术和**。
反例:`SL = SR = 0.6·W_min_actual` ⇒ 装载**失败**(此时 `W_min_req = 1.2·W_min_actual + C_min > W_min_actual`)。

> **⚠️ 2026-09-17 就地修正(首轮评审第 7 项之一 —— 旧式是循环的)**
> 旧稿同时写了 ① `W_min = SL + SR + C_min`(**定义**)和 ② 断言 `SL + SR + C_min ≤ W_min`(**判据**)。
> 把 ① 代入 ② 得 `W_min ≤ W_min` —— **恒真,零信息**。这条「硬下界」永远不可能红。
> **病因**:一个**导出量**被拿来当作被约束量,断言因此退化为恒等式。
> **修法**:拆成**需求**(`W_min_req`,算出来的)与**实际**(`W_min_actual`,主题/布局声明的),
> 断言两者的大小关系 —— 这才是真正会失败的命题(缩小切片 / 放宽下限 ⇒ 红)。

**`C_min` 是什么、不是什么(2026-09-17 澄清)**:
- **是**:内容区在一维上的**绝对底线**(length,与字号档**无关**的物理量)—— 「这张纸再小,中间也得留得下这么多」。
- **不是**:字号 × 一个字宽。若把它定义成后者,则它会随 **49 的 `textScale`** 变动,
  而 F2 的 `fs_actual` 已被 `clamp` 到 `[fs_min, fs_max]` —— 两张纸的相互关系会变成**隐式**的。
  **`C_min` 保持为常量**,`textScale` 的影响走 **F2 的 `lineCount`**(行数增长 ⇒ 续页),
  不回流到 `C_min`。**这条链必须是单向的:F1 → F2,不得反向。**

**归属**:**42 自有**。

### F2 · 文本贴合(纸面容量)

文本贴合公式定义为:

`fs_actual = clamp(fs_theme × textScale, fs_min, fs_max)`(要求 `fs_min ≤ fs_max`)
· `N_max = max( 1, floor( C_target / advance(ch, fs_actual) ) )`
· `lineCount = ceil( N / N_max )`(**要求 `N ≥ 1` ⇒ `lineCount ≥ 1`**)
· `H_req = ST + SB + lineCount × LH(fs_actual)`

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 单行可容字数 | `N_max` | int | **`≥ 1`(经 `max` 钳制)** | 当前纸宽下每行几个字 |
| 字宽推进量 | `advance` | length | `> 0` | 一个字符推进多宽(中文全宽 / 西文比例) |
| 主题字号 | `fs_theme` | length | 主题变量 | 该纸面的默认字号 |
| 文本缩放 | `textScale` | float | `> 0` | **归 49 无障碍**(42 只消费) |
| 字号下限 / 上限 | `fs_min` / `fs_max` | length | **`0 < fs_min ≤ fs_max`** | 夹紧区间(**须自洽**,见断言) |
| 实际字号 | `fs_actual` | length | `[fs_min, fs_max]` | 夹紧后实际使用字号 |
| 待排字数 | `N` | int | **`≥ 1`** | 该段文本的字符数(`N = 0` ⇒ 无文本,不进本式) |
| 行高 | `LH` | length | `> 0`,随 `fs_actual` | 单行占高 |
| 行数 | `lineCount` | int | **`≥ 1`** | 折行后的行数 |
| **需求最小高** | `H_req` | length | 导出 | **纸面必须给够的高度** |

**输出范围**:`lineCount ∈ [1, 纸面可容行数]`;`H_req` 与 `W_min_req` 一起决定该段文本
**是否需要续页**(V-11 / E-10)。
**退化行为**:
- `advance = 0` ⇒ 除零 ⇒ **装载期断言拒**(不是运行期兜底);
- `N_max` 未钳制且 `C_target < advance` ⇒ `N_max = 0` ⇒ `ceil(N/0)` **除零** ⇒ 故 `max(1, ·)` 是**承重**的
  (一维纸面放不下一个字时,结果是「一行放一个溢出字 + 报冲突」,不是崩溃);
- 字体缺字 ⇒ 豆腐块 / fallback 字宽突变;
- `textScale` 叠加后超纸宽 ⇒ **42 不得裁改形态**,须**报冲突**(规则七的拒绝权)。

**装载期反例断言**:
① `advance > 0`(每字号档);
② **`fs_min ≤ fs_max`**(区间自洽 —— 反例 `fs_min = 20, fs_max = 12` 必须使装载失败);
③ 缺字 fallback 字体**位存在**;
④ `LH > 0`(每字号档)。

> **⚠️ 2026-09-17 就地修正四处(首轮评审第 7 项之二 —— 旧稿四处规格错误)**
> ① **`N_max = 0` 除零**:旧式 `floor(C_target / advance)` 在窄纸面上直接得 0,
>    `lineCount = ceil(N / 0)` **未定义**。修法:`max(1, ·)` 钳制 + 把它写进**退化行为**(不是隐藏的兜底)。
> ② **`N` 未定范围**:`N = 0`(空串)会让 `lineCount = 0`,与「`lineCount ≥ 1`」矛盾。
>    明写 **`N = 0` 不进本式**(空位是「可聚焦但零文本」,归 `AC-42-B5`,不是 0 行文本)。
> ③ **缺竖向再耦合**:旧式只算行数,**没算行数对高度的影响** ⇒ 「字号放大 ⇒ 行数增加 ⇒ 溢出纸面」
>    这条**最关键的链断了**,而 E-10(`textScale` 溢出报冲突)正依赖它。补 **`H_req`**。
> ④ **`fs_min ≤ fs_max` 缺断言**:夹紧区间的两个端点无相对约束 ⇒ 反例配置静默产出**负区间**,
>    `clamp` 行为依赖实现细节。补断言 ②。

> **⚠️ `fs_max` 的语义是截断,不是拒绝(与 E-10 的接缝,须与 49 对齐)**
> 本式的 `clamp(fs_theme × textScale, fs_min, fs_max)` 在 `textScale` 很大时**把字号压在 `fs_max`** ——
> 结果是**玩家的放大请求被静默吞掉一部分**(他要 ×2,给了 ×1.4)。
> **这是本式已知的、有意的行为收窄**,但仍需**显式登记**,否则会与 49 的承诺冲突:
> - 42 **保证**的是:**不因字号而裁切 / 缩到不可读 / 破纸**(规则七的拒绝权);
> - 42 **不保证**的是:**玩家的每一个缩放档位都被逐点兑现**。
> - 若 49 的无障碍要求是「档位必须逐点生效」,那么**瓶颈是纸面尺寸,不是 42 的实现** ——
>   据此**重新登记 `OQ-42-2`**(见 §Open Questions 的改写条)。
> - **中间路径(供 49 参考)**:超 `fs_max` 而不溢纸时,可走 **V-11 的续页**
>   (多一页 ≠ 裁切)—— 42 侧接口已具备,是否启用归 49 定。

**⚠️ 须 spike 核验的符号**:文本度量 API 族(**疑为 `MeasureTextSize` 系列,置信度中**)——
判据只断 `advance > 0` / `LH > 0` 的**性质**,不引符号名。

**归属**:**42 自有规则**;输入引用 **49**(`textScale`)/ **50**(字符串)。

### F3 · 布局可达性与焦点 rank 契约(**不是**焦点算法)

> **⚠️ 前提(2026-09-17 首轮评审补 —— 本节旧稿缺了这条,导致整节成立性悬空)**
> **引擎的焦点移动是几何的,而 8 的焦点顺序是语义的。** UI Toolkit 的 `FocusController`
> 消费 `NavigationMoveEvent` 后**按元素在屏幕上的几何位置**选「左 / 右 / 上 / 下的邻居」
> (空间投影),而 8 诊断的 UI-8.2 定的顺序是
> **面色 → 语声 → 姿态 → 呼吸 → 触感 → 病名 → 置信度(固定不重排)** —— 一条**语义**序。
> **二者只有在布局把语义序「画成」几何序时才一致。** 这不是风格问题,是**架构前提**:
> 布局若把置信度画在体征栏左边,玩家的手柄路径就会**先到置信度**,而 8 的语义序要求最后到。
> ⇒ **本节的 rank 契约因此增殖为「布局可达性」的书面约束**(下表),由 42 拥有、由布局满足。

**布局可达性约束(几何序 ⊇ 语义序)**:

| 约束 | 内容 | 违反后果 |
|------|------|---------|
| **L1 · 单块** | 同一语义序内的元素,在**任一分支下的几何布局**中都构成一个**不自交的阅读块**(不把序 2 的元素画到序 4 元素的右下 / 左下) | 手柄走位与语义序背离,固定序失效 |
| **L2 · 可走** | 从序 1 到序 K,**每一步都存在一个「向下一序」的方向键**(无死胡同 / 无跳序) | 某元素永远走不到(`K` 的满射在几何上失效) |
| **L3 · 不越栏** | 两栏布局下,**先走完一栏再进另一栏**,不得出现「栏间来回跳」 | 阅读被打断,玩家不知道自己在哪 |
| **L4 · 空位不夺焦** | 空 / 未查位置**可聚焦但零文本**(`AC-42-B5`),**不得**因「无内容」而被布局塌缩掉 | 焦点跳过一个语义位,玩家以为漏了 |
| **L5 · 重排守恒** | `AC-42-E` 组定义的重排事件触发后,L1–L4 **仍成立**(重排不是可达性的豁免) | 分辨率变更后手柄路径静默失效 |

> **判据形态**:L1–L5 是**布局约束**,不是运行期断言 —— 落在 §七 的**手工走查**载体上
> (P0 无自动几何断言;若后续引入布局 lint,则升为 CI 门)。**勿写成「引擎会保证」**:
> 引擎只保证**几何**邻居存在,不保证**几何邻居恰好是语义邻居**。

焦点 rank 契约定义为:

`rank: Focusable → 1..K`,且须满足**满射 + 单射**:`img(rank) = 全部可聚焦集` 且无重号。

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 本屏可聚焦元素数 | `K` | int | `≥ 1`(**P0 不开 0 屏,见退化**) | 该界面有几个可聚焦元素 |
| rank | `rank(e)` | int | `[1, K]` | 元素在**语义序**中的名次 |

**输出范围**:`rank` 恰好用满 `1..K` 一次。
**退化行为**:
- `K = 0` ⇒ 门**不应开** —— 若开了即是「门开着、无焦点 ⇒ 手柄按导航无反应」的**静默死锁**。
- `K ≠ |可聚焦集|` ⇒ **漏焦点元素**(某元素永远走不到),静默。

**装载期反例断言**(断**屏定义数据**,不断运行期函数 —— 见 `AC-42-B1` 的改锚说明):
① 每屏 `K ≥ 1`;**② 值域恰为 `1..K`(满射)**;③ 无重复 rank(单射)。
**判据本体是数据**,`rank` 是这份数据的**读法**。

> **⚠️ 42 不拥有 rank 的**语义**。** 焦点**顺序**(面色 → 语声 → 姿态 → 呼吸 → 触感 → 病名 → 置信度,
> 固定不重排)归 **8 诊断**(UI-8.2,规则七)。42 只持有「这样一个双射**存在**且**可断言**」的契约。

**归属**:契约 **42** 持有;顺序语义归 **8**。

### F4 · 两栈 z 序:先说清「两个数不可比」,再定谁压谁

> **⚠️ 本节已于 2026-09-17 就地重写(首轮评审 structural 提出,原稿的**前提**是错的)。**
> 旧稿把两栈 z 序写成一个**跨域全序**:`S_UITK = φ(S_UGUI)`,`φ` 严格单调 + 单射,
> 读者据此以为「调 `φ` 就能决定纸面与敌人读数条谁在上面」。**这是不可能的**:
>
> | 栈 | 合成域 | 关键引擎事实 |
> |----|-------|-------------|
> | **UI Toolkit(平面)** | **独立于相机的覆盖层** | `PanelSettings` 的 **Overlay** 模式在**全部相机之后**合成;**不参与**任何相机的深度排序 |
> | **UGUI world canvas(黄铜侧)** | **相机内** | World Space canvas 是**场景里的几何**,由相机按距离 / `sortingOrder` 在**相机内**排序 |
>
> ⇒ **两个数不是同一把尺子上的两个值** —— 它们是**两个不同合成域各自的序号**。
> `φ` 若存在,也只能是「**我的覆盖层 vs 你的场景几何**」这种**跨域偏序**,
> 而**不是**旧稿写的那种「取个单调函数就能比较」的全序。
> 旧稿的装载期断言(「`φ` 严格单调 + 单射」)**因此是在断言一个不存在的对象**。

**重写后的口径 —— 三层,从下往上:**

| 层 | 谁 | 由什么决定 | 可断言的形式 |
|----|----|-----------|-------------|
| **L1 · 相机内** | 世界几何 / 敌人读数条(UGUI world canvas)/ 主角 | 相机按**距离 + `sortingOrder`** 在**相机内**排序 | `S_UGUI` 及其**内部**一致性(**是本域全序**) |
| **L2 · 跨域** | 「覆盖层 vs 相机内」 | **Overlay 恒在所有相机之后** —— 这是一个**引擎结构性事实**,不是可调参数 | **不是** `φ` 能表达的东西;它是**二值**:覆盖层在相机之上 |
| **L3 · 覆盖层内** | 平面拟物 UI(纸面 / 卷轴 / 存档位 …) | `PanelSettings.sortOrder` 在**覆盖层域内**排序 | `S_UITK` 及其**内部**一致性(**是本域全序**) |

**⇒ 由此得出两条设计裁决:**

1. **黄铜侧读数条**永远**不可能**盖住**任何** UI Toolkit 平面 UI —— **这是引擎给的结构性保证**,
   不需要 42 做任何事(`AC-42-F4` 的判据随之从「`φ` 单调」改锚到这个**结构性声明**)。
2. **真正需要 42 管的是两份「域内一致性」**:
   - **① 覆盖层内**:平面 UI 各屏之间谁压谁(如模态页压住底层脉案)—— 由 `S_UITK` 表决定;
   - **② 相机内**:读数条与**世界几何**谁压谁(如读数条不该被墙挡住 —— **P0 已知限制**,`OQ-42-9`)
     —— 由 `S_UGUI` 表决定。
   **两张表各自内部一致,且各自只在本域内有序。** **不存在「把两张表合成一张」这个动作。**

| 变量 | 符号 | 类型 | 域 | 含义 |
|------|------|------|----|------|
| 覆盖层内序号 | `S_UITK` | int | **覆盖层域** | `PanelSettings.sortOrder`(**须 spike 核验属性名**) |
| 相机内序号 | `S_UGUI` | int | **相机域** | `Canvas.sortingOrder`(**须 spike 核验属性名**) |
| ~~跨域映射~~ | ~~`φ`~~ | — | — | **已删** —— 跨域是**结构性二值**(L2),不是可映射的序 |

**装载期断言(重写后)**:① `S_UITK` 表内**无重复序号**(同域内总序良定义);
② `S_UGUI` 表内**无重复序号**;③ **两表任一侧调值必须同批改配置**(CI 断言表与配置一致)。
**旧断言「`φ` 严格单调 + 单射」已废** —— 它断的是一个不存在的对象。

**归属**:**42 自有**(规则二)。**⚠️ 规则二的措辞须同批订正** —— 旧写「z 序须对齐」暗示两数可比,
应改为「**两份域内序各自一致;跨域由引擎结构性决定**」。

> **⚠️ 为什么这条重写重要(不是措辞洁癖)** —— 旧口径会把实现诱导到一条**注定失败的路**:
> 写一个 `φ`、调它、期望读数条与纸面的相对层序随它变化。
> 而引擎**根本不会**让世界几何盖住 Overlay 面板 —— 实现者会得到「调了没用」的结果,
> 然后归因为「spike 没做对」,而不是「数不可比」。**这是最难查的一类 bug:`φ` 的实现完全正确。**

### F5 · 图集页数预算

图集页数公式定义为:

`Pages_total = ceil( Σ_i pad2(w_i + 2·p) × pad2(h_i + 2·p) / A_page )`,
约束 **`Pages_frame ≤ Pages_max`**(**逐帧同时可见的页数**,不是总页数)

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 元件纹理尺寸 | `w_i` / `h_i` | px | `> 0` | 第 i 张元件纹理 |
| 图集填充 | `p` | px | `≥ 0` | 图集内边距(**须 spike 核验**,通常非 0;漏掉会低估) |
| 对齐取整 | `pad2(·)` | px | — | 图集通常按 2 的幂 / 4 对齐打包,直接按原尺寸求和会低估 |
| 图集单页可配额 | `A_page` | px² | `> 0` | `PanelSettings` 图集单页可容面积(须 spike 核验配置项名) |
| **全部**页数 | `Pages_total` | int | `≥ 1` | 整个元件库打包后占几页 |
| **单帧同屏**页数 | `Pages_frame` | int | `≤ Pages_total` | 某一屏实际取到几页 |
| 页数上限 | `Pages_max` | int | **由 spike 定,留白** | 超过即**断批** |

**输出范围**:`Pages_frame ≤ Pages_total`;约束施加在 **`Pages_frame`** 上。
**退化行为**:`Pages_frame > Pages_max` ⇒ 该屏的 UI **批次被打散**(一个面板的绘制要跨 N 个纹理 ⇒
N 个 draw call,且与其它 UI 的批次无法合并),UI 帧时间上升 ——
后果**不是「不好看」,是「断批」**(规则十一)。`A_page → 0` ⇒ 除零。

**装载期反例断言(核心 —— 2026-09-17 修)**:
**从实际的元件 / 纹理清单算出 `Pages_total`,再按 §UI Requirements 的逐屏取用关系算出
`Pages_frame`,断言 `Pages_frame ≤ Pages_max`** —— 两侧都是**同一份数据源**导出的。

> **⚠️ 2026-09-17 就地修正(首轮评审第 7 项之三 —— 旧稿是量纲不齐的)**
> 旧稿:公式断言的量是**面积**(`Pages = ceil(Σ 面积 / A_page)`),
> 而装载期断言断的量是**计数**(`元件数 × 每元件纹理数 ≤ 上限`)。
> **两边量纲不同 ⇒ 断言红不代表公式被违反、公式被违反也不必然让断言红**;
> 且 `Pages_max`(页数)与「元件数 × 纹理数」(张数)根本**不是同一个单位的阈值**。
> **修法**:断言直接落在 `Pages_*` 上,且**用同一份纹理清单**代入公式 —— 消除第二个隐性口径。
>
> **⚠️ 第二个修正(更承重)**:旧稿约束的是**总页数**。但断批的真实条件是
> **「一屏内同时用到的图集页数超过阈值」** —— 元件库共 8 页没关系,只要**任一屏最多取 2 页**就不会断批。
> 约束错了量,会把一个**可缓存的大库**误判成性能问题(导致有人去砍元件,砍错东西)。
> ⇒ 约束改锚到 **`Pages_frame`**;`Pages_total` 只作为**内存与打包**的观测值,不是门。
>
> **⚠️ 第三处(易漏)**:`p`(填充)与 2 的幂对齐未计入 ⇒ 面积和**系统性低估**,
> 一个「刚好卡在上限」的估算会静默超页。故显式写进公式。

> **⚠️ 与 `OQ-42-3` 的接缝** —— **✅ 2026-09-22 已消解**(`OQ-42-3` = 甲「不虚拟化(翻页制)」):
> 全案走翻页制、**不虚拟化** ⇒ 单页可视元素集是**页内容的函数**(**非**滚动位置的函数),
> `Pages_frame` 语义**确定**,本式**无需回填**。原「虚拟化若启用则含义变」的分支**不触发**。

**归属**:**42 自有**(规则十一)。

### F6 · 世界锚点面片尺寸(敌人读数条)

世界锚点面片尺寸定义为(**✅ 2026-09-22 用户裁定 `OQ-42-1` = 甲「恒定屏幕尺寸」—— 单一模式,不再并列分叉**):

- **恒定屏幕尺寸(唯一模式)**:`scale_world = k_screen × 2·d × tan(FOV_v / 2)`

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 锚点–相机距离 | `d` | length | `[d_near, d_far]`,`d > 0` | 敌人身上锚点到相机 |
| 垂直视场角 | `FOV_v` | deg | **`(0°, 180°)` 开区间** | **归 2 摄像机** —— 42 只**引用** |
| **屏幕占比系数** | `k_screen` | **`ratio`(无量纲)** | `(0, 1)`,可调旋钮 | 读数条占**屏高**几成 |
| 世界缩放 | `scale_world` | length | `> 0` | 面片最终缩放 |

> **⚠️ 2026-09-17 就地修正(首轮评审第 7 项之四 —— 一个符号两种量纲)**
> 旧稿两种模式都用 `k`,但**量纲不同**:模式 A 里 `k` 必须**无量纲**(它乘的是「距离 × 角函数」,
> 结果要是长度);模式 B 里 `k` 必须**是长度**(它**就是**结果)。
> **同一个符号两套量纲 ⇒ 旋钮表里那行 `k` 无法被填值,也无法被 lint。**
> 修法:拆成 `k_screen`(ratio)/ `k_world`(length),两个旋钮、两条调参记录。

> **⚠️ 2026-09-22 就地收窄(原「两模式须先裁一次」的分叉已裁决,单一化)**
> **用户裁定 = 甲「恒定屏幕尺寸」**:屏幕占比**恒定** ⇒ `d_far` 端**仍可读**;近端失效模式 =
> 面片缩入近裁剪面(**可见地消失**,非糊脸遮挡战斗)。
> ⇒ 42 **新增一条对 2 的相机 / `FOV_v` 依赖边** —— 2 侧 `camera-and-viewpoint.md` 已列本边并
> 登记反向义务 **`O-15`**,`FOV_v` 亦已于 2026-09-16 补齐(2 的 Tuning Knobs 组 2 / 组 5 +
> `entities.yaml`);**该依赖边自此「成立」**(原记「⚠️ 半 · 取决于 `OQ-42-1`」的状态解除)。
> 装载期断言 ④ 由**条件断言**(「模式 A 启用时」)**升为常驻断言**。
> **模式 B 及其 `k_world` 旋钮自此作废**(不再登记为可调旋钮);「两模式失效方向互补」的取舍叙述
> **保留为裁决依据的记录**,不再是待选路径。

**输出范围**:`d ∈ [d_near, d_far]` 内应保持可读。
**退化行为(已裁单一模式 A)**:

| 模式 | `d → 0`(贴脸) | `d → d_far`(远) |
|------|---------------|-----------------|
| **A · 恒定屏幕(唯一)** | `scale_world → 0` ⇒ **面片缩到近裁剪面内** ⇒ 被裁 / 闪烁(**不是**糊脸);屏幕占比**恒定** | 屏幕占比**恒定** ⇒ **仍可读**(这正是选 A 的理由) |

⇒ **失效方向 = 仅近端几何**;**`d_far` 端因屏幕占比恒定而免疫** —— 这是选 A 的实际依据:
战斗距离分布**偏向远端**时 A 不失效(B 的双端失效已在裁决中被弃)。
**「两模式失效方向恰好互补」的旧叙述**仅存为裁决依据,不再是待选路径。

`d` 锚点被遮挡 / 穿墙 ⇒ 条浮在墙前(**P0 最小实现不做深度冲突处理** —— 规则一,已知且已裁)。

**装载期反例断言**(全部**常驻**,无条件项):
① **`FOV_v ∈ (0°, 180°)` 开区间** —— 反例 `FOV_v = 0°`(`tan(0) = 0` ⇒ `scale_world = 0`)与
   `FOV_v = 180°`(`tan(90°) → ∞`)**均须使装载失败**(旧稿完全未约束该量,极端 FOV 会静默产出 0 或 ∞ 的面片);
② `d_near > d_min_plane`(不得近于近裁剪面);
③ `d_far` 有值且 `d_far > d_near`;
④ 42 **确实持有一条对 2 的 `FOV_v` 引用**(❌ 原为条件断言「模式 A 启用时」⇒ **2026-09-22 升常驻**
   —— 模式 A 已成唯一路径,该依赖边**无条件成立**;否则模式 A **不可实现**)。

**归属**:**42 自有**;`FOV_v` / 相机引用归 **2**(依赖边 **成立**,`O-15` 反向义务闭合)。

### F7 · 面板缩放 / 参考分辨率

面板缩放公式定义为(**✅ 2026-09-22 用户裁定 `OQ-42-12` = 甲「取 `min`」—— 单一化**):

`s = min( W_screen / W_ref , H_screen / H_ref )`

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 参考分辨率 | `W_ref` / `H_ref` | px | 主题配置 | 设计基准分辨率 |
| 实际分辨率 | `W_screen` / `H_screen` | px | — | 运行时 |
| 缩放 | `s` | ratio | `> 0` | 面板缩放 |
| 长宽比 | `aspect` | ratio | `[aspect_min, aspect_max]` | `W_screen / H_screen` |

**输出范围**:正常 `s ≈ 1 ± ε`。
**退化行为(已裁 `min`)**:
- **代价 = 一侧留黑**:`s = min(·, ·)` 在两个比值不等时,总有一边留空
  (纸在超宽屏上**整张缩小**,四周留黑)—— **留黑是 `min` 的固有代价,非实现缺陷**;
- **收益 = 纸面比例零失真**:`min` 保证纸的**长宽比恒不变**(拟物讲究纸张比例,一张被拉长的纸立刻出戏)
  ⇒ 与拟物铁律一致,这是选 `min` 的依据。

**装载期反例断言**:`s > 0`;`aspect ∈ [aspect_min, aspect_max]`;`W_ref / H_ref > 0`。

> **⚠️ 2026-09-22 就地收窄**:原稿并列「`min` / 加权 match」待裁,且**加权 match 需一个未定义的
> 权重 `w`**(⇒ 不裁就无法填 `s` 的表达式)。**用户裁定 = `min`**:取「零比例失真 + 一侧留黑」
> 而弃「填满 + 恒有比例偏差」。**加权 match 及其权重 `w` 自此作废**(不再登记为候选路径)。

**归属**:**42 自有**(面板配置)。

### F8 · 焦点门时序(**不变量,非算术**)

焦点门不变量定义为:

`∀t, ¬( Gate_UITK(t) ∧ Gate_UGUI(t) )`,且切换走**先关后开**,过渡窗口 `0 ≤ W_trans ≤ 1 frame`。

| 变量 | 符号 | 类型 | 范围 | 含义 |
|------|------|------|------|------|
| 平面栈的门 | `Gate_UITK` | bool | — | 该栈是否消费导航 |
| 世界栈的门 | `Gate_UGUI` | bool | — | 同上 |
| 过渡窗口 | `W_trans` | duration | **`0 ≤ W_trans ≤ 1 frame`** | 两门皆关的时长 |

**输出范围**:任意时刻**至多一门开**。
**退化行为**:`两门皆开` = 一次按键**两次焦点移动**(`AC-3-C2` 所禁)。
`W_trans` 越长 ⇒ 切换期吞掉的输入越多(方向:短是安全侧)。

> **⚠️ 「原子切换」的定义(2026-09-17 首轮评审就地订正)** —— 旧稿说「旧门关与新门开在
> **同一次原子转换**内」,而规则三 / States A 又说存在「两门皆关的窗口」。**二者不可同时为真**:
> 真原子 ⇒ 窗口恒为 0 ⇒ `W_trans ≤ 1 frame` 恒真、那条 edge case 成死条款。
> **裁定(用户 2026-09-17 采纳 systems 版)**:
> - **「原子」= 对外永不可观测到「两门皆开」**(这是**唯一**的原子性承诺,也是 F8 主式的全部内容);
> - **两门皆关的窗口允许存在,`0 ≤ W_trans ≤ 1 frame`** —— 先关后开的实现自由**保留**;
> - **「按键落在过渡窗口内被吞」那条 edge case 随之删除**(它描述的是允许窗口内的正常行为,
>   写成 edge case 反而把合法态固化成异常);**其余条目编号不顺延** —— 重编会让所有既有引用失效,
>   `E-3` 号位由「双绑定禁止态」条目承接(见 §Edge Cases 一)。
> - **`W_trans = 0` 是允许的**(帧边界提交的实现方式),不因此违反本式。

**再入(2026-09-17 新增)**:过渡窗口内**不得再触发**一次切换 —— 切换操作**不可重入**
(合并 / 去重;新栈就绪时以**当下**目标解析一次)。旧稿未禁「皆关锁死」的**嵌套**风险:
若允许再入,last-writer-wins 可能把门开在**已被撤销的旧目标**上。**皆开不变量仍守,但目标是错的**。

**断言形态**:EditMode 状态机断言 —— **只断性质,不引 post-cutoff 符号名**
(承规则四的「P0 焦点载体」三问纪律)。

**归属**:**42 自有**。

### 算例(F1–F8 逐条 —— 承 `.claude/rules/design-docs.md`「公式须含示例计算」)

> **口径**:下列数值**全部是占位符**(本次评审**不改任何机制数值** —— 数值由用户裁)。

## Edge Cases

> **格式**:每条 = **精确条件 → 精确结果**(不是「优雅处理」)。每条给出**归属**(谁负责)与

### 一、焦点(42 最脆的一环 —— 死锁比崩溃更隐蔽)

**E-1 若某屏可聚焦集为空(`K = 0`)** —— **该屏的门不开**;界面仍渲染(纸面 / 元件正常显示),
但**不接收导航**。玩家此时按导航键无反应是**正确行为**(没有可去的地方)。
⇒ 若实现里「门开了但无焦点」,即为 `AC-42-*` 所禁的**静默死锁**。
*归属:42。可机械断言:`K ≥ 1` 或门为关。*

**E-2 若焦点元素在运行期被移除 / 禁用(焦点悬空)** —— 引擎 `FocusController` **自动**选邻居;
若**选不到任何邻居**(屏内已无可聚焦元素),则**回落到 E-1**(门关)。
**42 不自行重算焦点**(规则四)。⇒ 若回合后焦点**丢失且门仍开**,那是 E-1 的漏检,不是本条。
*归属:框架。*

**E-3 若同一控件同时被官方 `Navigate` 与自建焦点动作绑定** —— 此为**禁止态**,
不是需处理的情况;由构造期断言**拒绝**(§Formulas F8 / `AC-3-C2`)。⇒ 42 侧与之同构的断言见 §Acceptance Criteria。
*归属:42 + 3。*
**⚠️ 本条是 2026-09-17 占用 `E-3` 空位的新条目**(原 `E-3` 已删除,见下块)——
它不是「需要处理的异常」而是**构造期就该被拒绝的禁止态**,保留在此是因为
**读者会先在这里找它**(三种禁来源见规则四)。编号未顺延:删一条便重编其余十二条,
会让所有既有引用(§Edge Cases 六、`systems-index`、其它 GDD)同时失效,
代价远大于「`E-3` 这个词在历史记录里有过两个含义」。

> **⚠️ 原 `E-3`(按键落在过渡窗口内被吞)已于 2026-09-17 删除** —— 见 §Formulas F8 的裁定块:
> 两门皆关的窗口是**允许态**(`0 ≤ W_trans ≤ 1 frame`),窗口内输入被吞是**其定义的一部分**,
> 不是「异常情况」。把它写成 edge case 会让读者以为这是一个**需要规避的失败**,
> 从而诱导实现去做「真原子切换」或「窗口内补发」—— 两者都超出 F8 的承诺。

### 二、两栈与渲染

**E-4 若两份域内序**之一**内部撞号(同域两条规则给出同一序号)** —— 同域内的相对层序**未定义**:
① **覆盖层内**撞号 ⇒ 平面 UI 两屏之间谁压谁随机(如模态页被底层脉案盖住);
② **相机内**撞号 ⇒ 读数条与另一世界锚点谁压谁随机。
⇒ **必须**由 F4 的装载期断言在**构建期**拒绝,不允许静默进入运行期(玩家只会看到「怪」,不会报 bug)。
*归属:42。*

> **⚠️ 本条已随 F4 重写(2026-09-17)**:旧稿写「若 `φ` 非单调 —— 世界锚点提示**盖住纸面**」。
> **那个失败模式在引擎里不可能发生** —— UI Toolkit Overlay 面板在全部相机之后合成,
> 世界几何**永远**盖不住它。真正的失败是**同域撞号**,不是跨域越位。

**E-5 若分辨率 / 长宽比在运行期突变(拖窗口、切分辨率、进出全屏)** —— 面板**重排**:
① USS 布局重算;② 九宫格按 F1 重切;③ **焦点空间的邻居缓存失效** ⇒ 焦点由引擎重算(仍是引擎的事,42 不重算)。
⇒ 若某元件在新尺寸下落到 `W < SL + SR`(**F1 退化**),该元件**按 F1 的处理**(报冲突或按最小尺寸钳制)——
**42 不得静默硬画**。
*归属:42。*

**E-6 若某个拟物效果必须程序化(UI Toolkit 运行时自定义材质受限,F5)** —— 该元件**迁到 UGUI 栈**,
**语义留在同一元件库**(规则五)。⇒ **禁**在 UI Toolkit 侧硬写一份退化观感当替代品。
*归属:42。*

### 三、数据绑定

**E-7 若呈现根处于「未绑定」** —— **不渲染任何数据驱动内容**;元件与布局**仍渲染**(纸还是纸)。
⇒ 禁用「未绑定 ⇒ 整屏不画」(会看起来像加载失败,而这是合法的初始态)。
*归属:42(§States B)。*

**E-8 若重绑在拖拽 / 长按进行中发生** —— **手势中止**(§States B 已定)。
⇒ **不再**向新数据源补发手势;42 **不持有**跨源手势状态。
*归属:42。*

**E-9 若 DTO 静态检查(`PresentationDtoGuard`)在类型树里扫到 `disease_id`** ——
**构建 / 装载失败**(不是运行时降级)。⇒ 必须**递归**扫(`List<DTO>` 元素 / 私有 / 继承字段);
仅扫顶层会漏(ADR-013 §三 / `AC-37-15`)。
*归属:42 承载,规则归 37。*

### 四、文本与主题

**E-10 若 `textScale` 叠加后文本溢出纸张** —— **42 报冲突**(规则七的拒绝权),**不得**裁切、
**不得**缩字号到不可读、**不得**撑破纸面。⇒ 这是一条**跨系统**边界:如果这条经常触发,

*归属:42 报冲突,根因在 49 / 纸面尺寸设计。* ⚠️ **登记进 §Open Questions(`OQ-42-2`)**。

⇒ 装载期断言:**所有被 `var()` 引用的主题变量均已定义**(禁止静默回退路径)。

**E-12 若字体缺字(中文字库覆盖不足)** —— 落到 fallback 字体;若 fallback 也缺 ⇒ 豆腐块。
⇒ P0 **只要求元件层留好 fallback 位**(完整字库覆盖归 P2 / 50)。**P0 不验收字库覆盖率。**
*归属:元件层 42;字库 50(P2)。*

**E-12b(2026-09-20 回刷 · 承 `/review-all-gdds` R-2⑤)** —— **语声字幕的呈现落点归 42**:
44 的 `AC-44-15`(病人语声字幕,WCAG 1.2.2)与 48 的教学口述字幕(`tutorial-and-onboarding.md:93-97`,

*归属:42 呈现 · 44 供语义(承 `AC-44-15`)。*

### 五、输入 / 时序

**E-13 若一个界面出现「滚动列表 / 多页签」且元素数超阈值** —— 触发 F5 的**断批**风险。

### 六、跨系统的「地板 / 上限」核对

- **8 诊断 UI-8.1 铁律四 + UI-8.2** —— 那一个「?」**只允许出现在置信度栏**(UI-8.1 铁律四),

### 二、视觉风格约束(《双材》对 42 的直接约束)

**两材分工 —— 不得互相渗透:**

| | 水墨侧(UI Toolkit 平面) | 黄铜侧(UGUI world,敌人读数条) |
|---|---|---|
| **材质语言** | 旧纸 · 墨(浓 / 淡 / 焦)· 印泥(暗红)· 装订线 | 黄铜 · 铜锈(青绿)· 蚀刻线 · 铆钉 |
| **允许手法** | 湿笔洇开 · 枯笔飞白 · 纸的压痕与折角 · **笔迹的属主差异**(玩家写的与系统写的同纸不同手) | 錾刻刻度 · 氧化斑 · 哑光金属 · 机械位移(齿 / 针) |
| **禁用** | 锐利矢量描边(笔锋必须不匀)· 镜面高光 · **任何刻度条 / 进度填充** | 发光 / 泛光 · 把刻度读成能量条的观感(**刻度本身合法** —— 见下) |

> **刻度条的禁令只对墨侧生效(2026-09-17 首轮评审裁定)。** 旧稿把「任何刻度条」写进
> 「**两栈皆禁**」的清单,却同时在 V-10 / §Player Fantasy 四 描述黄铜侧的**蚀刻刻度读数条**
> —— 字面自相矛盾,且 F3 若照字面 lint,敌人读数条**无法实现**(它是 P0 交付物)。
> **裁决**:① **墨侧**(纸 / 卷轴 / 墨迹 / 印章)**禁任何刻度条与进度填充** ——
> 进度只走「页数 / 纸厚 / 墨迹密度」;② **黄铜侧**(敌人读数条)**允许錾刻刻度** ——
> 它是**仪器**,读的是「身体作为机器」;但**不得**让其长成游戏 HUD 能量条(**观感禁令保留**,
> 判据见 §Player Fantasy 四 的材质渗透禁令)。**两材不得互相渗透**是本节的总纲。

**现代 UI 手法禁用(两栈皆禁 —— 与刻度条分开,此组无例外):** 纯色高亮块与描边 · 圆角卡片 + 投影 ·
扁平色块图标 · 线性渐变的「进度填充」· 闪烁 / 脉冲提示 · 数字角标 · 红点 · 任何 `X/N` 计数。

**色码约束(硬):** 暗红**只**用于血与印,**不**承载「警告 / 危险」语义;青绿**只**用于铜锈,
**不**作健康 / 中毒色码。**焦点可见**须靠**明度 + 形状**且仍是拟物(规则十;8 的 UI-8.2:**靠形状不靠颜色**)。
> **判据形态(2026-09-17 首轮评审订正)**:旧稿写「明度 + **凹凸**」,而「凹凸」依赖尚未 spike 的
> 方向性光照(`V-1` 标 `须 spike`)⇒ 不可判。**改以明度为可判通道**:
> 「焦点态前后的最小 luminance Δ 在**灰阶渲染**下 ≥ 阈值,以**黑白截图夹具**断言」
> (阈值归 49;判据格式承 `AC-8-21`「黑白截图可分」的既有先例)。凹凸为**加成**,不进判据。

> **⭑ 2026-09-21 注块(第二十八批 · 用户裁定 —— 上表「两材分工」的第三方元件归属澄清)**:
> 11 处方用药的**戥子档位读数元件**(戥杆倾角 / 药包鼓胀)登记为**黄铜侧**元件 ——
> 它落在「錾刻刻度 · 机械位移(齿 / 针)」的允许手法内,**不**触碰墨侧的「任何刻度条 / 进度填充」禁令。
> ⚠️ 两点硬约束(承 `ADR-013 §十-B`):
> ① 该元件**不得**退化为「数字角标 / `X/N` 计数」—— 上列禁用组**两栈皆禁、无例外**,

### 二、每屏对 42 的义务(**所有 P0 界面共有的契约**)

1. **焦点可达**:每个界面的**每个**可聚焦元素都在 rank 双射内(F3);`K ≥ 1`(E-1)。

### G 组 · 无障碍属性与承诺兑现(2026-09-17 首轮评审新增)

> **本组存在的理由**:首轮评审查出**多处写在散文里的 P0 承诺没有任何 AC 承载**
> (对比度的「全档均须满足」义务 · 动效缩放的挂点 · 规则五的元件库唯一出口 ·
> 规则八的设置壳边界 · 幻想直接层的「我的笔迹 / 墨还没干」数据路径),
> 以及一张**手工维护且会漂移**的载体欠账表。
> **承诺写在正文里、零判据 ⇒ 等于没写。** 本组把这些机械化。
> **计数**:`G1`(元件库唯一出口)· `G2`(设置壳不缓存他系统状态)· `G3`(对比度属性)
> · `G4`(动效缩放挂点)· `G5`(载体清账)· `G6`(笔迹与墨龄的数据路径),
> **G 组 = 6 条,全 BLOCKING**。

**`AC-42-G1`**(BLOCKING · 结构断言,**2026-09-17 新增 —— 承载规则五的零 AC 真空**)
**GIVEN** 全部 `.uxml` / `.uss` 与界面装配代码,**WHEN** 扫描,**THEN** **不存在**绕过元件库
**内联手写拟物样式**的路径(纸纹 / 墨迹 / 九宫格 / 主题色**只在元件库内出现**);
新增一种拟物变体**必须**改元件库,不得在界面内联。`[L]` · 文本 lint(禁字面颜色 / 纹理引用出现在界面层)。

> **⚠️ 规则五是 42 的**复用锚点**,却零 AC** —— 旧稿在规则五写了「新增一个界面若需要第五种元件,
> **先改元件库**……**禁**在界面内联样式里手写一份变体」,而 AC 组里**没有一条**能抓到它。
> `AC-42-F3` 断的是「库内**不该有**什么」(负面清单),**抓不到「界面偷偷绕开库」**。
> 二者方向相反,都需要。

**`AC-42-G2`**(BLOCKING · 装配断言,**2026-09-17 新增 —— 承载规则八的零 AC 真空**)
**GIVEN** 设置界面的各条目实现,**WHEN** 检查数据读写路径,**THEN** **条目语义不由 42 持有**:
音量 / mono 条目**读写的总线参数归 44**,42 只提供壳与焦点;
断言**不存在**「42 内缓存一份音量 / mono 值」的路径(缓存 = 第二份真相,破规则六)。
`[L]` · 引用集 + 类型树断言。

> **⚠️ 规则八同样零 AC** —— 「条目的语义归各自系统」是 42 与 44 / 3 / 49 的**分界线**,
> 而 `AC-42-D` 组只断「42 不写三流 / 不写存档」,**没断「42 不缓存别人系统的值」**。
> 拟物 UI 的诱惑恰在此处:设置界面「看起来像一本簿子」,很容易顺手在 42 内维护一份本地状态。

**`AC-42-G3`**(BLOCKING · 对比度**属性**断言,**2026-09-17 新增**)
**GIVEN** 元件库的全部主题 / 纹理档组合,**WHEN** 逐档取黑底 / 白底截图做**灰度亮度差**测量,
**THEN** **每一档下**关键前景(文字 / 记号 / 焦点高亮)与背景的灰度亮度差 **≥ 阈值**;
反例 `暗红字 + 深棕纸` **必须**使断言失败。
**阈值本身归 49 无障碍**(42 **不持**阈值 —— 它只持**「全档均须满足」这条义务**);
阈值未定期间,**该条记参数化 BLOCKING**(用占位阈值跑,49 成文后回填)。

> **⚠️ 本条补的是一个零 AC 真空** —— 旧稿在 §越界清单与 Tuning Knobs 两处都写了
> 「对比度阈值归 49,**但『任何档均须满足』这条义务归 42**」,却**没有任何 AC 承载这条义务**。
> 义务写在散文里、没有判据 —— 即「说了一个谁都不必证明的承诺」。
> ⇒ 新增 `G3` 把它机械化:**判据是「全档采样」这个形状**,与阈值的具体数值解耦。

**`AC-42-G4`**(BLOCKING · 动效缩放挂点断言,**2026-09-17 新增**)
**GIVEN** 42 的全部时长型观感(翻页 / 淡出 / 墨迹渗开 / 焦点移动动画),**WHEN** 扫描这些时长的
赋值点,**THEN** **无一处写死时长** —— 全部经**第四钩子的缩放系数**(规则十)求值;
断言存在一个可把该系数置 0(无动效)的路径,且置 0 后**界面仍完全可用**(无卡死 / 无等待)。
`[L]` · Roslyn banned members(禁字面时长)+ 装配断言。

> **⚠️ 为什么 P0 就要 BLOCKING** —— 与 `AC-42-A6`(调试视图)同理:**事后补挂点 = 改每一处动效**。
> 而且「置 0 后仍可用」这半条尤其承重:拟物 UI 的动效常**兼作状态变化的载体**(翻页表示"换页了"),
> 若把动效置 0 会让某个状态变化**失去唯一载体**,则那条状态变化的设计本身要重做。
> **这条 AC 会把那个隐患在 P0 暴露出来,而不是等 reduce-motion 需求到来时。**

**`AC-42-G5`**(BLOCKING · 载体欠账的清账断言,**2026-09-17 新增**)
**GIVEN** §七 载体欠账表,`WHEN` 在任一 story 标记 Done 前校验,
**THEN** 该 story 引用的**每一条** AC 的载体**均已存在**(非「待建」);
**且** §七 表本身**与 `tests/` / `.github/workflows/` 的实际内容一致**(表说待建而实际已建 ⇒ 失败;
实际未建而表说已有 ⇒ 失败)。
`[L]` · CI job(可复用 ADR-012 的 CI 门载体)。

> **⚠️ 为什么需要这一条** —— §七 表是**手工维护**的清单,而手工清单会**漂移**:
> 载体建好之后没人回来改「待建」二字,于是「欠账表」反过来变成**假的安全感**。
> `[I]` 类型的老做法(把状态写成一句话)无判据 —— 故本条断**两个方向**的一致性
> (表 vs 实际),并把它绑在 **story Done 门**上,而不是只做定期审计。

**`AC-42-G6`**(BLOCKING · 结构断言 + 纯函数断言,**2026-09-17 新增 —— 承载幻想两条承诺的数据路径**)
**GIVEN** §Player Fantasy 直接层承诺的「**这是我的笔迹**」与「**墨还没干**」两条,
**WHEN** 校验,**THEN**
① **零 freehand 采集**:42 的类型树内**不存在**任何笔迹坐标 / 压力 / 时间序列的采集类型,
亦**不存在**写笔迹数据的调用(`AC-42-D2` 的符号面已覆盖,本条断**类型面**);
② **变体来源闭合**:42 只消费 8 交来的变体族(**3–4 变体 × 3 浓度档**,`diagnosis-system.md:1458`),

(禁「每次重绘换形」);
④ **墨龄 = 纯函数**:`墨龄 = 当前 tick − 落笔 tick`,**42 内不存在任何计时器 / 累计时钟**;
两 tick 相等 ⇒ 墨龄 = 0;42 **不自行推进**墨龄。
`[L]` · Roslyn banned members(①)+ 装配断言(②③)+ 纯函数断言(④);**载体待建**,入 §七。

> **为什么归 G 组**:本条与 `G1`–`G5` 同型 —— 都是「**正文里写了承诺、AC 组里没有门**」。
