## 1. 概述 Overview

队伍 / 角色系统定义**"谁在场、他能做什么、他不在时会发生什么"**。它是三大机制的交汇点：**证候系统**在这里挂载"识证能力"（谁能望、谁能切、谁能检验、谁能治心），**战斗系统**在这里取得"本场牌池"与"每人独立的剂量 / 气机资源池"，**成长系统**在这里取得"节点效力"与"羁绊协作系数 Teamwork"。本系统**不发明新的医学机制**——它只提供一个**角色数据模型**与一台**聚散状态机**，让人物的来去、学养与关系，通过既有系统真实地改变"这场仗能不能打、怎么打"。它最重要的两条设计主张是：其一，**编成不是战力堆叠，而是"选择带哪几双眼睛"**——带错人，连病都看不见（单镜型）；其二，**聚散不是剧情过场，而是机制事件**——人走了，牌池会缺口、图谱会留白、羁绊会冻结。

> **快速索引** — 出战上限 4 · 每人独立双资源池 · 识证 = 望/闻/问/切 + 检验/心身 · 聚散两轴（roster × formation）· 羁绊只喂 Teamwork。

## 2. 玩家幻想 Player Fantasy

**"我不是在收集更强的角色，我是在凑齐一副看得见病的眼镜。"**

玩家要体验的，是一个医者**在病床前点名**的专注：这一场，要带谁去？带上陆九针，就有人能切脉、能读阴阳的深层；带上柳希白，显微镜下那具"看不出病"的躯体才会显出真相；带上清和，那些"药治不好的病"才有人应。而带人是有代价的——每个人的速度不同，谁先出手、谁能托住病人的正气、谁只有半瓶资源，都要在编成时想清楚。**"带对的人"比"带强的人"重要**，这是本作与常见队伍 RPG 最根本的差别。

这份专注的另一面，是**失去的重量**。当苏晚棠一意孤行离开队伍，玩家在编成界面里看见那个空位——不是少了一个数值，是**少了一种看世界的方式**：她参与过的"通"全部灰化，她那一手针再也刺不出去。等她归来，图谱要从半力重新磨合；当她在卷九殉职，她的节点凝固为"遗志"，仍能作为合方的一端，却再也不会长出新的一枝。玩家不会读到"角色已离队"五个字，他会在**编成页的空白**里，亲手摸到那个缺口。

**情绪目标**：点名的郑重（带对眼睛）+ 关系的实在（羁绊可感）+ 失去的空白（人走了，机制真的变了）。

## 3. 详细规则 Detailed Rules

### 3.1 系统定位与数据边界

| 上游 / 下游系统 | 从本系统取用 | 本系统不负责 |
|---|---|---|
| 战斗系统 `combat-system.md` | 在场队员的单方牌、合方牌可用性、每人独立的剂量/气机资源池、Speed（喂 CTB） | 出牌、伤害结算、CTB 公式、胜负判定 |
| 证候系统 `status-syndrome.md` | 队员的识证能力（望/闻/问/切 + 检验/心身）挂载点；气感 → 切诊可用性 | 诊法本身、证候向量、状态效果 |
| 成长系统 `progression-system.md` | 节点效力（EffectivePower 三态）、羁绊 → Teamwork（喂 `LinkBonus`） | 图谱结构、连线成本、节点解锁 |
| 关卡 / 遭遇系统 | 出战编成结果（牌池构成）、编成校验 | 遭遇编排、胜利条件、病人配置 |
| 对话系统 | 在场成员名单、羁绊值、聚散状态 | 对白、剧情触发 |
| 存档系统 | 聚散状态、资源池当前值、羁绊矩阵 | 序列化实现 |

> **边界声明**：本系统**不做医学判定**。切诊能不能用、检验能不能验出带菌者，判据在证候系统；本系统只声明"这名队员的气感/检验/心身是几"，并把该数值交给对应系统去 gate。**能力是数据，判定是别人的事。**

### 3.2 角色数据模型 Character Schema

```
Character:
  id:          pc_*                    // 可操作队员；boss_* 为非编成角色（反派）
  name:        string
  joinVolume:  int                     // 首次加入卷次（技能即剧情）
  roster:      未加入 | 在队 | 离队 | 归队 | 殉职    // "在不在队"（剧情轴），见 3.7
  formation:   出战 | 后备                            // "上不上场"（编成轴），见 3.7
                                                       // 后备 ≡ 旧称"暂离": (roster=在队 ∧ formation=后备)
  stats: {
    speed:   int 40..150               // 喂 combat §4.1 CTB
    dosage:  { cap: int, current: int, regen: int }  // 还原侧资源池（剂量），每人独立
    qiji:    { cap: int, current: int, regen: int }  // 整体侧资源池（气机），每人独立
    sense: {
      qi:      int 0..3                // 气感：>0 方可执行切诊（读阴阳深层）
      screen:  int 0..3                // 检验：>0 方可识别单镜型「带菌者」
      psyche:  int 0..3                // 心身：>0 方可触到「心因性疾病」
    }
  }
  tree: { reduction: Set<NodeId>, holistic: Set<NodeId> }   // 由 progression 托管
  cards: { singles: Set<CardId>, convergences: Set<LinkId> }
  bond: Map<CharacterId, int 0..100>                        // 羁绊（喂 Teamwork，见 3.8）
  teamEff: { effectivePowerOverride?, kReunionT? }          // 离队/归队/殉职，见 progression §4.7
```

> **为何 roster 与 formation 分成两轴**：人物的"**在不在队**"（剧情驱动）与"**上不上场**"（编成驱动）是**正交**的两件事——前者随时能被剧情改变并与节点灰化/羁绊冻结绑定，后者每关由玩家自由轮换且不影响节点。压成一个枚举会同时污染"可编成人数"统计、合方牌可用性判定与归队磨合计时三处逻辑（历史上正是三条 bug 的共同根因），故拆为两字段。

- **每人独立资源池**：剂量 / 气机**不共享**。一次出牌的费用**由发牌者自己的资源池支付**，不得跨人支付——这是"两套语言"硬边界在队伍层的延伸。理由：①使 CTB 有意义（快速角色出手多，但受**自己**的池限制）；②使编成有意义（苏晚棠"两侧均衡"的价值凸显）；③防止"一人攒池、全队挥霍"的退化策略。
- **资源回复**：每回合开始时各自回复 `regen`（受状态影响，见 `status-syndrome.md` §3.6.2 的 `st_qi_def` / `st_yin_def`——各自只削减**自己那侧**的回复）。

### 3.3 属性表 Attribute Set

**基础属性（每人各一）**：

| 属性 | 符号 | 范围 | 接入点 | 说明 |
|---|---|---|---|---|
| 速度 | `speed` | 40–150 | `combat-system.md` §4.1 CTB | 决定出手间隔 `T_next=(Threshold−Gauge)/Speed` |
| 剂量上限 | `dosage.cap` | 0–150 | 战斗资源池 | 还原侧资源池容量 |
| 剂量回复 | `dosage.regen` | 0–20 /回合 | 战斗资源池 | 每回合补入 |
| 气机上限 | `qiji.cap` | 0–150 | 战斗资源池 | 整体侧资源池容量 |
| 气机回复 | `qiji.regen` | 0–20 /回合 | 战斗资源池 | 每回合补入 |
| 气感 | `sense.qi` | 0–3 | 证候系统 切诊 gate | `>0` 方可执行切诊、读阴阳深层极 |
| 检验 | `sense.screen` | 0–3 | 证候系统 单镜型 gate | `>0` 方可识别「无症状带菌者」 |
| 心身 | `sense.psyche` | 0–3 | 证候系统 单镜型 gate | `>0` 方可触到「心因性疾病」 |

> **感知三值（气感 / 检验 / 心身）各自独立，互不替代**：气感读的是"无形之物在整体轴上的偏移"，检验读的是"有形之物在还原轴上的存在"，心身读的是"病在神不在形"。一名队员可以只有其中一项（沈砚之有检验无气感），也可以三项全有（清和有气感与心身）——**"缺项"正是单镜型的机制来源**，不做任何补偿。

**派生值**：

| 派生值 | 公式 | 用途 |
|---|---|---|
| 编成容量 | `min(4, 可编成人数)`，其中 `可编成人数 = \|{c : c.roster ∈ {在队, 归队}}\|` | 见 3.4 |
| 本场牌池 | `∪ singles(出战者) ∪ 可用 convergences`（合方牌要求两端均出战） | 见 3.5 |
| Teamwork(A,B) | `clamp(0.8 + 0.4 × Bond(A,B)/100, 0.8, 1.2)` | 见 3.8 / progression §4.3 |

### 3.4 战斗编成 Party Composition

- **出战上限 = 4**。
- **病人不占编成位**：病人（携带正气条者）是战场实体，不是队员；多病人关卡不改变出战人数上限（见 `combat-system.md` §3.1 / §5）。
- **上限为何是 4**（不是 3，不是 6）：
  1. **竖直切片本身只有 4 人**（沈砚之 / 陆九针 / 柳希白 / 苏晚棠）——上限若高于 4，切片期等于没有编成决策；若低于 4，切片无法全员上场，教学期的"两套眼睛"演示会缺人。
  2. **CTB 可读性**：每位医者都占行动条一格，加上病机与（可能的）多病人，4 医者 ≈ 一屏内可全程追踪的极限（性能预算见 §8：≤6 实体/场）。
  3. **"2+2"的自然落点**：4 位恰好容纳"还原 2 + 整体 2"的均衡队，也容纳"4 还原"的极端速攻队——**给玩家留出犯错的余地，是"不做强制失败"原则在编成层的体现**（见 `combat-system.md` §4.10）。
- **编成决定牌池，牌池决定战斗型**：单核 / 双核**由牌池实际内容涌现判定**（`combat-system.md` §4.10.1），本系统不贴任何"主树归属"标签。编成界面对玩家的呈现**只给信息、不给结论**——显示"本场牌池：还原 ✓ / 整体 ✓"，以及"缺眼"提示（若只有一侧），但**不阻止**玩家出战。
- **编成可携带后备**：后备队员（`roster=在队 ∧ formation=后备`）随时可换入，但**换人只在关卡边界进行**——战斗中不换编（见 §5）。

### 3.5 识证能力表 Perception Matrix

四诊（望/闻/问）**人人可为**；**切诊**需气感，**检验**需检验值，**心身**需心身值。下表为全篇六名可操作角色的**能力分布**（数值见 3.9 角色卡）：

| 角色 | 望 | 闻 | 问 | **切**（需气感） | **检验**（需检验） | **心身**（需心身） |
|---|---|---|---|---|---|---|
| 沈砚之 | ✓ | ✓ | ✓ | ✗（0）→ 卷六 **✓**（1） | ✓（2） | ✗ |
| 陆九针 | ✓ | ✓ | ✓ | **✓（3）** | ✗ → 卷三 ✓（1，镜检） | ✓（1） |
| 柳希白 | ✓ | ✓ | ✓ | ✗（0） | **✓（3）** | ✗ |
| 苏晚棠 | ✓ | ✓ | ✓ | **✓（2）** | ✗ | ✗ → 卷七 ✓（1） |
| 陈九章 | ✓ | ✓ | ✓ | ✗（0） | ✓（1，旁证） | ✗ |
| 清和 | ✓ | ✓ | ✓ | **✓（3）** | ✗ | **✓（3）** |

**三条 gate 规则（与 `combat-system.md` §3.5 / `status-syndrome.md` §3.2.2 一一对应）**：

1. **切诊 gate = 气感 > 0**。气感为 0 的队员**不能执行切诊**（UI 上不可选）。故**纯还原编成永远读不到阴阳深层极** → 心身病机对它**永久不可见**。这是单镜型的机制来源，**无需任何特判**。
   > **口径（已跨文档统一）**：`combat-system.md` §3.5 与 `status-syndrome.md` §3.4 均已记为"无气感者**不可执行**（**不返回深层阴阳，非假值**）"。本作**唯一**的随机源是问诊 90% 准确率（`status-syndrome.md` §4.7）；任何"返回假值/伪报"的实现都会凭空引入第二个随机源，**违反"失误是选择的结果，不是运气的结果"的核心承诺**。实现时以"**按钮禁用 + 不返回**"为准。
2. **切诊被动**：队伍中有**苏晚棠或陆九针在场** → 切诊耗 **0 行动**（辨证是中医角色的核心职能，见 `combat-system.md` §3.5）。望/闻/问 仍耗 1 行动。**"能免费切"与"能切"是两回事**——沈砚之卷六获得气感后**能**切，但队伍若无陆九针或苏晚棠，仍要耗 1 行动。
3. **检验 gate = 检验 > 0**（识别「无症状带菌者」），**心身 gate = 心身 > 0**（触到「心因性疾病」）。二者是**唯一**能处理对应单镜型病机的通道（`combat-system.md` §4.10.4）。

> **陈九章的例外职能「推演」**：他不提供任何医学识证（气感/检验/心身皆低），但**能揭示确定性数据**——本场病机的**传变阈值**与**速度**（皆为配置中的写死值，见 `status-syndrome.md` §4.4）。这让玩家可**预判**病势节奏，符合"可归因"原则，且**不引入随机**。他的"布局"牌可调整行动值（先手/迟滞），是 CTB 层的能力，不是诊断层的能力。

### 3.6 资源池与合方牌付费 Pool & Convergence Cost

- **单方牌**：由发牌者用**自己**的资源池支付（还原牌耗剂量、整体牌耗气机）。
- **合方牌（「通」）付费规则（"双付"）**：

```
合方牌费用 = 由两端队员各支付其对应侧资源的一半
若一端不可支付（殉职→遗志端；或该端队员不在场）：
    费用全部由在场的发起方承担
```

- **殉职的"遗志端"不付费，只给方向**：苏晚棠殉职（卷九）后，其节点凝固为遗志（`progression-system.md` §4.7），**仍可作为「通」的一端**贡献连线与加成，但**不承担费用**——她已不在了，出钱的是活着的人。这条规则同时守住了"遗志仍有用"与"死者不能发牌"两条直觉。
- **离队则整条「通」不可用**（`progression-system.md` §4.7：`EffectivePower = 0`）——合方牌直接灰化，不进入牌池。
- **陈九章的协同加成（放大器）**：若本场牌池为**双核**，陈九章在场时，同一回合内**先还原后整体（或反之）**连续出牌可获得协同加成，计入 `combat-system.md` §4.2 的加成和 `Σb`：

```
Σb_chen = 0.05 × min(本回合已打出的异侧牌数, 3)      // 上限 +0.15
```

  该加成**只对异侧配合生效**，单核牌池下**恒为 0**——这正是"催化桥：只放大、不供给"的机制化身（`progression-system.md` §3.5）。它落在 `Σb` 既有的 0–1.5 区间内，**不修改战斗系统的任何公式**。

### 3.7 聚散状态机 Roster State Machine

队员聚散由**两条正交的轴**描述（与 `progression-system.md` §4.7 的离队/归队/殉职三态**兼容**）：

- **`roster`（剧情轴）**：`未加入 | 在队 | 离队 | 归队 | 殉职`——由剧情驱动，绑定节点灰化与羁绊冻结。
- **`formation`（编成轴）**：`出战 | 后备`——每关由玩家自由轮换，**不影响节点**。

**`roster` 状态表**：

| roster | 语义 | 可编入出战 | 图谱节点效力 | 牌池 |
|---|---|---|---|---|
| **未加入** | 尚未入队 | ✗ | 节点不存在 | — |
| **在队** | 已入队 | ✓ | `EffectivePower = NodePower` | 单方牌可用；合方牌需两端均**出战** |
| **离队** | 剧情离队 | ✗ | **`EffectivePower = 0`（灰化）** | 其合方牌**不可用**；单方牌离场 |
| **归队** | 归来过渡期 | ✓ | `NodePower × K_reunion(t)` | 同"在队"，按当前效力 |
| **殉职** | 永久退场 | ✗ | `EffectivePower = NodePower`（**遗志**，凝固） | 单方牌**永久移除**；其参与的「通」**仍可作一端** |

**`formation` 状态表**（仅对 `roster ∈ {在队, 归队}` 的队员有意义）：

| formation | 语义 | 占编成位 | 图谱节点 | 合方牌 |
|---|---|---|---|---|
| **出战** | 本场编入 | ✓（≤4） | 正常 | 可作发起端 |
| **后备** | 在队但本轮未出战（= 旧称"暂离"） | ✗ | **不灰化** | **不可作发起端**（换上场即恢复） |

**`roster` 迁移表**：

| 当前 roster | 触发事件 | 新 roster | 附带效果 |
|---|---|---|---|
| 未加入 | 剧情加入 | 在队 | 节点首次点亮、牌池并入；`formation` 默认出战 |
| 在队 | 剧情离队 | **离队** | `EffectivePower = 0`、合方牌灰化、**羁绊冻结**；`formation` 强制解编 |
| 离队 | 剧情归队 | **归队** | `K_reunion(0) = 0.5`，每经历 1 个事件 / 战斗 +0.1；`formation` 恢复可编 |
| 归队 | 事件计数 `t ≥ 5` | 在队 | `K_reunion = 1.0`，效力满 |
| 在队 / 归队 | 剧情殉职 | **殉职** | 单方牌移除；节点凝固为遗志；**羁绊凝固**；不可逆 |
| 殉职 | — | （终态） | 无迁移 |

**`formation` 迁移**：任意 `roster ∈ {在队, 归队}` 的队员，可在**关卡边界**于 `出战 ↔ 后备` 间自由切换；战斗中途不可。

- **后备 ≠ 离队**：轮换下场（`formation=后备`）**不灰化节点、不断连**，换上即恢复可用；只有**剧情离队**才 `EffectivePower = 0`。这条区分让玩家敢做轮换决策，而不必担心"换下场就掉战力"。
- **归队与后备正交**：归队队员**亦可被轮换为后备**；后备期间 `K_reunion(t)` 仍**按事件正常推进**（磨合不因下场而暂停）。
- **队伍变动只在关卡边界发生**：战斗中途**不增删队员**（队员可被"击倒/离场"、其牌暂时不可用，但不改变编成——见 `combat-system.md` §5）。苏晚棠的离队（卷六末）与殉职（卷九）均为剧情事件，落在关卡之间。
- **沈砚之常驻**：主角自序章起**永不进入离队 / 未加入**（可为"击倒"、也可被轮换为后备），故**可编成人数 ≥ 1**、编成永不为空。

### 3.8 羁绊 / 团队协作 Bond & Teamwork

**设计定位（刻意做窄）**：羁绊**只有一个机械出口**——喂给成长系统的 `Teamwork` 系数（`progression-system.md` §4.3 `LinkBonus` 的乘数）。本项目**不**把羁绊做成第二套属性系统（不提供独立增益、不解锁独立技能树），以免它在"图谱"之外另立一个玩家要管的数值。**羁绊的全部意义，是让"这两名队员配合的合方技有多强"。**

```
Bond(A,B) ∈ [0, 100]
ΔBond 事件：
  同场出战一场遭遇          → +3
  剧情羁绊事件（对白/共同经历）→ +5 .. +15
  主线里程碑（共同完成）      → +10
衰减：
  连续 ≥ 2 章未同场            → 每章 −2（软衰减，防"轮换刷羁绊"）
上限：100；离队期间【冻结】（不增不减，也不衰减）；殉职后【凝固】

Teamwork(A,B) = clamp( 0.8 + 0.4 × Bond(A,B) / 100 , 0.8 , 1.2 )
```

| 羁绊值 | 名分 | Teamwork | 语义 |
|---|---|---|---|
| 0–24 | 陌路 | 0.80 – 0.90 | 同队不同心 |
| 25–49 | 同袍 | 0.90 – 1.00 | 共事之谊 |
| 50–74 | 知己 | 1.00 – 1.10 | 一个眼神就懂 |
| 75–100 | 生死之交 | 1.10 – 1.20 | 命可以交出去 |

- **校验**：`Bond=0 → 0.80`、`Bond=50 → 1.00`、`Bond=100 → 1.20`，与 `progression-system.md` §4.3 的 Teamwork 区间 `[0.8, 1.2]` **逐值一致**。
- **归队与羁绊**：归队时羁绊**不重置**（冻结后的值原样恢复），但**合方效力**由 `K_reunion` 另行压低——"情分还在，配合要重新熟"。两条曲线互不覆盖。
- **殉职后**：羁绊凝固为定值，其参与的「通」仍按该值计算 Teamwork（遗志端不付费，但仍享受协作加成）。

## 4. 公式 Formulas

### 4.1 编成容量 PartySize

```
PartySize = min(4, 可编成人数)
可编成人数 = |{ c : c.roster ∈ {在队, 归队} }|      // 与 formation 无关：出战/后备皆计入候选
```

| 变量 | 范围 | 说明 |
|---|---|---|
| 上限 4 | 配置常量 | 见 3.4 理由 |
| 可编成人数 | ≥1 | 沈砚之常驻（`roster` 永不离开 {在队, 归队}），永不为 0 |

**示例**：卷二（沈砚之 + 陆九针在队）→ `min(4, 2) = 2`；卷四（沈 + 陆 + 柳 + 苏）→ `min(4, 4) = 4`；**卷六末苏晚棠离队 → 可编成人数 = 5（沈/陆/柳/陈/清；苏 `roster=离队` 不计）→ `min(4, 5) = 4`**，玩家从这 5 人中选 4 人出战、1 人列后备（`formation=后备`）。

### 4.2 团队协作系数 Teamwork

```
Teamwork(A,B) = clamp( 0.8 + 0.4 × Bond(A,B) / 100 , 0.8 , 1.2 )
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|---|---|---|---|---|
| Bond(A,B) | int | 0–100 | 羁绊矩阵 | 见 3.8 的增减规则 |

**示例**：Bond = 60（知己）→ `0.8 + 0.4×0.6 = 1.04`；喂入 `progression-system.md` §4.3 `LinkBonus = (P_A+P_B) × Affinity × Teamwork`。
**预期输出范围**：[0.8, 1.2]，与 progression 的旋钮区间逐值一致。

### 4.3 羁绊增减 Bond Delta

```
ΔBond = 3 × 同场出战次数 + Σ 剧情事件值(5..15) + 10 × 主线里程碑
衰减： 若连续未同场章节数 ≥ 2 → 每章 −2（下限 0）
上限： Bond ≤ 100；离队期间冻结（ΔBond ≡ 0，不衰减）；殉职后凝固
```

**示例**：沈砚之与陆九针卷二同场 3 场 + 一次剧情事件（10）→ `ΔBond = 3×3 + 10 = 19` → Bond 从 0 升到 19（"陌路"偏上）。
**预期输出范围**：单卷增幅 0–40；全篇可达上限 100。

### 4.4 节点效力/归队磨合 EffectivePower（引用 `progression-system.md` §4.7）

```
在队   ： EffectivePower = NodePower          // 含 formation=后备（后备不灰化）
离队   ： EffectivePower = 0
归队   ： EffectivePower = NodePower × K_reunion(t),  K_reunion(t) = min(1.0, 0.5 + 0.1 × t)   t = 0..5
殉职   ： EffectivePower = NodePower（遗志，凝固；不可再成长，可作合方一端）
```

- **本系统只声明"哪些队员处于哪个状态"**；节点效力的计算与连线成本的扣除**由成长系统执行**（本系统不持有 NodePower）。

### 4.5 陈九章协同加成 Chen Synergy（喂 `combat-system.md` §4.2 的 `Σb`）

```
若 本场牌池为双核 且 陈九章在场：
    Σb_chen = 0.05 × min(本回合已打出的异侧牌数, 3)      ∈ {0, 0.05, 0.10, 0.15}
否则：
    Σb_chen = 0
```

**示例**：本回合先出 1 张还原牌再出 1 张整体牌 → 第二张牌 `Σb_chen = 0.05`；若已出 3 张异侧牌 → 封顶 `0.15`。
**预期输出范围**：[0, 0.15]，落在 combat `Σb` 既有区间 [0, 1.5] 内，**不修改战斗公式**。

### 4.6 资源池回复 Regen

```
每回合开始：
  对每名在场医者：
    dosage.current = min(dosage.current + dosage.regen × K_yin, dosage.cap)
    qiji.current   = min(qiji.current   + qiji.regen   × K_qi , qiji.cap)
其中 K_yin / K_qi 为状态系数（st_yin_def / st_qi_def，见 status-syndrome §3.6.2）
```

**示例**：陆九针 `qiji 15/regen`，叠加 `st_qi_def` 1 层（−20%）→ 本回合回复 `15 × 0.8 = 12`。
**预期输出范围**：单回合回复 0–20（每侧）。

### 4.7 编成与牌池构成 Pool Composition

```
牌池 P = ( ∪_{c : c.formation = 出战} c.cards.singles )
       ∪ ( ∪_{l ∈ 可用「通」} l.card )          // 「通」可用 ⟺ 两端 roster ∈ {在队,归队} 且 formation = 出战

has_R = ∃ card ∈ P : cost.type = 剂量
has_H = ∃ card ∈ P : cost.type = 气机
```

| has_R | has_H | 战斗型 | 出处 |
|---|---|---|---|
| ✓ | ✓ | 双核（常规） | `combat-system.md` §4.10.1 |
| ✓ | ✗ | 速攻型 Race | 同上 |
| ✗ | ✓ | 持守型 Sustain | 同上 |
| ✗ | ✗ | 非法（配置校验拒绝） | 同上 |

**示例**：卷一仅沈砚之 → 牌池全为剂量牌 → **速攻型**（教学关，与 `combat-system.md` §4.8 一致）；卷二加入陆九针 → 两池俱在 → **双核**。

## 5. 边界情况 Edge Cases

| 场景 | 会发生什么 | 理由 |
|---|---|---|
| 出战人数 < 4（前期 / 剧情缺员） | 允许，`PartySize = min(4, 可编成人数)`；编成界面留空位 | 竖直切片卷一只有 1 人 |
| 可编成人数为 0 | **不会发生**：沈砚之常驻，`roster` 永不进入 {未加入, 离队, 殉职}（仅可"击倒"或被轮换为后备） | 保证编成永不为空 |
| 玩家想带 5 人 | 拒绝：出战上限硬性为 4，多余者列后备 | 见 3.4 理由 |
| 编成后**牌池为空** | 配置校验拒绝该编成（理论上不可达，因每人至少 1 张单方牌） | 防空池（`combat-system.md` §4.10.1） |
| 战斗中队员被"击倒" | 其牌暂时不可用，**但编成不变**（不自动换入后备） | 战斗中不换编（3.7）；保护叙事 |
| 剧情在关卡中途要求队员离队 | **推迟到关卡边界**执行；战中不撤人 | 状态一致性 |
| 离队队员的合方牌 | 不可用（`EffectivePower = 0`）→ 灰化、移出牌池 | `progression-system.md` §4.7 |
| 殉职队员的单方牌 | **永久移除**（人不在了） | 直觉与机制一致 |
| 殉职队员参与的合方牌 | **仍可用**，该端作"遗志"贡献连线与加成，但**不支付费用** | "遗志仍有用，死者不发牌" |
| 合方牌两端之一**后备**（在队但本轮未出战） | **不可用**：合方牌要求两端均 **`formation=出战`**；但该队员**节点未灰化**，换上即恢复 | 牌要有人发；**后备 ≠ 离队**（节点不灰化） |
| 合方牌两端之一**不在队**（离队 / 殉职） | 离队→该「通」**灰化不可用**；殉职→该端作**遗志**仍可用、不付费 | `progression-system.md` §4.7 |
| 归队队员的羁绊 | **不重置**（离队期冻结，归来原值恢复）；但合方效力受 `K_reunion` 压低 | 情分在、配合生 |
| 羁绊衰减导致 Bond 归零 | 下限截断为 0（Teamwork = 0.8），无负值 | 数值安全 |
| 同一对队员羁绊反复刷 | 连续未同场即衰减（−2/章），且同场增益有章节频率上限 | 防刷 |
| 无气感的队员尝试切诊 | 按钮不可用；**不返回任何数值**（非"假值"） | 守"唯一随机源=问诊"；见 3.5 口径澄清 |
| 无检验值的队伍遇「带菌者」 | 四诊一律"无显著证候"；玩家可**转诊**换编成重试，**不判负** | `combat-system.md` §4.10.4 / §4.10.6 |
| 无心身值的队伍遇「心因性疾病」 | 检验/靶向对病邪条效力 ≈ 0；同上，可转诊 | 同上 |
| 编成含单侧牌池即出战 | **放行**（"惨胜"之路）；评级计入单核罚项 | `combat-system.md` §4.10.6，**不可违反** |
| 存档点在关卡中途 | 队伍变动只在关卡边界落盘；中途退出视为未变 | 状态一致性 |
| 霍崇光出现在编成候选 | **不出现**：`nonParty = true`，编成 UI 永不列出 | 见 3.9 |

## 8. 验收标准 Acceptance Criteria

- [ ] **出战上限为 4**：编成第 5 人被拒绝并给出提示；病人不占编成位（守卫检查）。
- [ ] `PartySize = min(4, 可编成人数)`，且**永不为 0**（沈砚之 `roster` 不可进入 {未加入, 离队, 殉职}；尝试设置被校验拒绝）。
- [ ] **资源池每人独立**：还原牌由发牌者自己的剂量池支付，整体牌由气机池支付；**跨人支付被拒绝**（守卫检查）。
- [ ] 资源回复符合 4.6：陆九针 `qiji.regen=15` 叠 `st_qi_def` 1 层 → 本回合回复 12（±0.01）。
- [ ] **切诊 gate = 气感 > 0**：气感为 0 的队员**切诊选项不可用**（UI 禁用，守卫检查）；**不返回任何"假值"**（无第二随机源，守卫检查）。
- [ ] **切诊被动**：队伍含苏晚棠或陆九针 → 切诊耗 0 行动；二者皆不在 → 耗 1（守卫检查）。
- [ ] **检验 gate = 检验 > 0**：无检验值的编成遭遇「带菌者」时，四诊返回"无显著证候"；含柳希白（检验 3）时可识别（两侧可测）。
- [ ] **心身 gate = 心身 > 0**：无身心值的编成遭遇「心因性疾病」时，还原牌效力 ≈ 0；含清和（心身 3）时可处理（两侧可测）。
- [ ] **单核 / 双核由牌池涌现**（4.7 表）：卷一（仅沈砚之）→ 速攻型；卷二（+陆九针）→ 双核——**不引用任何角色归属标签**即可判定。
- [ ] 编成含单侧牌池即出战**被放行**（"惨胜"），评级计单核罚项——**不得有无解编成**（逐关回归测试）。
- [ ] **roster 迁移**（3.7 表）逐条可测：`在队→离队` 令 `EffectivePower = 0`、合方牌不可用、羁绊冻结；`离队→归队` 按 `K_reunion 0.5→1.0` 恢复；`归队→在队` 在 `t≥5` 时效力满；`殉职` 为不可逆终态。
- [ ] **后备 ≠ 离队**：轮换下场（`formation=后备`）时该队员**节点不灰化、连线不断开**，换上即恢复可用；但**不能作为合方牌的出战端**（合方牌要求两端均出战）。二者为两件独立的事（守卫检查）。
- [ ] **归队与后备正交**：归队队员被轮换为后备期间，`K_reunion(t)` **仍按事件正常推进**（下场不暂停磨合）。
- [ ] **离队**：苏晚棠离队（卷六）时其合方牌灰化、移出牌池、羁绊冻结（不增不减不衰减）。
- [ ] **殉职**：其单方牌永久移除；其参与的「通」**仍可用**、遗志端**不支付费用**、羁绊凝固（守卫检查）。
- [ ] **队伍变动只在关卡边界**：战斗中尝试增删队员被拒绝（守卫检查）。
- [ ] **Teamwork 公式**（4.2）：`Bond=0→0.8`、`Bond=50→1.0`、`Bond=100→1.2`，逐值可测，且落在 `[0.8, 1.2]`。
- [ ] **羁绊增减**（4.3）：同场 +3/场、剧情事件 +5..15、连续未同场 ≥2 章 −2/章、上限 100、下限 0——逐条可测。
- [ ] **陈九章协同 `Σb_chen`**（4.5）：双核且在场时按异侧出牌计数，封顶 +0.15；**单核牌池下恒为 0**（守卫检查）。
- [ ] **陈九章一人不改变单核/双核**：仅将他加入纯还原编成，牌池判定仍为速攻型（守卫检查）。
- [ ] **霍崇光不出现在编成候选**：编成 UI 与牌池均不含 `boss_huo`（守卫检查）。
- [ ] 移动端 / 低配置下，编成界面（≤7 候选、4 位）渲染在 **16ms** 内完成（60fps 帧预算内）。
- [ ] 聚散状态、资源池当前值、羁绊矩阵可**完整存档 / 读档**（往返一致）。
- [ ] 所有数值（属性、上限、系数、羁绊阈值）来自外部配置，实现中**无硬编码**。
