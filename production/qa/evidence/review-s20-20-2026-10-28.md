## §三 原判定逐条(修复前实况)

### B-1 · `ApplyBakedInitial` 非原子 + 报文误导(**BLOCKING**)

**原判定**:`World.cs:101` 先置 `_moduleCatalogForBaseline`,再于 `:102` 调本体。两个后果均**静默**:

1. **半应用**:骨架 `[合法格, 非法 module_id 格]` 时,`i=0` 已 `Restore` 落库(`:148`)
   且已 `OccupyCells` 占格(`:150`),随后 `i=1` 抛 ⇒ 世界停在「开档少了几件、
   但少的那几件的格**已经被占住**」的中间态,**无任何信号**。
2. **报文误导**:标志已置 ⇒ 调用方重试时收到「已应用过一次」,而它**从没完整应用过**
   —— 报文把「失败了」说成了「做过了」。

**主会话独立复核**:✅ 成立。逐行读过 `:96-103` 与 `ApplyBakedInitialBaseline()` 的 `:106-154`。

### B-2 · fail-closed 夹具「零落库」断言恒真(**BLOCKING**)

**原判定**:`world_buildslots_bake_test.cs:531-561` 的骨架是**单格**(`moduleId: 999`)⇒ 抛在
`i=0` ⇒ 循环体**一次都没跑完过**,本就不可能落库。后面那条
`Assert.That(world.Structures.EnumerateInstances().Any(), Is.False, "抛之前不得落任何实例")`
**恒真** —— 那不是「证明零落库」,是「没机会落库」。

**主会话独立复核**:✅ 成立。该夹具的注释(`:556-557`)正确避开了「断言 `BakedInitialStructureCount`
== 0 是恒真」这个坑(那属性只在循环末尾赋值),但**单格骨架**让整条夹具的判别面同样失效。

### S-1 · 导出门 `module_id` 值域漏 `0`(**须修**)

**原判定**:`LevelConsistencyCheck.cs:106` 判 `s.ModuleId == SlotSpec.NoModule`(即 `== -1`),
而 ADR-022 `:176` 的契约是 **`module_id ≥ 1`**。差集 = `module_id = 0` **从导出门漏过去**,
只有绑定器(`:373` `n.Int < 1`)与 codec 才拒。而导出器是「唯一作者」——
作者的错就该在作者自己的工具里报,漏到绑定期等于把报文指到下游。

**主会话独立复核**:✅ 成立。

### S-2 · 基线 id 段与重放 id 段可重叠(建议 · **跨卡**)

**原判定**:基线发号 `1..N`(`World.cs:125-153`),而 baseline 之前的存档(schema 1)里
玩家放置也从 `1` 起号 ⇒ 重放第一条 `Placed(id=1)` 撞上基线第 1 件。
`StructureKinds.cs:221-222` 的 `_instances[structureId] = …` 对同号是**静默覆盖**,
且 `Restore` **从不碰占用表** ⇒ 被覆盖那件的足迹**永久不可走**。

> 🔁 **2026-10-28 措辞订正(原文不删)** —— 「schema 1」是**用词错误**:仓库里它专指
> `world_buildslots.json` 的**作者态 JSON 格式**,与**存档格式** `SaveVersion` 无关。
> 真实类别是**时序**(基线诞生于 `d230eb36` / 2026-10-28 之前无基线)。
> **另:同会话内不可达**(基线 `CompositionRoot.cs:918` 与 writer `:941` 共用注册表,
> `Restore` 抬高高水位 ⇒ 玩家必得 `N+1` 起)。⇒ 本 S-2 的**可达条件**比原判定写的窄得多。
> 已登记为债册 **`TD-building-02`**(`open` / `P0 面 = N`)。

**归谁**:该缺陷的**修复面**在 `StructureRestorer`(归 S20-18),故原判定登记在此、
**修复与证明落在 `review-s20-18-2026-10-28.md` §五**。
