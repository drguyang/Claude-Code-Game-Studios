## Summary

7b 是**那本册子**。它是玩家**唯一能直接接触 7a 的面** —— 7a 的一切(三流 / 折叠 / 快照 /
迁移)对玩家不可见,**7b 把它呈现成一个可翻、可读、可选的槽位列表**。

**7b 只兑现呈现语义,不新增第四逻辑**(7a 规则十四的明文委派)。三条硬语义来自 7a:

1. **槽位只进不退** —— 你**不能改写**册子里已经写下的页;
2. **读档即锁** —— 同一会话内已载入的槽位锁 reads 侧;
3. **载入安全上下文门** —— 手动载入与手动存**同钩**:都须在**无未决医疗动作**时
   (2026-09-19 裁定,承首轮评审 BL-1)。

**7b 是 `S` 级系统**(`systems-index.md` §11):它**没有机制**,只有**呈现**。
它的全部设计任务 = **把规则十四的三条约束(含载入安全上下文门),做成玩家看得懂的拟物交互**。

> **⚠️ 反 save-scum 的承载面。** 7a 的「恰好三个触发点」计数防不了玩家趁**没犯错**时存盘
> (规则十四:`:188`)。**7b 是这条防线的玩家可见侧** —— 它必须让「为什么不能覆盖」**可理解**,
> 而不是**无声拒绝**。
>
> **⭑ 2026-09-19 修订(承首轮评审 BL-1)**:反 scum 的三道守**全部在写侧** —— 只进不退 /
> 读档即锁 / 叙事事件上下文(`persistence-service.md:191-200`)。**读侧本身没有闸**:手动存只许在
> 「无未决医疗动作」⇒ 恰是出诊前后;存 A → 坏判断 → 读 A(A 被锁)→ 此刻仍无未决动作 ⇒ 存 A+1
> (合法,只进不退)→ 再坏 → 读 A+1…… **每页 = 一次免费重试**;跨会话锁则复位。首轮评审因此裁定:
> - **7b 的承诺收窄** —— 「你不能用读档洗掉一次坏判断」的**写侧**由 7a 规则十四守,其**读侧**
>   由 7a **载入安全上下文门**守(未决动作中不可载 ⇒ 洗不掉「正在处理的判断」);**跨会话不设锁字段**
>   (ADR-010 §六):重开游戏 = 重新开始「今天」,不提供对过去坏判断的撤销。
> - 页面措辞随之改:不问「我回不回得到判断之前」,而问「**我能不能用读档把我正在处理的这单判断洗掉**」。

## Overview

7b 是**呈现层的第五件套**(42 底座 · 39 是纸 · 44 是耳朵 · 48 是那个教你的人 · **7b 是那本册子**)。
它与 42 / 39 / 44 / 48 同构:**只触发 / 只渲染,永不持有游戏状态**(承 ADR-013 §9 C3)。
**7b 是 42 的模态闭集成员**(现 7 员;2026-09-21 前登记为「六屏闭集」。`ModalId.SaveSlots`,枚举权威 = `ADR-013 §十 / §十-B`;成员表见 `skeuomorphic-ui.md` `AC-42-F1` · `interaction-system.md` 模态门行 —— ⚠️ 原行号引用已随 42 修订漂移,以 §锚为准)

## Player Fantasy

**「这是一本册子,记到哪儿就是哪儿。」**

- **册子的物理性** —— 翻页有纸纹,槽位是**页上的条**,不是**列表项**。
  承 42 的 USS 元件库(纸纹 / 墨迹 / 卷轴九宫格)。
- **记到哪儿就是哪儿** —— 玩家能理解:**这本册子只能往后写,不能撕掉重来**。
  这个「不讲道理」的规则,必须**在幻想层讲得通**:**医案是写下的,不能改**。
- **读档洗不掉坏判断** —— 你**不能**用「读回上一页」把正在处理的这单判断作废
  (**载入安全上下文门**:未决医疗动作中不可载入)。你**可以**在无未决动作时**重开**一个断点,
  但 **7b 不承诺跨会话撤销** —— 重开游戏 = 重新开始「今天」。
- **不被告知为什么拒绝** —— ⚠️ **但也不能无声拒绝**。区别在于:
  **给的是世界内的解释**(页角的一行小字 / 一条墨痕),**不是弹窗**。

> **⚠️ 7b 的幻想有硬边界:它不能变成「读盘屏」。**
> 无「载入进度」标题、无「覆盖存档?」对话框、无「存档成功」toast。
> **7b 是一本册子,不是设置菜单**(承 42 的反幻想纪律)。

## Detailed Rules

### 规则一:三层分离 —— 7a 逻辑 / 7b 语义 / 42 渲染

| 层 | 拥有什么 | 依据 |
| --- | --- | --- |
| **7a 持久化** | 槽位**写入** · `slot_seq` 单调校验 · **禁载语义** · 槽位头信息(**tick / 时间戳 / 摘要**) | `persistence-service.md` 规则十四 · AC-7a-19 |
| **7b 存档位 UI** | 槽位列表的**呈现组织** · 约束的**呈现**(灰置 / 文案语义) | 本节 |
| **42 拟物 UI** | **渲染**与**焦点导航** | ADR-013 §三 |

> **⚠️ 判据**:**7b 不得调用 `Checkpoint(slot)` 之外的写入 API**,**不得**自己判断「能否覆盖」
> —— 覆盖被拒**由 7a 返回**(`slot_seq` 单调校验),7b **只呈现结果**。

### 规则二:槽位只进不退 —— 呈现为「只能往后写」

**7b 呈现的语义**(来自 7a 规则十四 ①):

| 情形 | 7a 的行为 | 7b 的呈现 |
| --- | --- | --- |
| **写时序递增槽位**(上次叙事事件之后) | 允许 | 新页可取,可写 |
| **覆盖既有槽位**(`slot_seq` 不增) | **拒绝** | 该页**灰置 / 不可选**,页角一行小字说明 |

> **⚠️ 呈现的方式是「世界内的」**(页角小字 / 灰墨),**不是弹窗 / 红字 / 抖动**。
> **「为什么不能覆盖」的解释文本归 7b 的文案;那条约束的判定归 7a。**

### 规则三:读档即锁 —— 呈现为「这本已合上」

**7b 呈现的语义**(来自 7a 规则十四 ② + **载入安全上下文门**):

- **从某槽位载入后**,该槽位在**同一会话内**锁 **reads 侧**;
- **7b 呈现锁状态**(灰置),**锁的持续到下一次叙事事件触发**(AC-7a-19);
- **禁载语义在 7a** —— 7b **不实现**锁,只**画出来**。

> **为什么锁**:防「先手动存 → 读档 → 再手动存」的循环(规则十四:`:194`)。
>
> **⭑ 2026-09-19 修订(承首轮评审 BL-1)**:**载入 = 7a 的「载入安全上下文门」** —— 与手动存同钩,
> 都须在**无未决医疗动作**上下文(共用观察钩子)。未决动作中发载入请求 ⇒ **7a 拒绝**,7b 呈现
> 册子**当前不可读**。**7b 的呈现本体**因此从「一句纯只读」变成**两投影**:页级「读音 / 写因」分离
> (见 F-7b.2)。**补遗**:`Gating` 状态已加入 7a 加载状态机(`persistence-service.md` 加载状态机)。

### 规则四:叙事事件上下文 —— 呈现为「现在还不能写」(也还不能读)

**7b 呈现的语义**(来自 7a 规则十四 ③ + **载入安全上下文门**):

- **手动存只允许在「脉案落笔 / 病例结案 / 出诊启动」等叙事事件之后的无未决医疗动作上下文**;
- **不在该上下文时的手动存 → 被 7a 拒绝**;
- **手动载入与手动存同钩**(2026-09-19):不在该上下文时的手动载入**亦被 7a 拒绝**;
- **7b 的呈现** = 册子在该时刻**不可写也不可读**(页边无笔 / 灰置 / 页边折角),**零弹窗**。

> **效果**(7a 规则十四 `:201-202`):玩家能在**叙事事件之间**用手动槽存断点,
> 但**回不到任何一次判断之前** —— 手动槽永远在**最后一个叙事事件之后**;
> 且**洗不掉正在处理的判断**(载入安全门)。

### 规则五:7b 零游戏状态 —— 只读 `SaveSlot`,不写流

**7b 与 42 / 39 / 44 / 48 同构:不引用 sim 类型,不写三流。**

- 7b 读的是 **7a 的槽位列表**(`SaveSlot` 集合),**不持有任何缓存副本**;
- 7b **不 Append 任何 `SimEvent`** —— 存档是**基础设施**,不是**游戏事件**;
- **槽位列表是读时计算**(7a 的投影),**7b 不落盘任何槽位镜像**。

> **⚠️ 判据**:7b 的交付物类型若引 `SimEvent` / `PatientState` / `Fix`,
> **是契约违反**,由 **AC-7b-03** 的 asmdef 白名单 + IL 扫描断言(与 44 / 48 同型)。
>
> **⭑ 2026-09-19(承首轮评审 BL-3)**:`SaveSlot` 的**定义**位于 ADR-010 §Key Interfaces(本会话已补
> `struct SaveSlot { uint slot_seq }`);**tick / 时间戳 / 摘要**为 7a 的**列表投影 DTO**(`SaveSlotInfo`,
> 定义归 7b),**呈现量,不进确定性字节面**(ADR-012 对拍不受扰)。`Writable / Locked /
> InNarrativeContext(t)` 三量已在 7a 侧记明由**载入安全上下文门**门控。

### 规则六:无「存档成功」反馈(无提示音铁律的呈现侧)

**7b 绝不播报存档结果。**

- **无「已保存」toast / 无绿勾 / 无进度条**;
- **存档的反馈 = 世界内的动作**(合上册子 / 一条墨痕 / 页边的压痕)—— 承 42 的拟物元件;
- **拒绝的反馈 = 世界内的拒绝**(页不可撕 / 灰墨),**不是**错误弹窗。

> **⚠️ 承 ADR-018 §六 的无提示音铁律**(同一铁律的视觉 / 交互侧,与 ADR-020 §六 的镜头效果同源):
> 「存档已写入」是**状态播报**,**不在行为反馈白名单**(AC-44-09)。

### 规则七:焦点导航 —— 不可选槽位仍可聚焦

承 `technical-preferences.md`(拟物 UI 必须同时支持键鼠与手柄):

| 需求 | 7b 做什么 |
| --- | --- |
| **焦点顺序** | 按 `slot_seq` **递增**(册页序)—— **不可重排** |
| **灰置槽位** | **仍可聚焦**,有拒绝反馈(压痕 / 纸的钝响),**零提示文案浮层** |
| **描述** | 槽位头信息(tick / 时间戳 / 摘要)由 7a 给,7b 呈现 |
| **Submit / Interact** | 开册时 **South = Submit 归 7b,Interact 被 42 模态冻结**(世界交互经 4);**Submit 的焦点接收者 = 册页**(零双触发) |

> **焦点单栈门**(ADR-013 §三):存档册打开时,世界栈焦点冻结。**禁双 EventSystem**。
> **承 `AC-42-F1` 模态闭集**(现 7 员) —— 开册 = 42 模态;Submit 与 Interact 的键位区分归 42 的焦点桥
> (unity-ui 首轮评审要点,已并入)。

## Formulas

> **7b 不产生任何数值。** 它是呈现系统 —— 公式只有**排序**与**可选性投影**两条,全 `int`。

### F-7b.1 槽位排序(纯函数,零存储)

```
OrderedSlots(state) = sort_asc( SlotsOf(state), by = slot_seq )
```

| 变量 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `SlotsOf(state)` | 集合 | **7a** | 7b **不持有槽位集** —— 现查 7a |
| `OrderedSlots` | 序列 | — | **册页序 = `slot_seq` 递增** |

### F-7b.2 槽位可读 / 可写(两投影 —— **判定归 7a**)

```
Writable(slot) ⟺ ¬Locked(slot) ∧ InNarrativeContext(t) ∧ slot_seq(slot) ≥ next_writable_seq
Loadable(slot) ⟺ ¬Locked(slot) ∧ InNarrativeContext(t)
```

| 项 | 归属 | 说明 |
| --- | --- | --- |
| `Locked(slot)` | **7a** | 读档即锁(规则三) |
| `InNarrativeContext(t)` | **7a** | 叙事事件上下文(规则四)**= 载入安全上下文门同钩** |
| `next_writable_seq` | **7a** | 只进不退(规则二) |
| **`Writable(slot)` 的呈现** | **7b** | 灰置 / 可选 —— **7b 只投影,不判定** |
| **`Loadable(slot)` 的呈现** | **7b** | 可读 / 灰置 —— 同上 |
| **页级因由** | **7b** | 三义分通道(折角 / 笔迹 / 墨色)承载 —— 玩家区分「这页不能改写」vs「此刻整册不能打开」 |

> **⚠️ 两式是 7b 侧的**呈现投影**,不是 7b 的**判定**。**7a 是唯一判定者**;
> 7b 拿到 `Writable` / `Loadable` 后**只决定怎么画**。**这是三层分离的硬边界**(规则一)。
> **2026-09-19 修订(承首轮评审 BL-4)**:原 F-7b.2 只有 `Writable` 一式,且 `¬Locked` 为死项
> (锁管 reads,写侧已被 `slot_seq ≥ next` 拦);现拆 **`Writable` / `Loadable` 两投影**,
> 各配独立灰置通道,`Loadable` 由**载入安全上下文门**门控。

## Edge Cases

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| **玩家尝试覆盖既有槽位** | **7a 拒绝**;7b 呈现灰置 + 页角小字(**零弹窗**) | 规则二 |
| **玩家在无未决医疗动作上下文外手动存** | **7a 拒绝**(无叙事事件);7b 呈现册子不可写 | 规则四 |
| **玩家在无未决医疗动作上下文外手动载入** | **7a 拒绝**(载入安全上下文门);7b 呈现册子不可读 | 规则三 / 四 |
| **读档后同一会话内再次载入同槽位** | **7a 拒绝**(reads 侧锁);7b 呈现灰置 | 规则三 |
| **下一次叙事事件触发后** | 锁解除 + 安全门解除(7a);7b 呈现册子恢复可选 | AC-7a-19 |
| **损坏存档(校验失败)** | **7a 自动回退 `bak`**;提示的**承载归 42 / 7b**(7a 只给语义 —— 「回退到上一 checkpoint」) | ADR-010 §四 · `persistence-service.md:405` |
| **`ConfigVersion` 不匹配** | **非致命**(ADR-010 §七)—— 7b 呈现「配置已更新」语义(**⚠️ 文案归 7b,见 OQ-7b-4**) | ADR-010 §七 |
| **纯手柄单机** | 全部槽位经焦点导航;**灰置槽位仍可聚焦**(有反馈,零浮层) | 规则七 · AC-7b-06 |
| **无存档槽位**(首次游戏) | **册子空白**;首个 checkpoint 后出现 | 规则二 |
| **槽位列表为空时打开存档册** | **允许** —— 空白册页;零「无存档」弹窗 | 规则六 |

| **灰置的呈现强度**(墨色 / 质地) | 未定 | — | 可理解性 | 太弱 = 玩家不懂为何不可选(无声拒绝) |
