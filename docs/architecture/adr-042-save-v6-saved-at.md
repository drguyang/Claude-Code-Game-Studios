## Context

### 1. 四条用户指令(2026-11-06,逐字)

1. 「存档每行最前的序号没必要」 —— 行首的槽位序号(壹 / 贰 / …)对「我该读哪一页」零帮助。
2. 「可以每行最后增加一半大小字体的真实世界时间(年月日小时分钟秒)」 —— 玩家要能分辨「这一页是什么时候写的」。
3. 「已锁换成灰色背景进行区分」+ 追加「已锁不保留小字」 —— 状态**只走色彩通道**。
4. 「点击只显示读入,覆写显示灰色暗示不可覆盖存档」 —— 覆写入口保留但灰置。
   经追问澄清:**只有「已锁」行不可覆写**;未锁的已有档行仍可「启封 / 重写」。
5. 追加澄清(本轮唯一的语义级裁定):「**把锁改到写侧**」。

### 2. 第 5 条为什么是**语义级**的,不是文案级

改前(ADR-041 §D3,2026-11-04 裁):**锁在读侧** ——
`SaveService.RequireLoadable` 碰上 `_ledger.IsLocked(slot)` 直接抛,`SlotProjections` 的两条公式是

```text
Writable(slot) ⟺ InNarrativeContext(t)
Loadable(slot) ⟺ ¬Locked(slot) ∧ InNarrativeContext(t)
```

屏上随之:已锁行的「启封」灰置、「重写」仍可用,且**不进二段态**(2026-11-05 的整改,
因为默认焦点会落到「重写」上 ⇒ 一次确认就毁档)。

用户要求的「已锁行点开后**启封还是墨字**」在这个模型里**做不到** ——
把它画成可用的墨字,按下去只会抛异常、落日志、屏上零反应。那正是 2026-11-05 那条整改
要消灭的形态。⇒ 要么放弃这条要求,要么**把锁换到另一侧**。用户选了后者。

### 3. 第 2 条为什么必须是 v6,而不能读文件时间

| 候选 | 否决理由 |
|---|---|
| **存档文件 mtime** | 不走存档格式确实便宜,但 mtime 会被**拷贝 / 备份 / 恢复**改写;`.bak` 回退时读到的是备份文件的写入时刻,不是那一档的落笔时刻。玩家看到的时间会凭空变化,而屏上没有任何提示说它不可信。 |
| **世界 tick 换算** | 那是**游戏内**时间,不是真实世界时间 —— 用户要的是后者。 |
| **只显示「第 N 日」** | 今日已在显示;它解决不了「同一天存了五次,该读哪一页」。 |

⇒ 用户裁定 **写进存档头**:时间跟着档走,拷贝不变。代价是存档格式 +1 个字段、
一条迁移脚本、黄金夹具重签。

## Decision

### D1 — 存档 v6:头部末尾追加 `SavedAtUtcTicks`(i64)

```text
v5 头部定长 = 92 B(不含校验和)   v6 = 100 B
v5 全头   = 124 B                v6 = 132 B
```

字段位置 = **头部定长段的末尾**(紧接 `IntensityMax`)。追加在头部末尾而非正文末尾的理由与
ADR-038 §D3 逐字相同:迁移链按「从末尾算的字节」比对正文(`SaveMigrationChain.TailBody`),
**尾部追加必破该断言**。

`SaveVersion` **5 → 6**;`SaveHeaderCodec.FixedSizeFor` / `HeaderSizeFor` 各加一档。

### D2 — 迁移 `SaveMigrationV5ToV6`:补 **0**(未知),不伪造

在 `FixedSizeV5`(92)处插入 8 字节 `0`,版本号写 6,其余字节逐位不动。

⚠️ **为什么不补一个「估计值」**:v5 及更早的档**从未记录**落笔时刻,补任何值都是伪造 ——
后果是册子上每行都标着一个「看起来发生过、其实没发生过」的时刻。`0` = 未知,
呈现层对 0 **一律不显示**(ADR-037「未知 ≠ 无差异」同一条纪律)。

### D3 — 墙钟的**唯一**生产读取点 = 装配层组版闭包

`CompositionRoot` 的 `compose` 闭包传 `savedAtUtcTicks: DateTime.UtcNow.Ticks`。

- `SaveComposer.Compose` 的该形参**可省略**(默认 `0` = 未知),仅允许**夹具**模拟老档时使用;
- **`Sim` 程序集仍零墙钟 API**(ADR-040 V-8 的判据原样保留);
- 三流 / 重放 / 判定**一律不读**该字段 —— 它与 sim 的确定性面零交集。

### D4 — 呈现:本地时区,`yyyy-MM-dd HH:mm:ss`,半字号

- 存 **UTC**、显示**本地时区**(玩家认自己墙上的钟);
- 格式 `2026-11-05 23:41:07`(定长、可排序、无本地化歧义);
- 字号 = 纸面 24px 的**一半**(12px,`--skeuo-font-size-slot-time`);
- 位置 = 行的**最右端**(用户追加裁定「时刻加在行末尾」),二段态的墨字插在它与行文字之间;
- `0` / 越界 ⇒ **零字**(不占位、不编造)。

### D5 — 锁从**读侧**搬到**写侧**

```text
Writable(slot) ⟺ ¬Locked(slot) ∧ InNarrativeContext(t)     ← ¬Locked 回到写入门
Loadable(slot) ⟺ InNarrativeContext(t)                     ← 摘掉 ¬Locked
```

- `SaveService.RequireLoadable` **删掉锁门**;`SaveSlotLedger.EnsureWritable` **新增锁门**(门 ①′);
- 反 scum 的承重件从「禁止重读」换成「**禁止把当前进度盖回你刚读回来的那一槽**」;
- **未锁**槽的覆写**仍然合法**(ADR-041 §D2 那半条裁定不动);
- ⚠️ **显式后果**:读过的档可以**无限重读**。这是裁定的直接推论,不是遗漏。

### D6 — 行文字:去序号;已锁 = 整行灰底、**零字**

- 行首序号删除;有档行 = `第壹日 昼`(§5.4 字段二的降级形态),尾缀只保留 `前版` / `此页已损`;
- 已锁 ⇒ `save-slot-locked` 类(墨色稀薄覆盖 `rgba(43,36,22,0.14)`),**不再写「· 已锁」**、
  **不再出页角注**(用户明确要求);
- ⚠️ **`DayNumber == 0` 的回退**:此时退回「只写序号」—— 唯一仍会看到序号的形态,
  目的是「有档的行不得画成空白行」。

### D7 — 二段态:已锁行照常展开,「启封」可用、「重写」灰置且不可获焦

- 焦点**恒**落「启封」(唯一恒可执行的那一枚);
- 灰置 = 墨色降档(`.save-slot-choice-disabled`)+ **退出焦点序**;
- 删掉 2026-11-05 的「已锁不进二段态 + 页角注」分支 —— 它解决的是同一个灾难
  (默认焦点落在「重写」上 ⇒ 一次确认毁档),现由「重写灰置且不可获焦」继续挡住。

## Consequences

### 正面

- 册子上每页都能回答「这一页是什么时候写的」,且时间**跟着档走**(拷贝 / 备份不改它);
- 「已锁」的原因不再需要一句文案解释:灰底 = 这页现在动不了,点开看得见**能做什么、不能做什么**;
- 7a 的锁语义与玩家直觉对齐 —— 锁的是「别覆盖」,不是「别再看」。

### 负面 / 风险

| # | 风险 | 处置 |
|---|---|---|
| R1 | **反 scum 变弱**:读过的档可无限重读 | 如实登记。锁仍挡「读→改→再读」的**写**那一半;ADR-041 §D3 的原论证(「读 A → 覆写 A → 再读 A」)仍成立,只是断点换位置 |
| R2 | **存档字节变**(头部 +8 B)⇒ ADR-012 的集成级黄金夹具须重签 | 本轮无真实存档(用户已清空),夹具侧逐条更新;`save_v6_saved_at_test` 钉住新布局 |
| R3 | v6 之前的档迁移后**没有时间**,册子上那几行只有「第 N 日」 | 诚实缺省;今日零真实存档 ⇒ 实际不可见 |
| R4 | 灰底是**纯色彩通道**,色觉障碍玩家读不出「已锁」 | 用户明确裁定「不保留小字」。仍可分辨的是**按下去的反应**(重写灰置不可获焦)。补非色彩通道须先改该裁定 |
| R5 | `SaveComposer` 的 `savedAtUtcTicks` 可省略 ⇒ 未来调用方可能静默写 0 | 生产调用点唯一(`CompositionRoot`);`save_v6_saved_at_test` 在**真实装配**上断言落笔后非零 |

## Alternatives

| # | 方案 | 为什么不取 |
|---|---|---|
| Alt 1 | 保留读侧锁,只把已锁行的「启封」画成可用墨字 | **UI 说谎**:7a 会抛,玩家看到「按了没反应」—— 正是 2026-11-05 整改要消灭的形态 |
| Alt 2 | 时间读文件 mtime | 见 Context §3:拷贝 / 备份 / 恢复都会改写它,而屏上没有任何提示 |
| Alt 3 | 时间留在 `worlds.index`(按世界),不进档头 | 一个世界有 16 个槽,它们在同一个世界里;按世界的时间回答不了「哪一页更新」 |
| Alt 4 | 让 `SaveHeader` 之外旁挂一个 `.meta` 文件存时间 | 破单文件原子写与校验和耦合(ADR-010 §一),且引入「两份文件不同步」的新失效面 |
| Alt 5 | 保留「· 已锁」小字作非色彩通道 | 用户明确裁定不保留;已知风险登记为 R4 |
| Alt 6 | 已锁行直接隐藏「重写」而非灰置 | 用户要的是「**显示灰色**暗示不可覆盖」—— 消失等于不告知 |

## ADR Dependencies

- **ADR-010 §一 / §七** —— 布局与逐版本迁移协议:本件是第 4 条真实迁移;
- **ADR-012** —— 存档字节黄金夹具须随布局重签;
- **ADR-038 §D3 / Amendment A** —— 「头部末尾追加」的两条先例,理由逐字复用;
- **ADR-040 §D4** —— 「墙钟不进存档头」的边界句**就地收窄**(见下方 Amend 注);
- **ADR-041 §D2 / §D3 / §D5** —— 覆写合法那半条不动;§D3 的「覆写不清锁」现**不可达**;
- **`AC-7a-19 (d)`** —— 读档即锁的**落点**从读侧改到写侧(AC 编号与「读到就锁」的事实不变)。

### 对 ADR-040 §D4 的窄修订(已就地落注)

原文:「墙钟**只用于选择面**……不进 `SaveHeader`」。本件把它收窄为:

> 墙钟**不进 sim**(`Sim` 程序集零墙钟 API、三流 / 重放 / 判定不读),但**可以进 `SaveHeader`**
> —— 且只有**一个**字段(`SavedAtUtcTicks`)、**一个**写入点(装配层组版)。
> 「选择面」的语义由「世界列表」扩到「存档册行」。

### 对 ADR-041 §D3 的窄修订(已就地落注)

「覆写一个已锁槽**不解锁**」这条不变式**保留**,但其**适用面已消失**:
已锁槽根本进不来写路径(`EnsureWritable` 门 ①′ 先抛)。保留该注的理由是不变式本身 ——
将来若有人放开写侧门,`OnCheckpointCommitted` 也绝不能顺手解锁。
