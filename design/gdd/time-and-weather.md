## Summary

5 是**世界的节拍器**。它回答三个问题:**现在是什么时辰 · 什么季节 · 什么天气**。

**5 与 ADR-005 的边界是本 GDD 的第一条铁律**:

> `ITickProvider.CurrentTick` 是**全案 tick 的唯一来源**(ADR-005)。**5 不拥有它。**
> **5 拥有的是 tick 的语义** —— 多少 tick 是一天、多少天是一季、
> 哪一段 tick 是夜、某一 tick 的天气是什么。

| 层 | 归属 | 形态 |
| --- | --- | --- |
| **tick 本体** | **ADR-005** | 单调递增的 `long`,主机唯一推进 |
| **tick 的语义映射** | **5** | 时辰 / 日 / 季节 / 天气 |
| **生态区 → 气候属性** | **6** | 查表(**6 定义,5 消费** · `O-6-5`) |

**5 的天气是派生态**(承 ADR-009 §二):**它是 `(WorldSeed, tick, 生态区)` 的纯函数**,
**不进流、不存档、重建期重建**。这与「静态地形 = 确定性重建」同构。

> **⚠️ 5 的产出不是一个数,是一张「当前情境」的表**:时辰(`isNight`)· 季节(`season_index`)·
> 天气(`kind`/`intensity`)· 天光连续读数(`skylight`,仅 42)· `EnvMod` 的环境分量(`EnvMod_raw`)。
> **5 不结算任何玩法** —— 它只**供料**(52 的 `TODMult` 是 52 对 `isNight` 的消费,不是 5 的产出)。

> **🔴 P0 活边清单(首轮评审 R-5-C 的显式风险接受,2026-09-19)**:5 在 P0 的**机制**消费者只有三条 ——
> ① `isNight` → 52 的 `TODMult`(时机轴);② `EnvMod_raw` → 21a F1(经 18);③ `season_index` → 17 的
> `SEASON_MULT[]`(值归数值轮)。**天气本体(`kind`/`intensity`)在 P0 零机制消费者** ——
> 「天气→52 强度轴」经首轮核实为**幻影边**(52 的强度轴五变量无天气项),已**降级 P1a 登记**
> (见规则七与 `OQ-5-8`);5→9 的「季节系数」边同为幻影(9 于 `disease-simulation.md:650` 自禁季节权重),
> 已在 9 侧撤销为「仅 tick 源」。⇒ **P0 的天气 = 纯呈现(42/44)+ `EnvMod_raw` 的 `kind` 项输入**。
> **Player Fantasy 的可感知腿是昼夜与季节,不是天气本身**;正向义务见 `AC-5-18`。

## Overview

**5 是「不显眼的承重墙」**:它在 GDD 目录里是最短的一份,却有三条**跨系统承重边**。

**5 的三个面**:

| 面 | 内容 | 消费者 |
| --- | --- | --- |
| **时间轴** | 日边界(`TICKS_PER_DAY`)· 季节 · 昼夜 | **52**(`TODMult` / 预算窗口)· 42(天光)· 44(声床) |
| **天气** | 当前天气 + 强度(派生态) | **42 / 44**(呈现)· **5**(F-5.4 的 `kind`/`intensity` 入 `EnvMod`)· ⚠️ 52 强度轴 = **P1a**(P0 幻影边已撤,`OQ-5-8`) |
| **环境项** | **`EnvMod` 的环境分量**(可为负) | **18 / 21a**(炮制修正)· **17**(季节修正曲线) |

> **⚠️ 5 是唯一可以**合法产出负 `EnvMod`** 的系统之一**(另一个是 24)——
> 承 21a `:484`「火候难控、背阴」。**负值是结构的一部分,不是错误**(见规则六)。

**5 不做的三件事**:

1. **不拥有 tick** —— tick 归 ADR-005(规则一);
2. **不定义生态区** —— 气候属性表归 6(规则二);
3. **不结算任何玩法效果** —— 它出**乘子与读数**,由 18 / 17 / 52 各自消费(规则七)。

## Player Fantasy

**「天在走,病也在走。」**

- **时间是压力,不是背景** —— 太阳落下去了,你还没到下一个村子;
  病人在等你,**他不会因为你天黑就病得慢一点**(支柱二)。
- **同一件事,不同的天** —— 背阴处晒不着太阳,药就做不好;
  雨季的山路难走。**「翻过这道坎,规则变了」**(承 6 的支柱三)有**时间**的一面:
  **同一个地方,冬天和夏天不是同一个地方**。
- **天气有它自己的意志** —— 你不能预约晴天。**出门前抬头看一眼**,然后决定带什么
  (与 20 的药箱取舍咬合 —— 支柱一)。⚠️ **首轮评审注(R-5-C)**:P0 的「天气」不改变
  移动与事件强度(腿被规则八 / `OQ-5-8` 关闭),「看一眼」在 P0 的机械指涉 =
  **`EnvMod_raw` 的 `kind` 项**(今天出去晒不干 / 灶前背光),其可感知性由 `AC-5-18` 兜底;
  「出门前看天预报目的地」的完整兑现挂 P1a(`OQ-5-2` / `OQ-5-8`)。

> **⚠️ 5 的幻想有硬边界:它不是一个「天气预报 UI」。**
> 无预报数值、无「明日 60% 降雨」、无季节进度条。
> **天候是抬头看见的,不是读出来的**(承 42 的拟物铁律 / U-3 禁数字 HUD)。
> 历书上写的**干支与节气**是**史实层的呈现**(支柱五),**不是机制读数**。

## Detailed Rules

### 规则一:tick 归 ADR-005,5 只拥有**语义**

**承 `adr-005:233`**:

```
public interface ITickProvider { long CurrentTick { get; } }   // 全案 tick 唯一来源
```

| 项 | 归属 | 5 的角色 |
| --- | --- | --- |
| **tick 的推进**(步长 / 暂停 / CatchUp) | **ADR-005** | **只读** `CurrentTick` |
| **日边界**(`TICKS_PER_DAY`) | **5** | **定义**(⚠️ 见规则四:与 52 同值) |
| **季节长度**(`TICKS_PER_SEASON`) | **5** | 定义(**真·季长参数** —— ✅ R-5-D 2026-09-19:F-5.2 实际用它,**不用 `TICKS_PER_DAY`**;首轮评审揭出此项此前是孤儿声明) |
| **昼夜相位** | **5** | 由 `FMod(tick, TICKS_PER_DAY)` 派生 |
| **天气** | **5** | 由 `(WorldSeed, 块(tick), 生态区)` 派生(R-5-A) |

> **⚠️ 判据(AC-5-01)**:5 的代码路径**不得**出现任何**写 tick** 的路径
> (`Time.deltaTime` / 墙钟 / 自增计数器)。**5 是纯读方。**

### 规则二:生态区气候属性归 6 —— 5 **消费**,**不定义**

**承 `world-and-ecozones.md:271` / `O-6-5`**:6 **只提供表**;季节推进与天气演化归 **5**。

| 项 | 归属 | 内容 |
| --- | --- | --- |
| **气候属性集**(每生态区一条) | **6** | 温度带 / 降水倾向 / 风 / 昼夜温差 … |
| **查表**(`EcozoneOf(cell) → 气候属性`) | **6** | 纯函数(承 ADR-015 §一 的烘焙逻辑层) |
| **季节推进 / 天气演化** | **5** | 本节 |
| **`EnvMod` 的环境分量** | **5** | 由「气候属性 × 季节 × 天气」派生 |

> **⚠️ 防越界的反向义务**:5 **不得**定义 `生态区` / `气候属性` 的字面 ——
> **若须新增一条气候属性,回 6**(承 `O-6-5`)。**双主 = R-6-13 被击破。**
>
> **⚠️ 无生态区时的兜底**:玩家**不在任何生态区内**(如未驻留 chunk,承 `OQ-6-8`)⇒
> `EnvMod` 取**全局默认**(承 `world-and-ecozones.md:742`)。**不得**取「最近区」。

### 规则三:天气 = 派生态 —— `(WorldSeed, 块(t), 生态区)` 的纯函数

**承 ADR-009 §二**:天气**不进流、不存档、重建期重建**。

```
Weather(tick, cell) = W( WorldSeed, WEATHER_BLOCK(tick), EcozoneOf(cell) )
WEATHER_BLOCK(t)    = t / WEATHER_BLOCK_TICKS        // 整除;块索引
```

> **✅ R-5-A(2026-09-19 首轮评审裁定)**:掷骰键从 `tick` 改为**块索引** ——
> 块内天气恒定、跨块重掷,相干时间 = `WEATHER_BLOCK_TICKS`(值归用户)。
> 原稿「逐 tick 独立掷骰」经 systems-designer 反证:TPD=1440 时数秒换一次天,
> 噪声闪烁,与 Game Feel「连续变化不是瞬切」直接相悖。
> **原稿 :307 的理据(「带转移链就必然进流」)为假** —— 按 `(WorldSeed, 块索引)` 重算
> 仍是纯函数、仍零历史、仍不进流。块哈希同时满足两侧:**有相干时间**(块内稳定)+ **零状态累积**。
> **不得**改由呈现层平滑 —— 42/44/20 有「只渲染不持状态」三件套纪律(ADR-013 §9 C3 / ADR-018 §一 / ADR-020 §五),
> 平滑需局部状态,相抵。

| 项 | 归属 | 说明 |
| --- | --- | --- |
| `WorldSeed` | **7a 存档头**(ADR-007 §二) | **不占 `SimEvent`**(避免鸡生蛋) |
| `tick` → `WEATHER_BLOCK(t)` | ADR-005 → **5** | 时间坐标 → 块索引(整除,零浮点) |
| `EcozoneOf(cell)` | **6** | 生态区(点 → 区) |
| `cell` | **消费方传入** | ✅ **R-5-B(2026-09-19)**:`cell` = **求值位置**,语义钉在 F-5.4 的调用点表;5 不自行决定 |
| **掷骰实现** | **`IEventAuthority`**(ADR-007) | **同一套确定性掷骰**(禁 `UnityEngine.Random`) |
| `Weather` | **5** | 天气枚举 + 强度 |
| `WEATHER_BLOCK_TICKS` | **5**(旋钮) | 块长 ⚠️ **值归用户**;`≥ 1`(装载期校验);`≤ TICKS_PER_DAY` **不作要求**(跨日块合法) |

**三条硬约束**:

| # | 约束 | 依据 |
| --- | --- | --- |
| ① | **每个输入可从事件流重构** —— `WorldSeed`(存档头)+ `tick`(事件流)+ 生态区(烘焙数据);`WEATHER_BLOCK_TICKS` ∈ 版本化烘焙配置(ADR-014),改块长 = 改 `ConfigVersion` | **ADR-007 的核心不变量** · ADR-016 §一 三源 |
| ② | **零墙钟、零 `UnityEngine.Random`、零帧数** | ADR-005 · ADR-016 §一 的「第四来源」禁令 |
| ③ | **天气不进流** —— 它是派生态,不是模拟态 | ADR-009 §一 Q1 判据 |

> **⚠️ 为什么「不进流」是对的**:如果天气进流,那么**每条天气事件都要占一条 `SimEvent`**
> —— 一天一条 = 存档无谓膨胀,而且**它与「不折叠」的世界流纪律冲突**
> (承 ADR-009 §六 的有界性论证)。**派生态 = 零成本重建。**

### 规则四:`TICKS_PER_DAY` 与 52 **同值** —— 常量共享,单一出处在本系统

**承 `random-events.md:116` / `:659`**:

> 「预算窗口 = 一个 `TICKS_PER_DAY`(与 5 时间天气的**日边界同值**;DC-3)」

| 项 | 归属 | 说明 |
| --- | --- | --- |
| **`TICKS_PER_DAY` 的值** | **5**(本条) | 52 **引用**,不重复定义 |
| **日边界的语义**(什么算新的一天) | **5** | — |
| **52 的预算窗口** | 52 | = `TICKS_PER_DAY` |

> **⚠️ 判据(AC-5-05)**:`TICKS_PER_DAY` 在代码中**只有一个定义点**。
> 52 若自行 `const`,`日边界与预算窗口静默漂移` —— 症状 = 事件预算在跨日时错位一格。
> **这是一个**两常量同值**的约定,须机械守**(单一定义 + 引用)。

### 规则五:昼夜相位 —— 纯派生,无状态

```
phase(tick)  = FMod( tick , TICKS_PER_DAY )                     // 0 .. TICKS_PER_DAY-1
isNight(tick) ⟺ FMod( phase(tick) − NIGHT_START , TICKS_PER_DAY ) < NIGHT_SPAN
```

> **✅ 首轮评审 B-1 修订(2026-09-19)**:原文此处写作「`phase ∈ [NIGHT_START, NIGHT_END)` 环绕区间」,
> 与 F-5.1 的 `(phase − START) mod TPD < SPAN` 是**两套参数化且无桥接方程**(数据文件可各自静默漂移)。
> **现定:单一参数化 = `(NIGHT_START, NIGHT_SPAN)`;`NIGHT_END` 删除**(原稿亦无对它的定义域校验)。
> 原稿注「`NIGHT_END` 必跨日边界」是一道**未校验的更强断言**(SPAN 允许 <TPD 且不跨),随 `NIGHT_END` 一并删除。

| 变量 | 归属 | 说明 |
| --- | --- | --- |
| `NIGHT_START` | **5** | 夜的起点 ∈ [0, `TICKS_PER_DAY`) |
| `NIGHT_SPAN` | **5** | 夜的长度 ∈ (0, `TICKS_PER_DAY`)(**跨日环绕合法**,见边例) |
| `isNight` | **5** | bool |
| `TODMult` | **52**(形状)· **5**(供 `isNight`) | 承 `random-events.md:780` |
| `NIGHT_THREAT_MULT` | **52** | ⚠️ 归 52,非本节 |

> **⚠️ 5 只交 `isNight`**,不交 `TODMult` —— 后者的**修正系数归 52 的表**
> (承 `random-events.md:780`「`TODMult_i` 逐条昼夜修正 … 5 时间天气」= **输入侧归 5**)。

### 规则六:`EnvMod` 的环境分量 —— **可为负**,是结构不是错误

**承 21a `:484` / `:871`**:`EnvMod ∈ [ENV_MOD_MIN, ENV_MOD_MAX]` 是 F1 的**运行时入参**,**可负**。

```
EnvMod_raw(cell, tick) = f( 生态区气候属性, 季节, 天气, 昼夜 )        // 5 的环境分量
EnvMod_total           = 24 的医馆分量 + 5 的环境分量                 // 21a 的既有语义(合并与钳制都在 21a)
```

> **🔴 B-3 修订(首轮评审,2026-09-19)**:F-5.4 原伪代码把 `clamp(..., ENV_MOD_MIN, ENV_MOD_MAX)`
> **直接写进了 5 的算式** —— 与本规则「5 不得越界钳制」正面冲突,且 Tuning Knobs 又把输出域钉在
> `[MIN, MAX]`,三处口径打架。**现口径:5 的原始分量允许越界,钳制唯一发生在 21a F1**。
> 若 5 侧钳制:5 的 −0.9 被截到 −0.5,叠 24 的 +0.4 ⇒ 21a 得 −0.1 而非 −0.5 ——
> 「环境差的惩罚被 24 的好机器无声抹掉」,规则六 :201 预言的失效成真,且**无自动防线**。
> 判据机械化为 **`AC-5-19`**(5 侧原始分量允许越界 + 21a 单次钳制)。

| 项 | 归属 | 说明 |
| --- | --- | --- |

## Formulas

> **本节公式全在整数 / Q16.16 域**(承 ADR-006)。**数值全归用户调** —— 本节只给**形状**。

**前置定义 —— `FMod`(floor-mod,唯一取模具名算子 · 首轮评审 B-1)**:

```
FMod(a, n) = a − n * ⌊a / n⌋          // 结果恒 ∈ [0, n);n > 0
```

> **⚠️ C# 的 `%` 是截断余数**(`(50 − 90) % 100 == −40`)—— 直接照抄本节算式而用 `%`,
> **正午会被判成夜**。全节一律 `FMod`;`AC-5-20` 以含 `phase < NIGHT_START` 的夹具守住这条。

### F-5.1 · 昼夜相位(纯取模)

```
phase(t)    = FMod( t, TICKS_PER_DAY )
isNight(t)  = FMod( phase(t) − NIGHT_START, TICKS_PER_DAY ) < NIGHT_SPAN
                                                     // 环绕安全的夜间判定
skylight(t) = Q16.16Ramp( phase(t), NIGHT_START, NIGHT_SPAN )
                                                     // 连续天光读数:0=最暗 → MUL_ONE=最亮,
                                                     // 在夜区间内单调下沉、昼区间内单调上升(形状 = 分段线性,斜率归数值轮)
```

> **`skylight` 的定位(✅ B-12,详见 Game Feel 节)**:**仅供 42 渲染插值**的派生连续读数 ——
> 块哈希 / 二值判定都是阶梯函数,天光「连续变化」需要一条**同为 `t` 纯函数**的连续腿,
> 而**不得**由呈现层持状态做平滑(三件套纪律)。**禁止进入任何判定路径**:判定只准用
> `isNight` / `season_index` / `Weather`(OQ-5-7 结清口径)。消费者不得对其做时间积分(承 F-5.3 B-8)。

| 变量 | 类型 | 归属 | 说明 |
| --- | --- | --- | --- |
| `TICKS_PER_DAY` | int > 0 | **5**(单一定义) | 与 52 同值(规则四) |
| `NIGHT_START` | int ∈ [0, `TICKS_PER_DAY`) | 5 | 夜的起点 |
| `NIGHT_SPAN` | int ∈ (0, `TICKS_PER_DAY`) | 5 | 夜的长度(**跨日环绕合法**) |
| `isNight` | bool | 5 | 供 52 |

> **⚠️ 朴素区间比较的真实失效**(首轮评审订正):原稿写「跨日时朴素比较**恒假**」—— **不准确**。
> 反例:`TPD=100, START=80, SPAN=40, phase=90` 时朴素式**为真**。真实失效 = **漏掉环绕段**
> `[0, (START+SPAN)−TPD)` —— 半对且静默,**比恒假更难发现**,这才是必须用 `FMod` 的理由。

**算例**(演示用整数,非定值):`TPD=100 · START=90 · SPAN=20`(夜跨日界)。
`phase=95`:`FMod(95−90,100)=5 < 20` ⇒ **夜**;`phase=5`:`FMod(5−90,100)=15 < 20` ⇒ **夜**(环绕段);
`phase=50`:`FMod(50−90,100)=60 ≥ 20` ⇒ **昼**;朴素式在 `phase=5` 处判**昼**(错)。

### F-5.2 · 季节(纯整除 · ✅ R-5-D 2026-09-19 重做)

```
season_index(t) = FMod( FDiv(t, TICKS_PER_SEASON), SEASONS_PER_YEAR )
year_index(t)   = FDiv( FDiv(t, TICKS_PER_SEASON), SEASONS_PER_YEAR )
FDiv(a, b)      = a / b          // 整数地板除;本域内 a ≥ 0、b > 0 ⇒ 与 C# `/` 等值
```

> **🔴 首轮评审 B-2**:原稿写成 `( t / TICKS_PER_DAY ) mod SEASONS_PER_YEAR` ——
> **不用 `TICKS_PER_SEASON`**(该量在 :95 声称归 5 定义,却是全文孤儿),
> 等于公式擅自把季节轴答死成「**1 季 = 1 天**」,与 Player Fantasy「冬天和夏天不是同一个地方」
> 和 `OQ-5-5` 的提问方式三重冲突。**现定:季长 = `TICKS_PER_SEASON`(5 定义,值归用户)。**
> `TICKS_PER_DAY` 与 `TICKS_PER_SEASON` **无整除要求**(日不必整季)。

| 变量 | 类型 / Range | 归属 | 说明 |
| --- | --- | --- | --- |
| `TICKS_PER_SEASON` | int > 0(**真·季长**) | **5** | 一季的 tick 数;⚠️ 值归用户 |
| `SEASONS_PER_YEAR` | int **≥ 2**(装载期校验) | **5** | =2 为最小合法轴(冬至夏反转);=1 轴退化,与「恒夜」同判据拒绝(✅ R-5-D) |
| `season_index` | int ∈ [0, `SEASONS_PER_YEAR`) | 5 | 供 17 / 52 / 42 |
| `year_index` | int ≥ 0 | 5 | ⚠️ **P0 零消费者**(登记):预备给 35 年代推进(P1a,`OQ-5-5`);保留定义不接任何判定 |

**算例**(演示用整数):`TPS=7200 · SEASONS=4 · TPD=1200` ⇒ 一季 6 天、一年 24 天;
`t=8000` ⇒ `FDiv=1` ⇒ `season_index=1`;`t=30000` ⇒ `FDiv=4` ⇒ `season=0 · year=1`。

> **✅ 5 → 17 的接口(2026-09-18 · `OQ-5-1` 结清)**:本节**只交 `season_index`(整数下标)**,
> **不做任何乘法、不持有季节修正系数**。17 的 F-17-3 消费为:
>
> ```
> Capacity(cell, t) = BaseCapacity(cell) × SEASON_MULT[ season_index(t) ] / MUL_ONE
> ```
>
> | 项 | 归属 | 说明 |
> | --- | --- | --- |
> | `season_index(t)` | **5** | 本节 F-5.2 的输出(**唯一交付物**) |
> | `SEASON_MULT[]` | **17 的 F-17-3** | 长度 = `SEASONS_PER_YEAR` 的 Q16.16 表(**值归用户**) |
> | `BaseCapacity(cell)` | **17 的 F-17-3** | 与季节无关的基数(⚠️ `OQ-8-11` 未定) |
>
> **⚠️ 割据理由**:季节修正的**作用对象是「采集」,不是「时间」** —— 5 若持有乘子表,
> 就等于把 17 的曲线搬进 5(越权),且 `SEASONS_PER_YEAR` 一变就要同步两处。**`index` 出、表留 17,一处不留。**
> **⚠️ 17 侧须回填**:`foraging.md` 的 F-17-3 目前只有 `Capacity` / `RegrowWindow` 两个未裁参数,
> **须补第三个 `SEASON_MULT[]` 并接上本节的 `season_index`**(见该 GDD 的 `OQ-17-1`)。

### F-5.3 · 天气(派生态 · 块哈希 · 掷骰走 `IEventAuthority`)

```
Weather(t, cell) = Roll( WorldSeed, FDiv(t, WEATHER_BLOCK_TICKS), EcozoneOf(cell) ) → { kind, intensity }
```

| 变量 | 类型 | 归属 | 说明 |
| --- | --- | --- | --- |
| `WorldSeed` | u64 | **7a 存档头** | ADR-007 §二 |
| `WEATHER_BLOCK_TICKS` | int ≥ 1 | **5**(烘焙配置) | 相干块长(✅ R-5-A);值归用户;改值 = 改 `ConfigVersion`(ADR-014 §五)。⚠️ **2026-09-20 `/review-all-gdds` R-5**:相干时长的秒级体感曾依赖 tick 频率标定 —— ✅ **已解除(2026-09-20:20 Hz ⇒ 一块 = 250 ms)** —— 量纲已标定(2026-09-20 OQ-8 / OQ-25-8 结案:20 Hz ⇒ 1 tick = 50 ms · 在场才模拟 · CAP=24)—— 值仍归用户 |

> 若玩法确需累积量(湿度 / 积雪),它是**模拟态**,须走 ADR-009 三问判据进流,不归 5 的派生态。

## Visual/Audio Requirements

- **视觉 = 天光**(承 42):
  - **昼夜**是**世界里的光**,不是 HUD 上的表盘。**无「现在是 03:00」的数字**;
  - **天气**在**世界里**(雨打在纸上、雪落在肩上),**不在 UI 上**;
  - **季节**由**地貌与植被的连续变化**承载 —— 其输入是 5 的 `season_index`(值/插值归 42)。
- **音频**(承 ADR-018 §六)—— **两条轴不得混挂**(✅ B-10,首轮评审):
  - **天气轴**(随 `Weather.kind/intensity` 起落):雨、风 —— 对应 44 已登记的强度层
    `amb_weather_{rain,wind}_l{n}`(`adr-018`/`audio-system.md`);
  - **昼夜生态轴**(随 `isNight` / `season_index` 起落):鸟鸣、虫声等 —— **这不是天气**,
    挂在天气层上会造成「有鸟鸣 = 晴天」的错误耦合;
  - **雪天脚步声**等**材质反馈**:归 **1/44 的 SFX 材质矩阵**(脚步在 44 侧已有登记),
    5 **只出 `kind`,不出任何素材触发**。
  - **禁**「天气变了 jingle」—— 那是**状态播报**,由 **AC-44-09** 白名单断言(✅ B-11:
    天气层的**进入与退出同样受约** —— 增益变化必须走**对称淡化**,禁硬切;淡化的时长参数归 44,5 不持有)。
  - **室内外切换**(44 的混响侧)与天气层的叠加关系:**归 44 登记**,5 侧仅交叉引用,不定义。
- **一律无数字**:无钟点 / 无温度 / 无季节进度条 / 无「明日降雨概率」。

> **本节只给边界与语义** —— 素材规格归 `/art-bible`、42 的元件库与 44 的声床清单。
> 44 侧的分区澄清与淡化条款随本轮涟漪回写(`audio-system.md`)。
