## 1. 概述 Overview

**TO FILL** — 一段话说清：本系统为何存在（教学约束散落四处、无人能说出总则）、它交付什么（六条口径规则 + 手段登记表 + 守卫检查）、它不交付什么（不造机制、不改数值、不写文案）。

> **一句话**：本系统是**教学的宪法，不是教学的实现**。

**核心问题陈述（待展开）**：教材（教学信号）已完成，但"教材编写原则"从未被写下——六条约束此刻各活在某一处散文里，**互相不知道自己存在**（详见 §3.1 对照表）。

---

## 2. 玩家幻想 Player Fantasy

**TO FILL** — 本系统的"玩家幻想"是**间接的**：它不是玩家直接体验到的系统，而是**玩家体验不到的那一层**。可写为：玩家从不觉得自己"被教学过"——他只觉得自己**看懂了一个医者怎么想**。若玩家说出"这是教程吧"，本系统即失败。

**待定问题**：是否需要一个"玩家可感知的教学节奏"目标（如"序章结束时玩家应能复述'要问寒热'但不能复述'怎么判断'"）——见 §8。

## 3. 详细规则 Detailed Rules

### 3.1 系统定位与边界

| 上游 / 下游 | 从本系统取用 | 本系统不负责 |
|---|---|---|
| **战斗系统** (#4) | 口径规则 1–4、6；呈现层模式的合规判定 | 战斗规则、`ΔE` / `M` / `Rating` 数值、旁观的 CTB 结构 |
| **关卡 / 遭遇系统** (#6) | 口径规则 5（门槛提示）；遭遇跳过策略的教学审查 | 节拍编排、窗口位置、门槛**条件**本身 |
| **对话系统** (#5) | 口径规则 1–4（对白与独白的语言约束） | 对白文本本身、心声带宽、关系门 |
| **任务 / 剧情流程** (#7) | 转归独白与教学 flag 的验收（规则 4 / 6） | 卷→章结构、`VolumeGate` |
| **UI / HUD** (#11) | "不显数值"的呈现层要求 | 排版、动效、图标、具体控件 |
| **无障碍** (#15) / **本地化** (#14) | — | 全部 |

> **边界声明（硬）**：本系统**不拥有任何数值**。若某处教学需求看起来需要新数值，那说明需求本身错位——应回到宿主系统（`combat-system.md` §7 旋钮 / `level-system.md` §4.5）登记。**本系统对机制数值零权限**（同 `feedback-medical-identity-not-numbers` 口径）。

### 3.2 六条口径规则（**本系统唯一真源**）

> 每条规则的**真源现散落于**下列宿主文件；本系统**收拢为真源**，宿主文件保留其实现细节但**服从本条**。宿主细节与本条冲突时，**以本条为准**。

| # | 规则 | 现散落处 | 反面例（禁） |
|---|---|---|---|
| **一** | **只用临床语言，禁用机制语言** | 甲b 文本约束③（`vol-01.md` §3.6） | "补液补的是虚""探虚实""M 才会涨" |
| **二** | **只给现象，不给原理** | `vol-01.md` §1.3 一级教学弧 | "因为她是表证，所以……" |
| **三** | **只给方向，不给路径** | `vol-01.md` §2.4（判词口径） | ✅"该散，不该清" ／ ❌"用麻黄因为同轴 0.7" |
| **四** | **缺口即教学——缺口必须具体** | 甲b 约束②（`vol-01.md` §3.6 / `combat-system.md` §4.8） | ❌ 泛化为"我看不见证候"；须具体指向某个未获取的信息 |
| **五** | **门槛提示只说动作，不说结论** | `level-system.md` §4.2「门槛提示口径」 | ✅"巷口那位，你还没问过" ／ ❌"尚未辨明寒热" |
| **六** | **纠偏在收束，不在回合内** | `vol-01.md` §1.3 二 / 三级 + §3.6 转归独白 | ❌ 回合内弹"你刚才漏了……"；纠偏一律走**收束独白** |

> **规则六为何是硬规矩**：二级教学弧的全部落点是 **"我赢了，可我不知道我为什么赢"**（甲a 转归："我说不清为什么"）。若回合内给纠偏，**发现**即降级为**复习**——与"战斗旁观是否亮数值"旋钮（`combat-system.md` §7）防的是同一个坑。**故纠偏的载体被钉死在收束独白上**。

### 3.3 教学手段登记表（**手段归宿主，本系统只登记与验收**）

| # | 手段 | 宿主（谁实现） | 本系统的职责 |
|---|---|---|---|
| 1 | **战斗旁观遭遇** | `combat-system.md` §3.10 / `level-system.md` §3.2.1 | 定"何时该用"；验收零输入 / 不显数值 / 回合推进信号（`act` + `narration`） |
| 2 | **门槛阻塞提示** | `level-system.md` §4.2 | 口径审查（规则五）；验收提示文本无辨证结论字样 |
| 3 | **悖证失败反馈** | `combat-system.md` §4.8 | 触发时机 + 文本约束（规则一 / 六） |
| 4 | **呈现层不显数值** | `combat-system.md` §3.10 + §7 旋钮 | 旋钮归属；定"何时该开" |
| 5 | **自由探索窗口** | `level-system.md` §3.4 | 提示程度的**上限**（不得提示该探什么轴） |
| 6 | **转归独白** | `vol-01.md` §3.5.1 / §3.6 | **规则四（缺口律）的验收** |
| 7 | **二级 / 三级递进** | `vol-01.md` §1.3 | 登记口径：二级与三级是**同一「治」段内的互斥分支**（甲 = 未探寒热 → 「打得慢、吃单核罚」；乙 = 已探寒热仍打反 → 悖证），**不是时序递进**——**不存在**「三级须在二级之后」的顺序守卫。本系统验收**两者各自可达**，且**同为"未探 / 已知仍错"两条痛法**，不互相前置。 |

> **手段 7 修订（2026-09-12，rev a → a+）**：原表述「顺序守卫：三级须在二级之后」**把未证判断写成了事实**——`vol-01.md` §1.3 的二级（甲：未探寒热）与三级（乙：已探仍打反）是**同一「治」段内的互斥分支**，二者由玩家的**探/不探**选择分岔，**不可能同时发生**，故「顺序守卫」**不可实现**。已改为**登记**口径（本系统原职责即"登记与验收"，非"发明守卫"，见 §3.1 硬边界）。同处修正本文件底部待办 3。

> **"何时该用"的判据（待填 §4）**：需要一个"新概念引入节奏"表——卷一引入「证候」、卷二引入「传变」、卷四引入「跨树」……每次**只引入一个**（`vol-01.md` §3.3 V1 已按此办理："同时引入两个新概念会稀释教学信号"）。

### 3.4 **TO FILL** — 教学信号的确定性边界

> 承核心承诺"失误是选择的结果，不是运气的结果"：教学信号**不得依赖随机**。本卷唯一随机源 = 问诊 90%（`status-syndrome.md` §4.7），且**卷一不使用**。本系统须明写：**教学段一律零随机**。

## 8. 验收标准 Acceptance Criteria

- [ ] **规则一**：教学段文本**不出现**机制词汇（`M` / 牌力 / 对证 / 轴名 / `ΔE` / 数值）。

- [ ] **零随机**：教学段无随机源（§3.4）。
- [ ] **数据驱动**：教学触发条件来自外部配置，无硬编码。
