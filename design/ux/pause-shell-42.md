## 1. 类型声明与闭集边界

本 spec 是 `AC-42-F1` **八员闭集第八员**「**⑧ 暂停壳(42,`ModalId.Pause`)**」的 per-screen UX spec。
该员由 `adr-013 §十-C Amendment C`(2026-10-31 用户裁定 A)增设 —— **它是唯一一个由 42 自身拥有、
而非法呈现其它系统的模态成员**。

- **模态身份**:`ModalId.Pause = 8`(枚举权威 `Gameplay.UI/Skeuomorphic/ModalId.cs`)。开/关 = 模态开合,
  **不落为进流的边沿**(ADR-013 §十-B 豁免:42 是渲染器,不是状态源)。
- **屏幕空间**:UI Toolkit 平面拟物屏;非 world canvas。
- **它为什么必须是模态(而非叠层)**:它**挡路** —— 玩家在世界里的一切意图都该被拒收。
  规则七的门只认 `Modal ≠ None`;若做成「非模态叠层」,就得为同一种「挡住世界」的形态
  **发明第二套判据**,那正是本仓一直在防的形态(`adr-013 §十-C`)。
- **换屏 ≠ 叠模态**:「存档位」行是**换屏**(`OpenModal(SaveSlots)` 先关当前再开)——
  同一时刻至多一个模态容器(焦点单栈的结构前提)。`save-slots-7b.md §3` 的
  「册开在暂停壳之上」读法**自本轮起作废**(原文不删,已在彼处加注)。
- **本 spec 不新增任何判定**:「能不能存档 / 能不能载入」全归 7a;「这一行按下去去哪」归 42 的换屏表。
  暂停壳**不持有任何游戏状态**(ADR-013 §9 C3)。

## 2. Purpose & Player Need

玩家在行医途中放下手:「我得先停一下」。

**这个屏存在的理由**

- 7b 的**正式入口**在这里(`save-slots-7b.md:189` 逐字:「暂停壳 / 主菜单『继续诊治』」)。
  没有这个壳,存档位只能靠一个谁也不知道的按键打开 —— 那条链在生产上**不可发现**。
- 拟物铁律下没有系统级菜单:暂停的「解释」也必须长在世界里(放下手中的事 = 合上册子),
  而不是弹一个现代 UI。

**什么会变糟(若本屏不存在或做错)**

- 玩家**没有办法主动保存**。自动存档之外的主动留档路径断掉 = 玩家对进度的掌控感为零。
- 若暂停期间玩家仍能走动 / 查体 / 建造:「暂停」名不副实,而且会让玩家在最需要停下的时刻
  误操作(把病人放走、把料放错格)。

**玩家目标**:按下暂停键后**一眼看到「继续」**,以及「我能去存档」。

**游戏目标**:提供一个**可发现**的、挡住世界意图的停歇点,并从这里通向 7b。

## 3. Player Context on Arrival

| 问题 | 答案 |
|---|---|
| 刚才在做什么 | 世界内任意行为(行医 / 行走 / 建造),也可能是「想退出但找不到出口」 |
| 情绪状态 | 中低唤醒;可能是「想停一下」,也可能是「想确认进度安全」 |
| 认知负荷 | 低——他们正主动卸载负荷,所以本屏**必须极其短** |
| 已有什么信息 | 知道自己按了暂停;不知道自己能不能存档(这正是本屏要回答的) |
| 最可能想做什么 | ① 继续 ② 存档 |
| 最怕什么 | 按了暂停还停不下来 / 按下「存档」把进度弄坏 |

**情绪设计目标**:安静、确定、一按就懂。**不制造第二层选择**。

## 4. Navigation Position

```text
[世界] --Escape / gamepad start--> [暂停壳 ModalId.Pause]
[暂停壳] --「继续」--> [世界]
[暂停壳] --「存档位」--> [存档位屏 ModalId.SaveSlots]   (换屏,非叠模态)
[存档位屏] --Escape--> [暂停壳]                        (✅ 2026-11-03 用户裁定 = 甲,见 §14 OQ-PS-1)
```

> 🔁 **2026-11-03 · OQ-PS-1 已裁 = 甲「回暂停壳」**(用户裁定)。上图的 `[存档位屏] --Escape--> [暂停壳]`
> 自此**是权威语义**,不再是「最小壳的粗糙边」。
> **代价如实登记**:世界 → 暂停壳 → 存档位 之后,退回世界须按 **3 次** Escape(存档位 → 暂停壳 → 世界)。
> **理由**:存档位是暂停壳的**下一级**(层级语义自洽);且「Escape = 关掉当前这一层」这条读法
> 在暂停壳侧本来就成立(开合同键),改成「一律回世界」会让同一按键在两级上语义不同。
> ⚠️ **本裁定不覆盖其余 6 员**:`InventoryContainer` / `SettingsShell` / `Tutorial` / `ClinicPanel` /
> `PaperCloseup48` / `Processing` 的 toggle 语义仍**未裁** —— 它们今日按 Escape 会**换屏回暂停壳**,
> 那是 `TD-skeuo-03` 的机制 A,与本裁定无关(本裁定只说存档位这一员的**去向是暂停壳**是对的)。

- **入口唯一**:`Escape`(键盘)/ `startButton`(手柄),读面 = `PlayerInputReader.PauseTogglePressed`。
  **开合同键**(再按一次 = 关)。取 Escape 的理由:`UI/Cancel` 本就绑在它上面(它同时是模态的退出键),
  不新增绑重,也不与 `Interact`(E)/`Emergency`(F)冲突(ADR-011 §一)。
- ⚠️ **主菜单「继续诊治」入口不在 P0**:`Boot.unity` 直入世界,主菜单场景尚未接线。本 spec 只写
  世界内入口;主菜单入口的呈现归 42 的主菜单轮。
  🔁 **2026-11-01**:该支**已有 spec**(`design/ux/main-menu-42.md`,Approved)但**仍未实现** ——
  「不在 P0」的**登记**随之作废,**实现状态**仍是「未接线」。两者别混读。

## 5. Layout Specification

**最小形态 = 五行**(🔁 **2026-11-05 晚:参照英灵神殿第二层增「保存」**;同日早些增「退出游戏」;原 2026-10-31 裁定两行 · 2026-11-04 增「调治」第三行,原文保留见 §14 OQ-PS-3)。

```text
┌──────────────────────────────┐  纸面(元件库 SkeuoElement.Paper)
│  继续                         │  ← 行 0,tabIndex 0,开屏落焦于此
│ ──────────────────────────── │  ← .ruled 底格线
│  保存                         │  ← 行 1,tabIndex 1 → 一键落笔(台账 NextWritableSeq)
│  上次保存：19 分钟前          │     ↑ 副标题(只呈现;墙钟不进存档头/三流/sim)
│ ──────────────────────────── │
│  存档位                       │  ← 行 2,tabIndex 2 → ModalId.SaveSlots(开册逐行)
│ ──────────────────────────── │
│  调治                         │  ← 行 3,tabIndex 3 → ModalId.SettingsShell
│ ──────────────────────────── │
│  退出游戏                     │  ← 行 4,tabIndex 4 → Application.Quit()
└──────────────────────────────┘
```

> 🔁 **2026-11-05(用户裁定 · 触发 = `smoke-2026-11-05.md` 的 Batch 1 逐字报告
> 「按 esc 只有继续/存档/调制,没有退出游戏」)**:
> 局内此前**唯一的退出手段是关窗口** —— 主菜单第四行有「退出游戏」,但主菜单只在启动时可见,
> 进了世界就再也回不去。⇒ **暂停壳加第四行**,语义与主菜单第四行**逐字同构**
> (`Application.Quit()`;退出保存走既有的 `Application.wantsToQuit` 钩子,两处都不写盘)。
> - **排最后一行**,且**开屏焦点仍落行 0「继续」** —— 退出不可逆,不能让一次误按的起点在它上面。
> - **不做二次确认**:与主菜单第四行保持一致;退出前有 7a 的退出保存兜底(`save_exit.bin`)。
>   ⚠️ 若后续走查发现误退代价过大,另裁「行内二段态」(先例 = 存档册覆写 / 删除世界),**不在本行自创**。
> - 「制作名单」仍未裁、仍不放。

> 🔁 **2026-11-04(用户裁定 · 结 `TD-skeuo-04` 的 ① 半边)**:
> `settings-shell-42.md:54` 原写两个入口(主菜单「调治」项 / 暂停壳内项),但两者都被更晚的
> Approved 件排除 —— `main-menu-42.md:85-86` 明写「本屏不提供设置 / 退出 / 制作名单」,
> `OQ-PS-3`(2026-10-31)明写「只放继续和存档位」。⇒ 设置壳在生产构建里**永远打不开**
> (屏载体与目录登记齐,玩家零可见)。
> **裁定 = 暂停壳加第三行**(用户在此二分中选定),`OQ-PS-3` 自此被覆盖。
> ⚠️ 主菜单侧**不动**:`main-menu-42.md` 的「一张纸、一行」仍是权威,新增提示行亦按需创建。

| 项 | 规格 | 判据来源 |
|---|---|---|
| 容器 | 模态独占子容器,挂面板根下 | `AC-42-F1` 焦点单栈结构前提 |

⇒ **走查时不得以「不好看」判不通过**,同理也不得以「看起来还行」判通过。

> 🔁 **2026-10-31 缺陷驱动的一处例外(只填了「列宽」,其余仍留白)**:
> 编辑器 Play 实拍暴露两处**结构性**问题(不是审美问题,是「读不出」):
> ① **纸面没包住行** —— 首版把 `SkeuoElement.Paper` 当**流内兄弟**加在行前面,
>    空元素高度只有 padding+border(运行时 dump 实测 **40px**),两行则透明地压在世界暗面上,
>    暗字压暗底 ⇒ 字与底同色系,缩到 1× 几乎读不出;
> ② **行铺满整个面板** —— dump 实测行 **1680×57**,而焦点环是贴在行内的 overlay、尺寸 = 行尺寸
>    ⇒ 环被拉成一条横贯全屏的铜带,「焦点环住这一行」的语义丢失。
> 处置:行改为**纸面的子元素**(兑现上引 ASCII)· 新增 `.pause-column`(宽度 + 居中)。
> **两处都不改判定语义**,只让本 spec 已声明的形态真的出现在屏幕上。
> ⚠️ 因此「行内边距 / 纸纹浓淡 / 字号」仍**未定**,别把这次的宽度值当排版定稿。
>
> ✅ **② 已关(2026-10-31 续挖)**:窄列后行宽 1680 → **439**;环图的根因也定死了 ——
> **USS 的 `url(guid:…)` 把该图解析成 `Texture2D`(sprite=null),sprite 的九宫格边框丢失**,
> 故画成一块黄斑。改为 `SkeuoRuntimeDriver` 用 `[SerializeField] Sprite` **代码灌注**环图
> (slice 与几何仍以 USS 为单一出处),实拍已是干净的细矩形环。该修复**全屏共用**。
> 以下为定位过程留档:
> ⚠️ 原记录:「② 只修了一半」—— 窄列后行宽 1680 → **439**,但铜环图在本屏获焦行上**仍不是 2px 框**
> (实测:环元素几何正确、贴图本身是均匀 2px 铜框、改 `spriteMeshType` 无变化、品红探针证明
> 问题在「图怎么画」;而**同一构建的脉案屏环是干净的细金框**)。差异点未定位。
> 该面属**全局焦点载体契约**(`AC-42-G4` + `SkeuFocusVisible.uss` 冻结件 `focus-v1`),
> 改动须先裁 ⇒ **本屏不私改**。证据与已排除项见
> `production/qa/evidence/ac42f1-pause-shell-walkthrough.md` §七。

## 6. States & Variants

| 态 | 触发 | 呈现 |
|---|---|---|
| 关闭 | `ModalId.None` | 无容器、无焦点 |
| 打开 | `OpenModal(ModalId.Pause)` | 两行在、焦点落行 0 |
| 行焦点 | 方向键 / 手柄导航 | 焦点环(overlay 子元素,不挂类 ⇒ 不顶掉纸纹) |
| 行按下 | Submit / Click | 见 §7 交互表 |

**不存在的态**(显式声明,防实现期自行发明):无「加载中」· 无「不可用行」(两行恒可用)· 无多页。

## 7. Interaction Map

| # | 输入 | 上下文 | 结果 |
|---|---|---|---|
| 1 | `Escape` / `start` | 暂停壳已开 | **合上**(再按一次 = 关) |
| 2 | 方向键 / 左摇杆 | 焦点在行 0 / 行 1 | 焦点在行间移动(**官方 `FocusController`,42 不自实现焦点算法** —— ADR-013 §五) |
| 3 | `Submit` / `Enter` / 手柄南键 | 焦点在行 0「继续」 | `CloseModal()` → 回世界 |
| 4 | 同上 | 焦点在行 1「存档位」 | `OpenModal(ModalId.SaveSlots)` → **换屏** |
| 5 | 指针点击 | 任一行 | 与 3 / 4 同一入口(`Activate(rowIndex)`) |
| 6 | `E` / `F` / 移动 / 建造四键 | 暂停壳已开 | **全部丢弃**(规则七方向②,见 §8) |

**实现纪律**:两条输入路径(手柄 `NavigationSubmitEvent` / 指针 `ClickEvent`)必须汇到**同一个**
`Activate(int)`,不得各写一份判定(否则两条路径的行为会在将来的改动里分叉)。

**模式库对应**(`design/ux/interaction-patterns.md`):
- **P-01 单栈焦点门** —— 本屏是它的第二个载体(首个 = 纸面近景模态);开屏摘掉外部可聚焦元素、关屏还原。
- **P-04 双导航等价** —— §7 的 3/4/5 三行就是它的本屏实例(手柄 Submit 与指针 Click 同一出口)。
⚠️ 本 spec **不自实现焦点算法**(承 ADR-013 §五),以上两条都只是「引用现成模式」,不重述其行为。

## 8. Events Fired

**零事件。零 sim 参与。** 暂停壳的开合与换屏:
- **不写三流**(`IEventSink` 零调用)—— 模态开合是呈现态(ADR-013 §十-B 豁免);
- ~~**不停 tick**(见 §14 OQ-PS-2)~~ 🔁 **2026-11-01 用户裁定改判:停 sim tick**
  (ADR-013 §十-C **Amendment D**;原文保留)
- **不改世界状态**。

| 触发 | 下游 | 性质 |
|---|---|---|
| 开 / 合 | 42 自身容器 | 纯呈现 |
| 「存档位」 | `OpenModal(SaveSlots)` | 42 换屏 |
| 存档位行确认 | `ISaveSlotCommandSink.TryLoad` → `LoadSequencer.Load` | **7b / 7a 的判定**,不属本屏 |

**模态期的输入抑制**(规则七方向②,三个消费点共用同一读面 `IModalGateState.IsOpen`):

| 消费点 | 被丢弃的意图 | 边沿位 |
|---|---|---|
| `InteractionInputDriver` | E 查体 / F 急救 | **照常更新**(关屏不补触发) |
| `ModalInputFreeze` → 移动轴 | 位移 | 折零;~~tick 泵照常推进~~ 🔁 **2026-11-01:被 `worldFrozen` 闸跳过(世界真停)** |
| `BuildInputDriver` | 建造四动作 | **照常更新后再丢弃** |

⚠️ **边沿必须消费**:若挡路期只 `return` 不更新边沿位,关屏那一刻手里还按着的键会**补触发一次**
(「模态里没反应,一关就放下一块」)—— 这是已实测的失败形态,不是理论风险。

## 11. Accessibility

| 要求 | 本屏的落法 |
|---|---|
| **键盘可达**(L-1) | `Escape` 开合;方向键移焦;`Enter` 确认 |
| **手柄可达**(L-2) | `start` 开合;左摇杆移焦;南键确认 —— **焦点必须有落点**(开屏即落行 0) |
