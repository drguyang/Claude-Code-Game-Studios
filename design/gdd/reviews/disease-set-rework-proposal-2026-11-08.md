## 2. 「拆表」落在哪一层(2026-11-08 起草后自查订正)

**先说现状,再说改法。** 源文件 `assets/data/disease_registry.json` 今日是**一个 `diseases` 数组装 16 行**:
7 行 `kind: injury`(id 2–6 / 15 / 16)+ 9 行 `kind: disease`(id 7–14 / 17)。id 在**同一号段**里交错。

三条硬约束把「怎么拆」限制得很死:

1. **GDD 规则九(`:356-358`)不是禁止概念分离,而是禁止「省字段」** —— 原文:
   「伤情同样走这张 schema … 省字段 = 实现里多一个 `if kind == injury`」。
   ⇒ 拆完之后**两张表仍须是同一套字段**(伤表也照填 `curve.incubation` 等)。
2. **`DiseaseVitalsService` 今天按 id 解析任意病程** —— 伤情也走 `DiseaseCourse`
   (`_registry` 字典 + `TryGetValue(course.DiseaseId)`)。⇒ 若拆成**两个产物**,
   它必须同时装两张表再做并集,**运行期多一道联合缝**,而收益为零。
3. **规则九禁的是「按 `kind` 写分支」**,不禁止「按**显式字段**取子集」。
   ���取方读一个作者态字段(如 `appears_as_patient`)不等于 `if kind == injury`。

⇒ **建议的拆法 = 拆在数据形状上,不拆产物**:
`disease_registry.json` 由「一个数组」改为 **`"diseases": […9…]` + `"injuries": […7…]` 两个数组**,
**同一行 schema、同一 id 号段**;baker 读两数组、**按 id 排序后并集**写进**同一个 cooked 产物**。
- 选用的判据:**cooked 字节逐位不变**(见 §6 S1)⇒ 运行时、codec、ConfigVersion、预载、一切消费者**零改动**;
- 抽取方只拿 `Diseases` 视图 ⇒ 「伤情独立」在**作者态**成立,而运行期**零新缝**;
- 将来真要拆成两个产物(比如伤表要独立版本节奏),这一步不挡路。

> ⚠️ 备选「两个 cooked 产物」**不推荐**:它要求改 `DiseaseRegistryDataSet` / codec / Addressables
> 条目 / `DataCorePreloader` / `AddressablesDataProvider`,并且因为约束 2 还要加并集视图 ——
> 代价大一个数量级,换来的只是「作者态更独立」,而 §上面那条同样给到。

## 3. 目标结构

### 3.1 两张表(同一源文件 · 同一产物)

| 数组 | 内容 | 消费者 |
|---|---|---|
| `"diseases"` | **只装病**(今日 9 条 + `DIS_DIARRHEA` 水泻) | 9 的体征求值(经并集视图)· **病人出现驱动** · 病名册反查门 |
| `"injuries"` | **只装伤**(今日 7 条:刺/割/失血/抓/咬/钝击/药害) | 25 战斗结算 · 10 急救线 · 53 药害(经并集视图) |

- 两数组**行 schema 完全相同**(承规则九:伤行照填全部字段,只有 `kind` 不同)。
- **`DiseaseRegistryDataSet` 增两个只读视图**:`Diseases` / `Injuries`(按 `kind` 在**装载期一次**分桶,
  和 `All` 并列);**运行期消费方不写 `if kind ==`** —— 分桶只在数据边界做一次。
- 病表**新增两列**(仅病行需要;伤行填缺省):
  - `min_skill_level` —— 该病进入抽取池所需的**处方用药等级**门槛(0 = 开局即可见)。
  - `teach_point` —— 该病的**科普点**(一句话;供 42/教学链引用,**不进 sim 求值**)。
- cooked 行布局变(+两列)⇒ `schemaVersion` +1;`ConfigVersion` 变动(ADR-010 §七:非致命)。
- 旧产物**不迁移**:P0 尚无对外存档(R3 门),一次重烘即可;迁移脚本不做。
- **`kind` 是怎么进 cooked 的**:今日 cooked 里已有它(分桶靠它);若某行 `kind` 缺失 ⇒
  装载期**抛**(不默认成 disease,否则伤情会静默混进病人池)。

### 3.2 病人抽取(按等级动态)

```
池 = { d ∈ 病表 | d.min_skill_level ≤ 玩家「处方用药」等级 }
每 SpawnIntervalTicks 从池中取一名(顺序 = 病表序,池小则循环)
```
- 「处方用药」是**治疗选项**的技能(`skill-system` §3.1 逐字「用药选项解锁」)⇒ 用它对病种池分级最自然。
- 池为空(理论不可达:至少有一条 0 级病)⇒ **fail-loud**,不静默不抽。

### 3.3 词表口径:每病至少一词

- 时代俗名优先(1900–30 语境):`水泻` / `痢疾` / `湿温`(→ 伤寒,已裁)……
- 已裁:湿温 → 病种 10(`disease-simulation.md:442` 逐字)。
- **温毒**:注册表里**没有对应病种**。两个选项待裁 —— 删行,或等新表补病后再挂。
- AC-37-35 的**非双射**仍成立(一病多词:伤寒 / 湿温;一词多病:不强求)。
