## Overview

诊断与体征揭示是**把「身体里正在发生的事」变成「医生能看到的事」的那一层**,
并在它之上承接全案的核心动词 —— **判**。

它做两件事。

**一是揭示。** 9 疾病与伤情模拟持有一切真值 —— `position`(现在多重)、
`trend`(正在变好还是变坏)、`signs[]`(体征词表)—— 但**真值不等于可见**。
8 决定哪些真值能被读出来、读得多细:同一个危重病人,诊断 5 级的医生看到「脸色不好」,
诊断 50 级的医生看到「面色苍白、口唇发绀、呼吸浅快、四肢湿冷」。
技能给你的不是新工具,**是你的眼睛变了**。

由此得出一条口径(2026-09-14 裁定):**体征是读数的入口。**
没有客观体征可揭示时,8 的读数就是**「全正常」** —— 不是错误状态,是合法输出。
但「读不出」有两种,必须能分辨(玩法核心之一):**我还没做**(你清楚地知道自己没查,
动作随时能做 →「我没查到」);与**体征不存在**(你查全了也一样空)
→「确实没有」。后者是 P0 叙事钩子《他回来了》第二幕的地基。
*(⚠️ 2026-09-14 裁定⑨后,「手段够不着」已不存在 —— 四法出生自带,没有任何手段被等级锁住。)*

**二是判断。** 揭示永远是残缺的,而玩家必须在残缺上**落笔**:
写下病名,或承认自己不知道。诊断等级决定这份判断的上限 ——
10 级以下没有证据时只能冒险;10 级起允许**一次低置信度判断**;
**20 级起阴性读数第一次算数,鉴别诊断由此成立**(排除相近病名);50 级起误诊几乎不再发生。
**8 不给任何疗效加成** —— 它给的是**信息量与准确率**。
疗效是 P1a 辨证的事,这正是「还原 × 整体」两种看法的分界(《支柱三》)。

**为什么它必须存在**:全案的核心假设是「判断 → 施治」这个循环本身就好玩
(`game-concept.md` MVP 核心假设),而**判断**这一层没有别的主。
去掉 8,9 的真值无处可读、11 处方没有输入、37 病例没有病名,
拟物 UI 的无血条铁律**失去唯一的替代反馈来源** —— 玩家会看到一个人,但看不懂他。

**它同时是「主角自己无血条」的承担者。** 9 定「玩家也是一个 `PatientState`、
走完全相同的病程」,视觉锚点定「主角自己永远没有血条 —— 他的状态只能靠呼吸、
视野边缘、把脉音去读」。把**人**(病人)的体征变成可见、把**己**(主角)的体征变成可感,
是同一张映射表的两半。

**与 9 的边界(2026-09-14 裁定)**:9 出**无条件真值**,8 拥有**解释权**。
若 9 按技能过滤读数,**同一份病史在两台机器上会读出不同 `Progress`**(技能等级不同),
**直接破坏 ADR-005 的逐位一致** —— 所以门槛在 8,不在 9。
8 经 `IVitalsQuery` 门面取 `VitalsDto`(**ADR-005 指定的唯一浮点出口**),
**只读不写**:读数永不回写病史事件流。

## Player Fantasy

**核心幻想一句话:同一个病人,三个月前你只能猜,现在你一眼叫得出名字。**

> **⚠️ 措辞校正(2026-09-14 复核裁定):** 本系统的锚点讲的是**「分得开」,不只是「看得见」**。
> V-8.8 的医学诚实规则准许 Lv1 就看出整体层的异常(「躺不平」「喘得急」),临床上已能指向病名 ——
> **真正的成长奖励发生在鉴别层**:从「都是发热 + 肚子不对」到「伤寒 vs 痢疾分得开」。
> 故锚点一的下半句改成「**我看得见,且越来越分得清**」,不做「从瞎到看见」的承诺。

三个锚点:

1. **「我看得见,且越来越分得清」—— 技能改变的是你的眼睛,不是你的工具箱。**
   这是 `skill-system.md` §2 锚点一「第一次看穿」的机制归属:同样的面色、同样的脉,
   去年只能给一个笼统的印象,今年是「**苍白、发绀、浅快、湿冷**」四个词,
   而且**这四个词算数了**(可以据以排除相近的病)。
   诊断不给你新工具,它给你一副新眼睛,以及**一份可以信的底气** —— 这句话在本系统里是**字面意义**,不是修辞。

2. **「我知道我在猜,还是我知道我在判断」—— 不确定本身有形状。**
   这是本系统最重要的手感:两种「读不出」**必须能被分辨**。
   **我还没做**(动作随时能做,四法出生自带 —— 你的问题是「我没查」,解法是**现在就查**)
   vs **体征不存在**(你查全了也是一片空白 —— 你的问题是「确实没有」,解法是**停下来重新想**)。
   混为一谈,判断就退化成碰运气;能分辨,它才是一门手艺。
   *参照*:《请出示证件》给的是「证件信息不全」;本作给的是
   **「信息不全,而且你知道缺的是哪一块」**。

3. **反面锚点:「我全都做对了,那我错在哪?」**
   这是 P0 叙事钩子《他回来了》第二幕,也是本系统唯一一次**自愿失效**:
   一个查体全正常的病人、西药全无效、脉案上病名那栏**空着**。
   **判断系统最有分量的时刻,不是它给出答案的时候,是它诚实地不给答案的时候。**

> **反幻想一:这不是血条。** 玩家**永远不会**看到「病情:42%」。
> 他看到的是**一个人** —— 面色、语声、姿态、呼吸、触感。
> 数值是内部语言(`disease-simulation.md` 的反幻想段),**8 是那句话的机制护栏**。

> **反幻想二:这不是查表。** 9 的 §UI 铁律已禁掉「疾病名录 / 图鉴」——
> 能翻表对答案,「判断」就退化成「检索」,**查体与望闻问切全部作废**。
> **知识必须被挣得**:9 的禁令与 30 的**新颖度加权**(首次遇见的对象 ×3.0)是同一件事的两面。

> **反幻想三:这不是确诊按钮。** 8 **不给疗效加成** —— 写下病名不等于治好。
> 它改的是**你有多大概率做对选择**,不改变选择本身的后果。
> **后果属 #53 医疗后果与责任,不属 8。**

> **与 9 的幻想互补**:9 的幻想是「**世界不为你暂停**」,8 的幻想是「**但世界不全给你看**」。
> 两个合起来才是完整的那句话 —— **病是真的,而你只能看到它的一部分。**

> **支柱对齐**:支柱一「治疗的主体是判断,不是操作」——
> 8 是**判断**这一层唯一的主。支柱三的 P0 半边「**P0 只有还原**:
> 诊断技能回答的是『这是什么病』」也落在这里。
>
> *`creative-director` 未咨询 —— Lean 模式。生产前须人工复核。*

## Detailed Rules

### Core Rules

**规则一 · 只读不写,且不持状态。** 8 的一切输入经 `IVitalsQuery` 门面(`VitalsDto`)取得 ——
**ADR-005 指定的唯一浮点出口**。**8 永不回写病史事件流**:病人身上发生的事只由
**11 处方**(对因 / 对症处置)与 **25 格斗**(伤情)写,8 只读。
同理,**8 不持任何运行时状态** —— 它拥有的是**映射表与门槛**(数据 + 曲线);
玩家写下的病名、已查记录归 **37 病例 / 39 脉案**持久化。
*(对齐 `systems-index.md` §9 **C3** 对 42「只渲染、不持状态」的同一条纪律。) *

**规则二 · 体征是读数的入口。** `position`(现在多重)与 `trend`(向好还是向坏)
**不可直接读** —— 它们只经**已揭示的客观体征**间接可得。一次查体因此有三种读数:

| 读数 | 含义 | 玩家看到的 |
| ---- | ---- | ---- |
| **阳性** | 查了,读到体征 | 具体的体征词(粒度由精度决定,见规则四) |
| **无异常** | 查了,**没**读到体征 | 「查了,没有」—— **但这份「没有」有多可信,取决于熟练度**(见规则三) |
| **未查** | **还没查**,或玩家选择不查 | 「没查」(显式,见规则五) |

**无客观体征 ⇒ 全通道「无异常」= 合法输出,不是错误态。**
这是 9 的潜伏期口径(`disease-simulation.md` Edge Case 1 / AC-22)在 8 的**免费复用**。

> ⚠️ **三态的口径随 2026-09-14 裁定一并变了。**
> 原文的「未查」= **手段够不着**(一个墙);现在的「未查」= **还没做**(一个状态)。
> 手段不再是墙了(四法出生自带),于是**低熟练度的代价从「查不了」变成「查了也读不准」**。
> 「无异常」这一格因此不再是干净的结论,而是**带把握度的结论** ——
> 这正是规则三那张精度档表存在的理由。

**规则三 · 揭示走「手段 → 通道 → 体征」三级。**

**(1) 通道**由 **9 定义**,固定五条:**面色 · 语声 · 姿态 · 呼吸 · 触感**。
*(9 拥有**通道清单**,8 拥有**词表** —— 见 R-8.1。)*

**(2) 手段:视触叩听 + 问诊 —— 出生自带,无等级门槛。**

> **⚠️ 2026-09-14 用户裁定(本系统最重要的一条口径):**
> 西医四法**不作为等级奖励发放**。一名医生**从第一天起就会**视诊、触诊、叩诊、听诊,
> 也会问诊。**等级买到的不是新工具,是熟练度** —— 同一只手、同一副耳朵,
> 读出来的东西**有多准、有多细**。
>
> **依据有三,指向同一处:**
> - `skill-system.md:48` 的成长触发源原文就是「**完成一次查体 / 问诊**并作出诊断」——
>   **它是「用」驱动,不是「等级解锁工具」驱动**;
> - 本系统 §Player Fantasy **锚点一**:「技能改变的是**你的眼睛**,不是你的**工具箱**」——
>   把四法做成等级奖励,等于让这句话在自己脸上破产;
> - **医学常识**:任何一个医学生都会听诊,区别在他**听不听得出来**。

| | 说明 |
| ---- | ---- |
| **P0 的五种手段** | **视诊 · 触诊 · 叩诊 · 听诊 · 问诊** —— **Lv1 起全部可用** |
| **等级改变什么** | **精度** —— 同一份客观体征,你能读出几个词、够不够具体 |
| **等级不改变什么** | **可得性** —— 不该有任何手段被等级锁住 |
| **成长怎么来** | **用** —— 做一次查体 / 问诊就涨,**不论对错**(`EmitGrowth`,见 §Interactions) |

**`DIAG_TIERS`(10 / 20 / 35 / 50)的层义 = 精度档,不是手段解锁档:**

| 诊断 Lv | 精度档 | **阳性**读到什么 | **阴性**读到什么 |
| ---- | ---- | ---- | ---- |
| **1–9** | **粗**(印象) | 「面色不好」「喘得急」「说话没力气」 | 「没看出什么」—— **不构成排除** |
| **10–19** | **中** | 「面色发白」「呼吸浅快」「肚子按着不对」 | 「听着没什么」—— **弱排除,自己也不敢信** |
| **20–49** | **细**(可用) | 「面色苍白、口唇发绀」「双肺底细湿啰音」 | 「腹软、无压痛、未扪及肝脾」—— **构成排除** |
| **35** | *(检验)* | 显微镜 / 化验 —— **P1a 范围**(P0 无显微设备);须 9 增列第六通道 → **D-8-2** | 同左 |
| **50** | **满** | 全通道满精度 | 全通道满精度 |

> **⚠️ 「阴性」这一列现在是「把握度」,不是「权限」。**
>
> 原设计把阴性做成**硬门槛**(Lv20 才有资格说「腹部无压痛」)—— **已改为软梯度**。
> 谁都能说「我按了,没说什么」;**区别在于这句话算不算数**。
> 一个 Lv5 医生的「没异常」**不构成排除**,因为**他也不知道自己有没有漏**;
> 只有到细档,「腹软、无压痛」才第一次成为**可以据以排除痢疾的证据**。
>
> **这比硬门槛更医学诚实**:实习医生不会因为「没资格」而闭嘴 —— 他会说,
> 但他**自己也不确定**;而这份不确定,正是低熟练度的真实手感。
>
> **「医学知识的考查性」由此转移**:不再是「你有没有资格查」,
> 而是「**你知不知道该去听什么、该去按哪里**」——
> 怀疑心衰就去听**肺底**,怀疑痢疾就去按**肚子**:
> **动作人人能做,想到要做才是本事。系统仍然不给任何提示。**

> **深度不是独立手段。** 「腹诊 / 颈项 / 瞳孔」不是新方法,是**同一方法做深了** ——
> 由**精度**表达,不进 `reveal_by` 枚举(见 R-8.1)。
> 故 8 的**手段枚举只有五个**,且**五个都从 Lv1 起可用**。
>
> **`DIAG_TIERS` 的数值仍归 30,层义(每一档读出什么)归 8**(2026-09-14 裁定②)——
> 只是这条裁定的**内容变了**:原先是「哪一档解锁哪个手段」,
> 现在是「**哪一档读到多细**」。30 的数值不必改。

> **⚠️ 两套诊法不得混线。** P0 的 8 **只有西医体格检查**,本作有两套观察体系:
>
> | | **西医体格检查**(P0 · 本系统) | **中医四诊**(P1a · 14 辨证) |
> | ---- | ---- | ---- |
> | **四法** | **视诊 · 触诊 · 叩诊 · 听诊** | **望 · 闻 · 问 · 切** |
> | **回答什么** | 「这是什么病」`skill-system.md` §3.5 | 「这个人整体如何」§3.6 |
> | **归属** | **8 诊断(P0)** | **14 辨证(P1a)** —— 8 **不拥有、不描述** |
>
> 依据:`game-concept.md:99`「观察(**西医查体** / **后期的**望闻问切)」
> + `skill-system.md:49` 辨证 *(P1a)* 完成一次望闻问切。
> **望闻问切在 P1a 由 14 叠加**,8 的通道 / 词表 / 精度档是 14 的**上游**,
> 14 在它之上加「情志 · 体质 · 时序」三维(`skill-system.md:227`)。
> **8 不为中医预留任何字段** —— 需要时由 14 自己扩。
> **若把望闻问切写进 `reveal_by`,就等于让 P0 用上了 P1a 的手段** —— 跨档越界。

**(3) 体征**走哪条通道、由哪个手段可查 —— 见 **R-8.2 体征词表**。
**9 的 `signs[]` 是对 R-8.2 的外键,不是自由文本。**

> **关键推论**:某体征**客观存在、但病人无法配合该手段** ⇒ 该通道读空,且脉案标**「未查」**。
> **这正是规则二第三态的机制本体。**
>
> **⚠️ 2026-09-14 裁定⑨后本条已改写。** 原文写的是「**手段够不着**」——
> 但四法出生自带之后,**手段不再可能够不着**(没有任何手段被等级锁住)。
> 「未查」因此只剩**两个合法来源**:① **玩家没做**(自己的选择)·
> ② **病人查不了**(昏迷不能问诊、不能坐起不能查三凹征)。
> **② 就是本条的新内容** —— 它是裁定⑨之后唯一一类「客观上查不了」。
> **⚠️ 注意区分**:「查了、但读数太低读不出」**不是未查**,是**已查 + 把握不足** ——
> 依据规则五(医生客观知道自己做了检查),判据见 §Edge Cases 第二行。

**规则四 · 熟练度决定精度 —— 对阳性与阴性**一视同仁**。**
`READ_FLOOR(Skill_诊断)` 只改变**「读得多细、多准」**,**永不改变「有没有」**。同一份客观体征:

> Lv5 → 「面色不好」(而且他自己也拿不准) ······ Lv50 → 「面色苍白、口唇发绀」(他确定了)

**「有没有」是 9 的真值,「多细、多可信」是熟练度的事 —— 两条正交。**
阴性同样吃这条:**低熟练度的「没异常」不是「不存在」,是「我没读到」**。
*(公式形状见 §Formulas;数值待用户裁定。)*

> **⚠️ 「一视同仁」不等于「同一条曲线」(2026-09-14 复核补)。**
> 阳性与阴性吃**同一个熟练度**,但它们是**两个可分离的量**:
> **检测不确定**(阳性体征存在,而我没看见 —— 假阴性率的反面)
> vs **缺席置信**(若它存在,我抓得住吗 —— 决定「无异常」够不够格当**排除证据**)。
> 临床上这两者**可以背离**:一个医生辨得出啰音,却仍不敢**排除**啰音。
> **P0 允许把两者合并为一条曲线(更简单),但 §Formulas 不得默认它们同形** ——
> 必须为两者各自预留参数,否则日后分叉就是**数据模型变更**,不是在公式里调个数。

**规则五 · 「读不出」的两态:一条显式,一条隐式。**

- **「已查 / 未查」是显式的。** 医生**客观知道**自己做了哪些查体 —— 这是事实,不是判断。
  脉案上**未查的通道留空行**(有格线、无字、无压痕)—— **显式的是「我做了什么」**。
- **「查了,是阴性 vs 查了但读不准」是不显式的。** 低熟练度下这两者**手感上分不开** ——
  一个 Lv5 医生听到「没什么」,**不知道是真没有,还是自己漏了**;
  要靠经验,系统不给结论。

> ⚠️ **表现层写死(2026-09-14,§Visual/Audio V-8.4):**
> **显式的是「我对自己的把握」;隐式的是「病人有没有体征」。后者绝不可呈现。**
> - 「未查」的表现是**空行**,**不是** badge / 灰字 / 占位符 ——
>   任何形式的「未查」徽章都会把「未查」本身变成一种**读数**,违反规则五。
> - **阴性绝不抹掉世界上的体征**:阴性 = **我写不出**,不是**世界没有**(见 §Visual/Audio V-8.2 硬禁令)。

> *医学依据*:实习医生清楚地知道自己**没按肚子**,也清楚地听到**自己没听到什么** ——
> 但他**不知道自己漏了什么**。**知道没做,和知道自己做得准不准,是两种知识。**

这条区分是本系统最重要的手感(§Player Fantasy 锚点二)。
它的机制载体是**精度档**(规则三表):粗档的「没看出什么」**不构成排除**,
细档的「腹软、无压痛」才第一次成为**可以据以排除痢疾的证据**。
**P0 的鉴别诊断就是精度爬到细档的结果** —— 不是你新学会了什么动作,
而是**你终于能相信自己的手和耳朵**。Lv35 的检验只是**给这条线再加一档**(P1a)。

**规则六 · 落笔是一个公开的物理动作。** 玩家在脉案上**手写病名** + 勾**一档置信度**
(「确定」/「疑似」)。
病名清单 = **已见过的病**(复用 30 的 `(技能, 对象)` 新颖度表里的诊断对象),
**不是完整注册表** —— 你没见过疟疾,就写不出「疟疾」这两个字。
**允许空置**:不写是合法终态 —— 《他回来了》第二幕的载体就是**脉案上病名那栏空着**。
可**划掉重写**,改写留下可被看见的痕迹。

> **⚠️ 手柄 / VR 下的输入通路见 §UI-8.4 的边界条款(2026-09-14 用户裁定⑥)。**
> 手柄没有手写板 ⇒ 走**拟物病名册**(翻页指认),**只收录已见过的病、无分类、无搜索、零线索**。
> **它与「疾病名录 / 图鉴 / 自动补全」禁令的界线是机制性的,不是措辞性的** ——
> 该条款给出三条判据,违反任一条即退化为图鉴。

**规则七 · 误诊不报错。** 写下病名后,系统**不给任何对错提示、不给任何暗示**。
反馈是**延迟的**,且只经病人:**「他没好转」是唯一的信号**。

> *医学依据 + 铁律一「死亡必须被挣得」的镜像*:错就是错,系统不替你说。
> 诊断正确性**只在结算时使用**(37 病例关闭 / **#53 医疗后果与责任**),**不在当下暴露**。

**规则八 · 8 不给疗效加成。** 诊断等级**不进任何治疗公式**。
8 给的是**信息量与准确率**,不是疗效。疗效是 **P1a 辨证(14)** 的事 ——
这正是「还原 × 整体」两种看法的分界(《支柱三》的 P0 半边)。

**规则九 · 主角自身的感知走同一张表,但只有一条通道。**
主角是一个 `PatientState`(9),他的体征经**同一套通道**外显 —— 但**医生不能给自己查体**:

| | **病人侧** | **主角侧** |
| ---- | ---- | ---- |
| **可用通道** | 五条(面色 · 语声 · 姿态 · 呼吸 · 触感) | **只有一条:体感**(呼吸 · 疼痛 / 触感 · 姿态 / 平衡)+ **视觉边缘**(视野收窄 / 发黑) |
| **精度门槛** | 随诊断等级提升(规则四) | **不随诊断等级提升** |

**主角自读不是「精度低」,是「通道少」** —— 你看不见自己的脸(面色),听不清自己的语声变化,
但你**感觉得到**呼吸、疼痛、站不稳。这半边**与诊断等级无关**:医生对自身症状的误判是真实的。
*依据:`systems-index.md` §9 **C3** 的字面范围 + 9「玩家也是一个 `PatientState`」+
视觉锚点「主角自己永远无血条」。**呈现落地见 §Visual/Audio + §UI Requirements。***

### 体征词表(Sign Lexicon)—— 8 的数据契约

> 这是 **8 拥有的核心数据**。9 的 R1 注册表里 `signs[]` 是**对本表的外键**
> (与 `item-database.md` 的 `inflicts_injury` 指向 9 的 R2 同一手法),
> 构成一条**三级引用链:21a → 9 → 8**。
> **通道清单归 9,词表与层义归 8**(2026-09-14 裁定②)。

#### R-8.1 词条结构

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `sign_id` | string | 体征词条主键(如 `sign_pallor`) |
| `display_词` | string ×3 | 玩家看到的词,按**精度档**分列(粗 / 中 / 细)。**粗档对 Lv1–9,细档对 Lv≥20** |
| `channel` | enum | **9 的五通道之一**:**面色** / **语声** / **姿态** / **呼吸** / **触感** |
| `reveal_by` | enum | **P0 只有五个**:**视诊** / **触诊** / **叩诊** / **听诊** / **问诊** —— 西医体格检查。**五者均 Lv1 可用,等级不参与** |
| `tier_named` | level | 该体征**可被指名**的最低等级。**取值域 = `{Lv1} ∪ SLOT_BOUNDS`**(= `{1, 10, 20, 50}`,见 F-8.2)。`Lv1` = **出生自带 · 粗档即可指名**的类别标记,**不是** `DIAG_TIERS` 的档位。**低于它:该体征给出粗档印象、但不构成证据 —— 但动作照样能做** |
| `polarity` | enum | **阳性体征** / **阴性体征**(见下) |
| `neg_weight` | float | **该体征作为排除证据的权重** `NEG_WEIGHT_j` —— **仅阴性体征有意义**(阳性留空)。见 §Formulas F-8.3;**权重是词表属性,不是公式常量**,加新体征时不必动公式。⚠️ **硬约束 `NEG_WEIGHT_j > 0`(C-6)** —— 取 0 会让 `L*_j` 成为空集,把该阴性体征从鉴别里**静默抹掉**(见 F-8.3) |

> **`reveal_by` 只有五个值,且没有 `tier` 字段 —— 手段不上锁。** 深度(浅表 / 深部触诊)
> **不进枚举**:「腹诊 / 颈项 / 瞳孔」不是新方法,是**同一方法做深了**,由 `tier_named` 表达。
> 把「腹诊 / 颈项 / 瞳孔」当独立手段是最容易犯的错。

> **`tier_named` 的含义随 2026-09-14 裁定一并变了。** 原文是「低于它 = 未查(墙)」;
> 现在是「**低于它 = 读得出印象、但叫不出名字**」——
> **动作永远能做,只是低熟练度时读出的东西没有证据力**。
> 例:`sign_rales` 的 `tier_named` = 10,意思不是「Lv10 才准听诊」,
> 而是「**Lv10 起你才听得懂那是什么声音**」;Lv1–9 的医生已经在听了,只是听不出名堂。
>
> **⚠️ `tier_named` 与 `slot_j`(精度档)的分工必须钉死(2026-09-14 复核补):**
> **`slot_j` 决定「脉案上写哪个词」**(粗 / 中 / 细,由熟练度爬到哪一档决定,永远有词);
> **`tier_named_j` 决定「这个词算不算证据」**(`可读_j`,喂给 37 / #53 的判据)。
> 二者**可以背离**:Lv5 查 `sign_rales` → 纸上有「胸里有声,说不清」(粗档词),
> 但 `可读_j = false`,**这条不构成阳性证据**。**纸上有字 ≠ 证据** —— 这正是本系统的核心手感。
> **分工与阴性侧对称**:阳性侧 `tier_named` 卡「何时能指名」,阴性侧 `L*_j` 卡「何时能排除」,
> 两条都是**同一份熟练度的不同投影**,都**不是权限**。

> **`channel` 只有 9 的五条,8 不新造通道。** 其中 **`面色` 是「一般检查 · 头面」通道**
> —— 含面 · 结膜 · **口腔黏膜**(故 `sign_flush` 的结膜充血与麻疹的口腔黏膜斑都归它)。
> **非体格检查的证据不属任何现有五通道** —— 已知两类诉求:
> **检验 / 镜检**(P1a)· **P1a 辨证要用的舌脉**。8 不得自行扩通道;
> **两类并到同一个缝上,统记 D-8-2,由 9 一次扩清。**
> *(第三类 —— **问诊所得病史**,已于 2026-09-14 裁定为**通道外独立证据类**,
> 不由 9 的 F2 投影,**不需要扩通道**;见 R-8.2「病史」组。)*

> **中医四诊不在这张表里。** 望闻问切属 **P1a 的 14 辨证**,不是 8 的手段枚举。
> 8 的表是 14 的**上游**:14 在此之上加「情志 · 体质 · 时序」三维。
> **若把望闻问切写进 `reveal_by`,就等于让 P0 用上了 P1a 的手段** —— 跨档越界。

> **`polarity` 是本表最容易写错的地方。**
>
> - **阳性体征**:存在即有意义(面色苍白、湿啰音)。
> - **阴性体征**:**不存在才有意义** ——「腹部无压痛」「肺部未闻及啰音」,它的价值在**排查**。
>
> **阴性体征的「算不算数」随精度档走,不随权限走。**
> 粗档的「没看出什么」**不构成排除**;细档的「腹软、无压痛」才构成排除。
> **这就是规则五那条显式 / 隐式区分的机制本体** ——
> 低熟练度的医生**说得出口,但自己也不敢信**。
> **鉴别诊断不需要任何额外注册表字段**:它完全由「阴性体征 + 精度档」交付。
> **P0 的阴性来自床边(触诊 · 叩诊 · 听诊),不来自化验。**

| ③ | `sign_relative_bradycardia` / `sign_neck_stiffness` 去留 | **都要** | 相对缓脉 → 伤寒鉴别点;颈项强直 → **破伤风**(与角弓反张同源,修正原「P0 病种外」的错标) |
| ④ | 麻疹「3C」(咳嗽 · 流涕 · 结膜充血)单列? | **不单列 3 条** | 咳嗽 / 流涕 并入 `sign_flush`;**新增 `sign_koplik`(口腔黏膜斑)单列一条** —— 见下 |
| ⑤ | 风湿热环形红斑 / 皮下结节单列? | **不单列** | 只留 `sign_joint_swelling`;「**游走性**」已承担其鉴别价值 |
| ⑥ | **两套诊法混线**(用户 2026-09-14 指出) | **P0 只用西医体格检查** | 原文误把**望闻问切**当作 Lv1–9 的基础手段,又在 Lv10+ 叠西医方法 —— **等于让 P0 用上了 P1a 的手段**。**已改**:`reveal_by` 收敛为**视诊 / 触诊 / 叩诊 / 听诊 / 问诊**五个值;望闻问切归还 **14 辨证(P1a)**。依据 `game-concept.md:99`(「西医查体 / **后期的**望闻问切」)+ `skill-system.md:49` |
| ⑦ | **「闻诊」误用** | **改「一般检查」** | `sign_voice_*` 一组原标「闻诊 + 问诊」—— **闻诊是中医四诊之一**。西医里听语声属**一般检查**(视诊范畴),与**听诊**(听诊器)是两回事。已改 |
| ⑧ | 深度是否算独立手段? | **不算** | 「腹诊 / 颈项 / 瞳孔」不是新方法,是**同一方法做深了** —— 由精度档表达,不进 `reveal_by` 枚举。**叩诊**是此前遗漏的第四法,已补(新增 `sign_dullness`) |
| ⑨ | **视触叩听是否要等升级才掌握?**(用户 2026-09-14 裁定) | **不等 —— 出生自带** | **原文把四法做成等级奖励,是错的。** 依据:`skill-system.md:48` 的成长触发源原文就是「完成一次查体 / 问诊」—— **「用」驱动,不是「等级解锁工具」驱动**;且与 §Player Fantasy 锚点一「技能改变的是**你的眼睛**,不是你的**工具箱**」直接冲突。**已改**:五手段全部 Lv1 可用;**等级只买熟练度(精度)**;`tier_min` → **`tier_named`**(「能指名」而非「能使用」);阴性由**权限**改为**把握度** |

> **④ 为什么破例单列 Koplik 斑。** 用户要求「增加一点点医学知识的考查性,
> 不用太强也别太简单」—— Koplik 斑正是**这个刻度**:
> 它不是冷门知识(每个医学生都背过),但**要想到去掰开病人的嘴**。
> 而且它是麻疹在**出疹前**唯一的特异性所见 —— 单列它,让「**你多知道一件事,
> 就早一天下判断**」这句话在数据上成立;不单列 3C,是因为咳嗽流涕结膜充血
> **任何热病都有**,列出来只是噪声。

#### 旗舰示例:为什么 9 的两层(病情 / 体征)要在这张表上才成立

**风湿热 → 风湿性心脏病** 是 9 的 R3 里的一处**医学诚实性铁律**:
水杨酸缓解关节症状,**不阻止心脏受累**。在 R-8.2 上它长这样:

1. 玩家看到 `sign_joint_swelling`(游走性关节红肿)+ `sign_flush` → 落笔「风湿热」
2. 11 处方给柳树皮 → **关节体征改善**(对症)
3. **但** `sign_orthopnea` / `sign_rales` / `sign_pallor`(心衰侧)**继续发展** ——
   因为 9 的 `Progress` **只被对因处置改**,柳树皮不改它
4. **玩家的判断是对的,治疗却是不完整的**

**8 在这里只做一件事:让第 3 步看得见。** 没有 `sign_orthopnea` 这一行,
玩家只会觉得「病人怎么又重了」;有了它,玩家能自己推出来**「关节是症、心是病」**。
这不是 8 的失职,是 9 的两层设计**第一次在 8 的表上变得可见**。

### States and Transitions

8 有两张状态机:**读数**的状态机(病人身上,被动)与**判断**的状态机(脉案上,主动)。
两张机不共享状态 —— **读数归 39 脉案持久化,判断归 37 病例结算**,8 只定义转移规则。

#### S-8.1 通道读数的两类形态(先分类,再谈转移)

**这是本节的地基**:同样是「已揭示」,两类体征的**时间行为完全不同**。

| | **持续型(被动)** | **快照型(需动作)** |
| ---- | ---- | ---- |
| **判据** | **不需要执行检查动作**就能得到 | **必须执行一次检查动作**才产生读数 |
| **哪些** | **视诊**所见 —— 面色 · 语声 · 姿态 · 呼吸(视)| **触诊 · 叩诊 · 听诊** · 瞳孔反应 · 问诊 |
| **怎么来** | **站着就能看见** | **一次动作 = 一张快照** |
| **时间行为** | **跟随 9 实时刷新** —— 病人变,你立刻看见 | 病情再变,**快照不变** |
| **为什么这样分** | 技能改变的是**你的眼睛**(规则四):学会了看苍白,就一直看得见 | 「医生不能时刻把听诊器按在病人胸口」—— 医学上就是快照 |

> **⚠️ 判据是「要不要动手」,不是「是不是视诊」。** 少数视诊也需动作
> —— **瞳孔反应**要照光、**三凹征**要病人配合 —— 它们归**快照型**。
> 分类看的是**玩家有没有一个可执行的动作**,不是医学书目里的归类。

> **这张分类表同时解掉了三个问题**:
> ① **《他回来了》第二幕的「全正常」是活的** —— 持续型通道实时渲染,
> 病人**确实**看起来没事,不是 UI 卡住了;
> ② **误诊不报错的依据** —— 没有快照就没有「上一条读数」可以偷偷更新(规则七);
> ③ **9 的潜伏期口径免费成立** —— 持续型通道全阴性 = 一个人看起来好好的。

> ⚠️ **持续性不泄漏深层结论。** 你能**看见**病人脸色变差(视诊,Lv1 就会),
> 但**看不见**「肺里有没有罗音」—— 后者必须再听一次。**可见与可知是两回事。**

> **一处看似矛盾、实为有意的边界(2026-09-14 复核确认):**
> `sign_voice_weak` 等归**持续型**(语声,不用动手就能听),
> 而 `sign_delirium` 的**正式评估**归**问诊**(快照)—— 同一体征族跨了两类。
> **这是故意的**:你会**注意到**病人在喃喃(持续型),
> 但要**判定**是不是谵妄、有没有表情淡漠,得**做一次问诊**(快照)。
> **分类看的是「有没有一个可执行的动作」,不是「属于哪个通道」** —— 与本节判据一致。

#### S-8.2 单通道读数状态机

> **⚠️ 2026-09-14 裁定后,本节删去了「锁闭」态。** 四法出生自带,手段不再上锁,
> 因此**没有「等级不够、动作不可用」这个状态** —— 它随裁定⑨一起作废。
> 新的代价形式是:「**动作能做,但低熟练度时读不出东西、或读出来不算数**」——
> 那不是状态,是**精度档**(规则三表)。

| 状态 | 触发 | 玩家看到 | 可执行动作 |
| ---- | ---- | ---- | ---- |
| **待查** | 尚未查(或玩家选择不查) | **空行** —— 有格线、无字、无压痕(**不是「未查」徽章**,见 V-8.4) | **查体** |
| **阳性** | 查得阳性体征 | 体征词(**粒度由精度档定**)· 浓墨有收锋 | 复查(刷新) |
| **阴性** | 查毕无体征 | 「查过,无异常」—— **粗档时词的语域更含糊、墨更淡**(**不挂标签**,见 V-8.3) | 复查(刷新) |
| **旧** | 快照超过 `STALE_WINDOW`,或 9 报**状态转移**(F4) | **旧字被时间处理**(洇散 / 氧化黄 / 纸背水渍);**新读数压印在其上** | 复查(刷新) |

**转移:**

```
待查 ──[执行查体动作]──► 阳性 | 阴性
阳性 | 阴性 ──[STALE_WINDOW 到期 或 9 的 threshold_transition]──► 旧
旧 ──[再次执行查体动作]──► 阳性 | 阴性
任意 ──[病例关闭(37)]──► 清除
```

> **「阴性」格里的把握不足是裁定⑨的直接产物。** 粗档的阴性**照样显示**,
> 但**词的语域更含糊、墨更淡** —— 它诚实地表达「我查了,但我不确定我查得准」。
> **数据侧保留「把握不足」这个状态**(F-8.3 照样算),但**不挂 UI 标签**:
> 加一个显式标签 = **变相数值**,反而削弱这条设计最大的优点(见 §Visual/Audio V-8.3)。
> 这比原来的「锁闭」(你根本不能查)医学更真,也让**玩家的成长看得见**:
> 同一个病人、同一个动作,**三个月后你的「无异常」才算数了**。

> **「未查」是玩家自己的选择,不再是一堵墙。** 医生清楚地知道自己「还没查」——
> 这是事实(规则五的显式半边)。**手段上没有「查不了」这个状态了**(裁定⑨):
> 想查随时能查,区别只在你**读不读得出来**。
> **⚠️ 唯一的例外是病人侧:病人无法配合时该通道恒为「未查」**
> (昏迷不能问诊、不能坐起不能查三凹征、剧痛抗拒不能触诊)—— 见 §Edge Cases 第四行
> 与 AC-8-31。**那是「病人查不了」,不是「手段被锁」** —— 两者必须分清。
>
> **⚠️ 「旧」不是可选功能,是从 9 推导出来的必需品。** 9 的病程是时变的 ——
> 今天没有罗音,不代表后天没有。若快照永久有效,**心衰进展将永远读不出来**
> (`DIS_RHEUMATIC_FEVER` → `compounds` → `DIS_HEART_FAILURE` 的旗舰示例当场失效)。
> 双触发里,**「状态转移即失效」是白拿的** —— 9 的 F4 已经产出这个事件,8 只是订阅。
>
> **⚠️ 但裁定⑨给「旧」加了一条新的设计风险(→ 记 OQ-8-1):**
> 快照随时可复查,而**复查无成本**(除了世界时间),那么玩家会不会**每次说话前都重查一遍**,
> 让 `旧` 永不触发?若是,**持续型/快照型的区分就退化成「多点几次」**。
> 这不是本文能单方面解决的 —— **查体动作的时间成本归 D-8-3**,而它是否足够构成约束,
> 取决于 10 的具体数值。**本节的立场:8 只声明机制存在,不假装它已被平衡。**

> **⚠️ 一条不靠数值的托底(2026-09-14 复核补 —— 直接回应 OQ-8-1)。**
> 同一病人、同一通道,**在 `RECHECK_WINDOW` 内复查不产出新读数** ——
> 给的是「**你刚刚才查过**」(或一个**衰减的精度**),而不是重掷一次。
> **这不是门槛**:动作照样执行、照样涨熟练度、照样留在脉案上;
> 它是**写实** —— 你不会在十秒内把听诊器再按回同一个胸口。
> **效果:把 OQ-8-1 从「全押在 10 的时间成本上」降为「有结构性托底,数值只剩打磨」。**
> **但不取消 OQ-8-1**:`RECHECK_WINDOW` 与查体耗时如何配合,仍归 10 / 4(**D-8-3**)。

> **查体动作会消耗世界时间**,这是 9 的幻想「世界不为你暂停」的直接接合 ——
> 你查得越细,病人走得越远。**具体耗时归 10 急救动作 / 4 交互系统**,8 只声明它存在
> (→ 记 **D-8-3**)。

#### S-8.3 判断状态机(脉案上那一栏)

| 状态 | 含义 | 怎么进入 |
| ---- | ---- | ---- |
| **空** | 病名那栏空白 | 默认;**也是终态** |
| **疑似** | 写下一个病名,置信度「疑似」 | 落笔 |
| **确定** | 写下一个病名,置信度「确定」 | 落笔 |

**转移:**

```
空 ⇄ 疑似 ⇄ 确定          [落笔 / 改写 / 擦掉 —— 任何时候都允许,无代价、无冷却]
任意 ──[37 病例关闭]──► 结案(判断冻结,交 #53 结算)
```

**三条不可动摇的性质:**

1. **空是合法终态,不是「还没写」。** 《他回来了》第二幕的载体就是它 —— 玩家查遍了、
   写不出名字,系统**不催、不提示、不给兜底清单**。
2. **改写永远允许,且留痕。** 划掉重写是**公开的物理动作**(《双材》的拟物 UI)——
   纸上会留下划痕。**痕是给玩家自己看的,不是给系统的评分输入。**
   > **⚠️ 改写不是可疑行为(2026-09-14 复核补,致 #53)。** 依据新证据改判是**好的临床行为** ——
   > **#53 结算时不得因「改写次数」扣分**,否则惩罚的正是设计要奖励的事。
   > 痕只用于**回看**(37 的记录),不用于**计分**。
3. **置信度不改变任何数值。** 它**不被 8 消费** —— 8 只记录。它的去向是
   **37 病例(记录)** 与 **#53 医疗后果与责任(结算时的权衡输入)**。
   *为什么 8 不消费它*:规则八 —— 8 不给疗效加成,自然也不该给「自信加成」。
   **写下「确定」而错了,重量落在 53,不落在 8。**

#### S-8.4 动作词表(Action Lexicon)—— **D-8-12 结案(2026-09-19 用户裁定:路线甲 = 模态分流)**

> **本节是 4 交互系统转 Approved 的全案唯一硬前置的兑现体**(承 `interaction-system.md` 规则五 /
> `OQ-4-1` / 本文件 `D-8-12`)。**词表唯一 owner = 8**(2026-09-18 用户裁定单主,不再「8 / 10」并书);
> 10 自陈「是动作实例,不是动作清单」(`emergency-procedures.md:62`)的立场**成立且被采纳** ——
> 10 的动作住直读通道,本表不复制其定义,只登记路由。

**核心裁决:世界空间的裸 `Interact` 打到病人 = 「就诊」,单义。** 岔口不在「按下去是哪一义」,
在「进入模态后选哪一行」—— **三义岔口就此取消**。

| 动作 | 触发形态 | 裁决输入 | 路由到 | 依据 |
| ---- | ---- | ---- | ---- | ---- |
| **就诊 / 立案** | 世界空间裸 `Interact`(经 4 路由 `Kind = Patient`) | 无(单义) | **37**(`CaseOpened` 以该 tick 为立案时刻) | `case-system.md` 规则二两路径的「就诊交互」;**载体欠债本节结清** |
| **查体**(五手段) | **模态内行级动作**(脉案屏焦点行 + `Submit`) | `IModalState.Modal = Casebook`(4 不裁决 —— 动作不进 4 的出境) | **8**(S-8.2 状态机) | 脉案屏 = `ModalId.Casebook`(ADR-013 §十);行级动作的呈现归 42、耗时归 10(**D-8-3 不变**) |
| **施治(落笔)** | **脉案方笺上落笔**(书写动作自带目标) | 模态内,无空间岔口 | **11** | 11 规则一「把判断写下来那一笔」—— 笔本身就是目标绑定 |
| **急救** | **10 的 `Armed` 直读通道**(ADR-011;不经 4) | 10 自有模态 | **10** | `emergency-procedures.md` 规则七;`Armed` 期 10 压制 `InteractIntent`(4 的 `Accept` 门,4 读不裁) |

**为何取路线甲(模态分流)而非路线乙(病人粗状态分流)—— 三条结构理由(用户裁定 2026-09-19)**:
1. **医学顺序即输入顺序**:望闻问切**先于**处方 —— 世界空间一个键**结构上装不下**这个顺序;
   模态内行级动作天然表达「对这一通道做这件事」。
2. **零新裁决输入**:甲的裁决输入 `IModalState.Modal` **已在 42/ADR-013 落盘**(4 已在读,规则七);
   乙须扩 13 的视图字段 ⇒ 牵动 `OQ-4-6` 改判与已 Approved 的 13 重开。
3. **与 ADR-009 §七 拾取同构**:拾取 = 意图事件 + 当下判距;就诊 = 意图事件 + **当下模态**;
   两者都是「意图不带语义,语义由当下上下文定」,不新增第四来源。

**四条边界(本表所立,逐条可验)**:
- **B-1** 4 的出境载荷**逐位不变**:仍为 `(病人, InteractIntent)` 全整数意图 —— **本结案不改 4 的任何输出形状**;
- **B-2** 查体行的行级动作**住模态(42 的脉案屏)**,不经 4 的世界空间路由 ⇒ 与 `AC-4-09`
  (模态开集拒收世界意图)**正交,无同键双触发**;
- **B-3** 本表是**路由登记表不是数值件**:查体耗时(`D-8-3`)/ `RECHECK_WINDOW` 数值 / 急救动作实例
  的归属**全部不变**;
- **B-4** **P1a 的望闻问切(14 辨证)进表时只加行**,不得把岔口改回空间分流
  (那会推翻 B-1/B-2 的结构前提 —— 登记为对本节的**重开触发条件**)。

**对下游的生效声明**:4 的 `OQ-4-1` 就此**真实结清**(前次 ✅ 是转给空地址的假闭合);
37 的「就诊交互」载体欠债结清(37 仍只订阅「动作已开始」信号,立案时刻 = 该 tick);
`AC-4-15` / `4-DC-5` 脱离 `NOT-RUN`。

#### 五条边界铁律

**① 8 与 11 处方用药之间没有数据流 —— 这是刻意的。**
**病名不给 11。** 病名是**玩家的私人笔记**;11 的输入是**玩家自己选的药**与 9 的真值。
若让 11 按病名结算,系统就会**替玩家把他的判断执行下去**,
「你按错误的判断开了正确的药」这种体验当场消失。
**判断与施治之间那一步,必须由玩家的手来完成** —— 这就是《支柱一》。

**② 8 不向 9 写任何东西。** 读数、病名、置信度**都不回写病史事件流**。
否则 ADR-005 的「病史事件流是唯一真源」会被玩法层的读数污染,
两台机器的 `Progress` 从此不再逐位一致。

**③ 8 不拥有任何持久化。** 8 是**映射表 + 状态机规则**(数据 + 语义);
读数的存档归 39,判断的存档归 37。**8 重启后不丢任何东西,因为 8 什么都没存。**

**④ 成长事件的主机唯一性(2026-09-14 复核补 blocking #7)。**
`EmitGrowth(诊断, 病种对象, novelty)` **只在主机执一次** —— **客户端本地跑 8 时不得发包**。
理由:ADR-005 规定**主机唯一执行 Step / CatchUp**,`EmitGrowth` 会改 `QueryLevel(诊断)`,
而该等级**进 `Progress`**(确定性域的一部分)。若允许客户端自刷,
一台客户端就能**单方面改掉自己(进而整个会话)的成长状态** —— **分叉 + 作弊双开**。
**实现约束**:`EmitGrowth` 的调用点须被 `IIdAuthority`(ADR-005 五个抽象点之一)门控;
客户端只**呈现**成长结果,不**发起**成长事件。**这是 ADR-005 在 8 上的直接落点。**

**⑤ 联机脉案归属:每人一本(2026-09-14 用户裁定)。**
1–4 人联机下,**每个玩家拥有自己的脉案** —— 读数、病名、置信度、改写痕**均不共享**。
理由:规则六说落笔是**公开的物理动作**、规则七说误诊**不报错**;
若四人共用一本,一人的落笔会成为另一人的**提示**(「他写了『伤寒』,那我照抄」),
**规则五(不泄漏)在联机下被击穿**,且「判断」退化为「看队友答案」。
**每本脉案的内容仍逐位一致**(同一病人的客观体征对四人是同一个真值)——
**分叉的只有玩家自己的判断,这正是设计要的。**
**边界**:脉案归 **39** 持久化,按 `player_id` 分册;37 结算时按**各自**的判断记录计。
**这条同时回答 blocking #11。**
**⭑ 2026-09-19 口径订正(承 39 首轮评审)**:此处「逐位一致」指 **9 的整数体征真值**
(`VitalsDto`);39 页上的**体征词**随各人精度档分叉(铁律⑤「各按自己技能显字」),
不是逐位一致的对象。39 的 `AC-39-04 ②` 已按此收窄。

### F-8.1 门槛曲线(阳性侧)

| 变量 | 含义 | 归属 |
| ---- | ---- | ---- |
| `Skill` | `QueryLevel(诊断)`,`∈ [0, SKILL_CAP]` 整数 | 30 |
| `SKILL_CAP` | 等级上限 = 60 | 30(`entities.yaml` 已登记) |
| `s` | `clamp(Skill, 0, SKILL_CAP) / SKILL_CAP` ∈ [0,1] | 8(归一化) |
| `BASE_READ` | 门槛**上端锚**(Lv0 时读得最少) | 8 · **待裁** |
| `READ_FLOOR_MIN` | 门槛**下端锚**(满技能) | 8 · **待裁** |
| `READ_GAMMA` | 曲线陡度 | 8 · **待裁** |

```
READ_FLOOR(Skill) = READ_FLOOR_MIN + (BASE_READ − READ_FLOOR_MIN) × (1 − s)^READ_GAMMA
```

**三个锚点(缺一不可):**

| 锚 | 值 | 为什么 |
| ---- | ---- | ---- |
| 上端 | `READ_FLOOR(0) = BASE_READ` | 0 级时门槛**最高** —— 读得最少。**`BASE_READ` 是上限,不是基准** |
| 下端 | `READ_FLOOR(SKILL_CAP) = READ_FLOOR_MIN` | 满技能时门槛**最低**,但不是零 |
| 单调 | `Skill ↑ ⇒ READ_FLOOR ↓` | 技能涨、门槛降、读出的东西多 |

> **硬约束:`READ_FLOOR_MIN > 0`。** 门槛**永不为零** —— 满技能的医生**也不是全知**。
> 这与规则一(8 只读不写)和规则八(不给疗效加成)同源:**精度有上限,人也有。**
> 落到数值上还有一层:`READ_FLOOR_MIN ≥ Project(σ)`,其中 σ 是 9 的 F1 病情扰动
> —— 否则「满技能能读出 9 自己都算不准的差」。→ **D-8-5**。

**可读性判定:**
```
display_词_j(t) = 词表[ slot_j(Skill) ]         # 空白档按 F-8.2 向下回退 —— 决定「纸上有哪个词」
可读_j(t)      ⟺ Skill ≥ tier_named_j  ∧  Sign_j(t) ≥ READ_FLOOR(Skill)   # 决定「这个词算不算阳性证据」
```
两行**分工不同、都会用到**(2026-09-14 复核补 blocking #2/#3):
- **第一行永远出词** —— 由 `slot_j` 决定,纸上看得到粗 / 中 / 细档的说法;
- **第二行才判证据力** —— 两个条件是**与**关系,分别对应规则三(档位)与规则四(精度):**能不能指名** × **值不值一读**。

> **⚠️ 「有词」≠「可读」—— 这是刻意的,不是漏洞。**
> Lv5 的医生查 `sign_rales`:纸上有「胸里有声,说不清」(粗档词),
> 但 `5 < tier_named(=10)` ⇒ `可读_j = false` —— **纸上有字,不构成阳性证据**。
> 这让「读过但没读懂」在脉案上**留下痕迹**(玩家知道自己查了、也知道自己没听出名堂),
> 同时**不给它在 37 / #53 里的证据力**。**若把两行合并成一行,这个中间态就没了。**

> ⚠️ `Sign_j(t)` 需要一个 **[0,1] 的归一化值**才能与门槛比较 —— 而归一化分母与
> `SCALE_病种` 同源,是**模拟层**的事。**9 补一个 `Project(Sign_j) → [0,1]`,8 不造归一化。**
> → **D-8-4**。(对齐本文「本系统**不**拥有的东西」表:`Progress` 未归一,归 9。)

### F-8.2 精度与档位(连续量 vs 离散档)

```
Precision(Skill) = s = clamp(Skill, 0, SKILL_CAP) / SKILL_CAP      # 连续,只喂 F-8.1
```

**档位映射 —— 全套总计、无空洞、无越界(2026-09-14 复核修正 blocking #3):**

```
SLOT_BOUNDS  = (10, 20, 50)                          # 4 槽的 3 个切点
TierIndex(Skill) = #{ b ∈ SLOT_BOUNDS : b ≤ Skill }  # ∈ {0,1,2,3},对整个 [0, SKILL_CAP] 有定义
SlotOf(i)    = 粗(i=0) | 中(i=1) | 细(i=2) | 满(i=3)
slot_j(Skill) = SlotOf( TierIndex(Skill) )
```

| `Skill` | `TierIndex` | `slot` |
| ---- | ---- | ---- |
| `0 ≤ Skill < 10` | 0 | **粗** |
| `10 ≤ Skill < 20` | 1 | **中** |
| `20 ≤ Skill < 50` | 2 | **细** |
| `50 ≤ Skill ≤ 60` | 3 | **满** |

> **⚠️ 修正说明(原式有洞)。** 原文写的是
> `TierIndex = i s.t. DIAG_TIERS[i] ≤ Skill < DIAG_TIERS[i+1]` ——
> 它**在 `Skill < 10` 与 `Skill ≥ 50` 无定义**(4 槽 vs 5 区间),
> 而这两段恰恰是**「粗档」与「满档」本体**(§规则三 表里的 1–9 与 50)。
> 后果:Lv0–9 与 Lv50–60 的玩家**拿不到任何词表输出**,`slot_j` 未定义。
> **现改为对 `SLOT_BOUNDS` 的计数式** —— 计数天然钳位在 `{0..3}`,**对全体 `Skill` 有定义**,
> 且**无中间空洞**。
>
> **`DIAG_TIERS`(10 / 20 / 35 / 50)与 `SLOT_BOUNDS`(10 / 20 / 50)的关系:**
> 二者**只差 `35`** —— **`35` 是 P1a 的检验线**(§规则三 表标 *(检验)*),
> **不是槽边界**,故不进 `SLOT_BOUNDS`。`DIAG_TIERS` **四个数值仍全归 30**
> (2026-09-14 裁定②);**8 只是不拿 `35` 做槽划分**(P0 无显微设备,该档在 P0 无词可出)。
> **⚠️ 这也解释了 `tier_named = Lv1`**:`Lv1` 是**「出生自带下限」类别标记**,
> 不是 `DIAG_TIERS` 的档位 —— 取值域是 `{Lv1} ∪ SLOT_BOUNDS = {1, 10, 20, 50}`
> (见 R-8.1 `tier_named` 字段),`35` **不得**用作 `tier_named`。
>
> **⚠️ 跨文档耦合(登记 blocking #9):** `SLOT_BOUNDS` 是 `DIAG_TIERS` 去掉 P1a 项后的投影。
> **30 若改 `DIAG_TIERS` 的 10 / 20 / 50 三值,8 的槽划分、`tier_named` 取值域、
> 以及 AC-8-11 / AC-8-32 同时被击穿。** 该耦合**必须登记**(见 §Dependencies **D-8-9** 与
> §Tuning Knobs),不能藏在公式里。

| 量 | 形态 | 谁看得到 |
| ---- | ---- | ---- |
| `Precision` | **连续** | 只有 `READ_FLOOR` 用它 —— 玩家**看不见** |
| `TierIndex` / `slot_j` | **离散** | 玩家**看到的词**走这条 |

> **非线性只出现在第二段。** 连续量 `Precision` 本身是线性的;曲线感来自 `SlotOf` 的**阶跃** ——
> 玩家感知到的是「**突然有一天叫得出名字了**」(`skill-system.md` §2 的「第一次看穿」),
> 那正是档跃,不是渐进。`DIAG_TIERS` 的**数值**(10 / 20 / 35 / 50)归 30,
> `SlotOf` 的**映射**归 8(2026-09-14 裁定②)。

**空白档回退:** 若 `slot_j` 对应的词为空(`sign_koplik` 的粗 / 中档就是「—」),
**向下回退到最近的非空档**(如 `sign_rales` 在粗档无专属词时回退到中档「肺里有水声」);
若更低档也全空 ⇒ 该体征在此精度下**读不出** ——
**按阴性形态显示**(「已查 · 无异常」+ 把握不足),**不是阳性**。
这保证 R-8.2 表里合法的空档不会被误读成「一定读得到」。

> **⚠️ 2026-09-14 复核措辞修正:** 原文此处写「读数记为『**未查 / 无异常**』」——
> **这是错的,把规则五的两个状态并成了一个。** 医生做了查体 ⇒ 该通道**必然是「已查」**;
> 回退到底只是**读不出**,不是**没查**(§Edge Cases 第二行有完整判据)。
> 「未查」**只**来自①玩家没做 ②病人查不了,**与词表有无词无关**。

### F-8.3 阴性把握度曲线(**与阳性分开的参数**)

> **依据规则四的复核注(2026-09-14):** 检测不确定(阳性体征在而我漏了)与
> 缺席置信(若它在,我抓得住吗)**是两个可分离的量**,临床上会背离。
> **P0 允许把形态合并(同一条曲线形状),但参数必须各留** ——
> 否则日后分叉是**数据模型变更**,不是在公式里调个数。

```
C_neg(Skill)    = NEG_CONF_0 + (NEG_CONF_CAP − NEG_CONF_0) × s^NEG_GAMMA
W_j             = NEG_WEIGHT_j                 若 polarity(j) = 阴性
                = NEG_WEIGHT_FALLBACK           若 polarity(j) = 阳性   # 阳性「读不出」时的兜底权重
把握度_j(Skill) = clamp( C_neg(Skill) × W_j , 0 , 1 )
构成排除证据     ⟺  把握度_j(Skill) ≥ EXCLUDE_CONF_MIN
```

| 变量 | 含义 | 待裁 |
| ---- | ---- | ---- |
| `NEG_CONF_0` | Lv0 时的缺席置信(粗档「没看出什么」的底气) | ✅ |
| `NEG_CONF_CAP` | 满技能时的缺席置信 | ✅ |
| `NEG_GAMMA` | 曲线陡度 —— **只允许整数或 1/2**(见 G-1) | ✅ |
| `NEG_WEIGHT_j` | **该体征的排除权重**(R-8.1 字段)—— **仅阴性体征有值** | ✅ |
| `NEG_WEIGHT_FALLBACK` | **阳性体征读不出时的兜底权重** —— 使「把握度」对**两类体征都有定义** | ✅ |
| `EXCLUDE_CONF_MIN` | 「这句话算数」的阈值 | ✅ |

> **`NEG_WEIGHT_j` 是 R-8.1 新增的第 7 个字段(OQ-D 裁决)。** 有些阴性比别的更有分量 ——
> 「腹软、无压痛」排除痢疾的力度,不等于「肺部未闻及啰音」排除某病的力度。
> **权重是词表属性,不是公式常量** —— 加新体征时不必动公式。

> **⚠️ 2026-09-14 复核修补 blocking #4 —— 两处此前无定义,现已补上:**
>
> **(a) 阳性体征「读不出」时的把握度,此前未定义。**
> §Edge Cases 第二行规定:体征客观存在、但 `Sign_j < READ_FLOOR` 或该档无词时,
> 该通道按**阴性形态 + 把握不足**显示。但 R-8.1 明说 `neg_weight` **阳性留空** ——
> 于是这个「把握不足」**没有权重可用,公式在这里是未定义的**。
> **修法:`W_j` 引入兜底常量 `NEG_WEIGHT_FALLBACK`**(公式常量,不是词表字段)——
> **阳性体征的 `neg_weight` 字段保持留空**(词表契约不变),
> 读不出时的把握度改用它计算。**两类体征因此都有确定的把握度。**
>
> **(b) 「不泄漏」要求两类在玩家眼里不可分,`W_j` 的分支不破坏它。**
> F-8.5 要求把握度只是 `(Skill, sign_id)` 的函数 —— `polarity(j)` **是词表字段**,
> 与病人实际病情无关,故 `W_j` 的分支**不引入任何 `Sign_j` 依赖**。
> **玩家看不出「真阴性」与「阳性没读出」的差别,也不必看出**(规则五隐式半边)。
>
> **(c) `L*_j` 的适用范围。** `L*_j` 只对**阴性体征**有玩法意义(排除证据);
> 阳性体征的 `W_j` 兜底值**只服务「把握不足」这个标签**,**不参与任何排除判定** ——
> 阳性体征**不得**被 `L*_j` 当作排除证据消费(判据:37 / #53 只看 `polarity = 阴性` 的行)。

**导出的 `L*_j`** —— **阴性**体征 j **第一次构成排除**的等级:
```
L*_j = min { Skill ∈ ℤ : 把握度_j(Skill) ≥ EXCLUDE_CONF_MIN }   # 仅 polarity(j) = 阴性
```
它与 `tier_named_j` 是**两个不同的量**:`tier_named_j` 决定「能不能**说出**这句话」(规则三),
`L*_j` 决定「这句话**算不算数**」(规则五)。

> **⚠️ `L*_j ≥ tier_named_j` 此前只是一句断言,现升为约束(登记 blocking #9 的姊妹项)。**
> 它**必须**成为**跨旋钮约束 C-7**(见 §Tuning Knobs):说不出的话,谈不上算数 ——
> 但若 `L*_j` 的取值区与 `tier_named_j` 分叉(`L*_j < tier_named_j`),
> 就会出现「**还叫不出名字,却已经拿它当排除证据**」的规格自相矛盾。
> **在 R-8.2 阴性组的取值下(`tier_named = Lv20`),C-7 退化为 `L*_j ≥ 20`;
> 与 AC-8-F1 的 `L*_j ∈ (15, 20]` 联立,得 `L*_j = 20`(阴性组全四行同锚)。**
> **这不是「钉死在一点」的过约束** —— 阴性组**本就该同锚**(它四行的医学地位相同),
> 分叉只会制造无意义的调参维度。

### F-8.4 噪声:禁用条款

**8 不引入任何翻转项、随机项或误差项。** 没有 `± rand()`、没有「看错」掷骰、
没有假阳性 / 假阴性概率。

**三条理由:**
1. **与 `READ_FLOOR` 的语义冲突** —— 门槛是**确定性的下限**,不是概率密度。
   加个掷骰就变成「这次没读到是运气」,而设计要的是「**这次没读到是我还没学会**」。
2. **破坏 ADR-005 逐位一致** —— 读数派生自定点真值;掺随机,两台机器读出不同结果。
3. **医学诚实** —— 低熟练度的真实表现是**读得粗、不敢信**(规则五的隐式半边),
   不是**读错**。实习医生遗漏啰音,不是因为他的耳朵在掷骰子。

> **「看错」不在 P0(OQ-F 裁决)。** 若日后要落,**边界归 §Edge Cases**,
> 且必须与 `Sign_j` 隔离 —— 见 F-8.5。

### F-8.5 不泄漏不变式(0.4)

**`C_neg` 与「把握不足」标签只能是 `(Skill, sign_id)` 的函数,永不含 `Sign_j`。**

即:玩家看到的把握度**不因病人实际病情而变**。若把握度随 `Sign_j` 浮动,
「我今天怎么特别没底气」本身就成了**泄漏** —— 玩家能靠 UI 反推病有多重。
这是 S-8.1「可见与可知是两回事」与规则五在公式层的落点。

### F-8.6 定点判定与护栏

**8 不在 ADR-005 的 int64 / Q16.16 域内。** 它在 `VitalsDto`(`IVitalsQuery` 门面)**之后**,
是全案**唯一浮点出口的消费侧** —— **故 8 自己出浮点,设计上不违反 ADR-005**。
**但这不等于「规格上已证明逐位一致」** —— 见 G-4 与其后的说明。故须**四道**护栏:

| 护栏 | 内容 | 缓解 |
| ---- | ---- | ---- |
| **G-1** | **不用 libm 超越函数。** `pow` / `exp` 的末位不保证跨平台一致 | 曲线指数**只取整数或 1/2**:整数次幂 = 重复乘法;`x^(1/2)` = `sqrt`,**IEEE-754 强制正确舍入**(基本运算,非超越函数),是确定的。或干脆**预计算成定表**(整数等级 → 门槛值) |
| **G-2** | **不掷随机** | F-8.4 的禁用条款 |
| **G-3** | **档位判定走整数等级** | `Skill ≥ tier_named_j` 与 `SLOT_BOUNDS` 的比较**不经过 `Precision` 浮点** —— 避免 `19.9999999` 落在哪一档的边界抖动 |
| **G-4** | **浮点位宽钉死 + 禁 FMA 收缩依赖**(2026-09-14 复核补 blocking #5) | ① **位宽钉死**:8 的内部标量**一律 `System.Single`(IEEE-754 binary32)**,**不得**出现 `double` 与 `Single` 混算的隐式提升(混算 = 两种舍入路径);② **禁 FMA 收缩依赖**:`a*x+b` **不得**依赖硬件是否融合成单次 FMA —— FMA 只做一次舍入,与「先乘后加两次舍入」**结果可能差 1 ulp**,而 IL2CPP / 不同 CPU 的融合策略**不保证一致**。**对策:凡 `a*x+b` 形状(含 `C_neg` 的线性项与 `READ_FLOOR` 的插值)一律走「预计算定表」或显式 `Mul` 后 `Add`**,禁止编译器自行收缩 |

> **G-1 与 `NEG_GAMMA` 的取值约束是同一件事**(OQ-I 裁决):指数的可选集被定点纪律**限死了**,
> 不是设计偏好。若日后要更自由的曲线,正道是做**定表**,而不是放开 `pow`。

> **⚠️ 关于 G-4 —— 「不违反」与「已证明」是两回事(2026-09-14 复核裁定)。**
> 8 出浮点**是否破坏 ADR-005**,专家分歧的裁决是「**双方各对一半**」:
> **设计上不违反** —— 8 与 9 用的是**同一种数值宽度 + 基本运算 + `sqrt`**(无超越函数、无随机),
> 且 8 **从不回写**病史事件流(规则一),故它不可能让模拟层分叉。
> **但规格上此前未证明** —— `float` 的**中间表示**与 **FMA 收缩**在 IL2CPP / 不同 CPU 上
> **不保证逐位相同**,而 ADR-005 的安全论证依赖「主机与客户端的浮点出口一致」。
> **修法 = 修护栏,不改规则**:位宽钉死 + 禁 FMA 依赖(上方 G-4)+ **加跨平台逐位一致 AC**
> (下方 **AC-8-F5**)。
> **⚠️ ADR-005 自身已标注「IL2CPP 逐位性需实测」** —— 本系统的 G-4 是**在该实测落地前
> 的保守前提**,不是对 ADR-005 的推翻。**实测结果若证伪 G-4 的前提,须回改本段。**

| Lv20 | 伤寒 | 同上 | Lv20 | 「腹软、无压痛」**笔迹笃定** | ✅ **构成排除证据** |

> **⚠️ 「把握不足」不是一个可读的标签(2026-09-14 复核补 blocking #8)。**
> 本表右列此前写作「查过 · 无异常 · **把握不足**」,易被误实现成**文字标注**。

**AC-8-F1**:`L*_{sign_abd_soft} ∈ (15, 20]`,等价于
`C_neg(15) × NEG_WEIGHT < EXCLUDE_CONF_MIN ≤ C_neg(20) × NEG_WEIGHT`。
**这条约束比单个旋钮的取值更重要** —— 它把「细档第一次算数」钉在 Lv20,与规则三表一致。

**AC-8-F2 · 双参数可分离(复核④)**:固定 `Skill`,只调 `NEG_*` **不放宽任何阳性体征的可读性**;
只调 `READ_GAMMA` **不改变任何阴性的把握度**。两族参数互不污染。

**AC-8-F3 · `READ_FLOOR_MIN > 0`**:构造 `Sign_j < READ_FLOOR_MIN` 的用例,满技能仍读不出。

**AC-8-F4 · 不泄漏(F-8.5)**:同一 `(Skill, sign_id)`、两个 `Sign_j` 不同的病人 ⇒
把握度标签**逐位相同**。**须各取一个阳性体征与一个阴性体征各测一遍** ——
证明 `W_j` 的 polarity 分支**不引入** `Sign_j` 依赖(见 F-8.3 修补 (b))。

**AC-8-F5 · 跨平台逐位一致(2026-09-14 复核补 blocking #5)**:对**同一组** `(Skill, Sign_j, sign_id)`
输入,在**至少两个不同平台/后端组合**(如 Windows+IL2CPP + Linux/Mono、
或 x86-64 + ARM64 的 IL2CPP)上运行 F-8.1 / F-8.2 / F-8.3 的**全部浮点路径**,
`READ_FLOOR` / `TierIndex` / `slot_j` / `把握度_j` 的**二进制表示逐位相同**。
**⚠️ 这条与 AC-8-1 不同**:AC-8-1 只测**同平台双跑**(确定性),**全绿也可能跨平台分叉** ——
**本条才是 ADR-005 联机一致性的守门**。**若失败,首选修法是 G-4 的定表化,不是放宽判据。**

## Edge Cases

> 本节只写 **8 这一层**的边界 —— 模拟层的边界(9 的潜伏期、未治病人哨兵等)在 9 的
> Edge Cases 里,8 不重复。判据:**首次接触的医学从业者不会在这里出戏**。

| 情况 | 处理 |
| ---- | ---- |
| **病人无任何客观体征** | 全通道「**已查 · 无异常**」—— **合法输出,不是错误态**(规则二)。**不构成排除**:把握度仍按 F-8.3 走。与 9 的潜伏期口径同源。《他回来了》第二幕的载体 |
| **体征客观存在,但值低于 `READ_FLOOR`,或该体征在此档下无词** | 该通道**仍然是「已查」** —— 规则五:医生客观知道自己做了检查,**系统不得改口说「未查」**。显示为**阴性形态 + 把握不足**,**与真阴性在玩家眼里不可分**(那正是规则五的隐式半边)。空白档先按 F-8.2 **向下回退**;回退到底仍无词 ⇒ 按阴性形态显示。<br>⚠️ **阴性形态只改「纸上的字」,绝不改「眼前的病人」** —— 世界侧**照旧渲染该体征**(若该体征属持续型通道,病人看起来就是不对的,而你只能写下「没看出什么」)。**阴性 = 我写不出,不是世界没有**(§Visual/Audio V-8.2 硬禁令) |
| **体征客观存在,但玩家没做该手段** | 读空 + 「**未查**」。**手段全部 Lv1 可用**(裁定⑨),所以这永远是**玩家没做**,不是**做不了** |
| **病人无法配合该手段** | 该通道**恒为「未查」**。例:昏迷 / 谵妄 ⇒ 不能**问诊**;不能坐起 ⇒ 三凹征、端坐呼吸的**视诊**不可得;剧痛或小儿抗拒 ⇒ **触诊**不可得。**这是裁定⑨之后「未查」的第二类(也是唯一一类)合法来源** —— **手段没被等级锁,但病人可能查不了** |
| **同一通道多条体征同时可读** | **全部并列显示,不相斥**(如疟疾的「面色发黄」与失血的「面色苍白」可同现)。**8 不替 9 做取舍**:若两病推高**同一个** `sign_id`,合并发生在 **9 的 F2 投影**里,8 只读那个合成值 → **D-8-6** |
| **同一体征被两条通道 / 两个手段承载** | 按 `channel` 归属;**`reveal_by` 只决定「怎么查」**。例:`sign_neck_stiffness` 归**姿态**通道,但须**触诊**所得 |
| **阴性体征已达 `tier_named`,但把握度不足** | 显示词条,**但绝不加任何标注 / 徽章 / 颜色** —— 说得出口,不算数。**「把握不足」只由承载形态传达**(墨色、笔迹笃定度,§V-8.3),**不以文字或标记出现**(违反即击穿规则五,见 UI-8.4)。这正是 `tier_named`(说得出)与 `L*_j`(算不算)的分工 |
| **多个阴性体征都够排除** | **各自独立判定,不相乘、不相加**。**这是有意的不合并**:在本作里排除是**确定性判定**,不是**概率合并** —— 否则「再多查一项」会退化成一根**可刷的置信度条**;且临床上的两个弱证据本来也不等于一个强证据 |
| **查体进行中病情变了** | **快照型**按**动作完成那一 tick** 采样(不是开始时刻);**持续型**(视诊)跟随**当前 tick** 实时刷新(S-8.1)。**这是一条逐位一致的边界** —— 采样时刻不定死,两台机器会读出不同的词 |
| **9 的 `threshold_transition` 连续到达** | 「旧」状态的转移**幂等** —— 连来三个事件仍是一个「旧」,不叠加标记、不重复弹提示(口径归 9,8 只消费) |

**需要展开的五条:**

**① 病史的误读 / 隐瞒 —— 不在 P0(OQ-F 裁决)**
病人在问诊里**说错、漏说、或故意隐瞒**,**8 不建模**。8 把「问诊所得病史」当作**通道之外的第二类证据**(R-8.2「病史」组),**如实记录病人所说,不判定真伪**。
- **理由一**:说谎与误记是 **13 病人 AI / 38 对话**的事,不是诊断的事。
- **理由二**:若 8 去判定病史真伪,8 就**持有了「真相」** —— 直接违反规则一(8 不持状态)。
- **边界划在**:病史的**真伪**归 13 / 38;**病史的临床解读**(脓血便意味着什么)归 8。
- **转述同样如实记录**:民初的**家属代诉、旁人转述**极常见。8 **不区分自述与转述** —— 对它而言都是「病人侧说出的病史」;**「谁说的」这个来源标注归 39 脉案**。
- **日后若要落误读**,必须在 8 **之外**加一层(病人口述 → 真伪 → 8 读),**8 的表与公式不动**。

**② 掉级后的精度回退**(死亡惩罚在 8 上的可见面)
玩家死亡 ⇒ `Skill` 下降 ⇒ `READ_FLOOR` 回升,`TierIndex` 可能**跌回低档**:
原本叫得出「双肺底细湿啰音」的等级,掉级后只剩「听着没什么」。
**这就是「手生」在 8 上的具体样子** —— 但**已写下的病名不回退**(病名归 37 持久化)。
**系统不提示、不解释这次回退**,玩家自己发现。
> **叙事口径跟随 `skill-system.md` §3.3**:框定为「**一个有身体的人,重伤初愈、手不稳**」,
> **不是**「死了一次所以忘了」—— 与「掉级 = 手生 ≠ 遗忘」的既有裁定一致。

**③ 病人中途死亡 / 病例被 37 关闭**
读数状态机(S-8.2)在**任何状态**下清除;判断状态机(S-8.3)**冻结**并交 #53 结算。
**8 不记录死亡原因** —— 它连病人死没死都不持有,那是 9 与 37 的事。

**④ 玩家在「未查」状态下落笔**
**允许。** 8 **不校验**「你有没有查够」—— 那会是系统替玩家踩刹车。
规则六的「允许空置」与这条是同一枚硬币的两面。

**⑤ 联机:两名玩家的诊断等级不同**(2026-09-14 用户裁定:脉案**每人一本**)
同一病人、同一动作,**两人读到的精度可以不同**(读数是个人的)。
**但 9 的真值不受影响** —— 读数不回写病史事件流(边界铁律②),两台机器的 `Progress` 仍**逐位一致**。
**8 的差异是表现层的,不是模拟层的。**

> **⚠️ 联机脉案归属已裁定(2026-09-14,回答 blocking #11):每人一本。**
> - **读数 / 病名 / 置信度 / 改写痕 —— 全部按 `player_id` 分册,互不可见**;
> - **客观体征是共享真值**(同一病人对四人同一个 `VitalsDto`),**分叉的只有判断**;
> - **理由**:共用一本会击穿规则五(不泄漏)—— 队友的落笔是**现成的提示**,
>   「判断」退化为「看答案」;而规则六(落笔是公开动作)指的是**对病人公开**(病人知道你在写),
>   **不是对队友公开**。
> - **落点**:分册归 **39**(见 §Interactions 铁律⑤ / **D-8-10**);37 按各自记录结算。
> - **表现**:四人各自的纸,**同一份读数在不同纸上因精度不同而字不同** ——
>   这本身就是「每人一副眼睛」的可视化(锚点一)。

**⑥ 自限病下的「试药枚举」绕道 —— 接受,但定价(2026-09-14 用户裁定③)**

**问题**:若病人的病是**自限的**(不治也会好,9 的 `self_limiting`),而 P0 可选药**只有三味**,
则**规则七的延迟反馈会变哑** —— 玩家可以「三味药挨个试」:第一味无效 → 换第二味 → 病人自己好了
→ 误以为第二味对症。**「判断」这一步就被跳过了,而承重墙(支柱一)本该由它承重。**

**裁定:不堵,但让绕过它变贵。** 三条自然代价(全部**由 9 / #53 出,不新增 8 的机制**):

| 代价 | 机制出处 | 对玩家的感觉 |
| ---- | ---- | ---- |
| **时间与病程** | 9:试药期间的**病程照走**,自限病的**痊愈时刻不因试药提前** | 「我瞎试的这三天,他一直在难受」 |
| **病人代价** | 9 / #53:对症药可能**压住体征**(掩盖真相),停药后**反弹更重** | 「我把他治得看起来好些了,然后更糟」 |
| **登记债(D-8-11)** | 归 **#53 结算**:试药史是**判据之一**,不是**扣分项** | 「结果对,过程糊;结算时它记得」 |

> **⚠️ 为什么不堵(设计理由)。** 用**机制**去堵枚举(如「试药一次扣分」「锁定已试药味」)
> 会同时惩罚**合法的临床试错** —— 民初孤身游医**本来**就靠观察与试探,
> 那是**史料**,也是支柱五。**堵它 = 把医学诚实换成机制护栏**,得不偿失。
> **自然的代价(时间、病程、病人)已经足够贵,且它们是「真实世界的贵」,不是「系统的贵」。**
>
> **⚠️ 登记(记账,不落 8):** 本绕道是**已接受的设计缺口**,记 **D-8-11**,
> 落点 #53(结算须把试药史纳入**判据**,但**不得**单列为扣分项 —— 与「改写不扣分」同源)。
> **⚠️ 待观察**:若实测显示玩家**普遍**用枚举代替判断(而非偶发),
> 须回到这一条重新定价 —— **这是 P0 playtest 的观察点之一**。

> **一条医学事实注(不强求下游实现,2026-09-14 用户裁定「只写事实注」):**
> **破伤风病人的声、光、触刺激可诱发肌肉痉挛** —— 换句话说,**查体动作本身可能改变病人状态**。
> 本注只声明这个事实,**8 仍然只读不写**:若日后要落,
> **「查体触发了什么」的写路径归 10 急救动作 / 13 病人 AI**(与 D-8-3 同源),
> **8 只声明它存在**,不实现、不写回病史事件流。

## Tuning Knobs

> **本节所有默认值均为 `*待裁*`** —— 数值由用户裁定。
> 这里交付的是**旋钮清单 + 安全区间 + 交叉约束**:「往哪拧会动到谁」。

### 一、门槛族(F-8.1 · 病人侧读出的下限)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |

> 拧得太高 = 高技能玩家也长期在雾里,**整个「技能买精度」的成长手感失效**。
> **它同时是 `READ_FLOOR` 的下端与 `D-8-5` 的验证对象** —— 两处受力。

> ⚠️ **`READ_GAMMA` 只改「多快爬到位」,不改两端的锚。** 端点由 `BASE_READ` / `READ_FLOOR_MIN`
> 钉死意味着:**调陡度不会让 Lv0 的玩家变强或变弱**,只是重分配中间段的难度。
> 这是 F-8.1 用两端锚参数化(而不是用「基准 + 系数」)的收益。

### 二、阴性族(F-8.3 · 「说没有」算不算数)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `NEG_CONF_0` | Lv0 时的**缺席置信** —— 粗档「没看出什么」的底气 | `∈ [0, 1]`。**可以很低**(低技能说「没有」本就心虚) | `*待裁*` |
| `NEG_CONF_CAP` | 满技能时的缺席置信 | `∈ [0, 1]`;**必须 `≥ NEG_CONF_0`** —— 否则曲线反向 | `*待裁*` |
| `NEG_GAMMA` | 阴性曲线的陡度 | `> 0`;**取值集被 G-1 限死:整数或 1/2** | `*待裁*` |
| `EXCLUDE_CONF_MIN` | 「这句话**算数**」的阈值(F-8.3 的判定线) | `∈ (0, 1]`;**必须 `≤ C_neg(SKILL_CAP)`** —— 否则连满技能都不能排除(全表死) | `*待裁*` |
| `NEG_WEIGHT_j` | **逐体征**的排除权重 | **住在 R-8.1 词表,不在公式里**(新增体征不动公式);**仅阴性体征有意义**;**硬约束 `> 0`(C-6)** | `*待裁*`(逐条) |
| `NEG_WEIGHT_FALLBACK` | **阳性体征读不出时的兜底权重**(F-8.3 修补(a))—— 使把握度对两类体征都有定义 | **硬约束 `> 0`**;`∈ (0, 1]` 量级与 `NEG_WEIGHT_j` 同域。**只服务「把握不足」形态,不参与排除** | `*待裁*` |

> ⚠️ **`NEG_CONF_CAP` 与 `NEG_WEIGHT_j` 相乘后才进判定** —— 两者**可以互相补偿**,这正是陷阱:
> 把 `NEG_WEIGHT_j` 调大以「让某个阴性更重要」,会**同时**把该体征的 `L*_j` 拉低
> (更早就能排除)。**若本意只是「更重要」而不是「更早」,改的是 `EXCLUDE_CONF_MIN` 的家族,不是权重。**
> 想清楚要动的是**门槛**(何时算数)还是**分量**(多重要)—— 这两个诉求在本曲线里**共用一个乘子**。

> **阴性族与门槛族正交(C-4)。** 调 `READ_GAMMA` **不改变任何阴性的把握度**;
> 调 `NEG_GAMMA` **不改变任何阳性的可读性**。§Formulas 的 UC-8-F1(伤寒 vs 痢疾,
> Lv15 不排除 / Lv20 排除)**只由阴性族决定** —— 它是阴性族的回归锚,不是门槛族的。

### 三、状态机窗口族(S-8.1 / S-8.2 · 读数什么时候算「旧」)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `STALE_WINDOW` | 快照型读数**保鲜期**;超期 → 「旧读数 · 建议复查」 | **必须 `> 0`**;**量纲锚在 `TICK_SECONDS`**(D-8-7)。**太长 → 心衰进展读不出来**(旗舰示例当场失效) | `*待裁*` |
| `RECHECK_WINDOW` | 同通道复查的**去重窗** —— 窗内复查**不产出新读数** | **必须 `> 0`**;**建议 `≤ STALE_WINDOW`** —— 否则「刚查过不能查」比「该复查了」还长,自相矛盾 | `*待裁*` |

> **`RECHECK_WINDOW` 是本轮的 OQ-8-1 托底,不是门槛。** 窗内复查
> **照样涨熟练度**(不惩罚行为),只是**不产出新读数** —— 这是写实,不是惩罚。
> **它把 OQ-8-1 从「全押在 10 的时间成本上」降为「有结构性托底,数值只剩打磨」**;
> 与查体耗时的最终配合仍归 10/4(**D-8-3**)。

## Visual/Audio Requirements

> **本节方向来自 `art-director`(2026-09-14,lean 模式单独 spawn)。三处分叉已裁**:
> **精度档 = 甲 · 频带对比分层** · **「把握不足」= 甲 · 笔迹与语域** · **主角视野边缘 = 甲 · 水墨渗边**。
> **8 交付的是数据表(通道 × 档位 → 渲染参数),不是渲染代码。42 只渲染、永不持有状态。**

### V-8.0 总纪律:《双材》是机制语法,不是美术皮

> **水墨 = 看(整体、活的、会散)。黄铜与纸 = 记(还原、定格的、算数)。**

这与 S-8.1 的持续型 / 快照型是**同一刀**:

| | **持续型**(视诊) | **快照型**(触叩听问) |
| ---- | ---- | ---- |
| **媒介** | **世界里**,水墨 | **脉案上**,墨与纸 |
| **时间** | 活的,跟 9 实时刷新 | **墨水干在纸上 = 快照冻结** |
| **谁给** | 13 病人 AI(动画)+ shader | 39 脉案 + 42 渲染 |

> **「看」发生在世界上,「词」发生在纸上。两者永不同框。**
> 世界上没有浮字、没有标注、没有图标;脉案上没有动画、没有进度、没有徽章。

### V-8.1 唯一渲染契约:精度档 = **解析带宽**,不是遮挡开关

> **技能买的不是颜色,是对比与定位。世界从不说谎,只是低档时你分辨不出来。**

实现方式:**同一套颜色常量 + 三层空间 mask,精度档决定哪几层参与最终对比。**

| 通道 | **粗**(Lv1–9) | **中**(Lv10–19) | **细**(Lv20–49) |
| ---- | ---- | ---- | ---- |
| **面色**(肤色 shader) | **低频**:整体去饱和 + 一层灰。唇与面**不分离** | **中频**:面部内部出现分区(面 / 唇 / 结膜) | **高频**:唇、甲床、结膜**三处局部定标**;冷青紫只作**局部对比峰**出现 |
| **呼吸**(13 动画) | 只有「节奏快」一个维度;胸腔起伏被水墨化成一团运动的影子 | 胸式 / 腹式第一次分开 | 吸呼比、深浅、**三凹征**(锁骨上窝 / 肋间 / 剑突下)三个局部凹陷有无 |
| **姿态**(13 动画) | 整体轮廓的「不对劲」(靠着、不愿躺平、烦躁换姿势) | 具体体态模式(半卧 → 端坐) | 局部细节(颈项僵硬、牙关、角弓反张的分节) |
| **语声**(44 音频) | 一个「没力气」的整体印象 | 音量 / 气声比例 / 语速可辨 | 断续、不能成句、气声支持缺失 |
| **触感**(手 + 手柄震动 / VR) | 一个模糊的烫 / 凉 | 分区域(额 vs 四肢) | 干湿分离 → **湿冷** |

> **为什么这样是对的**:它精确复刻 R-8.2 的三档词表 —— 苍白是**低频**(整片),发绀是**高频**(局部)。
> 词表的分档本来就是物理事实,不是巧合。
> 它也不像「降质」:低档画面依然**完整、干净、诚实**,少的只是局部辨析 ——
> 这同时满足色彩哲学(恶化 = 去饱和;高饱和只留给「血色回涌」与瞳孔收缩)。
> 它让 §Player Fantasy 锚点一更准确:不是「模糊变清晰」,是**「同一个东西,现在你叫得出名字」**。

> **词怎么进脉案(钉死,否则 39 会自创一套):**体征词由系统以**玩家的笔迹**写进脉案,
> **不弹窗、不浮字**,但有一个**笔尖在纸上走的过程**(0.3–0.5s)。
> 素材用**有限笔迹变体**(每词 3–4 个手写变体 × 3 档浓度),**不做自由书写**。

### V-8.2 四态:载体是**墨的有无与纸的状态**,不是色相

**这是规则五的唯一视觉载体**,也是本节最要紧的一张表:

| 态 | **世界**(水墨,永远实时、永远诚实) | **脉案**(纸与墨) |
| ---- | ---- | ---- |
| **待查** | 病人就在那里,你看得见 | **空行**:有格线、无字、纸面平整。**没有水痕,没有压痕** |
| **阳性** | 体征按档在世界上可见 | 字,**浓墨,有收锋**;粒度 = 词 |
| **阴性** | **世界上体征照旧渲染**(⚠️ 见下) | 字仍在,但**换语域**(「听着没什么」),**淡墨、无收锋**;把握越低墨越淡 |
| **旧** | 世界已经变了 | 字被时间处理:洇散、氧化黄、一条从纸背透出的水渍;**新读数压印在旧字之上**(旧字隐约可辨) |

> **判据一句话:字的有无 = 行为的有无。**「我做过什么」在纸上必须有重量。
> **四态的区分不许靠色相**(色盲 + 黑白截图下失效),靠**墨的浓度与纸的形态**(亮度 / 形态差):
> 待查 = 无字;阴性 = 淡字;阳性 = 浓字;旧 = 被时间处理过的字。**这条自动满足无障碍。**

> **「旧」的新读数压印,顺带满足规则六的「改写留痕」** —— 一举两得。

> **「旧」的附加手段(可选,供手柄导航):**页边一个铅笔小勾(临床病历上「待复查」的物理做法)。
> **不许**感叹号、不许红色、不许弹窗、不许「叮」。

> ⚠️ **一条硬禁令:阴性形态绝不许抹掉世界上的体征。**
> **阴性 = 我写不出,不是世界没有。** 若实现层把阴性做成「病人看起来也正常了」,
> 那是**双重欺骗**,医学受众当场出戏。
> **世界侧照旧渲染** —— 阴性只改**纸上的字**,不改**眼前的病人**。

### V-8.3 「把握不足」的呈现(裁定:甲 · 笔迹与语域)

**不加标签、不加问号、不变色、不弹窗。** 它由三件事承担,由弱到强:

1. **词的语域**(R-8.2 已做:「听着没什么」vs「双肺未闻及啰音」);
2. **墨的质量**(把握度 `< EXCLUDE_CONF_MIN` → **淡墨 + 无收锋**);
3. **最强的一件:世界与纸之间的落差** —— **病人明明不对,你只能写下「没看出什么」。**

> **第 3 条是承重的一条。** 它**不需要任何 UI** —— 玩家自己就会发现「我在猜」,
> 而那正是 §Player Fantasy 锚点二的手感。
> **数据侧仍保留「把握不足」这个状态**(S-8.2 / F-8.3 照样算),只是**不给它一个 UI 标签** ——
> 加一个显式标签反而**削弱**了这条设计最大的优点。

> ⚠️ **「?」只属于病名栏**(复核要求「确定 / 疑似」肉眼不同,那里用**迟疑笔迹 + 边上一个 `?`**)。
> **它绝不许溢到体征栏。体征栏加「?」= 变相数值。**

### V-8.4 规则五的表现层写死(显式 vs 隐式)

> **显式的是「我对自己的把握」;隐式的是「病人有没有体征」。后者绝不可呈现。**

| | **显式的**(可被玩家看见) | **隐式的**(绝不可见) |
| ---- | ---- | ---- |
| **内容** | 我有没有查 · 我有多大把握 | 病人身上**客观上**有没有这个体征 |
| **载体** | 墨的有无与浓度 · 词的语域 · 页边铅笔勾 | **什么都没有** —— 世界只呈现病人的样子 |

> **落到实现:待查是「空行」(无字),不是任何 badge / 灰字 / 占位符。**
> 当前表格极易被实现成一个「未查」徽章 —— **那会让「未查」变成一种读数,违反规则五。**

### V-8.5 主角自身的一条通道(裁定:甲 · 水墨渗边)

| 通道 | 呈现 | **禁止** |
| ---- | ---- | ---- |
| **视觉边缘** | **水墨的纸边被墨蚕食**,墨边是**湿的、在渗**(有动态) | 干净的径向暗角;**脉冲 / 心跳式闪烁** |
| **呼吸** | 呼吸声变响、**频带变窄**;环境音被低压滤掉(低氧的耳朵感) | 用音效「报」血量 |
| **姿态 / 平衡** | 摄像机**极低频、微幅**漂移 + 脚步节拍变化 | **摇晃**;**VR 下任何镜头效果**(9 已禁) |
| **把脉音** | 自己的心跳走**同一套**音频;但**偶发、不可控** —— 只在**安静、屏息、侧卧压耳**(枕下搏动)时偶可闻及 | 做成常驻读数;**在不成立的条件下响**(⚠️ 见下) |

> **⚠️ 把脉音的触发条件原写「安静 / 躺下 / 屏息」,医学不成立(2026-09-14 复核补 blocking #12)。**
> **正常人躺下听不到自己的心音** —— 心音可自我闻及的经典条件是
> **侧卧、耳压枕下(枕下搏动)或在极安静环境屏息时**,不是「躺下」。
> 照原文实现会**让每个躺下的病人都响起心音** —— 医学受众的第二个出戏点。
> 现改为「**安静 · 屏息 · 侧卧压耳**」,并**一律标为偶发、不可控**(与「通道少」的立意一致)。

> **三条设计理由:**
> ① **「偶发」是「通道少」的表达** —— 医生不能给自己诊脉,他不是精度低,他是**够不着自己**;
> ② **主角侧不做快照、不进脉案** —— 他没有一张可以给自己写的纸。这是「通道少」的表现,不是省略;
> ③ **两套语汇不许互染** —— 主角侧用「边缘渗墨」,病人侧**永不用**这套语言。
> 若主角受伤时画面渗墨、而病人也渗墨,玩家会把两者读混。

> ⚠️ **主角侧的视野边缘若做成 post-process 伤害暗角,立刻读成「COD 红边」**,
> 与「无血条」立意正面冲突,且是 VR 晕动源。**必须走水墨渗边。**

### V-8.6 《他回来了》:让「真的没事」与「系统没告诉你」物理可分

**唯一的区别是墨水:**

- 「系统没告诉你」→ 纸上**根本没有墨**(空行)。
- 「确实没有」→ 纸上**写满了实笔的「无异常」**,五行俱在。

> **「没有发现」必须是玩家自己写下的一个东西,不是系统留下的一片空白。**

配套三条硬规定:

1. **世界上他必须是最有生命力的那个人。** 「Loading 中 / UI 坏了」这个失败模式来自**静止**。
   他要有呼吸起伏、眨眼、视线跟随、能正常交谈、喝药时的环境互动。**「正常」必须读作「活着」。**
2. **病名栏的空白是「一张等着落笔的纸」,不是灰色的「未知」。** 可写性必须可见
   (否则玩家不知道这里能写),但**不许有任何提示文案、兜底清单或催促**。**可写 ≠ 有内容。**
3. **他身上不许出现任何灰色 / 问号 / 未解锁 / 加载态元素**,也不许出现「此人健康」的正面提示
   —— 那也是一种读数。**「什么都没有」必须由玩家自己读出来。**

### V-8.7 音频:44 是本节最重的技术债

> 语声与听诊是**音频优先通道**,而 44 现在是 **Foundation 零依赖 + 全案两行描述 + P0 就要求它承担状态反馈**
> (`systems-index.md` §8 已自认「最名不副实」)。**8 对 44 有**四**条硬需求,必须在 44 写 GDD 之前定:**

| # | 需求 | 若不做会怎样 |
| ---- | ---- | ---- |
| **①** | **呼吸分两层渲染**:基础气流层 + 附加音层(细湿啰音等);**精度档 = 通带与噪声底,不是静音开关** | 低档就是「没录到」,玩家以为漏了素材 |
| **②** | **语声走「变体库混合」**(⚠️ **2026-09-14 复核降格** —— 原写「运行时参数调制」) | 逐病种重录台词 —— 后期是**重录级灾难** |
| **③** | **暴露「接触噪声 / 信噪比」参数** | 没有它,`READ_FLOOR` 在音频侧**无处落地** |
| **④** | **联机时的精度分混:统一取主机技能**(2026-09-14 用户裁定②) | 单 `AudioListener` 无法为四人各跑一套 DSP —— 见下 |

> **⚠️ 需求②已降格(blocking #12)。** 原写「**支持运行时参数调制**(音量 / 气声比例 /
> 语速 / 断句 / 共鸣)」,这是**把音频引擎当成语音合成器**的假设 ——
> Unity 的音源管线**不原生支持**对已录制语声做那五项独立调制
> (音高偏移会同时改共振峰,听上去是「变声器」而不是「病人说话」)。
> **务实规格:每个病种录一组「基础语声变体」**(如 男/女 × 强/中/弱 × 数种句尾),
> **运行时按 (病种, 精度档, 体征强度) 选变体并交叉淡化** ——
> 这是**变体库混合**,不是**参数调制**。
> **代价已登记**:素材量上升(见下方素材债),但**远低于逐句重录**,
> 且**在 44 的能力范围内**。 **44 的 GDD 须按此规格写,不得按参数调制写。**

> **⚠️ 需求④(联机分混)是一处**无法按字面实现**的需求。**
> 规则五在联机下的直觉读法是「四人各自的精度档 ⇒ 四套听诊音」,
> 但 Unity **单 `AudioListener` 每设备只有一条混音总线** —— 同屏广播式听诊音
> **不可能**对四个人各跑一套(那是每设备四条 DSP 链)。
> **裁定(用户,2026-09-14):联机下音频精度统一取「主机技能」。**
> 理由:①**音频是表现层**,规则五的**实质**(把握度不定数值)由**脉案的字**承担,
> 不由听诊音的层次承担;②**主机技能**与 ADR-005「主机唯一执行」同源,
> 是四人里**唯一有权威的**那个技能值;③ 四人各听一套只会让**联机同步状态更脆**。
> **边界**:脉案**仍每人一本、各按自己技能显字**(铁律⑤);**分叉的只有音**。
> **须在 44 的 GDD 里写明此降格。**

> **第 ①③ 条是整个设计里最优雅的一处音频-机制对应:**
> **低技能 ≠ 把啰音静音;低技能 = 更高的接触噪声底、更窄的通带、更少的频段细节。**
> 听诊器的摩擦声、衣料声、病人自己的呼吸声混进来 —— **这正是真实的实习医生体验。**
> 它同时是 **`READ_FLOOR_MIN > 0` 的听觉实现**:背景噪声永不为零,但也不至于毁掉信号。

> ⚠️ **听诊音必须准确。** 细湿啰音 = **吸气末、断续、细密的爆裂音**(搓头发 / 撕 velcro 那种),
> **咳嗽后不消失** —— **不是连续水声**。R-8.2 粗 / 中档的「肺里有水声」是**刻意的外行措辞**
> (它对应低精度档的玩家认知,没有问题),**但实现必须按准确音做**,否则是医学受众的第一个出戏点。

> **无提示音铁律延续:**不许用 audio sting / ducking **报**病人状态变化。
> 但**允许**纸面的物理声(笔尖走路、翻纸、纸的摩擦)—— 它是**行为反馈**,
> 而且顺便解决了「待查」在**无 hover 导航**下的可读性(空行没有纸面压痕声)。
> **主角与病人共用同一套声源系统**(规则九「同一张表的两半」)。

> ✅ **2026-09-15 ADR-018 已接住本节四条硬需求(D-8-8 结清)。** 44 的架构已定型为与 42 同构
> (**只触发 / 只渲染,永不持有游戏状态**):`AudioCueDto`(无 `disease_id`,受 `PresentationDtoGuard`
> 递归扫描覆盖)· 混音拓扑含独立的 `Stethoscope` 总线 + 快照 · 音频事件表走 ADR-014 烘焙管线。
> 四条映射:
> ① **呼吸两层渲染** → `AudioCueDto.Tier`(0/1/2)+ `Intensity`(0–255)承载精度档,
> 通带 / 噪声底为资产侧参数(**AC-44-01 / 02**);
> ② **语声变体库混合** → 事件表的 `CueId` + `Tier` 选变体交叉淡化,ADR-018 §三 明写按此规格、**不得按参数调制**(**AC-44-03 / 04**);
> ③ **接触噪声 / 信噪比** → 独立的接触噪声 cue 通道 + `Stethoscope` 总线增益(**AC-44-05 / 06**);
> ④ **联机精度取主机技能** → ADR-018 §五 单 `AudioListener` 约束,**精度统一取主机技能**(**AC-44-07**)。
> **无提示音铁律 → AC-44-09(BLOCKING)**:白名单断言机械拒收 sting 类 cue;
> **细湿啰音医学准确性 → AC-44-08**(非连续水声)。`TR-diag-021…025` 登记这五条。

### V-8.8 最大视觉风险:把「低技能」做成「画面降质」

**这一处做错,代价是三重同时叠加**:看起来像**美术没做完**;读起来像**游戏在惩罚玩家**;
而最致命的是 —— 医学受众会认为**「你在装作看不见临床上显而易见的东西」**。

> **解法是一条硬规则:**
> **整体层永不满技能化。** 轮廓、体态、呼吸的粗节奏、面色的总体色调、语声有无力气 ——
> **永远满精度、永远诚实、永不随技能变**(这正是 S-8.1「持续性不泄漏深层结论」的字面执行)。
> **随技能解锁的只有局部层**:唇 / 甲床 / 结膜、啰音、三凹征、相对缓脉、肝脾界。
> **技能买的是「把一个人拆开看」,不是「看见他病了」。**

**最危险的三个具体点:端坐呼吸 · 三凹征 · 口唇发绀。** 这三个在今天的医学教育里是「一眼就有」的。所以:

- 低档**绝不允许**呈现一个教科书级征象却给一个含糊的词(那就是「游戏在装傻」);
- 要么它在**整体层本就可见**(那就老实说「躺不平」),要么它**本就只属局部层**(三凹征、发绀)
  —— **根本不在低档世界里成形**。

**绝不做**:全屏模糊、马赛克 / 雾遮挡、「灰色未解锁」、任何形式的「技能不够」提示。

### UI-8.1 脉案页:五通道区 + 两栏

**8 要求的布局语义**(具体视觉由 39/42 定):

```
┌───────────────────────────────┬──────────────┐
│  病人:______  时刻:______    │  病名:       │
├───────────────────────────────┤  (空行 = 合法)│
│ 面色 │ ____                  │  ┌────────┐  │
│ 语声 │ ____                  │  │ 确定   │  │
│ 姿态 │ ____                  │  │ 疑似   │  │
│ 呼吸 │ ____                  │  └────────┘  │
│ 触感 │ ____                  │  划掉重写(留痕)│
└───────────────────────────────┴──────────────┘
```

**四条布局铁律:**

1. **五行固定成序,永不留空、永不隐藏。** 未查的通道留**空行**(有格线、无字)
   —— **不是**灰字、不是「未查」徽章、不是占位符。**空行本身 = 显式的「我还没做」**
   (规则五,V-8.4)。**隐藏未查行 = 抹掉了「我知道我没查」这个事实。**
2. **无进度条、无完成度、无「X/5 已查」计数。** 那会把判断变成**清单打勾**
   —— 玩家会开始「刷满五格」而不是「想清楚要查什么」。
3. **病名栏与体征栏物理分离。** 病名是**玩家写下的东西**,体征是**系统写下的东西**
   —— 两者笔迹同源(都是「我的手」),但**空间上分栏**,因为**归属不同**:
   病名可空置、可划掉;体征行只能由查体动作产生。
4. **置信度必须肉眼可分。** 「确定」与「疑似」靠**笔迹的笃定 vs 迟疑**、
   **墨色深浅**、以及**那个「?」**(**只在此处允许**)区分。
   ⚠️ **「?」绝不许溢出到体征栏** —— 体征栏加「?」= 变相数值。

### UI-8.2 无指针焦点导航(硬约束)

> `technical-preferences.md`:「拟物 UI(无血条 / 无小地图)**必须同时支持键鼠与手柄导航**
> —— 手柄没有指针,脉案 / 出诊箱 / 纸质地图的全部交互都需要焦点导航路径。」

**8 交出的语义**(实现归 42):

| 需求 | 8 的语义规定 |
| ---- | ---- |
| **焦点顺序** | **面色 → 语声 → 姿态 → 呼吸 → 触感 → 病名 → 置信度**。**固定自上而下**,不得因「哪些已查」而重排 —— 重排会让肌肉记忆失效 |
| **焦点落在空行上** | **必须有反馈**(纸面压痕声 / 行高亮),**但不得显示任何提示文案** —— 玩家自己决定要不要查这一行 |
| **不可用动作** | **P0 没有不可用动作**(裁定⑨:四法出生自带)。故**不存在灰掉的按钮** —— 这本身是一条无障碍红利 |
| **「旧」的手柄可读性** | 页边**铅笔小勾**(临床病历的物理做法),不靠颜色(见 V-8.2) |

> **⚠️ 无 hover 状态下「待查」的可读性,靠纸面物理声解决**(V-8.7 已允许「行为反馈」类音效)。
> **这是 UI 与音频在本系统唯一的耦合点。**

### UI-8.3 主角侧:不进脉案

> **主角没有一张可以给自己写的纸。** 这是他「通道少」的表现,不是省略。

| 项 | 规定 |
| ---- | ---- |
| **主角体征不出现在任何脉案 / 面板上** | 全部走**世界层呈现**(视野边缘 / 呼吸声 / 步态,V-8.5) |
| **主角侧无「未查 / 阳性 / 阴性」状态机** | 那套机器只属于**病人**(S-8.2);主角侧不做快照、不记读数 |
| **唯一的例外:把脉音** | 走同一套音频,**偶发**(安静 / 躺下 / 屏息时),**不可控、不可刷** |

### UI-8.4 负向声明(8 明令禁止的界面元素)

> **本节与 9 的 §UI Requirements 同为「负面声明为主」** —— 因为本系统的界面风险
> 不在「少了什么」,而在「多了什么」。

| **禁止** | 为什么 |
| ---- | ---- |
| **任何数值 / 百分比 / 进度条** | 反幻想一:玩家看到的是**一个人**,不是「病情 42%」 |
| **疾病名录 / 图鉴 / 词条自动补全** | 反幻想二:能查表对答案,判断就退化成检索,查体全部作废 |
| **`READ_FLOOR` / 技能等级 / 精度档的任何显性提示** | 「技能不够」提示 = 把隐性门槛变成显性读数;技能要**被感觉到**,不是**被读出来** |
| **「确定 / 疑似」之外的第三档置信度** | S-8.3 三态(空 / 疑似 / 确定);加第四档就是加决策负担而不加信息 |
| **诊断结果的对错提示 / 提示音 / 战斗式 feedback** | 规则七:误诊不报错,反馈只经病人 |
| **「你已发现 N 个病例」之类的收集计数** | 会诱导玩家**凑数**而非判断 |

> **⚠️ 边界条款:手写病名在手柄 / VR 下的输入通路(2026-09-14 用户裁定⑥)。**
>
> **冲突**:规则六要求**手写病名**,而 `technical-preferences.md` 要求**手柄完整可用**;
> 手柄 / VR **没有手写板**。若在此处降级为「从列表里挑」,**必须划清它与上表
> 「疾病名录 / 图鉴 / 词条自动补全」禁令的界线** —— 否则前者会被后者击穿。
>
> **裁定:拟物化选择 + 裁定边界。** 手柄 / VR 下,病名栏**不变成下拉列表**,
> 而是**一本翻开的病名册**(拟物:纸页、手写条目、翻页),玩家**翻到并「指认」**那一页。
> **它不是名录 —— 差别有三,全部是机制性的:**
>
> | | **允许(病名册)** | **禁止(名录 / 图鉴 / 补全)** |
> | ---- | ---- | ---- |
> | **收录范围** | **只有玩家已见过的病**(复用 30 的 `(技能, 对象)` 新颖度表)—— **没见过就翻不到** | **完整注册表** —— 能对答案 |
> | **组织方式** | **无分类、无索引、无搜索** —— 按**遇见顺序**排列,一本越翻越厚的册子 | 按症状 / 系统 / 首字母分类,**可检索** |
> | **是否给线索** | **零线索** —— 不显示「相关体征」,不排序,不猜测你要找什么 | **自动补全 / 高亮匹配 / 「你可能想找」** |
>
> **核心理由**:规则六的原话是「**你没见过疟疾,就写不出『疟疾』这两个字**」——
> 禁令防的是**超出已有知识**,不是**换一种输入方式**。
> 病名册**只让玩家从自己已挣得的知识里挑**,与「手写时你只能写出见过的病」
> **在信息量上完全等价**;翻册**同样是一个物理动作**(有纸声、有翻页),不违反规则六的拟物要求。
>
> **⚠️ 硬约束(AC-8-43 / AC-8-44 守门):** 病名册**不得**有搜索框、不得有分类标签、
> 不得有自动补全、不得显示任何体征线索、**不得包含玩家没见过的病**。
> **违反任一条即退化为图鉴**,当场击穿反幻想二。
> **键鼠侧不受影响** —— 仍是手写(或手写 + 同一本病名册并存,由 42 定 UI 形态)。
