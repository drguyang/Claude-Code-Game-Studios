## Summary

29 拥有**玩家自身**的死亡与复活。它做三件事:**判定一次死亡成立** · **结算代价两件套**
(掉落物 / 技能熟练度;精神压力归 P1a)· **把玩家放回复活点**。

**边界是硬的**:病人的死亡归 **9 + 53**;29 **只管玩家**。25 格斗是玩家受伤的主要来源,
但 **29 不读武器伤害数值** —— 它只消费一个**死亡成立**的布尔。

**确定性**:掉落的**发起**(`PlayerDied`)与**落点**(`ActorCellEntered`,**由 1 发**)都经世界流;
掉落**清单**从世界流重建;掉落**位置**从 7a 快照取(表现态)。
**掉级不是新真源** —— 它是 `Level(s)@t` 的一个**纯函数投影**,由世界流的 `PlayerDied` + 病史流的
`SkillGrown` 折叠得出(见 F-29-1),**不落任何新 Kind**。

## Overview

29 是「**主角也有身体**」这条承诺的机制落点。它的存在回答一个问题:
**医者不杀,那医者自己呢?**

它是**惩罚系统,不是惩罚叙事**:代价各有机制出口,且**都不掉「你已经学会的东西」**
(不掉已解锁动作 / 知识 / 脉案 —— `game-concept.md:322`)。掉的只有**手上的**与**身上的**。

**29 是终局惩罚的最小实现**,刻意做小:

- **不做**存档回滚(死亡不回档 —— 回档会摧毁「判断有后果」)
- **不做**尸体回收玩法(那是 P1a 的诱惑)
- **不做**死亡惩罚的数值系统(数值归 30 / 用户的平衡轮)

> ✅ **`OQ-25-1` 已于 2026-09-19 裁定为「路甲」**(9 的 F4 对「战伤类 + 逐实体自限门」判死)。
> 29 在 P0 **有**实现对象;本 GDD 的 15 条 AC **全部属 P0**。
> **判定顺序**:9 出 `DeathCandidate` → 29 消费 → 29 结算并落流(见规则二)。

## Player Fantasy

**「我倒下了 —— 而世界没有停。」**

三个时刻,三种感觉:

1. **倒下** —— 不是「Game Over」弹窗。是**水墨侧的一个人躺下来**(承 25 §五 视觉锚点:
   「交手 = 黄铜;倒下 = 水墨」)。玩家失去控制权的那一瞬**是安静的**。
2. **回来** —— 醒来时你在**医馆床榻上**。你的东西还在原地,你得**再走一趟**。
   这一段「狼狈的回程」是 29 交付的**核心体验**,不是副作用。
3. **手生** —— 技能掉 5%,但框定是「**手生**」不是「遗忘」(`skill-system.md:158`)。
   你没有忘 —— 你只是**手上没感觉了**。**这个区分对整个主题很重要**:
   主角是一个有身体的人,身体会受伤,受伤会影响手艺。

> **⚠️ 幻想的两个 P0 降级(均已显式登记,非默认成立)**:
> - **第三层「精神压力」在 P0 是哑的**(OQ-29-3 裁定「维持两件套」)—— 压力轴归 **47 精神压力**(P1a)。
>   P0 的 29 **不发**任何压力事件(其 Kind 由 47 的 GDD 定义,见规则四),⇒ **P0 死亡代价 = 掉落 + 手生 两件套**。
> - **「狼狈的回程」的主通道载体在 P0 缺席** —— 无位置标记 · 全案无小地图(`skeuomorphic-ui.md:1195`)。
>   **P0 靠空间记忆走回**(用户裁定 2026-09-19,**接受 P0 无标记**);**拟物载体 = 纸质地图上的一处
>   折痕 / 墨点,归 43 纸质地图与出诊箱(P1a)**(`skeuomorphic-ui.md:1133`)。详见规则五 · AC-29-16。

| 环节 | 归属 | 接口 |

> **29 的规则三 / 四 / 五(代价与复活)与触发源无关** —— 它们消费的是「死亡已成立」这个事实,

### 规则三:代价一 —— 掉落物(清单从世界流,位置从快照)

**掉落 = 玩家携带的 `ItemInstance` 身份集合,散落在死亡点。**

```
死亡成立 ⇒ 对玩家携带的每个 ItemInstance i:
    DropSpawned { instance_id = i.id, spawn_anchor = death_cell, item_key = i.key, qty = i.qty }
    DropClaimed { instance_id = i.id, claimer = 无主 }  // 或直接不 Claim,留待玩家回捡
```

**关键分工**(承 `adr-009:310` / `persistence-service.md:249`):

| 面 | 来源 | 为什么 |
| --- | --- | --- |
| **掉落清单**(掉了哪些) | **世界流重建**(模拟) | 清单是模拟态 —— 可从 `DropSpawned` / 已有归属事件重构 |
| **掉落位置** | **7a 快照**(表现态) | 位置是表现态,不进流(ADR-009 §五「身份进流 / 位置表现」);快照是**优化非真相**,丢了只是慢(重走一遍世界流最后位置) |

> **⚠️ `death_cell` 的定义(2026-09-19 修订 · 承首轮阻断 B4)**:
> `death_cell := ` **该玩家在世界流中的最后一条 `ActorCellEntered` 之 `cell`** ——
> **一个整数格,从世界流读出,不读实时物理位置**。
> 原稿写「判定用当时的实时物理位置」**违反 ADR-020 §四**(玩家连续位置 = 纯表现态,禁入 sim)
> 且破坏 ADR-012 的逐位重放。**已就地废止该读法。**
> 表现态的「宽容半径」只影响**掉落物的视觉散开**,不影响 `spawn_anchor` 的取值。
> (性质:**派生态** —— 由世界流确定性重建,零新状态。)

**禁**:29 **不得**在客户端本地铸造 `DropSpawned` 的 `instance_id` 之外的任何新身份;
`DropSpawned` 的**写者 = 主机唯一**(ADR-005);`instance_id` 的铸造权 = 20 的 `mint(g)`(D-21-27)。

### 规则四:代价二 —— 技能掉级(29 拥有时机,30 拥有公式)

```
Level_new(s) = ( Level(s) × 19 ) / 20          // C# 整数截断除法,∀ s ∈ 技能集 ∖ 判断类
```

- **全部技能,逐项结算** —— **判断类技能(诊断 / 辨证)除外**(2026-09-19 用户裁定)。
- **漏掉的**:已解锁的动作 · 已学的知识 · **已写的脉案**(`game-concept.md:322`)· **判断力本身**。
- **实现**:29 **不自己算** —— 29 发起一次「死亡结算」**运行时调用**,**30 执行** §4.3
  (`skill-system.md:457`「下游 · 死亡与复活系统 | 执行 §4.3 的掉级」)。
  **29 拥有时机,30 拥有公式**(单一出处)。

> **⚠️ 判断类技能豁免(2026-09-19 用户裁定 · 支柱一)**:
> 「死亡是**判断失败**的代价,不是**判断力**的损失」。**诊断 / 辨证 的等级不参与掉级** ⇒
> 已解锁的**鉴别诊断门(诊断 20 级)**与 **P1a 辨证门**永不因死亡被撤销。
> 这条裁定同时消解了原稿的一个未定义缺口(「掉到门槛以下时门槛是否撤销」)—— **不再存在该场景**。
> 其余 17 项技能照掉(手艺会生,判断不退化)。

> **⚠️ 掉级 = 流的纯函数投影,不是新真源**(2026-09-19 修订 · 承首轮阻断 B3):
> `Level(s)@t` **可由两条既有流确定性重建** ——
> `Level(s)@t = fold( 病史流中的 SkillGrown(s, …) , 世界流中 ≤ t 的 PlayerDied 事件数 )`,
> 即「每次成长加上去、每次死亡乘 19/20」。**⇒ 掉级不需要自己的 Kind,29 也不需要发「掉级信号事件」。**
> 29 对 30 的调用是**同 tick 的运行时调用**(纯函数式,无第二编码);
> 原稿的「一次掉级信号」**是拟物化措辞,已删**。任何声称需要为掉级新增 Kind 的实现 = 造第二真源。

### 规则五:复活 —— 落点由 29 决定,写入归 1

**复活 = 玩家被放回复活点。**

| 面 | 归属 | 依据 |
| --- | --- | --- |
| **复活点**(哪一格) | **医馆床类家具格**(2026-09-19 用户裁定 OQ-29-2)—— 见下 | Valheim 式「床」的医学化 |

| **传送频次上界** | **本规则兑现** —— 见下 | 结清 1 的 `O-3` / `OQ-1-8` |

> **⚠️ 写者修正(2026-09-19 · 承首轮阻断 B6)**:原稿写「29 写一条 `ActorCellEntered`」**与
> `architecture.yaml:52`「`ActorCellEntered` 写者 = 1」直接冲突**。**已改**:29 调 1 的
> `TeleportTo(cell)`,**由 1 发该事件**(1 是玩家运动与跨格事件的所有者)。29 的代码路径对
> `ActorCellEntered` 的 `Append` 调用点数 = **0**(见 AC-29-09)。

**复活点定义(OQ-29-2 裁定,2026-09-19)**:

```
revive_cell = 医馆房间(24)内某一「床类」家具格的整数格
              若有多个 ⇒ 取 24 的确定性规则选定格（具体规则归 24 的下一轮）
若医馆未建 / 无床 ⇒ 退回世界出生点（ADR-015 逻辑层的固定格）
```

> **为什么是床**:`clinic-machine.md` 的房间谓词已含床(示例「床 ≥ 2 ∧ 有手术台」),
> **不新立系统**;「被抬回床榻」是「医者也是人」的最小拟物落点。
> **⚠️ 24 侧义务**:24 的 GDD(**已 Approved**)未定义「复活点」——
> 其下一轮须补「床类家具格的确定性选定规则」并在 Dependencies 反向列 29(见 §Cross-References)。

**「复活传送频次上界」的登记(结清 `player-controller-and-movement.md:1059` / `O-3` / `OQ-1-8`):**

```
复活传送 ≤ 每 tick 一次（主机串行裁决天然保证）
且 ≤ (玩家数 × 1) 每死亡事件 —— 复活不是持续位移源
```

> **为什么这是有界的**:复活是**离散事件**,每次死亡至多触发**一次**传送;
> 死亡本身受**死亡冷却**(F-29-2)约束 ⇒ 传送率上界 = `玩家数 / DEATH_COOLDOWN`,**有限**。
> **这使 ADR-009 §六 的世界流有界性论证在 29 侧闭合**(EC-4 的第三个输入,承 `:1099`)。

**复活不重置**:病程不重置(世界继续走)、玩家携带物保持空(东西在地上)、
**不重置敌人的位置** —— 世界没有为你暂停。

**回捡约束(2026-09-19 用户裁定 · 兑现 20 的 R7)**:

> 掉落物**散落在死亡格,须走回该格才能 `DropClaimed` 取回** ——
> **P0 无「远程拾取 / 自动回箱」路径**(20 的边界义务)。
> 这条约束是 F-29-2 冷却之外**第二道**「死亡不被用作免费清负重」的闸门(死 → 空手 + 负重清零,
> 但东西在地上,载重轴不被绕过)。**判据见 AC-29-17**。
> **P0 无位置标记**:靠**空间记忆**走回;拟物载体(纸地图墨点)归 **43(P1a)**。

### 规则六:死亡呈现 —— 无 Game Over 界面

**29 不产出「游戏结束」屏。** 倒下 → 一段安静的过渡 → 医馆醒来。
**这是幻想的主通道**,不是可选的润色(承 44 评审的核心结构洞察:幻想主通道必须有载体)。

**硬约束**:

- **绝不**显示「你死了」的**文字化弹窗 / 大标题**(反幻想;承 42 拟物 UI 的「纸上世界」)。
- **绝不**显示死亡统计面板(掉了多少东西 / 掉了多少技能)。**代价要玩家自己发现**。
- **绝不**播放「失败」提示音(ADR-018 §六 无提示音铁律:禁止用音效播报状态)。
  「倒下」的动作声音 ∈ 行为反馈白名单;「你失败了」的 jingle ∉ 白名单。

## Formulas

> 本节公式全部 `int` 或经 `FixParse` 的定点字面量。**数值归用户调**(见 §Tuning Knobs)。

### F-29-1 · 掉级(归 30,29 只发时机)

```
Level_new(s) = ( Level(s) × 19 ) / 20              // ∀ s ∈ 技能集 ∖ 判断类
              ────────────────────────
              整数截断除法（C# int `/`）—— 不是 Fix.Div,不是 floor_Fix(Mul)
```

| 变量 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `Level(s)` | int ∈ `[0, 60]` | 30 | 当前等级 |
| `19 / 20` | int 常数 | 本节(对应 `skill-system.md:477` `DEATH_LOSS`) | **整数比**,不是 `Fix` 字面量 |
| `Level_new(s)` | int | — | 落回 30 |

> **⚠️ 定点陷阱(2026-09-19 修订 · 承首轮阻断 B2)**:
> 原式 `floor_Fix(Level × FixParse("19/20"))` **算错一格** ——
> `FixParse("19/20") = 62259`(Q16.16),`40 × 62259 >> 16 = 37`,而表值要求 **38**。
> `floor_Fix(Mul)` 与 `(L×19)/20` **不等价**(前者先量化再 floor,丢了低位)。
> **修正**:`Level` 是 `int`,**直接用整数截断除法**,不进入定点乘法域。
> **禁用** `Fix.Div`(它的 `ROUND_HALF_AWAY_FROM_ZERO` 会把 10→9.5 舍成 10,反向错误)。
> **⚠️ 30 侧义务(挂 30 的下一轮,本轮未改 30 正文)**:`skill-system.md` §4.3 的公式
> 写 `floor(current_level × 0.95)` 且注为「`0.95` 经 `FixParse`」—— **同源同错**
> (其**表值**已正确,公式行与表矛盾)。**须由 30 的下一轮改为整数截断形式**。
> **在 30 修正前,以本 GDD 的 F-29-1 为掉级语义的权威式**(29 是掉级时机的拥有者,
> 30 是公式承载者;两者在 30 修正前存在一处已知口径差,已登记不静默)。

### F-29-2 · 死亡冷却(防刷死)

```
DeathAllowed(actor, t) ⟺ ( t − last_death_tick(actor) ) ≥ DEATH_COOLDOWN
last_death_tick(actor) := max{ Tick(e) : e ∈ 世界流 ∧ Kind(e) = PlayerDied ∧ actor(e) = actor }
```

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `last_death_tick(actor)` | int | **唯一来源 = 世界流的 `PlayerDied` 事件重算**(F-29-1 的 `PlayerDied` Kind)—— **零独立计数器** |
| `DEATH_COOLDOWN` | int(tick) | ⚠️ **未定**(用户平衡轮);**须 > 0**,否则「无限刷死」= 掉落经济漏洞 |

> **为什么这次不会静默失败(2026-09-19 修订 · 承首轮阻断 B1)**:
> 原稿的 `last_death_tick` 依赖一条**根本不存在**的死亡事件 Kind ⇒ 冷却**永远读不到值** ⇒
> 静默退化为「无冷却」(掉落经济漏洞)。修法 = **登记 `PlayerDied` 世界流 Kind**:
> **它无条件发出**(背包空也发),故冷却**总有真值**。`PlayerDied` 是纯实体侧事件,不受库存状态影响。

> **为什么需要冷却**:无冷却 = 玩家可反复自杀来**清空负重 / 刷新状态**。
> 这是 **F-29-2 的存在理由**,与「惩罚不痛但讨厌」的设计目标一致(`skill-system.md:366`)。

### F-29-3 · 掉落清单(世界流纯函数)

```
DroppedSet(death_event) = { i : i ∈ InventoryOf(actor, 世界流@Tick(death_event)) ∧ i 未被 claim }
```

> **`InventoryOf` 是玩家背包的**世界流重建**(20 的 `AC-20-03`)。** 29 不持有背包 —— 20 持有;
> 29 只读「这一刻的背包投影」。**零新状态**(承 ADR-009 §一 Q1 判据)。

### F-29-4 · 掉级的流重建(不落新 Kind 的依据)

```
Level(s)@t = Level₀(s) + Σ_{e: SkillGrown(s)} Δlevel(e)    再逐次乘 19/20：
          = fold_left( 病史流 ≤ t 的 SkillGrown(s) , 世界流 ≤ t 的 PlayerDied ,
                       (acc, ev) => ev 是成长 ? acc + Δ : acc × 19 / 20 )
```

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `SkillGrown(s, Δ)` | 病史流事件 | 30 的成长事件(`skill-system.md:519`),携带 `ΔLevel` |
| `PlayerDied` | 世界流事件 | 本 GDD 新增(见 §Detailed Rules 规则二 / F-29-2) |
| `Level₀(s)` | int | 开局等级(1) |

> **本条是「掉级不进流」的证明**:序列可从两条既有流**确定性重建** ⇒
> 掉级是**派生态**(ADR-009 §一 Q1),不需要第三条载体,**不存在重复真源**。
>
> **⚠️ 前置未完全落地(登记,不静默)**:`SkillGrown` 的**正式登记**仍是 **30 侧的残留义务**
> (`skill-system.md:578`「`entities.yaml` 追加 `SkillGrown` + ADR-009 §三 骨架补记,**本轮不落**」;
> 全库当前 `SkillGrown` **零登记**)。⇒ **F-29-4 与 AC-29-16 的前提在 30 登记落地前不成立** ——
> 该两条**不得在 `SkillGrown` 登记前记绿**(`BLOCKED-BY`:30 的 `SkillGrown` 登记义务)。
> 掉级语义本身(**F-29-1**)不受影响(它只依赖 `Level` 的当前值)。
