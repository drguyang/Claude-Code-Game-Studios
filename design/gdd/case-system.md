## Overview

病例系统是**「病例」这种东西的宿主**。诊断(8)揭示体征、疾病与伤情模拟(9)让病程在病人身上
自己走,而 37 负责把这一切**收拢成一个可以打开、可以处置、可以结案、也可以一直耽搁下去的单元**。

它是《大医精诚》里玩家实际**从事**的那个东西。玩家不「战斗」,玩家**办案**:
接下一个病人 → 看他的体征 → 在脉案上落下(或空着)一个病名 → 施治 →
决定这个案子算了结还是先搁着。**一个病例从「立」到「结」,中间的世界不会停。**

37 持有**病例的生命周期与结算主权** —— 它与 8 的分工是严的:
8 拥有**状态机规则**(读数四态、判断三态),37 拥有**病例这个容器与它的存续**;
9 拥有**病程**,37 只是给病程套上一个玩家可见的壳。
**改 37 不改动任何一个病种的数学,但会改变每一个病种对玩家的呈现方式。**

**37 是支柱四「拼出来的图样」的 P0 唯一载体。** Boss 不是站在你面前的实体 ——
是**三份分散在不同地点的脉案,摆在一起才看得出是同一件事**。
37 的职责是把这三份脉案**都变成可打开的病例**,并在三个案子都结案时,
记录下「这三例同源」这个**客观事实**:

> **37 从不告诉玩家「你认对了」。** 玩家自己认出图样的那一刻,系统保持沉默 ——
> 它只是把材料摆在那里,并且诚实地记账。

数据层(供实现参照):一个病例 = 一条**病史事件流的包装**(ADR-005 的 `SimEvent`,
病人归属唯一由 9 经 `IIdAuthority.Next()` 分配)+ 8 的判断记录(读数 + 落笔 + 改写史)
+ 37 自己的生命周期标签。结案时经 `IEventSink.Append` 发出后果事件,由 53 承接;
**37 不持声誉、不持制度权限** —— 那些是 P1a 的事。

> **架构引用(收窄口径)**:本 GDD 引用 ADR-007 的**事件种类**与 `PatientId.None` 哨兵契约;
> 世界级聚合信号使用哨兵,不污染 `max(patient_id)` 高水位。**不引用** ADR-007 所约束的
> 52 F1 权重行为(`ReputationMult` / `HistoryMult` / 配额换算)—— 那些在二轮复核中刚被第三次重写。

## Player Fantasy

**核心幻想一句话:你手上有一叠没结的案子 —— 而案子不会因为你没空就先自己结掉。**

三个锚点:

1. **「一本案子,一支笔,我自己判断」—— 决定权在我手上,而且它会留痕。**
   没有人会告诉玩家「这个病例该诊断成什么」。病名的那一栏是**玩家自己写的**,
   写错也可以,留空也可以 —— 37 不报错、不扣分、不弹窗。
   这和 8 的规则一脉相承(`S-8.3`:空是**合法终态**),但 37 把它抬到了**案子**这一层:
   **一个病例的可书写性,就是「判断」这个词对玩家的全部意义。**
   *参照*:《请出示证件》的盖章台 —— 但那边的权威在系统,**这边的权威在玩家自己**。

2. **「我搁下了,但我没忘」—— 那个没结的案子一直在我这里。**
   P0 没有「任务列表」,有的是一叠**脉案**。没写病名的那一格、没结的那一例,
   **它不会消失,也不会被系统标红**。玩家自己要记得它。
   这一条是《他回来了》第二幕能被**感知到**的机制条件 ——
   空栏之所以有分量,是因为**玩家自己一直看着它**。
   *(⚠️ 反幻想一:绝不能做成「待办事项列表」—— 那会把「记着」外包给系统。)*

3. **「这些东西是同一件事」—— 认出图样的那一刻。**
   三份脉案散在不同地点、不同时间。**它们都有同一个病名栏。**
   玩家自己把三份摆在一起,自己看出「同源」。
   **系统永不报「你答对了」** —— 37 只是**记录**三个病例同源这个客观事实,
   发一个聚合信号。**认出这件事,系统不做,玩家做。**
   这是支柱四「Boss = 你拼出来的图样」在 P0 的唯一落点。

> **反幻想一:这不是待办列表。** 玩家**永远不会**看到「未结病例:3 / 5」。
> 没有进度条、没有红点、没有到期提醒。**案子是东西,不是任务。**
> 一旦未结案变成可被清空的任务队列,「记着」这件事就被外包了,
> 锚点二的重量随之归零。

> **反幻想二:这不是打勾。** 「结案」**不等于「诊断正确」**(game-concept 支柱四铁律:
> 进度挂**处置结果**,不挂**诊断正确**)。玩家可以诊断错、可以空着病名,
> 只要他把这一例**处置过并关闭**,案子就结了。
> **37 从不为「诊断正确」发奖励,也从不为「诊断错误」发惩罚** ——
> 后者是 53 的即时后果,前者根本不存在。

> **反幻想三:这不是图鉴。** 病例**不可检索、不可排序、不可按病名分组**。
> 玩家只能**翻**。想看出同源,他得真的把三份摆在一起。
> **这是「拼图样」的机制前提** —— 一旦可以按 `disease_id` 分组,
> 归纳就被系统代劳了,「认出」这件事本身消失。

> **与 8 / 9 的幻想互补**:
> 9 的幻想是「**世界不为你暂停**」,8 的幻想是「**但世界不全给你看**」。
> **37 是第三个半句:「而你说它是什么,就是什么 —— 后果由你担。」**
> 三条合起来才是完整的:病是真的 · 你只能看到一部分 · **但写下去的那一笔是你的。**

> **支柱对齐**:支柱一(判断为骨)—— 37 提供判断的**载体与结论**,是判断唯一能「落地」的地方;
> 支柱四(Boss = 拼出来的图样)—— 37 是该图样在 P0 的唯一载体。
> 支柱五(史实为骨)—— 病例的时代质感与病种的史实约束,37 落笔时必须经得起考据。

> **⚠️ 诚实记账(承 52 的「承重问题」体例,2026-09-15)**:锚点 3 的**图样可辨识度**
> 在 P0 **尚未被验证** —— 三案链是**手工编排**的,三份脉案能否真的让玩家「看出来」,
> 只有在 playtest 之后才知道。**这是本系统最大的设计风险,登记见 Open Questions。**

## Detailed Design

> **承重判定(整节的总纲):病例是「记录」,不是「实体」。**
>
> 「一次就诊 = 一个病例」+「未结案永久开着」这两条合起来,逼出一个必须写死的区分:
> **病例的存续与病人的存续是两回事**。病人走了、死了、你再也见不到他了,
> 那一例**仍然开着** —— 因为病例是一页**记录**,不是一个人。
> 人归 13 病人 AI,页归 37。**这一条不写死,《他回来了》第二幕的「那一格空栏」就没有家。**

### Core Rules

**规则一:病例是什么。**

一个病例 = **一次就诊**的完整单元,承载四样东西:

| 组成 | 谁生产 | 37 做什么 |
| ---- | ---- | ---- |
| **病史** | 9(该病人的病史事件流) | 包装、引用,**不复制** |
| **读数记录** | 8(五通道状态机) | 存,**不重新判定** |
| **判断记录** | 玩家(在 39 脉案上落笔) | 存,**含改写史** |
| **处置记录** | 10 / 11 / 25(施治动作) | 存,**不作为正确性判据** |

> **37 不复制 9 的状态机。** 病例**不是**「病人在哪一态」的镜像 —— 病人走九态(潜伏…死亡),
> 病例只走**两态**(开 / 结)。两者**正交**:一个「死亡」的病人可以有一个「开着」的病例。
> **把它们做成同一台状态机,就等于让「结案」被病人的死活决定** ——
> 而本作明令进度**不挂结果挂处置**(`game-concept.md` 支柱四铁律)。

**规则二:立案(病例从哪来)。** 两条路径,缺一不可:

| 路径 | 触发 | 立案时刻 |
| ---- | ---- | ---- |
| **A · 事件注入** | 52 注入的医疗事件(**急召出诊** / **原型疫情**) | **玩家抵达病人处、发生就诊交互时**(不是事件降临的那一刻 —— 急召出诊的要点就是「你得走过去」) |
| **B · 自然就诊** | 病人自己上门(13 病人 AI) | 就诊交互发生的那一 tick |

**立案是一次玩家动作**,因此它进事件流(ADR-005 / **ADR-008** —— 病例事件落**病例流**,
`CaseOpened` 为三 Kind 之一)。
**`case_id` = `( Tick , Patient , Seq )` 三元组**(ADR-008 §二 —— `Seq` 仅在同一
`(Tick, Patient)` 内单调,单独取 `Seq` 会撞号;见 F-37.2)—— 确定性、可从流重构、
**不需要第七个抽象点、不需要任何新计数器**(沿用 ADR-006 Amendment B 的「从流重建」口径)。

> **⚠️ 37 注入的三个条目里,只有两个立案。** **药材短缺不立案** ——
> 它是缺资源的**环境事件**,没有病人。它是 37 注入 52 的医疗内容,但**不产生病例**。
> 这条不写死,实现会去为「药材短缺」硬造一个病人。

**规则三:串接(复诊)。** 同一 `patient_id` 的多个病例,在脉案上**显式串成一组**
(拟物呈现:一叠纸用线订在一起,P0 版沿用 #43 的地图钉线语汇)。

- **串接键 = `patient_id`**;**展示排序键 = `(patient_id, CaseOpened 的 (Tick, Seq))`**
- **串接不等于合并。** 每一例**各有各的病名栏** —— 第二幕那一格是**新的空格**,
  与第一幕写满的那格**并排存在**。**对比就是全部意义**;合并它们,钩子当场失效。
- **复诊的触发归 52(脚本条目),复诊的语义归 37** —— 与三案链同构
  (见 `random-events.md` 规则二裁定)。

**规则四:判断记录的存储。** 37 存 8 交来的三样:**读数** + **落笔**(病名 + 置信度)+ **改写史**。

> **⚠️ 改写史进记录,但永不进计分。** 依据 AC-8-29 与 S-8.3 性质 2:
> **改写不是可疑行为,是好的临床行为**。37 存它是为了玩家**回看**,
> **不是**为了交给 53 当扣分项。**任何「改写次数」参与结算的实现,都是错的。**

**规则五:处置记录的边界。** 37 存「玩家对这一例做了什么」(开了什么方、做了什么动作),
**但 37 不判定它对不对**。正确性是 **#53 的裁量**。37 只保证**记录完整、可回放**。
处置事件本身在**病史流**(9 的求值输入,ADR-008 §一),37 的 `已处置` 判定跨流读它
(ADR-008 §四),`treated` 布尔在结案时**快照进 `CaseClosed` 载荷**。

**规则六:结案(唯一出口,玩家显式)。**

1. **结案只有一条路径:玩家在 39 脉案上对某一例执行「结案」。** 系统**永不自动结案**。
2. **前置条件:「已处置」成立(ADR-008 §四,2026-09-15 用户裁定)。**
   `已处置(c) := 本案在病史流中存在 ≥1 条处置事件,且其 Tick ∈ [CaseOpened.Tick, CloseTick]`
   **∧ 玩家在结案页勾选「已处置」**(UI 仪式,不产生独立事件)。
   病人不必痊愈、不必在场、病名可以是**空的**。
   (《他回来了》的收尾就是「他还病着,病名那栏空着」——
   如果结案要求病名非空,那一格永远结不了。)
3. **结案是单例的**:一次关一例,绝不能「全选结案」。
4. **结案不可撤销。** 关掉的案子**不重开**(判断已冻结,见 S-8.3)。
   要再记一次,那是**新的一例**。**重复结案幂等拒收**(2026-09-15 复核 #10):
   同一 `case_id` 的第二条 `CaseClosed` 被拒绝,不产生新事件(判定 = 流前缀纯函数)。
5. 结案时:8 的**读数态全部清除**、**判断态冻结**交 53(AC-8-47 落点)→
   37 冻结该例 → 发一条结案事件(走 `IEventSink` 落**病例流**,ADR-008 §一)→
   **53 订阅结算**。**37 自己不产生后果**。
   `CaseClosed` 载荷**快照**:`disease_set`(病种集,可空)+ `treated` 证据快照
   (ADR-008 §三/§四 —— 重放永不跨流查询,折叠也无害)。

**规则七:未结案永久开着。** 没有超期、没有红点、没有「N 例未结」计数、没有催办。
病人离开视野、病程走到死亡,**那一例照旧开着**,直到玩家自己关掉它。

> **这是反幻想一的机制落点。** 「记着」这件事**不许外包给系统** ——
> 一旦系统替玩家记住,锚点二的重量归零。

**规则八:同源检测(「图样」的判定)。** 见 Formulas 的 F-37.1。要点:

- **判的是「结案」不是「诊断正确」**(`game-concept.md` 支柱四铁律)。玩家诊断错、
  空着病名,**只要三例都被处置过并关闭,模式即成立**。
- **「已处置」是结案的前置条件**(ADR-008 §四,2026-09-15 用户裁定):
  `已处置` = **病史流存在 ≥1 条处置事件**(Tick 落在 `[CaseOpened.Tick, CloseTick]` 窗口内)
  **∧ 玩家在结案页显式勾选「已处置」**(UI 仪式,不产生独立事件)。
  **不认处置内容对不对** —— 对错仍是 53 的裁量。**不勾不能结案**;无处置事件佐证**不能结案**。
  `treated` 布尔在结案时**快照进 `CaseClosed` 载荷**(ADR-008 §四),重放不跨流查询。
- **系统的反应是「记录」,不是「祝贺」。** 37 **不发任何「你答对了」的提示**。
  它只发一条**世界级**聚合事件(哨兵 `PatientId.None = -1`,ADR-007 §四),
  载荷为**加盐哈希键** `SplitMix64(WorldSeed, "case-salt")`(ADR-008 §五 —— 防御纵深,
  非保密层;规则九唯一落点 = AC-37-15),由 53 去产生可见的世界变化。
  **玩家能不能把这个因果连起来,是玩家的事。**

**规则九:37 知道真相,且必须守口如瓶。** 这是本系统最重要的一条性质。

> **37 是玩家侧唯一「知道 `disease_id`」的系统** —— 它包装的就是 9 的病史事件流,
> 真实病种**就在它手上**。而它**绝不可以**把它透露给玩家:不给提示、不进 UI、
> 不参与分组、不参与排序(反幻想三:**病例不可检索、不可排序、不可按病名分组**)。
>
> **一旦 `disease_id` 泄漏到呈现层,归纳被系统代劳,「认出」这个玩法当场消失。**
> 37 是全案**唯一**一处「知道答案而必须闭嘴」的地方 ——
> 这条在代码层等价于:**`disease_id` 不得出现在任何交给 42 / 39 的数据结构里**。
>
> **⚠️ 保密语义收窄(ADR-008 §五,2026-09-15)**:保密 = **「player 不可见」**(呈现层
> DTO 静态检查,AC-37-15),**不是**「client 不可知」—— 病史流明文 `onset` 事件与存档
> 已含病种,客户端持流副本,「client 不可知」从来就是假的。`PatternRecognized` 的
> **加盐哈希键**(`SplitMix64(WorldSeed, "case-salt")`)是**防御纵深**,**不是保密层**
> (P0 ≤ 8 病种枚举空间必然可逆)。规则九的**唯一**落点 = AC-37-15 的 DTO 静态检查。

**规则十:37 不拥有什么。**

| 不拥有 | 归谁 |
| ---- | ---- |
| 病程推进 · 九态 · 病种注册表 | 9 |
| 读数 / 判断的**状态机规则** | 8 |
| **后果**(家属反应、村落的信任、疫区是否被压住) | **#53**(P0)· 31 声誉(P1a,订阅 53) |
| **制度性权限**(防疫督办权) | 33(P1a) |
| 病人这个**实体**(在场、走动、呻吟) | 13 |
| 脉案的**持久化与呈现** | 39 |
| 声誉 · 数值奖励 | 无 —— **P0 的 37 不发任何数值奖励** |

### States and Transitions

| 状态 | 进入条件 | 退出条件 | 行为 |
| ---- | ---- | ---- | ---- |


> **⚠️ 没有第三条边。** 病人死亡 **不是**病例的转移条件 ——

### F-37.1 同源检测(Pattern Detection)—— 支柱四 Boss 的机制本体

**这是全节唯一的「判定」。** 它回答「玩家认出了图样吗」—— 而答案永远不在病名栏里。

```
ClosedSeq(D, k) := 满足 [c.state = 结 ∧ D ∈ c.disease_set] 的病例,
                   按【病例全序】(CaseClosed.Tick, Patient, Seq) 升序的第 k 个
                   —— 且 MemberSet 须互异 patient_id(2026-09-15 裁定)

ThirdClose(D)  := ClosedSeq(D, PATTERN_THRESHOLD)          // null 若不足
PatternFired(D) @ t  ⟺  ThirdClose(D) ≤ t
FiredSet(t)    := { D : ThirdClose(D) ≤ t }                 // 派生,不存储
MemberSet(D)   := { ClosedSeq(D, 1..PATTERN_THRESHOLD) }    // 冻结于触发时刻,此后不增
```

| 变量 | 类型 | 范围 | 来源 | 说明 |
|------|------|------|------|------|
| `D` | enum | 9 的 R3 表 | **结案时快照入 `CaseClosed.disease_set`**(非实时读) | **37 不得外泄**(规则九) |
| `PATTERN_THRESHOLD` | int | ≥ 2 | 调参旋钮 | P0 = **3** |
| 病例全序 | tuple | 全序 | `(CaseClosed.Tick, Patient, Seq)` | F-37.2 定义 |
| `MemberSet` 互异性 | set | — | **三条 CaseClosed 的 `patient_id` 互不相同**(2026-09-15 裁定) | 同一病人三诊同病种**不触发** |
| `FiredSet` | set | — | **派生** | 迁移后逐位可回放 |

**Output Range:** `{null, 序}` 与布尔。**无 `Fix`、无浮点** —— 全 `int` 比较。

**Example(P0 三案链):** 三例 `DIS_MALARIA` 在 Tick 400 / 447 / 463 结案 →
`ThirdClose` = 第 3 者(Tick 463)→ **发一次**世界级聚合事件,`MemberSet` = 那三例。
之后第四例间日疟在 Tick 500 结案 → `FiredSet` 已含 D → **不重发、第四例不进 `MemberSet`**。

> **四条性质,逐条对应裁定 + 复核:**
>
> 1. **判「结案」不判「诊断正确」。** 公式的输入只有 `state` 与 `disease_set`(结案快照)——
>    **病名栏是空是错,公式一概不看。**
> 2. **无时间窗口。** `≤ t` 不含下界 —— 三例可以在任何跨度内结案。
>    图样是**模式**,不是**竞速**。
> 3. **阈值是 `≥` 不是 `==`**(复核 #7)。同 tick 批量结案让计数 2 → 4 也能触发。
> 4. **`FiredSet` / `MemberSet` 均由流派生且冻结**(复核 #3 / #7)。不需要新计数器;
>    `MemberSet` 在触发 tick 定格,**不随后续结案增长**。
> 5. **成员互异**(2026-09-15 创意总监裁定):`MemberSet` 的三条 `CaseClosed` 须
>    `patient_id` 互不相同 —— 同一病人复诊三例不算「三起病例」,不得触发世界级疫情。

**边界:**

| 条件 | 结果 |
| ---- | ---- |
| 同病种已结案 < 3 | `ThirdClose = null`,不触发 |
| 恰 3 / 4+ 同 tick 达标 | **在触发 tick 发一次**;成员集取全序前 3(三元组全序 ⇒ **无平局**) |
| 第 4 例同病种 | 不重发;不进 `MemberSet` |
| **同一 `disease_id` 的两场叙事上不同的疫情** | **P0 视作同一个** —— 「严格精确相等」的已接受代价(2026-09-15 裁定) |
| 结案顺序 ≠ 立案顺序 | 无关 —— 只用结案全序 |
| **玩家空手连关三例** | **不可能** —— 无处置事件佐证(ADR-008 §四)且未勾选的病例**不可结案**(F-37.2) |
| **同一病人三诊同病种(成员不互异)** | **不触发** —— 同源图样要求**成员互异**(三条 CaseClosed 的 `patient_id` 互不相同;2026-09-15 创意总监裁定) |

### F-37.2 病例身份 · 全序 · 结案前置(Identity, Total Order, Close Precondition)

```
case_id     := ( Tick , Patient , Seq )   of 其 CaseOpened 事件
病例全序     := ( Tick , Patient , Seq )   of 其 CaseClosed 事件
跨流全序     := ( Tick , StreamPriority , Patient , Seq )   // ADR-008 §二
ThreadKey   := Patient
SortKey     := ( Patient , CaseOpened 的 (Tick, Seq) )
已处置(c)   := ∃ treatment event e ∈ 病史流: e.Patient = c.patient_id
               ∧ c.opened_tick ∈ [e.Tick, c.CloseTick]       // ADR-008 §四(B-2 修正:原 c.anchor.Tick)
可结案(c)   := c.state = 开 ∧ 已处置(c) ∧ 玩家已勾选「已处置」(规则八)
```

| 变量 | 范围 | 来源 | 说明 |
|------|------|------|------|
| `Seq` | int64 | ADR-006 Amendment A:**同一 `(Tick, Patient)` 内**单调 | **复用,不新造序号** |
| `case_id` | 三元组 | ADR-008 §二 | **可用、不折叠、无平局** |
| `Tick` | int64 | `ITickProvider`(ADR-005) | 全序的一部分 |
| `StreamPriority` | enum | ADR-008 §二:病史流 < 病例流 | 跨流排序用,病例内部恒为病例流 |
| `已处置(c)` | bool | ADR-008 §四 | **处置事件在病史流,窗口 = [CaseOpened.Tick, CloseTick]** |

**Output:** 唯一三元组;`SortKey` 全序;`已处置` / `可结案` 布尔。**无新计数器**
(沿用 ADR-006 Amendment B「从流重建」口径)。

> **⚠️ 这里正是复核 #1 / #6 的落点。**
> - `Seq` 只在同一 `(Tick, Patient)` 内单调 —— **单独当 `case_id` 会撞号**(复核 #1)。
>   故 `case_id = (Tick, Patient, Seq)`,三元组保证唯一且无平局;
>   **跨流全序还要补 `Patient`**(ADR-008 §二:同 tick 两位病人各有 `Seq=0`,缺 `Patient` 则平局)。
> - **「已处置」必须是结案的前置条件**(复核 #6)。否则玩家空手连关三例即可触发 Boss,
>   而「例例要有交代」(`game-concept.md` 支柱四铁律)当场作废。
>   「已处置」= **病史流存在 ≥1 条处置事件**(Tick ∈ `[CaseOpened.Tick, CloseTick]`)∧ 结案页勾选
>   (ADR-008 §四)。**不认处置的内容对不对**,对错仍是 53 的裁量;
>   **窗口限定堵复诊后门** —— 复诊第二例不能凭首诊的处置通过前置(Opus 复核 #4)。

**承重账 —— 病例流事件(复核 #2 / #3 / #5 的总闸,ADR-008 已落盘):**

> 37 引入 **`CaseOpened` / `CaseClosed` / `PatternRecognized`** 三个 `Kind`
> (另有 **`JudgmentRecorded` / `JudgmentRevised`** 判断记录类,ADR-008 §三)。
> 五者全部落**病例流**(ADR-008 §一,`IEventSink` 按 Kind 纯函数路由)。
> - `CaseOpened` 载荷快照 `(patient_id, opened_tick, disease_snapshot)`(复核 #1 / ADR-008 §三)。
>   *(2026-09-15 B-2 修正:原写「`anchor` 不透明」—— 该字段已拆为 `opened_tick`(立案 tick),
>   「不透明」措辞删除;`PatternRecognized` 的锚点另用 `anchor_case: CaseId`。)*
> - `CaseClosed` 载荷**快照本案 `disease_set`**(病种集可空,F-37.3)+ `treated` 证据快照
>   (复核 #2 / ADR-008 §四:病人后续新发病不得追溯改写旧案归属,计数突变)。
> - `PatternRecognized` 载荷是**加盐哈希键**(`SplitMix64(WorldSeed, "case-salt")`),
>   不是裸 `disease_id`(复核 #3 / ADR-008 §五:防御纵深,非保密层)。
> - 四类记录(病史 / 读数 / 判断 / 处置)**全部事件化**(复核 #5:任何一条不经
>   `IEventSink` 的状态都是主机迁移后的静默丢失)——
>   判断记录(落笔 / 改写)落**病例流**,**不违反 8 铁律②**(diagnosis-system.md:810
>   禁回写病史流的是玩法层记录);读数归 39,走 39 GDD 定。
>
> **ADR-007 §三 追加的五个 Kind,不含这三个。** **2026-09-15 已裁并落盘:
> `adr-008-case-event-stream`(✅ Accepted)。** 依赖它们的 AC 已解锁。**

### F-37.3 一案与病种的基数(Cardinality)

```
CaseDiseases(c) := c 的病程区间 overlap 到的病种集(快照于结案 → CaseClosed.disease_set)
若 |CaseDiseases(c)| = 0  → 该案【不入 F-37.1】
若 |CaseDiseases(c)| = 1  → 正常计入
若 |CaseDiseases(c)| ≥ 2  → 【一案进多组】—— 对每个 D ∈ CaseDiseases(c) 各计一次
```

> **纯伤情案无病种,不入检测。** 一人两病时一案进两组 —— 这不是漏洞,
> 是「同一个身体上两个病同时存在」的正确表达(9 的规则十 · D-8-6 共病)。
> `CaseClosed.disease_set` 是**集合**不是单值(ADR-008 §三)—— 与 F-37.1
> 的成员判据「`D ∈ CaseDiseases(c)`」字面一致。

### 待裁旋钮(数值归你)

| 旋钮 | 当前值 | 安全范围 | 调高 | 调低 |
| ---- | ---- | ---- | ---- | ---- |
| `PATTERN_THRESHOLD` | **3**(P0 手工编排) | ≥ 2 | 图样更难凑齐,「认出」更稀有,但可能永不触发 | 2 = 两例即同源,**太廉价,归纳变猜测** |
| 立案交互的判定半径 / 就诊触发条件 | *待裁* | — | 立案更宽松 | 急召出诊失去「你得走过去」的分量 |

> **37 只有这两个旋钮。** 没有概率、没有倍率、没有曲线 —— **这是刻意的**(规则十:P0 不发任何数值奖励)。

## Edge Cases

**D · 病例身份与全序（规则一 · 六 · F-37.2）：**

| 场景 | 结果 | 理据 |
| ---- | ---- | ---- |
| 两人同 tick 就诊 | `case_id = (Tick, Patient, Seq)` —— `Seq` 在同一 `(Tick, Patient)` 内单调，两人各有 `Seq=0`，**三元组不同** ⇒ 不撞号（复核 #1） | F-37.2 |
| 同一病人复诊（必在不同 tick） | 新病例，`case_id` 三元组不同；脉案上**串接**为一组（规则三） | ThreadKey |
| 玩家对同一例连点两次「结案」 | **幂等拒收**：第二条 `CaseClosed` 不产生事件（复核 #10） | 规则六-4 |
| 结案顺序 ≠ 立案顺序 | 无关 —— 只用**结案全序**（F-37.2），不用立案序 | F-37.1 |

**D · 病种与快照（规则九 · 十 · F-37.3）：**

| 场景 | 结果 | 理据 |
| ---- | ---- | ---- |
| 纯伤情病例（无病种） | **不入 F-37.1 检测** | F-37.3 |
| 病人结案后新发第二种病 | 不追溯改写 —— `CaseClosed` 载荷已**快照**本案 `disease_set`(病种集,ADR-008 §三,复核 #2) | F-37.2 |
| 一人同时患两病（共病） | 一案进**两组**（各计一次） | F-37.3 · 9 规则十 |
| `disease_id` 泄给呈现层 | **不可能** —— 交给 39 / 42 / 48 的 DTO **类型层面不含**该字段（规则九） | 静态可查 |

**D · 结案与后果（规则八 · 六 · S-8.3）：**

| 场景 | 结果 | 理据 |
| ---- | ---- | ---- |
| 玩家空手连关三例 | **不可能** —— 无处置事件佐证(ADR-008 §四)且未勾选的病例**不可结案**(F-37.2) | F-37.2 |

| 第四例同病种结案 | 不重发；不进 `MemberSet`（**冻结于触发 tick**，复核 #7） | F-37.1 |

| 场景 | 结果 | 理据 |
| ---- | ---- | ---- |
| 病人死亡但病例未结 | 病例照旧「开」—— 死亡只改病人的状态，不改病例 | 规则一 |

## Tuning Knobs

> **37 是全案旋钮最少的 Feature 系统** —— 没有概率、没有倍率、没有曲线。
> 这是刻意的(规则十:P0 不发任何数值奖励)。本节只列真正属于 37 的旋钮;
> 属于 52 / 8 / 9 的,只指过去,不重复登记(避免重复旋钮)。

### 属于 37 的旋钮(只有三个)

| 旋钮 | 当前值 | 安全范围 | 调高会怎样 | 调低会怎样 |
| ---- | ---- | ---- | ---- | ---- |
| **`PATTERN_THRESHOLD`** | **3**(P0 手工编排) | ≥ 2(**< 2 构建期拒绝**) | 图样更难凑齐,「认出」更稀有 —— 可能永远不触发 | 2 = 两例即同源,**太廉价,归纳退化成猜测** |
| **立案交互的判定半径** | *待裁* | — | 立案更宽松(远一点也能立案) | 急召出诊失去「你得走过去」的分量 |
| **就诊触发条件**(B 路径 / 自然就诊) | *待裁* | — | 更易触发就诊 | 病人可能在玩家离开后错过就诊窗口 |

### 与 37 相关但**归他人**的旋钮(不重复登记)

| 旋钮 | 归属 | 为什么 37 不持有 |
| ---- | ---- | ---- |
| 医疗事件模板的 `W_base` / 档位 / 触发方式 | **52** | 池条目与调度归 52(规则二裁定) |
| `disease_id` 注册表 / 曲线 / 阈值 | **9** | 病种归 9,37 只快照 |
| 门槛 / 阴性 / 状态机窗口 / 词表属性(C-1…C-8) | **8** | 状态机规则归 8 |

### 极端行为

- **`PATTERN_THRESHOLD` 调太高**:P0 三案链永不触发 → 支柱四的 Boss 在 P0 成为摆设
  (这正是 Open Questions「图样可辨识度」的风险面)。
- **立案半径调太小**:急召出诊「抵达 + 交互」立案点可能因半径过窄而无法触发 → 医疗事件模板空转。
- **就诊触发条件调太严**:B 路径(自然就诊)可能整个 P0 不出现 → 玩家只能靠事件注入见病人,
  锚点「案子一直在我这里」落空。

## Visual/Audio Requirements

> **37 是内容与生命周期的宿主,视觉/音频需求以「负面声明」为主** —— 与 8 / 9 的体例一致
> (`diagnosis-system.md` V-8.x · `disease-simulation.md` UI 铁律)。37 不新增任何视觉语言,
> 只约束「什么不能出现」,防止实现把 37 的内部真相(病种、同源)画出来。

| 事件 | 视觉反馈 | 音频反馈 | 优先级 |
| ---- | ---- | ---- | ---- |
| **结案** | 这一页被**合上**的拟物动作(纸页翻合 / 归档压平)—— **不得**出现任何「结算成功」的辉光、徽章、提示条 | 纸页合上的自然声响;**无**任何「成就达成」式音效 | 中 |
| **同源触发** | **无**任何玩家可见的呈现 —— 图样被辨认这件事**必须保持静默**(规则八:系统永不报「你答对了」)。世界的变化由 53 负责(疫区被压住 / 在场的人反应) | **无**任何提示音 | 高 |
| **立案** | 新病例在脉案上**多出一页**的拟物呈现 | 落纸声响 | 低 |
| **串接(复诊)** | 同一 `patient_id` 的多页用**线订**成一叠(P0 版沿用 #43 地图钉线的语汇)—— 不得用颜色 / 徽章 / 分组标签 | 无 | 中 |

> **硬约束**:任何一处呈现**不得**暴露 `disease_id` / 病种名 / 同源关系
> (规则九 · AC-37-15 / AC-37-16)。「这叠纸是三例同源」这件事,**只由玩家自己在纸上看出**。
