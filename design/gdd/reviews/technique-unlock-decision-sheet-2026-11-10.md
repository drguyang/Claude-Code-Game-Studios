## 1. A 类 —— 数值 / 内容(给值即落地,不改代码)

### A1 急救动作 2 / 3 的表行(**最值钱的一条**)

**现状**:动作表已外部化(T14),`assets/data/emergency_action.json` 今日**只有 1 行**(动作 0)。

```bash
grep -c '"action_id"' assets/data/emergency_action.json   # ⇒ 1
```

⇒ 玩家一旦被判定为「会清创缝合 / 蛇伤处置」,系统会**响亮拒绝**(`EmergencyActionTable.Require` 抛),
而不是静默用止血包扎的参数。

**要给的**:动作 2(清创缝合)/ 动作 3(蛇伤处置)各一行 —— 字段列表:

| 字段 | 含义 | 动作 0 的现值(参照) |
|---|---|---|
| `polarity` | 极性枚举序数 | `2`(平) |
| `base_potency` | 基础效力(Fix 字符串,`"1"` = 1.0) | `"1"` |
| `mag_threshold` | 幅度门阈值(整数,1…65536) | `50` |
| `min_edges` | 最小边数 | `1` |
| `min_hold_ticks` | 最小保持 tick | `5` |
| `half_life_ticks` | 衰减半衰期(tick,≥1) | `100` |
| `duration_ticks` | 持续 tick | `200` |
| `result_mul` | 三档,按 Missed/Weak/Applied | 必须是 `["1/4","1/2","1"]`(AC-10-16 构建期钉死) |

**选项**

| # | 选项 | 后果 |
|---|---|---|
| A1-a | 给两行数值 | 玩家能做清创 / 蛇伤;**但还需要 B2**(选动作的交互),否则仍然做不到 |
| A1-b | 只给动作 2 | 破伤风 / 咬伤 / 钝击三处技法可用,蛇毒仍缺 |
| A1-c | 先不给 | 现状;两门技法的投放会命中「有技法、无动作」的响亮拒绝 |

**建议**:A1-a,与 B2 同批裁 —— 单给数值而没交互,玩家体验不变。

### A2 R1 投放门槛:解锁技法 10 之前病种数到不了 3

**现状**(T11 实测,`draw_surface_audit_test`):

```
起步集 {0,1} ⇒ 可投放 6 行 = 5 伤 + 1 病(而那 1 病是「未声明」副作用,不是设计意图)
技法 0 → 4 伤 · 技法 1 → 0 行 · 技法 2 → 3 · 技法 3 → 1 · 技法 10 → 5 病 · 11 → 1 · 12 → 1
```

map §8 R1 的处置写着「每章解锁后复核『可投放病种数 ≥ 3』」—— **当前内容不满足**:
解锁到技法 3 时才有 3 个病种。

**选项**

| # | 选项 | 后果 |
|---|---|---|
| A2-a | **补数据**:给早期技法(0/1/2)挂更多病种 | 前期病种密度上来;但要动 `treatable_by` 与病种归属,可能牵连 `handle` 派生(见下注) |
| A2-b | **调门槛**:R1 由「≥3 病种」改为「≥2」或「≥1」 | 一处改口径;但 P0 前期仍然只有伤情,手感问题不解 |
| A2-c | **接受现状**:P0 前期以伤情为主,病种随技法 10 解锁才铺开 | 零成本;需要你确认「前期不看病、只看伤」是想要的节奏 |

⚠️ **A2-a 有一个陷阱**:给伤情填 `causal` 极性会把它们的 `handle` 从 `symptomatic_only` 改判成
`causal`,而 GDD `:294` 把 `none` 钉死为「仅 DIS_TETANUS」、`AC-43` 逐病种断言 ——
那是**改裁决**,不是补数据。所以补数据时极性必须留在 `symptomatic`。

**建议**:A2-c 或 A2-b。A2-a 是最大的内容工程,且会触碰 handle 语义。

## 2. B 类 —— 机制裁决(定规则,我实现)

### B1 章节状态:钩子病例的「每章 1 例」今天是**整局 1 例**

**现状**:`HookCasePolicy.MaxPerChapter = 1`,但**运行期没有「章」这个概念**
(无 GDD 字段 / 无存档字段 / 无事件)⇒ `HookCaseLedger` 只数全局,配额退化成整局 1 例。

**要定的**:章是什么、从哪来。

| # | 选项 | 后果 |
|---|---|---|
| B1-a | **由 5 的时间参数推导**(如每 `TICKS_PER_SEASON` 一章) | 零新数据;但「一章 = 一季」是否成立要你确认,且章与叙事进度是否同步存疑 |

## 4. 建议的处理顺序

1. **B1 = d**(P0 不做章节)—— 零成本关掉一条。
2. **A3**(技法 1 归宿)+ **A6**(奇遇位置)—— 两条都是短决策,能立刻改数据。
3. **A1 + A4 + A5-a + B2 + C3 同批** —— 这是唯一能让链条**真正转起来**的一批:
   「处置病人 → 学会技法 → 手册缺页消失 → 能做新动作」。
   缺任何一环,其余环节的行为都不可见。
4. **A2** 与 **C1 / C2** 留到最后 —— 它们是节奏与呈现问题,不是阻塞。

> **一句话**:代码侧的管道已经接到头。**要让这条链在游戏里看得见,最小的一组裁定是
> A1 + A4 + A5-a + B2 + C3 + A3。**
