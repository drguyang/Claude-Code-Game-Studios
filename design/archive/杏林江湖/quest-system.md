## 1. 概述 Overview

本系统是《杏林江湖》的**叙事骨架与推进引擎**：它把 `story-bible.md` 的十卷史实叙事，翻译成一条**玩家可走、可存、可核对**的确定性流程。它做四件事：①**编排卷与章的顺序**（十卷固定脊，卷内病例关/支线章可分支）；②**管理剧情 flag 账本**（对话与关卡产出的 `StoryFlag` 在此登记、在此被门槛消费）；③**核对伏笔/回收**（15 条伏笔的埋设与回收位，关键 5 条带机械落点）；④**调度队伍聚散**（加入/离队/归队/殉职的骨干节点固定，玩家改变的是"以何种姿态经历"）。

本系统**不设计单章内容**——病例关内的主节拍与探索节点归 `level-system.md`（#6）；它只决定**哪一章在什么时候出现、门槛是什么、走完这卷后世界变成什么样**。它**不产出对白**——对白归 `dialogue-system.md`（#5）；它只**消费**对话产出的 `StoryFlag` / `BondDelta` / `EpiphanyEvent`，并**下发**"当前情境"给对话。

设计立场（承 `story-bible.md` §2）：历史是**不可改的**——卷三的疫情一定被扑灭，卷八的废止案一定被暂时搁置，卷九的大疫一定暴发，苏晚棠一定在救人里殉职。玩家能改变的，是**代价、关系、理解与传承**。这不是"玩家无力"，而是把主题做进机制：**医学的胜负不写在历史里，写在每一个"被算进去的人"身上。**

## 2. 玩家幻想 Player Fantasy

**"我不是在重写历史，我是在经历它——历史记住了日期，我记得那些人。"**

玩家推动的不是一张"改天换地的分支图"，而是一段**无法回头、只能前行的医术生涯**：他知道大疫会来，却拦不住；知道她会走，却留不住；能做的只是把每一次救治、每一句话、每一分信任，做到当下一刻的极限。终局回看《杏林汇通录》时，真正属于玩家的，是**那张图谱的形状**与**一路上人名清单的厚度**，而不是"历史被我改成了什么样"。

对资深玩家（论道层）：幻想是"**在既定的史实里，走出只属于我的那条缝**"——同一个史实锚点，不同的队伍构成、不同的伏笔回收、不同的关系档位，拼出不同的结局文本与图谱密度。

## 3. 详细规则 Detailed Rules

### 3.1 系统定位与数据边界

| 归属 | 拥有 | 不拥有 |
|---|---|---|
| **本系统 #7** | 卷 → 章 的**序列与门槛**；`StoryFlag` 账本；伏笔/回收账本；聚散调度；卷末结算；关系层分支 | 单章内的主节拍（归 #6）；对白（归 #5）；战斗结算（归 #4） |
| **关卡系统 #6** | 单章（病例关）内的主节拍、探索节点、代价三通道、疫情单向接口 | 章与章之间/卷与卷之间的顺序与门槛 |
| **对话系统 #5** | 场景、节拍、心声/发问、对白文本 | flag 的**登记与消费**（本系统登记并消费） |

**边界钉死**：#6 的 `TaskSystem` 接口只收「章配置 id + 上下文」、只回「章完成 + 结果包」。

```
// #7 → #6（下发）
ChapterRequest = { chapterId, context: { roster, revealedAxes, flags, formationSetup } }
// #6 → #7（回传）
ChapterResult  = { chapterId, completed, rating, trustDelta, flags: [StoryFlag], epidemicHandoff?, foreshadowDrops: [ForeshadowId] }
```

### 3.2 三层剧本结构：卷 → 章 → 节拍

| 层 | 拥有者 | 原子性 | 说明 |
|---|---|---|---|
| **卷 Volume** | 本系统 | 一个史实锚点 | 十卷，顺序固定（见 §3.3） |
| **章 Chapter** | 本系统 | 一次结算 | 病例关（主线章）或支线章；是玩家可见的"一个故事段落" |
| **节拍 Beat** | 关卡系统 #6 | 一次推进 | 章内的诊/问/治/变/结（`level-system.md` §3） |

**层级不可越位**：章**不直接**观测节拍；它只收 #6 回传的 `ChapterResult`。这保证"节拍层改玩法"与"章层改叙事"可以独立迭代。

### 3.3 卷脊：十卷固定顺序

十卷**严格线性**（`story-bible.md` §七）。卷脊记录（数据驱动，非硬编码）：

| 卷 | 史实锚点（固定不变量） | 队伍变动（骨干） | 本卷大顿悟 | 主要形式 |
|---|---|---|---|---|
| 序 / 一 · 归舟 | 废科举(1905) | 主角登场 | "旧的……只是还没被听懂" | 叙事引入 · 病例推理入门 |
| 二 · 旧医 | 新旧学堂并行 | **陆九针加入** | "'看不见'不等于'不存在'" | 完整病例推理 |
| 三 · 疫城 | **东北大鼠疫扑灭(1911)** | **柳希白加入** | "医学的敌人是死亡，不是另一种医学" | 疫情资源博弈 + 推理 |
| 四 · 杏林血 | 漏列中医案(1912) | **苏晚棠加入** | "争的是两个都不愿承认自己不全的人" | 门户论辩 · 回合策略战 |
| 五 · 论战 | 协和筹建 · 衷中参西(1918) | **陈九章加入** | "赢的是让道理被敌人之外的人听懂" | 论战 · 说服机制 |
| 六 · 气海 | 大流感 · 五四(1918–19) | **清和加入；苏晚棠离队** | "'看见'是承认自己一直看漏了什么" | 顿悟谜题 · 心象探索 |
| 七 · 邪疫 | 军阀混战 · 霍乱(1920–24) | **苏晚棠归队** | "复仇解决不了死亡" | 战地危机管理 |
| 八 · 废止 | **废止案暂缓(1929)** | （无进出，关系最紧） | "最深的胜利是让自己的道理被听懂" | 论战白热化 · 无战斗收束 |
| 九 · 汇通 | **大疫暴发(1929)** | **苏晚棠殉职** | "把每一个'不算数'的人都算进去" | 总决战 · 综合玩法 |
| 十 · 种子 | 国医存续（史实） | 各归其所 | "传承是把问题交出去" | 无战斗 · 收束传薪 |

> 卷脊是**只读真源**：任何系统不得改写卷顺序或史实锚点。改动须走 design-change 流程（`story-bible.md` 附）。

### 3.4 章：病例关（主线）与支线章

| 章类型 | 必需性 | 阻塞卷推进 | 产出 | 竖直切片范围 |
|---|---|---|---|---|
| **主线章**（病例关） | **必需** | **是** | 评级、`TrustDelta`、主线 `StoryFlag`、伏笔投放 | 卷 1–3 全部实现 |
| **支线章**（人物 / 伏笔） | 可选 | 否 | `BondDelta`、关键伏笔回收、图谱碎片 | 卷 1–3 各 1 个示例 |

- **支线章不阻塞主线**：玩家可整卷跳过支线章直推主线（与 `level-system.md` §5"探索节点可跳过"同构——**探不探是权衡，不是关卡**）。
- **支线章的价值**：回收关键伏笔、提升关系档位、补全图谱——**跳过的代价是理解不全（收束文本更薄），而非失败**。
- **每章只结算一次**（§4.6 幂等）。

### 3.5 剧情 flag 账本 StoryFlag

- **登记**：任何系统产出的 `StoryFlag { flagId, value }`（对话 `dialogue-system.md` §3.10、关卡 `level-system.md`）一律交本系统**登记入账**，去重按 `flagId`（后者覆盖前者取最新 `value`）。
- **消费**：门槛（§3.8）、分支（§3.9）、关系档位（§3.10）**只读**本账本，不各自另立状态。
- **可见性**：flag 对玩家**不可见**（不显示"你获得了 flag"），其效果只通过**世界状态变化**（谁在场、能问什么、走哪条支线）被感知。
- **命名空间**：`vol{c}.{chapter}.{slug}`（如 `vol3.epilogue.lifesaved`）——保证跨卷不冲突、便于存档核对。

### 3.6 伏笔账本 Foreshadow Ledger

`story-bible.md` §九的 15 条伏笔，按**是否有机械落点**分两类：

**关键伏笔（5 条，有机械落点）**——回收时**点亮图谱节点 / 免费生成「通」/ 解锁论战铁证**：

| # | 伏笔 | 埋 → 收 | 机械落点 |
|---|---|---|---|
| 1 | 祖父遗稿"陆九针"三字 | 卷一 → 卷四 | 回收时解锁图谱节点（陆九针 × 苏问岐）；触发卷四大顿悟事件 |
| 3 | 主角的病理学笔记 | 卷一 → 卷六 | 卷六"投炭盆"= **顿悟事件** → 免费生成一条「通」（`progression-system.md` §3.6） |
| 7 | 苏问岐遗稿证词（指向霍崇光） | 卷四 → 卷八 | 卷八论战**铁证 gate**：未回收则终局说服缺一张关键牌（喂 #8） |
| 8 | 苏晚棠对霍崇光的仇恨 | 卷四 → 卷六/七 | **离队/归队**的关系层门槛来源之一（§3.10） |
| 10 | 陈九章推算的大疫 | 卷五 → 卷七/九 | 卷七预警 flag → 解锁卷九"提前布防"支线（**不改变大疫必发生**） |

**叙事伏笔（10 条，纯账本）**——只供作者核对与 QA 校验，**不产生系统输出**：其余条目（#2 母亲药茶、#4 陆九针救错人、#5 柳希白数字、#6 顾慎行签字、#9 差点成为霍崇光、#11 清和不动心、#12 战地孩子、#13 被忽略的病人、#14 请愿病重代表、#15 书名）登记**埋设/回收位**，供终局文本按"已回收数"分级呈现。

- **可错过**：关键伏笔若**未回收**（前置 flag 未集齐），不报错、不阻塞——只是该落点**不点亮**，终局文本更薄（§4.3）。
- **不可逆**：埋设位一旦过卷、其回收前置未满足，即视为**永久错过**（对应真实叙事的"当时没在意"）。

### 3.7 聚散调度 Roster Schedule

- **骨干固定**：卷脊表的队伍变动（陆九针加入卷二、柳希白卷三、苏晚棠卷四、陈九章卷五、清和卷六、**苏晚棠卷六离队 / 卷七归队 / 卷九殉职**）为**固定事件**，必发生、不可跳过。
- **落在关卡边界**：所有 `roster` 迁移由本系统在**章与章之间**下发（`party-system.md` §3.7"队伍变动只在关卡边界发生"）；战斗中途不增删。
- **主角常驻**：沈砚之永不进入 `未加入/离队`（`party-system.md` §3.7）。
- **关系层分支**：事件**是否发生**不可改，但**如何发生**（在哪一章触发、伴随何种对白、附加多少 `BondDelta`、留下什么 flag）由关系档位决定（§3.10）。

### 3.8 门槛 Gate（确定性）

卷/章推进的门槛**全部确定性**，无随机、无检定：

```
Gate(x) = ∧ conditions
condition 种类：
  chapterDone(cid)       → 前置章已完成
  flagSet(flagId, op)    → 剧情 flag 满足比较（=, ≥, ∈）
  bondGE(char, thr)      → 羁绊 ≥ 阈值（50 / 75，与 #5 §3.7 同）
  convergenceGE(rate)    → 图谱汇通率 ≥ 阈值（`progression-system.md` §4.4）
  rosterIs(char, state)  → 某角色处于某聚散态
```

- **未满足门槛**：推进被**拒绝**，系统提示"还差什么"（如"尚未与陆九针深谈"）；玩家须先补（走支线章 / 提升羁绊 / 回收伏笔）。
- **门槛只读不写**：Gate **不产出** flag（避免"为过门槛而生成状态"的循环）。

### 3.9 关内分支与再汇合 Branch & Merge

- **分支**：章内可设**分支点 BranchPoint**——玩家的选择（对话入心、病例处置、资源取舍）产出不同 `StoryFlag`，改变**过程、代价、关系**。
- **汇合**：卷内所有分支在**卷末汇合点 MergePoint** 收束回**同一史实节点**（`HistoricalInvariant`，§4.5）。**分支改变的是"怎么走到那里"，不是"走到哪里"。**
- **分支不叠加爆炸**：采用**分支-再汇合**（branch-and-remerge），而非组合爆炸——分支态只以 flag **局部**存在，汇合点后不携带未回收的分支。这保证十卷的剧本规模**线性可控**。
- **关系层分支例外**：唯一"跨卷携带"的分支是**关系档位**（§3.10）与**关键伏笔回收数**——它们是玩家能动性的**唯一长期账**。

### 3.10 关系层分支 Resolution（同一事件的多姿态）

骨干事件不变，但**呈现姿态**分档：

| 档位 | 条件 | 效果（只改文本与附加量，**不改事件是否发生**） |
|---|---|---|
| **0 · 陌路** | Bond < 25 或无共同经历 flag | 事件以最冷的方式呈现；附加 `BondDelta = 0` |
| **1 · 同袍** | Bond ≥ 25 | 基础文本；附加 `BondDelta = +5` |
| **2 · 知己** | Bond ≥ 50 | 加深文本；附加 `BondDelta = +10`；解锁专属支线章 |
| **3 · 生死之交** | Bond ≥ 75 **且** `flagSet(sharedTrial)` | 最深文本；附加 `BondDelta = +15`；解锁终局专属对白 |

> 阈值 25 / 50 / 75 与 `party-system.md` §3.8 名分档、`dialogue-system.md` §3.7 关系门**同源**；`sharedTrial` 指卷内共同经历的重大关卡 flag。

### 3.11 卷末结算 Volume Settlement

每卷末（`MergePoint` 之后）执行一次**确定性结算**：

1. **队伍落定**：执行本卷的骨干聚散事件，`roster` 状态写入持久态。
2. **伏笔核对**：登记本卷埋设/回收，更新 `ForeshadowState`。
3. **代价归档**：本卷各章 `TrustDelta` / 评级 / 死伤规模（§4.5）汇总入卷档案。
4. **图谱核对**：检查汇通率（喂 §4.4 的卷门槛）。
5. **大顿悟结算**：本卷大顿悟 → `EpiphanyEvent`（`progression-system.md` §3.6，免费一条「通」）。
6. **写快照**：产出 `QuestSaveSnapshot`（§4.7），交存档系统 #10。

### 3.12 双终局与图谱封笔（卷九 / 卷十）

- **卷九双终局**：两场并列终局——①**与霍崇光的理念之战**（玩法：以"不可量化、个体化"的医道破其"数据节奏"，`combat-system.md` §4.10）；②**与疫病的生死之战**（苏晚棠殉职即在其中）。二者**皆必发生**；玩家的**关系档位**与**关键伏笔回收数**决定终局文本的厚度与《杏林汇通录》的完成度。
- **卷十图谱封笔**：委托 `progression-system.md` §3.8——玩家把最珍视的若干「通」标注为"传给后人"。本系统只**触发**该流程并记录结果，不重定义。

## 4. 公式 Formulas

### 4.1 卷推进条件 VolumeGate

```
VolumeGate(v+1) = ∧ {
  allChaptersDone(v),                 // 本卷全部主线章完成
  epiphanyTriggered(v),               // 本卷大顿悟事件已触发
  convergenceGE(ConvMin[v])           // 图谱汇通率 ≥ 本卷阈值（可选门槛，见 §7）
}
ConvMin[v] = 卷配置（默认：序–卷三 0.0；卷四起 0.2，逐卷 +0.05，上限 0.5）
```

| 变量 | 范围 | 来源 | 说明 |
|---|---|---|---|
| allChaptersDone | bool | 章账本 | 本卷主线章是否全完成 |
| epiphanyTriggered | bool | 卷脊 | 大顿悟事件是否已触发 |
| ConvMin | 0.0–0.5 | 卷配置 | 卷级汇通率门槛（教学期 0，含卷四后的软墙） |

**示例**：卷三完成（3 个主线章 + 大顿悟），`ConvMin[3]=0.0` → `VolumeGate(卷四)=true`。卷四若 `ConvMin[4]=0.2` 而汇通率 0.15 → **拒绝推进**，提示"你的《杏林汇通录》还太薄"。
**预期输出**：bool；单调（已通过的卷不回退）。

### 4.2 章完成判定 ChapterComplete

```
ChapterComplete(c) = c.result.completed ∧ c.settled = false → settle(c)
settle(c): applied = true; flags ← merge(result.flags); trustDelta ← result.trustDelta
```

| 变量 | 类型 | 说明 |
|---|---|---|
| completed | bool | #6 回传的章完成标记 |
| settled | bool | 本系统是否已结算（幂等，见 §4.6） |

**说明**：`settle` **只执行一次**；重复进入不重复结算（§4.6）。

### 4.3 伏笔回收判定 ForeshadowCollected

```
ForeshadowCollected(f) = f.mechanical ∧ (f.preFlags ⊨ flags)     // 机械伏笔：跑机械落点
NarrativeCollected(f)  = f.revealed                              // 叙事伏笔：只记名义
RecoveredCount = |{ f : f.mechanical ∧ ForeshadowCollected(f) }| + |{ f : narrative ∧ NarrativeCollected(f) }|
```

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| mechanical | bool | — | 是否关键（机械）伏笔（§3.6，共 5 条） |
| preFlags | set | — | 回收所需前置 flag |
| RecoveredCount | int | 0–15 | 总回收数（关键 5 + 叙事 10），喂终局文本分级 |

**示例**：关键伏笔 #7（卷八铁证）的 `preFlags = {vol4.evidence.obtained}`；若卷四未回收 → 卷八 `ForeshadowCollected(#7)=false` → 论战缺铁证牌，`RecoveredCount` 少 1。
**未回收不报错**：仅落点不点亮（§3.6）。

### 4.4 关系层分支档位 ResolutionTier

```
ResolutionTier(char, event) =
  3  if bond(char) ≥ 75 ∧ flagSet(sharedTrial(char))
  2  elif bond(char) ≥ 50
  1  elif bond(char) ≥ 25
  0  else

附加量 BonusBondDelta(tier) = { 0: 0, 1: +5, 2: +10, 3: +15 }[tier]
```

| 变量 | 范围 | 说明 |
|---|---|---|
| bond(char) | 0–100 | 羁绊（`party-system.md` §3.8） |
| sharedTrial | flag | 共同经历 flag（卷内重大关卡） |
| tier | 0–3 | 档位；**只改文本与附加 BondDelta，不改事件发生** |

**示例**：卷六苏晚棠离队事件**必发生**；若其 Bond=60（tier 2）→ 离队对白走"知己"文本、附加 `BondDelta=+10`；若 Bond=10（tier 0）→ 走"陌路"文本、附加 0。**事件本身两种情况都不变。**

### 4.5 史实不变量与玩家变量 HistoricalInvariant

```
Fixed（不可改，史实锚点 + 骨干）:
  { 疫情扑灭(卷三), 废止案暂缓(卷八), 大疫暴发(卷九), 苏晚棠殉职(卷九) }

Variable（玩家可改的"怎么经历"）:
  死伤规模 Severity        ∈ [S_min, S_max]     // 由代价三通道决定（level §4.4）
  关系档位 ResolutionTier  ∈ {0,1,2,3}          // §4.4
  关键伏笔回收 RecoveredKey ∈ [0,5]              // §4.3
  顿悟获得 EpiphanyAcquired ∈ {true,false}       // 未获得可后补（花 IP）
```

| 变量 | 范围 | 决定者 |
|---|---|---|
| Severity | [S_min, S_max] | 本卷各章 `VitalRate` / `ShiftCount` 汇总 |
| ResolutionTier | 0–3 | 羁绊 + flag（§4.4） |
| RecoveredKey | 0–5 | 关键伏笔回收数（§4.3） |
| EpiphanyAcquired | bool | 卷末大顿悟是否触发（§3.11） |

**钉死**：`Fixed` 集合**任何系统不得改写**；玩家能动性**只在 `Variable` 集合内**。这是"史实不可改，只改经历方式"的形式化落地。

### 4.6 幂等与去重 Idempotency

```
settle(章/事件) 幂等：applyCount(id) ≤ 1
flag 覆盖：同 flagId 后写覆盖前写（取最新 value）
伏笔：埋/收各记一次，重复触发视为已记
BondDelta：单场 ≤ +15；单章累计 ≤ +30（与 #5 §4.7 单场上限同源）
```

**示例**：玩家反复进出某支线章 → `settle(chapterX)` 第二次被拒（`applied=true` 已存在），不重复发 flag / 伏笔 / `BondDelta`。

### 4.7 存档快照 QuestSaveSnapshot

```
QuestSaveSnapshot:
  volumeId, chapterId
  flagLedger:   Map<flagId, value>
  foreshadow:   {埋设: Set, 回收: Set}
  rosterState:  Map<charId, roster>       // party §3.7 五态
  volumeArchive: [{ severity, trustDelta, rating }]   // 卷档案
  settledIds:   Set<id>                   // 幂等账
```

| 字段 | 说明 |
|---|---|
| flagLedger | 全量剧情 flag（含 value） |
| foreshadow | 伏笔埋/收集合（§3.6） |
| rosterState | 聚散态（持久） |
| settledIds | 已结算 id 集，保证读档后不重发 |

**往返一致**：本快照可**完整存档 / 读档**，往返后所有门槛/分支判定结果不变。

## 5. 边界情况 Edge Cases

| 场景 | 会发生什么 | 理由 |
|---|---|---|
| **玩家想跳卷** | **拒绝**：卷脊严格线性，`VolumeGate(v+1)` 未满足不可进入下一卷 | 史实锚点不可乱序（§3.3） |
| **玩家拒绝经历骨干事件**（如不想让苏晚棠离队） | **不可拒绝**：骨干事件由卷末结算强制下发，无"跳过"入口 | 史实不可改（§4.5） |
| **关键伏笔永久错过**（过卷后前置 flag 未满足） | **不报错、不阻塞**：该落点不点亮，`RecoveredCount` 少 1，终局文本更薄 | 叙事的"当时没在意"（§3.6） |
| **支线章全跳过** | **允许**：主线照常推进；代价是关系档位更低、图谱更薄、终局文本更薄 | 探不探是权衡（§3.4） |
| **同一章重复进入** | 首次结算后 `settle` 幂等；再进入**只重看文本**，不重发 flag / 伏笔 / BondDelta | 幂等（§4.6） |
| **门槛条件变得不可满足**（如需要 Bond≥50 但该角色已殉职） | 卷配置**校验期**即拒绝：殉职角色的 `bondGE` 门槛会被配置检查标红；运行时该门槛**恒真**（视为"已无可提升"，不再阻塞） | 防止死锁（§3.8 / §4.5） |
| **汇通率门槛卡主玩家**（卷四起 ConvMin>0） | 提示"图谱还太薄"，引导玩家走支线章 / 主动连线；**不判负** | 软墙非硬墙（§4.1） |
| **关系档位在事件后变化**（如离队期间 Bond 冻结） | 离队期 Bond **冻结**（`party-system.md` §3.7）；档位取**事件触发时**的 Bond 快照，事后变化不追溯改写该事件文本 | 事件文本一旦经历即固化 |
| **卷末大顿悟未触发**（条件未满足） | `VolumeGate` 拒绝推进；提示"你还没有真正想通这一卷"；玩家需补足前置（走支线 / 回收伏笔） | 顿悟是卷推进必需项（§4.1） |
| **存档于章中途 / 战斗中途** | 章中途：可在**节拍边界**由 #6 落盘；战斗中途**不可存**（`level-system.md` §5）；本系统只在**章边界**写 `QuestSaveSnapshot` | 状态一致性（§4.7） |
| **读档后重新触发已结算事件** | 由 `settledIds` 拦截：已结算 id 直接跳过 | 幂等账（§4.7） |
| **世界线冲突：分支 flag 与史实不变量矛盾** | **史实胜**：`Fixed` 集合优先，任何分支 flag 不得改写 `HistoricalInvariant`；配置期校验拒绝矛盾配置 | 史实不可改（§4.5） |
| **【切片】后续卷系统未实现**（卷四起） | 卷 1–3 完整实现；卷四起卷脊数据**存在但标记 `stub`**，`VolumeGate` 到卷三末**正常收束**，不进入未实现区 | 竖直切片边界 |

## 7. 调参旋钮 Tuning Knobs

| 旋钮 | 当前值 | 安全范围 | 增大影响 | 减小影响 |
|---|---|---|---|---|
| **卷级汇通率门槛 `ConvMin`** | 卷四起 0.2，逐卷 +0.05（上限 0.5）；教学期 0 | 0.0–0.5 | 双用要求更硬、更早逼迫合方 | 更宽容、允许单一流派更久 |
| **关系档位阈值**（25 / 50 / 75） | 25 / 50 / 75 | 0–100 | 高档更难达、关系分支更稀有 | 更易达、关系分支更常见 |
| **档位附加 BondDelta**（0/+5/+10/+15） | 0 / 5 / 10 / 15 | 0–20 | 关系反馈更强 | 关系推进更慢 |
| **关键伏笔机械落点开关** | 5 条全开 | 0–5 | 更多伏笔影响图谱/论战 | 关键伏笔退回纯账本 |

| **死伤规模区间 [S_min, S_max]** | 卷配置 | 0.0–1.0 | 软失败代价更重、史实更"惨烈" | 代价更轻 |

## 8. 验收标准 Acceptance Criteria

- [ ] **卷脊线性**：尝试乱序进入卷（跳过前置卷）被**拒绝**；`VolumeGate` 逐卷可测（§4.1）。
- [ ] **史实不变量不可改**：`Fixed` 集合（疫情扑灭/废止案暂缓/大疫暴发/苏晚棠殉职）在任意分支下**恒成立**；配置校验拒绝与之矛盾的配置（守卫检查，§4.5）。
- [ ] **骨干聚散必发生**：陆九针/柳希白/苏晚棠/陈九章/清和加入、苏晚棠离队/归队/殉职——各在指定卷触发，**无跳过入口**（守卫检查，§3.7）。
- [ ] **关系层分支只改姿态**：同一次骨干事件，`ResolutionTier` 不同（0–3）时**文本与附加 BondDelta 不同**，但**事件的 `occurred` 恒为 true**（两侧可测，§4.4）。
- [ ] **分支-再汇合**：卷内任一分支路径，在卷末 `MergePoint` 均收束到**同一 `HistoricalInvariant`**；未回收分支 flag 不跨卷携带（守卫检查，§3.9）。
- [ ] **门槛确定性**：Gate 的全部条件（`chapterDone`/`flagSet`/`bondGE`/`convergenceGE`/`rosterIs`）皆确定性判定，**无随机**（守卫检查，§3.8）。
- [ ] **门槛只读**：推进被拒绝时**不产生**新 flag（守卫检查，§3.8）。
- [ ] **本系统零随机**：除战斗内"问"诊法（战斗系统托管）外，本系统全部判定确定性（回归测试：同输入连测 100 次，输出一致）。
- [ ] **关键伏笔回收判定**：关键伏笔 #1/#3/#7/#8/#10 的 `preFlags` 满足即回收、落点点亮；不满足则**不报错、不阻塞**，`RecoveredCount` 少 1（两侧可测，§4.3）。
- [ ] **关键伏笔机械落点**：#7 未回收 → 卷八论战**缺铁证牌**（喂 #8）；#3 回收 → **免费生成一条「通」**（与 `progression-system.md` §3.6 一致，守卫检查）。
- [ ] **叙事伏笔为账本**：其余 10 条不产生系统输出，只登记埋/收（守卫检查，§3.6）。
- [ ] **幂等结算**：同一章/事件重复进入，`settle` 只生效一次，不重发 flag / 伏笔 / `BondDelta`（守卫检查，§4.6）。
- [ ] **flag 去重覆盖**：同 `flagId` 多次写入取**最新 value**（守卫检查）。
- [ ] **单章 BondDelta 上限**：单章累计 `ΔBond ≤ +30`；单场 ≤ +15（与 #5 §4.7 一致，守卫检查）。
- [ ] **汇通率门槛**：`ConvMin` 未达时卷推进被拒绝并提示"图谱还太薄"；**不判负**（两侧可测，§4.1）。
- [ ] **存档往返**：`QuestSaveSnapshot`（volumeId/chapterId/flagLedger/foreshadow/rosterState/volumeArchive/settledIds）可**完整存档 / 读档**，往返后门槛与分支判定结果**不变**（往返一致，§4.7）。
- [ ] **读档不重发**：读档后重新触发已结算事件被 `settledIds` 拦截（守卫检查，§4.7）。
- [ ] **不可满足门槛不死锁**：殉职角色的 `bondGE` 门槛在运行时**恒真**（不再阻塞）；配置期校验标红（用例，§3.8）。
- [ ] **支线章可跳过**：整卷跳过全部支线章，主线仍可收束；代价体现为关系档位更低 / 图谱更薄（守卫检查，§3.4）。
- [ ] **切片边界**：卷 1–3 完整实现；卷三末 `VolumeGate` 正常收束，不进入 `stub` 卷区（守卫检查）。
- [ ] **双终局必发生**：卷九两场终局（霍崇光理念之战 / 疫病生死之战）在任意分支下**皆发生**；玩家能动性只影响终局文本厚度与图谱完成度（守卫检查，§3.12）。
- [ ] **图谱封笔委托**：卷十只**触发** `progression-system.md` §3.8，不重定义其规则（守卫检查）。
- [ ] 所有数值（卷脊、章表、门槛、伏笔、档位阈值）来自外部配置，实现中**无硬编码**。
