## 2. 两条「选完之后才查出来」的事实

### 2.1 A1 实际是 3 行,不是 2 行

```bash
python3 -c "import json;d=json.load(open('assets/data/emergency_action.json'));print(len(d['rows']),[r['action_id'] for r in d['rows']])"
# ⇒ 1 [0]
```

动作表今日**只有动作 0**。清单只点了 2/3,是因为技法 1 覆盖 0 行、永远调不出来;
而 A2「补数据」一旦给技法 1 挂上病种,动作 1 立刻可达 ⇒ `EmergencyActionTable.Require(1)`
会在第一笔处置上**响亮拒绝**。⇒ A1 内容批必须给 **1 / 2 / 3 三行**。

### 2.2 A3-b 单独做**解不掉**那条豁免

`TechniqueCoverageExemptions` 里原写:

> 出口二选一 —— ① 给某个病种挂上它;② 把它从 `StartingTechniques` 移出。**任一落地后删本行。**

**这句是错的。** 缺口门的判据是**集合相等**(`technique_side_gap_gate_test` ①:
「零覆盖集 == 豁免键集」),而移出起步集**不改覆盖** —— 技法 1 仍然 0 行。
照那句话删,门当场转红。本批已就地订正该段文字,并写明「唯一出口 = ①」。

## 3. 各项的实现判断(逐条)

### 3.1 B1-b:章号必须是**绝对量**

载荷 `(chapter, source_id)`,其中 `chapter` = **推进之后**的章号。

- 若存**增量**,「从流重构当前章」就要逐条累加 —— 重放期任一条被折叠 / 丢弃,
  章号就**静默漂移**;
- 存**绝对量** ⇒ 「取最后一条」,天然可重建且幂等可判。

值域门只在**写者**侧(`ChapterAdvanceWriter`):`chapter < 1` 抛、倒退抛、同章 no-op。
⚠️ 起草期一度在**解码侧**也加了 `chapter < 1` 拒收,**实测当场打破**
`payload_encoder_test` / `payload_decoder_test` 的全 Kind 往返夹具(它们用
`Activator.CreateInstance` 造默认实参 ⇒ chapter = 0)。已撤回,并立判据
`test_valueDomain_gateIsAtWriter_notDecoder` 钉住这条分工。

**⚠️ 载体就位 ≠ 行为生效**:P0 尚无叙事系统发这条事件 ⇒ 章号恒 0 ⇒
「每章 1 例」在今日运行时**仍等于**「整局 1 例」。判据
`test_ledger_chapterScope_withoutProducer_equalsGlobal` 把「今日两者相同」钉住 ——
将来叙事轮接上生产者后,**该条应当转红**,那时才可以说「每章 1 例真的生效了」。

### 3.2 B2-b:换动作 = 作废重来

直读通道的 `Arm` 在非 Idle 态**抛**(重复预约 = 编程错误),故「按住时换动作」只能
`AbortAction()`(丢弃累计、**不发**事件)→ `Arm(新动作)`。

- 语义上对:做到一半换动作,之前的拍子本就不该算进新动作;
- 若玩家换完就松手,本次动作**零事件**(Abort 是零事件路径,规则六之甲);
- 目标沿用 `LastEmergencyPatient` —— 换动作不换病人。

**键位**:键盘 `1`–`4` / 手柄方向键(上=0 · 右=1 · 下=2 · 左=3)。
默认 `_selectedAction = 0` ⇒ **不按数字键的玩家行为零变化**。

### 3.3 C3-a:转诊键只解决「哪一例」

`HookCaseClosureWriter.TryRefer` 要 `CaseId` 三元组,而按键只给出「最近在场病人」。
`HookCaseReferDriver` 从**病例流**反查:取该病人**最后一条 `CaseOpened`**,且没有
对应的 `CaseClosed` ⇒ `CaseId(openedTick, patient, openedSeq)`(三元组**从事件头读**,
不是另存)。

⚠️ **不得读成「转诊已可用」**:
- 钩子病例的**配额**仍归 `HookCasePolicy`;
- **送医**(`ReasonHospitalized`)今日**没有按键** —— 只接了转诊。

### 3.4 C2-a:删字段的连带面

删 `teach_point` 不是删一个 `public string` 就完事,四处必须同批:

| # | 位置 | 改动 |
|---|---|---|
| 1 | `Sim/RegistrySchema.cs` | 删字段 |
| 2 | `Editor.Tools.Bake/DiseaseRegistryBinder.cs` | 两处白名单 + 读取点 + **`ReadOptionalString` 整个方法**(唯一调用点就是它) |
| 3 | `Editor.Tools.Bake/DiseaseRegistryCookedWriter.cs` | 行尾少一个 `i32 字节长 + UTF-8` |
| 4 | `Gameplay.Presentation/DiseaseRegistryCookedCodec.cs` | 同上 + `ExpectedSchemaVersion` 3 → **4** |
| 5 | `assets/data/disease_registry.json` | 作者态 `schema_version` 3 → **4** |
| 6 | `DataCooked/disease_registry.cooked.bytes` | **重烘**(4618 B,`ConfigVersion 0x7DFAB072`) |
| 7 | **`DataCooked/53_cost_table.cooked.bytes`** | **必须同批重烘** —— 它的 `ConfigVersion` 由注册表派生,不改则漂移门红(实测首跑即此形态) |

### 3.5 顺带修掉:kindgen 的**静默截断**

`tools/kindgen/kindgen.py` 的 `parse_eventkind_cs` 原实现是 `body.split("}", 1)[0]` ——
**遇到第一个 `}` 就截断**。而成员行尾注释里只要出现一个 `}`(ADR-044 那条
`reason∈{0 转诊,1 送医}` 就是),其后**全部成员静默消失**。

当时 `CaseReferred` 恰好是最后一条,所以没暴露;本批在它后面追加 `ChapterAdvanced` 时
当场命中 —— 报「有 registry 无 C#」,而 C# 里明明写着。已改用配平花括号取体
(`_brace_body`,该文件本来就有这个辅助函数)。
