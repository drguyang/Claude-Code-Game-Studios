## 三、R-2 … R-10 逐条(判定 · 落点 · 证据)

### R-2(WARNING · 已修)—— `flex-shrink` 缺省

- **落点**:`SkeuoBrass.uss:53-71`(`.brass-detent`)
- **判定**:未声明 `flex-shrink` ⇒ 行容器变窄时档块被压缩;压缩**按基础尺寸加权**,故常态/落焦的**绝对**几何差缩水 ⇒ AC-025-1 ② 的「几何可分」随行宽漂移。
- **⚠️ 证据强度**:Unity 6.3 的 `flex-shrink` 默认值**无权威件可依** ——
  `docs/engine-reference/unity/modules/ui.md` 对 `flex-shrink` / `min-height` / `overflow` / `Clear()` / `ClassListContains` **零命中**。
  ⇒ 本条为**静态推导**,未在 6.3 实测(登记为未及核查项,见 §五)。
- **修复**:`flex-shrink: 0` + 理由注。

### R-3(WARNING · 已修)—— `.brass-scale` 两种观感并存

- **落点**:`SkeuoBrass.uss:27-42`;使用者 `CasebookScreen.cs:526`(顶层 `_brassScale`)vs `:557`(每行 `rowForm`)
- **判定**:改 `min-height` 后,该 class **内容驱动尺寸**:
  - 无档(表头 `_brassScale`,**从不调** `SetDetents`)⇒ 带空 ⇒ 高 = `min-height` **2px**;
  - 有档(每行)⇒ 高由带内容决定 ⇒ **12px 板**。
  ⇒ 「`.brass-scale` 恒为 2px 刻度条」这条隐含不变量**已失效**,而注释只写了改造理由、未登记双观感。
- **修复**:注释就地登记两种观感 + 「在行内实例上误加子件 / 误设高度前先读本注」。

### R-4(WARNING · 未修 → 落债)—— `TickCount` write-only

- **落点**:`BrassScaleElement.cs:51`
- **判定**:`element.TickCount` **生产侧零读**。实测:
  `PrescribeRequestDriver.cs:99` 读的是 **`selector.TickCount`**(`DentchDoseSelector` 的**另一个同名属性**,非本元件);
  本元件的 `TickCount` 仅测试读(`dentch_input_test.cs:69/609/612/614`)。
- **处置**:不在本轮修复范围(用户裁定)。**落债登记**,见 §六。
- ⚠️ **易混读警示**:`DentchDoseSelector.TickCount`(生产在读)与 `BrassScaleElement.TickCount`(write-only)**同名不同物**,不得据前者推断后者有消费者。

### R-5(WARNING · 已修)—— 白名单死码

- **落点**:`dentch_dose_form_test.cs` 的 `test_ac025_2_element_exposesNoMutableDoseState`
- **判定**:自动属性 `public int TickCount { get; set; }` 的背衬字段名由编译器生成为
  **`<TickCount>k__BackingField`**;而白名单数组写的是字面量 `"TickCount"` ⇒ `allowed.Contains(f.Name)` **恒不命中**。
  该测当前**巧合通过**,靠的是 `<TickCount>k__BackingField` 不含 `Dose`/`Selected`/… 任一禁止子串 ——
  即**白名单从未生效,却也不影响结果**,是典型死码。
- **修复**:白名单改 `BackingFieldName("TickCount")`(= `$"<{property}>k__BackingField"`),
  并加守卫 `Assert.GreaterOrEqual(whitelisted, 1, "白名单须**真命中** … 恒不生效的白名单是死码")`。
- **反证**:F16(把自动属性换成**显式**背衬字段 ⇒ 名字不再是 `<TickCount>k__BackingField` ⇒ 守卫转红)。

### R-6(WARNING · 已修)—— 层归属只用全文件 `Contains` 代理

- **落点**:`dentch_dose_form_test.cs` 的 `test_ac025_1_detentGeometry_comesFromBrassLayerVariables`
- **判定**:`theme.Contains(varName + ":")` 只证「变量在**文件里某处**」,**非**「在**黄铜层块内**」。
  黄铜层归属仅由另一条 `theme.Contains("黄铜(Brass)")` 代理 —— 两条断言**互不约束**:
  把变量搬到器具档层,第一条仍真、第二条仍真(注释块还在)⇒ **漂移测不出**。
- **修复**:新增 `LayerRange()` + `AssertDeclaredInLayer()`,按**行区间**判定;
  `test_ac025_3_uss_declaresDetentClassesInBrassLayer` 亦改为断言 `黄铜逐档形态` 标记的**行号**落在黄铜层区间内。
- **反证**:F17(把 `--skeuo-brass-detent-width` 的声明行搬到器具档层 ⇒ 转红,而全文件 `Contains` 仍为真)。

### R-7(WARNING · 已修)—— `root.Query<Label>()` 过宽

- **落点**:`dentch_dose_form_test.cs` 的 `test_ac025_5_dosePageText_carriesNoDecimalDigit`
- **判定**:`root` 是**整棵脉案树**,含 `display:none` 的并存页 ⇒ AC-025-5① 逐字只要求「**行内**」。
  过宽的后果是**假红**:未来任一并存页加数字即红,而本件无关。
- **修复**:收窄为 `page.Query<Label>()`,`page = root.Q<VisualElement>("prescription-page")`。

### R-8(MINOR · ✅ 已就地改注)—— 文档漂移

- **落点**:`story-025:32`(`Control Manifest Rules` 行)
- **判定**:该行写「绑定点**唯一** = `DentchDoseSelector.LoadInto(BrassScaleElement)`」,
  而 `AC-025-4` 逐字要求 `CasebookScreen.RefreshDentchDoses()` 每行携带自己的形态 ⇒ **自相矛盾**。
- **实测**:`git blame` 显示 `CasebookScreen.cs:529` 的既有调用点 = `c125742a`(**2026-10-12**,本件之前)⇒
  该行描述的是**改动前**状态,是**既有文档债**,非本件引入。
- **⚠️ 与 R-1 同类**:同文件、同缺陷类(AC / Manifest 措辞与代码实际不符)。
- **✅ 已就地改注(用户 2026-10-18 裁定「就地改注」)**:该行改为「**selector → element 绑定点唯一**
  = `LoadInto`」并显式声明「**行 → 形态**是另一条轴」+ 记录矛盾调用点 `:529` 系既有。
- **未破** `ADR-013 §9 C3`(42 只渲染)—— 本件未让 42 持有任何游戏状态。

### R-9(MINOR · 已修)—— `hierarchy.Add` vs `Add`

- **落点**:`BrassScaleElement.cs:44`
- **判定**:构造器用 `hierarchy.Add(_detentBand)`,全库其余处一律 `Add(...)`。
  对 `VisualElement` 二者**今日等价**(`contentContainer == this`)⇒ 无隐患,只增阅读成本;
  但 `Add` 是惯用写法且**抗基类变更**。
- **修复**:改 `Add`,并注明等价性与理由。

### R-10(MINOR · 已修)—— 负向门测错了面

- **落点**:`dentch_dose_form_test.cs` 的 `test_ac025_5_wholeBrassUss_hasNoFractionReadout`
- **判定**:该门扫的是 `N/M` **分式**;而 AC-025-5③ 逐字是「USS 无 **`content:` 数字**」。
  两条不是同一面 —— 旧门对 AC 的宾语**零判别力**(且负向门本性:删产码仍绿)。
- **修复**:改名 `..._hasNoNumericContent`,主断言改为全域 `content\s*:\s*"[^"]*\d`(对齐 AC),
