## Overview

疾病与伤情模拟是**这片土地上所有身体的规则**。它定义**存在哪些病、哪些伤**(注册表),
以及**它们如何在一个人身上推进**(病程)。

它是全案的**数据核心** —— 8 个系统读它:8 诊断从它取「体征词表」,
11 处方取「适应症」,13 病人 AI 靠它决定病人怎么表现,
24 医馆即机器靠它算恢复速度,**25 格斗靠它把「生命归零」登记为「昏迷」这一种伤情**,
37 病例靠它搭出病例,53 医疗后果接它的终态候选,34 公卫(P1a)订阅它的聚合事件。**改它一次,全案流血。**

但玩家永远看不到这张表 —— 他看到的只有**人**。一个被你看过、开了方、
你说「三天就好」的病人,**在你离开之后继续走他的病程**。他会好,或者他会坏,
而这**不需要你在场**。这就是本系统对玩家的全部意义:

> **这个世界上的病是真的 —— 你不看着它,它也在走。**

这条正是 P0 叙事钩子《他回来了》的地基:第二幕那个病人之所以能「回来」,
是因为**第一幕之后他的病程没有停**。

**本系统持有全案唯一一份「伤情与病名注册表」** —— 武器(21a 的 `inflicts_injury` 外键)、
昏迷(C1)、公卫(C4)全部指向它。

## Player Fantasy

**核心幻想一句话:你面前的每一个病人,都是一具真正在走的身体 —— 不是一张等你来改的血条。**

三个锚点:

1. **「他还没好」—— 世界不为你暂停。**
   你上午看过一个孩子,开了方,走了。下午你绕另一条路回来,他还在烧,而且更重了。
   这里没有「读档重来」。**病程在你离开的每一刻都在走。**
   这一条既是本系统存在的全部理由,也是 P0 叙事钩子《他回来了》能成立的前提 ——
   第二幕那个病人之所以能「回来」,是因为第一幕之后**没人替他按下暂停**。

2. **脉是会变的 —— 判断有时间成本。**
   早晨的脉与黄昏的脉不是同一个读数。**你晚一步去看,看到的就是另一个人。**
   这一条把「望闻问切」从一次性的检查,变成**有时间压力的判断**(支柱一):
   出诊有路程,病情有进展,而**你只能选先去哪一家**。

3. **你的判断真的落在了一个人身上。**
   同一个病人,你开的方对了,他往好的方向走;错了,他往坏的方向走。
   **而且你能在下次见到他时看出来。** 这是「判断为骨」唯一能被玩家真正感知的方式 ——
   不是分数,是**一个具体的人变了**。

> **反幻想:这不是血条。**
> 玩家**永远不会**看到「病人:42 / 100」。他看到的是
> **一个人脸色发白、说话没了力气、不肯喝药**。
> 数值是本系统的**内部语言**,不是玩家的语言 ——
> 这条同时是 42 拟物 UI 的硬约束,也是 8 诊断「体征 → 感知反馈」映射表的源头。

## Detailed Design

### Core Rules

**规则一:一切推进走定 tick,不挂帧。**
```
State[t+1] = Step(State[t], 处置, t)
```
tick 长度固定(`TICK_SECONDS`,见 Tuning Knobs)。线上由游戏循环驱动;
离线从存档的 `(t_last, State)` 用**同一个 `Step`** 补算到 `t_now`。
**禁止**:`Time.deltaTime`、帧数、真实墙钟。**任何一处用了,确定性破产。**

> ⚠️ **`Step` 与 `CatchUp` 不是两条函数**(2026-09-14 复核修正)。
> 原稿把两者当独立实现,于是「逐位相同」既无保证、也无从验证(复核 #4)。
> **修正:`Step(State, t) ≡ CatchUp(patient, t_last = t, t_now = t+1)`** ——
> `Step` 被**定义为**单 tick 的 `CatchUp` 特例。二者共用同一个求值器与同一套边界检测,
> **「同一函数」由构造保证,不是靠断言**。AC-3 据此改写。

**规则二:病程是解析式,不是逐 tick 累积。**
这条是确定性与「零成本预防」(冻结方向③)的同一件事。
```
Progress(t) = Base(t − onset_tick)                // 病种自然曲线(注册表 R1.natural_progress)
            + Σᵢ Offsetᵢ × Decay(t − tickᵢ)      // 已施加的处置,每次一个衰减偏移
            + Noise(patient_seed, t)             // 平滑低频噪声,查表哈希
```
`Noise` 用 **`hash(patient_seed, t)` 查表插值**,**不用状态里的 PRNG**。

> **关键收益**:任意 `t` 都能**直接求值** —— 无须重放、无须保存 PRNG 状态。
> **离线一个月 = O(处置次数),不是 O(tick 数)。**
> 若改成逐 tick 累积的随机游走,「离线补算」就退化成重放十万次 `Step`,
> 而且 PRNG 状态必须进存档 —— 存档变大、跨版本漂移、联机无法核对。
> **这一条现在免费,后期改 = 重写每个病种**(冻结方向②的落地)。

**规则三:病情与体征是两层,且**处置必须自带极性**。**
```
病情(progress) = 病本身的走向        ← 只有「对因」处置能改
体征(signs)    = 病情的投影 + 偏移    ← 「对症」处置改这里
```
于是**柳树皮降热,但不改病情**(对症不治本);**金鸡纳皮改病情**(对因)。
这是支柱一「判断为骨」最锋利的一刀 —— 玩家必须分清**哪个药改的是哪个数**。
(与 D-21-1 的 P0 三味原料直接对应;21b 逐味标注「对症 / 对因」。)

> ⚠️ **「对因 / 对症」必须是**数据**，不能只写在散文里**(2026-09-14 复核修正,blk #7)。
> F1 的 `Σ Offset × Decay` 与 F4 的 `last_effective_treatment` **只在 9 侧可求值**，
> 而判定它是否算「有效」需要知道该处置的极性 —— 这个极性**当前既不注册表里、
> 也不在事件 schema 里**(复核实测:`treatable_by[]` 无此字段)。
> **修正**:①`treatable_by[]` 的每一项增 `polarity ∈ {causal, symptomatic}`；
> ②事件流的处置条目**必须携带** `polarity`、`Offset`、`tau_half`(见规则六)。
> **缺了它,「任意 t 可求值」不成立,9 就退化成一个必须重放才能算的比较器。**

**规则四:病情输出「位置 + 趋势」两个数,解释权归 8。**
- `position` —— 现在多重
- `trend` —— 正在变好还是变坏

**9 无条件输出这两个真值;「玩家能不能读出来」是 8 诊断的判定**(门槛形状见 §UI Requirements)。

这给 8 诊断留出难度阶梯的空间,也给 30 技能一个真实的用武之地:
**技能不够,你只知道他重;技能够,你知道他是正往好里走还是正在死。**
*(阶梯的具体形状 —— 几级能读什么 —— 由 8 拥有,不在 9。)*
(这也是 `systems-index.md` §7 里「30 ↔ 37 循环」在 9 这一侧的接口。)

**规则五:在场与不在场,走同一条路径。**
**没有**「激活模拟」与「冻结」的区分。在场 = 每 tick 真走 `Step`;
不在场 = 用**同一个函数**补算到当前 tick。**同一个函数,同一份状态。**
这是 Player Fantasy 锚点一的机制实现,也是 `systems-index.md` §9 **C6** 的落地。

**规则六:存档存「病史事件流」,不存逐帧状态。**
```
病史 = [ (onset_tick, 病种_id, patient_seed, Seq),
         (tick, 处置_id, 施予者, polarity, Offset, tau_half, Seq), … ]
```
病情与体征都是它的**函数**,**存档里不出现它们**。收益三层:
存档小 · 不会漂移 · 联机换 authority 只是换外壳(**C6**)。
`patient_seed` 由 `hash(world_seed, patient_id)` 派生 —— **不可用 `Random.Range`**。

> ⚠️ **处置条目必须自带求值参数**(2026-09-14 复核修正,blk #7)。
> 原稿的事件只有 `(tick, 处置_id, 施予者)` —— 但 F1 的 `Σ Offset × Decay(t − tick)` 需要
> `Offset` 与 `tau_half`,F4 的对因判定需要 `polarity`。**这些量今天在事件里无处安放**,
> 「病史是唯一真源、任意 t 可由它求值」这句话就落不了地(复核:四方同指)。
> **修正:处置事件必须携带 `polarity` / `Offset` / `tau_half`。**
> `Offset` 与 `tau_half` 由 **11 处方 / 21a `drug_profile`** 提供(9 不认识药,只认这三元组)。
>
> **`Seq`**:全序所需的单调序号,由 `IIdAuthority` 统一发放。
> **两人同 tick 治同一病人**时,靠 `(Tick, Patient, Seq)` 定序 —— 见 §Dependencies 抽象点表。

**规则七:状态是纯数据。**
`PatientState` 是可序列化的纯值类型,**不挂脚本、不是对象、不持 GameObject 引用**
(冻结方向③)。将来换写法(含换 DOTS)**只换外壳**。

**规则八:34 公卫只订阅聚合事件,禁读个体(C4)。**
9 每 N tick 吐一次**生态区级聚合**(病种计数与趋势),34 只订阅它。
**9 不认识 34** —— 依赖是 `9 → 34`(出向),不构成分层环。

**规则九:注册表是数据,不是代码;病种数有硬上限。**
P0 病种 ~8(`systems-index.md` §8)。**新增病种 = 加一行数据,不改一行逻辑。**
任何「为某个特定病种写的 if」都是本规则的违反。

**规则十:一个人身上多个病 / 伤,各走各的曲线,合成只在「读数与阈值」这一步。**(2026-09-14 复核新增,blk #6 · D-8-6)

> **这是本次复核最承重的一处空白。** 原稿的 Edge Cases 说「伤情之间不叠加、不合并」,
> 但**旗舰教学线是共病**(风湿热 → 心衰),且 `PatientState`、`State(t)`、`position` 的合成
> 从未定义 —— **game-designer / systems-designer / network-programmer / narrative-director
> 四方独立命中同一处**。用户 2026-09-14 裁定:**取大 + 显式加成**。

```
设病人身上有集合 D = { 病种或伤情 d }
  position_d(t)          : 各 d 独立求值(F1)
  position_agg(t)        : = max_{d∈D} position_d(t)            // 取大
  State(t)               : 由 position_agg(t) 与 trend 判定     // 九态机只吃合成量
  compounds 显式加成      : 触发条件满足时,向【目标病种】的 Progress 加一项——
                           见 F5。加成写在数据里(compounds[].bonus),不是黑箱。
```

- **各 d 的 `Progress_d` 与 `State_d` 仍是独立的** —— 伤害/病程不被别人污染。
- **合成只发生在两个出口**:① 8 读到的 `position` / `trend`(取大后的聚合量);
  ② **9 自己的阈值判定**(危殆 / 昏迷 / 死亡)。
- **`compounds[]` 有触发语义**(不是装饰):`{ target_id, when: { component_id, min_position, min_duration }, bonus: { Δ_progress | Δ_rate } }`。
  旗舰例:风湿热 → 心衰 —— 当 `DIS_RHEUMATIC_FEVER.position ≥ min_position` 且持续 `≥ min_duration`,
  向 `DIS_HEART_FAILURE` 的 `Progress` 施加显式加成。**触发条数上限 1 层**(禁环:A→B→A 构建期拒绝)。
- **为什么取大不求和**:求和会让「多了个感冒」把重病读数虚推过阈值 —— 假性危殆。
  **取大 + 显式加成**让共病的恶化**必须被作者显式声明**,符合规则九(数据,不是涌现)。

### 伤情与病名注册表 (Registry — 优先冻结)

> **这是全案唯一一份。** 武器(21a 的 `inflicts_injury`)、昏迷(C1)、公卫(C4)
> 全部指向它。**伤情先冻结**(25 格斗线与 21a 的外键在等它,`systems-index.md` §8);
> **病名后冻结**(须过支柱五考据)。

#### R1 表结构:单表 + `kind` 判别字段(用户裁决 2026-09-13)

全案**一套 ID 空间**,由 `kind` 区分。外部只引一个 ID,不引两个 ID 空间。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `id` | string | 全局唯一。前缀:`INJ_` 伤 · `DIS_` 病 · `TOX_` 中毒 |
| `kind` | enum | `injury` / `disease` / `poison` |
| `zh` | string | 中文名(游戏内显示的唯一名称) |
| `severity` | enum | 轻 / 中 / 重 / 危 |
| `causes[]` | string[] | **入边**:武器 ID(21a)/ 事件 ID(52)/ 环境(5)/ 空 = 自发病 |
| `treatable_by[]` | struct[] | 可用处置:10 急救动作 / 11 处方适应症。**每项须带 `polarity ∈ {causal, symptomatic}`**(规则三 · blk #7) |
| `natural_progress` | curve | **无干预下的病程曲线**,按 9 的定 tick 采样。字段 schema 见 R1.3 |
| `signs[]` | ref | 体征词表(8 诊断读)。**可为空集** —— 空体征是「豁免类」病种的合法形态(见 R3.6) |
| `compounds[]` | struct[] | 并发症 / 继发伤。**带触发语义**:`{ target_id, when:{ component_id, min_position, min_duration }, bonus:{…} }`(规则十 · F5) |
| `lethal` | bool | 是否可致死 |

**R1.1 铁律:边是单向的。**
`causes` 是**入边**。武器(21a)以 `inflicts_injury` 指向伤情 `id`;
**伤情不认识武器**。反向引用会让 9 依赖 21a —— 把 Foundation 层的数据核心
拖进对内容层的依赖,那就是环。

**R1.2 铁律:`natural_progress` 必须存在且可序列化。**
它是 Player Fantasy 锚点一(「世界不为你暂停」)的机制实现。
缺了它,病人一离开视野就冻结 —— 《他回来了》的地基就没了。
**它与 F3 的 `DeterministicTick` 是同一件事的两面**(见 Formulas)。

**R1.3 `natural_progress` 的字段 schema —— 上表那一栏不是「一个曲线」,是下面这组具名参数。**

> **为什么必须在这里写死**:F0 明令曲线的**禁止写成 `AnimationCurve`**(绑 `UnityEngine`,
> 违反规则七且不可跨平台),F1–F3 又把病程拆成了具名参数。
> **这些参数若在注册表里没有家,实现者拿着 R1 建不出 F1** ——
> 「注册表是数据」(规则九)就成了一句空话。本节是 R1 与 Formulas 之间的接口。

| 字段 | 对应公式量 | 类型 | 缺省行为 |
| ---- | ---- | ---- | ---- |
| `curve.incubation` | F1 `incubation` | int(tick 数) | **必填** —— 缺了就没有潜伏期 |
| `curve.a_peak` | F1 `A_peak` | `Fix` | **必填** —— 峰值幅度 |
| `curve.tau_rise` | F1 `τ_rise` | `Fix` | **必填**,须 `> 0` |
| `curve.tau_peak` | F1 `τ_peak` | int(tick 数) | **必填**,须 `> incubation` |
| `curve.tau_fall` | F1 `τ_fall` | `Fix` | `self_limit = true` 时**必填，须 `> 0`**;否则忽略 |
| `curve.plateau` | F1 `plateau` | bool | 默认 `false`。**与 `self_limit` 互斥** |
| `curve.self_limit` | F1 `self_limit` | bool | 默认 `false`(不自愈)。**与 `plateau` 互斥** |
| ⚠️ 未声明分支 | — | — | `self_limit=false ∧ plateau=false` = **急性保持型**:`τ ≥ τ_peak` 后 `Base ≡ A_peak`。**此组合仅当 `lethal = true` 合法**(校验 4) |
| `curve.sigma` | F1/F3 `σ` | `Fix` | 全局默认;可逐病种覆盖 |
| `curve.boundary_mode` | F3 `boundary_mode` | enum | **必填** —— `monotone` / `scan` |
| `relapse.a_rel` | F1 `A_rel` | `Fix` | 有 `relapse.*` 块时**必填** |
| `relapse.interval` | F1 `relapse_interval` | int(tick 数) | 写入时**校验 `> 0`**(见 Edge Cases) |
| `relapse.tau_fall` | F1 `τ_rel_fall` | `Fix` | 有 `relapse.*` 块时**必填** |
| `scale` | F2 `SCALE_病种` | `Fix` | **必填**,须 `> 0` —— 8 诊断的接口签名依赖它 |

**写入期校验**(构建期硬失败,不是运行期意外 —— 2026-09-14 复核扩为 10 条,blk #1):
1. `self_limit` 与 `plateau` **不可同为 true** —— 一个说会降,一个说会停,同时为真是配置错误。
2. `tau_peak > incubation` 且 `tau_rise > 0` —— 否则 F1 的分段会产出负指数或倒置区间。
3. `relapse` 块出现时三个字段**必须齐全** —— 半截的复发配置会算出未定义的 `τ_rel`。
4. **`self_limit=false ∧ plateau=false` 仅当 `lethal = true`** —— 否则该病永远停在峰值又不会死 = 无限迁延,是配置错误(补上原稿未定义的第三分支,见 F1)。
5. **`SCALE_病种 > 0` 且 `SCALE_病种 ≥ A_peak`** —— 否则 `position` 永久钉在 1.0(Tuning Knobs 已述,此处升为硬校验)。
6. **`A_peak > 0`**。
7. **`self_limit = true ⇒ tau_fall > 0`** —— `τ_fall = 0` 会算出 `e^(−τ/0)` = `0/0` = NaN。
8. **`relapse.* ⇒ a_rel > 0 ∧ tau_rel_fall > 0 ∧ interval > 0`**。
9. **三阈值严格单调** `CRITICAL < COMA < DEATH`,且 **`DEATH_THRESHOLD < 1`** —— 见 F4(把理论满格留给上界,避免保守舍入让死亡不可达)。
10. **`compounds[]` 无环**(A→B→A 构建期拒绝);**每条 `compounds` 的 `target_id` 必须在本表存在**。

> **`τ_half` 不在本表** —— 它衰减的是**处置偏移**,不是病情,所以它属于
> **11 处方 / 21a 的 `drug_profile`**(D-21-6 的「半衰期」字段),不属于病种注册表。
> **病种定义「病怎么走」,药定义「药怎么退」** —— 这条边界不要跨。
> **伤情(`kind: injury`)** 同样走这张 schema:大多数伤 `self_limit = true`(会自愈),
> `curve.incubation` 通常为 0(外伤无潜伏),但**字段照填不省** —— 省字段 =
> 实现里多一个 `if kind == injury`,违反规则九。

**R3.4 医学诚实性铁律:风湿热 → 风湿性心脏病 是两期,水杨酸不阻止心脏受累。**

> 但不改变心脏受累的进程**。若游戏做成「治了关节 → 心脏就保住了」,
> **医学受众当场出戏** —— 这是本项目的硬约束。
>
> 故本表把它设计成**同一疾病复合体的两期**:
> - **急性期(风湿热)**:柳树皮**缓和症状** —— 诚实地说,是**缓解,不是治愈**;
> - **心脏受累后(心衰)**:毛地黄**控制症状、延长带病生存** —— 是**缓和医疗**。
>
> **玩家在两头都有可见动作,但没有一个动作能「逆转」病程。**
> 这正是本作「**医者不是神**」在数值层的表达 —— 也是「医者不杀」的反面:
> 你能做的很多,但你救不了一切。

#### R3.6 豁免类:叙事钩子专用病种(2026-09-14 新增 · blk #6 · D-8-1)

> **为什么需要这个类别。** P0 叙事钩子《他回来了》**第二幕**的病人患的是**神经衰弱** ——
> 而神经衰弱**没有可外显的客观体征**,这与 R3 的设计关(「玩家有可见动作、结果有差别」)
> 正面冲突。**8 的裁定①已明令「不改 R3 的筛选判据」** —— 于是这里**新增一个合法类别**,
> 而非放宽既有判据、也非给某个病开后门(用户 2026-09-14 裁定:**新增豁免类**)。

**豁免类病种的合法形态**(三条同时成立):
1. **`signs[]` 可为空集** —— 8 侧对全通道读到「无异常」。**空体征是合法输出,不是失灵**
   (与潜伏期的 8 侧读数同形,但成因不同:潜伏是「尚未显」,豁免是「本就不显」)。
2. **尾部形态为 `plateau`** —— 长期低幅存在,不溃散也不消失。**`trend` 恒近 0**(见 F2 死区)。
3. **无 `treatable_by[]` 的 `causal` 项** —— 玩家的作用在**护理 / 陪伴 / 环境**(47 精神压力的反面),
   **不在药理**。这**不违反铁律一**:豁免类病种 `lethal = false`,本就永不致死。

**豁免类与设计关的关系**:豁免类**只豁免「玩家有可见动作」这一条**,
**史实关(支柱五)照过** —— 且**史实关的出处必须逐病种补全**(见 D-9-B)。

> ⚠️ **九态机对空体征病种的处理**:一个空体征病人**仍会走潜伏 → 发病 → 迁延**,
> 但 `发病 / 迁延` 在 8 侧的可见读数**全通道中性**。**这不是态机的例外,是同一套态的另一种读数**
> —— 态由 `position` 与 `trend` 判定(规则四),不依赖 `signs[]` 非空。
> **故 R3.6 不需要新增状态、也不需要改态机**(改写 narrative-director 的「系统内部说这人濒死、
> 眼前却是个正常人」—— 豁免类 `position` 低、`lethal=false`,**系统内外一致,不会说濒死**)。

#### 三条铁律

**铁律一:死亡必须被挣得(以「病种有没有对因手柄」为界)。**
只有 **`lethal = true`** 的病种,**且** `position_agg` 越过 `DEATH_THRESHOLD`,
**且**在处置窗口内**未获有效对因处置**,才会死。**不允许「时间到就死」** ——
那会把 9 变成倒计时器,把支柱一变成失败。
这是 `systems-index.md` §8「9 是高风险系统」在死亡路径上的护栏。

> ⚠️ **对无对因手柄的致死病种,P0 接受「越阈必死」**(用户 2026-09-14 裁定,blk #8)。
> P0 里 **`DIS_DYSENTERY`(痢疾)与 `DIS_TETANUS`(破伤风)没有对因药** ——
> 于是「窗口内未获有效处置」**恒真**,越过 `DEATH_THRESHOLD` 即死。
> **这是已裁定的设计后果,不是缺陷**:它正是铁律二「医者不杀 ≠ 医者无敌」的牙齿 ——
> 玩家对这两种病能做的是**预防与护理**(破伤风:清创;痢疾:支持疗法),**不是逆转**。
> **代价**:若玩家读不出「这病有没有对因手柄」,死亡会被感受为**随机**——
> 故 8 诊断必须让「这病我有没有牌」可读(接口已留,见 §Interactions)。

**铁律二:「疾病可以致死」是支柱二的悲剧面。**
25 把「生命归零」登记为**昏迷而非死亡**(C1);但**病可以杀死病人**。
你杀不了人,也救不回所有人 —— 这保住「医者不杀」不是「医者无敌」。
**疾病是本作唯一能合法夺走【病人】一条命的系统**,因此它必须**稀有、可预兆、可归因**。

> ⚠️ **「唯一夺命系统」的措辞限定在【病人】**(2026-09-14 复核修正,blk #2 · narrative)。
> 原稿的绝对表述与 **29(玩家死亡/复活)**、概念「玩家会死(英灵神殿式)」冲突。
> **修正:铁律二约束的是 NPC 病人,不约束玩家自身** —— 玩家自身的死亡与复活归 **29**。
> **9 只出 `DeathCandidate`(死亡候选),转移归 29 拥有**(见 §Debt Register D-9-C)。

**铁律三:「复发」与「同一个人得了另一种病」是两件事。**
- **复发(relapse)** = 病种自带的周期性,**写在 F1 的 `relapse.*` 块**,
  是「好转 / 迁延 → 发病」的边。P0 只有 `DIS_MALARIA` 带它。
- **第二幕的「他回来了」** = **同一个病人、另一种病**(神经衰弱,`causes` 空 / 47 精神压力)——
  **不是复发**,是**一个新的 onset**。两者在病史事件流里是不同的条目。

> ⚠️ 原稿把两者混为一谈(铁律三原标题「复发是 …→ 发病 的边,它是《他回来了》的机制载体」,
> 2026-09-14 复核修正)。**照原稿实现,会把外伤周期性「复发」成神经衰弱**,正面违背概念
> (narrative-director #3)。**修正:铁律三只讲复发;第二幕的载体是「同一病人的新 onset」。**

> `self_limit`(有些病自己会好)与铁律一合起来是一个重要设计后果:
> **不开方不等于杀人。** 玩家不该因为「什么都做」而必然活,也不该因为
> 「什么都没做」就必然败。这对「判断为骨」是必需的 ——
> 否则玩家会退化成「给每个病人用最多的药」。

## Formulas

### F0 数值域(先于一切公式)

> **裁决来源**:systems-designer 复核 + technical-director 裁决(2026-09-13)。
> **这是本系统最容易「看起来能跑、联机就分叉」的地方,所以它排在公式之前。**

**9 的全部数学在整数定点域,不在浮点域。**
`Fix` = 无行为纯 struct,内部 `long` 承载 **Q16.16**;中间乘法落 Q32.32 再移位回。
哈希用 **SplitMix64**(固定 64 位无符号,显式 `<<`/`|` 组装,**不走 `BitConverter` 的端序敏感路径**);插值用整数除法。

> ⚠️ **Q32.32 是中间表示,不等于 `long` 存储**(2026-09-14 复核澄清)。
> `Q16.16 × Q16.16` 的精确积需 ~64 位有效位(高精度中间需 ~96 位量级);
> **标准做法**:`Fix` 只用 `long` 存 Q16.16,做乘法时先提升到更大的中间类型(如 `System.Int128`
> 或手工 hi/lo 拆分)再移位回 Q16.16。**AC-4 的「不溢出」测的是这条路径**,不是 `long×long` 直接乘。
> *(复核曾以「96 位装不进 long」判为矛盾 —— 那是把中间表示与存储类型混为一谈;
> 但**规格未写明中间类型**确是真缺口,故此处补明。)*

**为什么不能用浮点**:基本四则运算在同指令序下 IEEE-754 逐位一致,但 `Math.Exp`/`Math.Pow` 走各平台 libm,**跨平台不保证逐位**;FMA 融合取决于 IL2CPP 转译后的 C++ 编译器选项。联机核对时就是**「同一病人、两台机器、读数不同」**。

> ⚠️ **定点 `Exp` 必须计入实现量 —— F1/F2 通篇依赖它**(2026-09-14 复核修正,blk #5)。
> 原稿的「200 行」只涵盖四则 + 哈希 + 插值,**没有 `e^x`**;而 F1 的 `Base` / `Relapse` / `Decay`
> 全是 `e^(−τ/·)`。**修正:定点库的范围明确包含 `Exp`(范围规约 + 多项式逼近 + 修正表)**
> —— 实现量因此上调,见下方代价评估。
> **定点 `Exp` 是纯确定性函数(同输入同输出),不违反 F0 的本意**,只是必须显式列入预算。

**代价评估**:定点库(四则 + `Exp` + SplitMix64 + 插值)约 250–400 行、零第三方依赖。
**性能的真实成本模型**(2026-09-14 复核修正,blk #5 · performance):原稿的
「每场病人数十实例 × 每处置一次求值」**与机制不符** —— `Step` 是**每 tick × 每病人**跑一次,
处置偏移只在**处置发生时**改一笔历史。**真实成本 = 病人数 × tick 频率 × 单次求值**,
而**「病人数」的范围从未定义**(规则八要生态区级普查,概念又说疫情「表现为散落的病例」,
差 2–3 个数量级)。**故本行改为:成本模型待实测标定,登记为 OQ-8。**
**「数十」这个数字在 `src/` 没有任何实现背书 —— 撤销该自引。**

| 纪律 | 内容 |
| ---- | ---- |
| **舍入** | 保守带内的一切比较用**向下保守舍入**(宁多扫一步);表现层用就近舍入 |
| **中间精度** | 乘法与 `Exp` 的中间量**在 Q32.32(或更宽)求值**,只在**最终出口**落回 Q16.16 —— 见 F1/F2 的抵消说明 |
| **误差预算** | 每次运算 ≤ 1 ulp(2⁻¹⁶);保守带外扩 `ops × 2⁻¹⁶`。**⚠️「实测 ≤ 3×2⁻¹⁶」为无出处自引,已撤销** —— 待 `src/` 实现后标定(否则保守带可能窄于真实误差 → 静默漏事件) |
| **唯一投影点** | 系统 9 的**查询门面**(`GetVitals(patient) → VitalsDto(float)`)。8 / 13 / 24 只能拿到 DTO |
| **强制手段** | `Fix` **不定义**到 float 的隐式转换,唯一出口是门面内的显式 `ToFloat()`;sim 层类型放**独立程序集**(需 `"noEngineReferences": true`,见 §Dependencies),门面是其中唯一浮点出口,code review 加检查项 |
| **序列化** | `Fix` 只存内部 `long` 原值 —— 7a 按整数处理,**无端序 / 格式坑**。禁止把 float 写进事件流 |

> ⚠️ **IL2CPP 逐位性(Unity 6.3)标注为「需实测验证」** —— 这是 post-cutoff 行为。
> 但**本裁决不依赖该实测**:即使乐观,libm 差异已足以否决浮点路线。

### F1 病程求值

```
Progress(t) = clamp( (Base(τ) ⊔ Relapse(τ)) + Σᵢ Offsetᵢ × Decay(Δᵢ) + Noise(seed, t), 0, +∞ )
   【时间原点约定 —— 全式只有一个绝对量 t】
     τ  = t − onset_tick   : Base / Relapse 的自变量,「距 onset 的时长」,不是绝对 tick
     Δᵢ = t − tickᵢ        : 距第 i 次处置的时长
   【潜伏期抑制】τ < incubation  ⇒  Progress(t) ≡ 0   ← 噪声不得使潜伏病人"有读数"

Base(τ) = 0                                                  , τ < incubation
        = A_peak × (1 − e^(−(τ−incubation)/τ_rise)) / R_rise , incubation ≤ τ < τ_peak
        = A_peak × e^(−(τ−τ_peak)/τ_fall)                    , τ ≥ τ_peak ∧ self_limit = true
        = A_peak.                                            , τ ≥ τ_peak ∧ plateau = true
        = A_peak                                             , τ ≥ τ_peak ∧ 急性保持型(二者皆 false,须 lethal,见 R1.3 校验 4)

  R_rise = 1 − e^(−(τ_peak − incubation)/τ_rise)     ← 上升段归一化因子(常数),保证 τ = τ_peak 处 Base = A_peak

Relapse(τ) = A_rel × e^(−(τ − τ_rel)/τ_rel_fall) · [τ ≥ τ_rel]
τ_rel      = relapse_interval × (复发次数 + 1)      ; 相对量 —— 与 τ 同原点

Decay(Δ)   = e^(−Δ/τ_half) · [Δ ≥ 0]                ; Δ < 0 一律取 0 —— 禁止负 Δ 让指数爆炸

⊔ = 取大(max)，不是相加
```

> ⚠️ **三处修正(2026-09-14 复核,blk #1)**:
> 1. **上升段加了归一化 `R_rise`** —— 原稿 `A_peak×(1−e^(−…))` 在 `τ_peak` 处远小于 `A_peak`,
>    而衰减段首值恰为 `A_peak` ⇒ **曲线在峰值跳变,AC-6「相接于 A_peak」为假**。
>    除以 `R_rise` 后上升段在 `τ_peak` **恰好等于 `A_peak`**,连续。
> 2. **补上原稿未定义的第三分支** —— `self_limit=false ∧ plateau=false` 时 `τ ≥ τ_peak`
>    在原稿里**没有任何分支**(Base 未定义)。**今定义为「急性保持型」`Base ≡ A_peak`**,
>    由校验 4 限定只能用于 `lethal=true`(痢疾 / 破伤风)。
> 3. **`Decay` 加 `[Δ ≥ 0]` 门** —— 原稿 `Decay(Δ)=e^(−Δ/τ_half)` 在 `t < tickᵢ`(求值早于处置)
>    会指数爆炸。**处置的时间反演必须归零。**
>
> ⚠️ **潜伏期抑制噪声**:原稿 `τ < incubation` 时 `Base=0` 但 `Noise ∈ [−σ,σ]` **可为正**
> ⇒ `Progress > 0` ⇒ 8 侧读到非中性体征,**破 AC-22 与 Edge Case 1**。今显式抑制。

| 项 | 含义 | 关键约定 |
| ---- | ---- | ---- |
| `τ = t − onset_tick` | **全式的原点约定** | Base / Relapse 共用同一个相对时基。**曾经写作 `t_rel = onset_tick + …` 是错的** —— 那是绝对量,与相对量的 `τ` 相减会把首次复发推到负时刻 |
| `(Base ⊔ Relapse)` | **括号是运算优先级,不是文风** | 取大**只作用于这两条曲线**;`Σ Offset×Decay` 与 `Noise` 在括号外相加。少这个括号,读出 `Base ⊔ (Relapse + Σ + Noise)` 也「说得通」—— 那是另一个系统 |
| `Base(τ)` | 单次发作的自然曲线 | **两段指数拼接**,单峰;上升段经 `R_rise` 归一化,在 `τ_peak` 与衰减段**连续相接于 `A_peak`**;`τ ≥ τ_peak` 有三分支(self_limit 衰减 / plateau 保持 / 急性保持型保持) |
| `Relapse(τ)` | 复发(F1 显式项,**不是状态机加边**) | `τ_rel` 由**病史事件流直接计数**得出 —— 保持闭式、可离线直接求值。**带 `relapse.*` 的病种永不入「痊愈」**(R3.3 注) |
| `⊔` | 取大 | 主曲线与复发曲线重叠时**取大不取和** —— 否则病情假性叠加 |
| `clamp(…, 0, +∞)` | 下界 0 | 防过度治疗把 `position` 压成负数、`trend` 符号反转。**⚠️ 仅对【有对因手柄】的病种起作用** —— plateau 型(心衰/伤寒)无对因,不可被压到 0 |
| `Decay(Δ) = e^(−Δ/τ_half)·[Δ≥0]` | 处置偏移的衰减 | 线性叠加,**顺序无关**(和式可交换)—— 这是要保住的优点。**`Δ<0` 必须归零**(防指数爆炸) |
| `Noise` | 平滑低频噪声 | 查表 + 整数插值,**纯哈希,不持 PRNG 状态**。**潜伏期(τ<incubation)不施加** |

**两条不可动摇的取舍:**

1. **`τ_fall = ∞` 被取消。** 改用显式 `self_limit` / `plateau` 布尔分支 ——
   ∞ 做哨兵值在配置漏填时会退化成 `exp(−∞)=0` 或 `0/0=NaN`,而且 **JSON 没有 ∞ 字面量**。
2. **`Offset` 是绝对值,不是比例。** 「重病人吃同一剂药降幅更大」交给 **11 处方按病情选剂量**,
   **9 不承担** —— 一旦 `Offset` 挂钩 `Progress`,叠加就不再顺序无关,确定性叙事随之破产。

> **复发的设计含义**:复发是《他回来了》的机制载体。它被放进 F1 而不是状态机,
> 是因为状态机加边会让「解析式」偷偷退回「分段拼接」,F3 求值就必须知道所有复发时刻 ——
> **反而更难**。放进 F1 后,复发次数只是一次计数。

### F2 体征投影

```
Signⱼ(t)    = Project(Progress(t), 病种)ⱼ + Σᵢ (对症处置偏移)ⱼ
position(t) = clamp(Progress(t) / SCALE_病种, 0, 1)

trend(t)          = (Progress(t + W/2) − Progress(t − W/2)) / W     // 展示用(8 读数)
trend_backward(t) = (Progress(t) − Progress(t − W)) / W             // 状态转移用(F4,因果)
两者都在 Q32.32 中间域求差,再与死区 TREND_EPS 比较:
   若 |trend| < TREND_EPS  ⇒  趋势判为「持平」(返回 0),不返回 ±1 LSB 的量化噪声
```

> ⚠️ **两处修正(2026-09-14 复核,blk #5)**:
> 1. **`trend` 的量化抵消** —— Q16.16 的刻度是 2⁻¹⁶,`trend` 是两个 `Progress` 之差。
>    在 plateau / 迁延段(如心衰),两值近乎相等,**直接相减的结果是 0 或 ±1 LSB 的纯量化噪声**
>    —— **恰在最需要趋势的心衰类病种上失真**。**修正:差分在 Q32.32 中间域完成 + 引入死区 `TREND_EPS`**,
>    使「持平」是一个**确定的判定**,而不是随机抖动。
> 2. **状态转移不再用中心差分** —— 中心差分要读 `t + W/2`(**未来**)。
>    展示层这样读无害(纯函数),但 **F4 在 tick `t` 上用未来时刻决定状态 = 非因果**。
>    **修正:状态转移改用 `trend_backward`(只读过去)**;`trend`(中心)仅用于 8 的展示读数。

> ⚠️ **9 只出原始量,不出可读性判定。** `position` / `trend` 是**无条件真值**;
> 「玩家能不能读出来」的门槛形状(`READ_FLOOR`、`BASE_READ`、技能 → 精度的映射曲线)
> **归 8 诊断拥有**(见本文件 §UI Requirements「门槛在 8,不在 9」)。
> **此处曾把门槛公式写在 F2 里,2026-09-14 迁出** —— 那是玩法决策,不是模拟决策。

| 约定 | 理由 |
| ---- | ---- |
| **病情 / 体征两层** | `Progress` 只被**对因**处置改;`Signⱼ` 被**对症**处置改(规则三) |
| **`SCALE_病种` 每病种自带** | 轻病重病各用各的尺,同一病种内可比、跨病种不可比。**这决定 8 诊断的接口签名** |
| **`trend` 用中心差分** | 一阶差分在处置发生在窗口内时会跳变 → 玩家看到「**突然变坏**」的假信号。中心差分天然抵消对称跳变,且解析式求值免费 |

> **`W` 与 `SCALE_病种` 都留在 9 —— 门槛的形状在 8。** `SKILL_CAP` 不属于两者:
> **9 不知道玩家技能多少**(否则同一份病史在两台机器上读出不同 `Progress`,破坏 ADR-005)。
>
> ⚠️ **`SCALE_病种` 为什么不迁 8**:它虽然决定 8 的接口签名,但它**同时是 9 自己的状态机变量** ——
> 危殆 / 昏迷 / 死亡全由 `position ≥ *_THRESHOLD` 判定,**而 `position = Progress / SCALE_病种`**。
> **迁走它,9 算不出自己什么时候死人。** 判据与门槛同源(「服务的是玩家读到什么」)在这里失效,
> 因为 `SCALE_病种` 服务的是**两个系统各自的语义**,不是单向下游。*(2026-09-14 复核裁定)*


### F3 定 tick 与离线补算

```
t = ⌊GameClock / TICK_SECONDS⌋

CatchUp(patient, t_last, t_now) from 病史:
  1. 枚举 (t_last, t_now] 内的【类 A 边界】—— 全部有闭式解:
       潜伏 → 发病     t_e = onset + incubation
       达峰 τ_peak      t_e = onset + tau_peak              ← 上升段归一化后此处仍是一个分段点
       复发(第 k 次)    t_e = onset + relapse_interval × (k+1)
  2. 类 A 边界切子区间;区间内 G(t) = Base(t) ⊔ Relapse(t) + Σ Offset × Decay(平滑可微)
  3. 每子区间用 |Noise| ≤ σ 得保守带 [θ−σ, θ+σ]:
       整带在阈值同一侧 → 跳过   ← 剪枝安全性:必须【整带】同侧才跳,否则会漏真穿越
       跨侧            → 定步长 + 二分定位穿越点(FIXED_ITER 固定迭代)
  4. 按序应用边界,写回缺失的病史事件

Step(State, t) ≡ CatchUp(patient, t_last=t, t_now=t+1)   // 同一函数,单 tick 是其特例

boundary_mode(每病种注册表字段) = monotone | scan

脉冲剪枝:第 k 个复发脉冲的峰值 A_rel × e^(−k × interval / τ_rel_fall) < ε_PRUNE ⇒ 其后脉冲全部忽略
```

**复杂度**(2026-09-14 复核重写,blk #4 · performance-analyst):

| 病种形态 | 类 A 边界数 | 与离线时长的关系 |
| ---- | ---- | ---- |
| 无复发块(`self_limit` 收尾) | `O(1)`(incubation + τ_peak) | **与离线时长无关** ✓ |
| 有复发块(疟疾) | `⌊离线时长 / interval⌋` | **线性** —— 除非启用 `ε_PRUNE` 剪枝,降为 `O(τ_rel_fall/interval × ln(A_rel/ε_PRUNE))` |
| `plateau` / 急性保持型的子区间内部 | `O(区间长度 / 步长)` | **线性** —— 该型无闭式根,只能定步长扫描 |

> ⚠️ **「不随离线时长线性增长」是一条有条件的话,不是无条件承诺**(复核修正)。
> 原稿宣称无条件,但**被自己的注册表击穿两处**:**① `DIS_MALARIA` 已在 P0**,
> 复发边界数随时长线性(离线一年 ≈ `365/intervals_per_day` 个边界);
> **② plateau 型(心衰 / 伤寒)的子区间可横跨整个离线期**,内部扫描 `O(时长/步长)`。
> **修正:① 引入脉冲剪枝 `ε_PRUNE`(旋钮,见 Tuning Knobs),把复发从线性降为常数;
> ② 明确 plateau 型的长离线是【近似线性】,接受代价或为其定义闭式根(留待实现期)。**
> **故 ADR-005 的验证判据须用「剪枝后」的口径**,否则对 P0 现有病种即不通过。
> 这条同时是 OQ-4(`σ` 双效应)的一部分:**保守带越宽,子区间扫描越多**。

> ⚠️ **规则二的「O(处置次数)」不是自动成立的**,它由四条共同保证:
> **① 类 A 边界有具名闭式 ② 类 B 用保守带(剪枝整带同侧才跳) ③ 每个病种登记 `boundary_mode`
> ④ 复发型病种启用 `ε_PRUNE`。**
> 缺任何一条,F3 就会**悄悄退化成扫描**。
> `boundary_mode` 必须**登记为数据**(规则九),否则会在**第 4 个月做存档时**
> 才发现某个病种不可闭式求解 —— `systems-index.md` §8 标的就是这个爆点。

### F4 阈值与转移判定

```
State(t) 只在 tick 采样点上判定 —— 不做一般求根

【判定顺序:严重度降序 —— 这条顺序是规格的一部分,不可改动】
   死亡 ← lethal ∧ self_limit = false
          ∧ position_agg ≥ DEATH_THRESHOLD
          ∧ (t − last_effective_treatment) > TREATMENT_WINDOW
   昏迷 ← lethal ∧ position_agg ≥ COMA_THRESHOLD            // C1 的登记点
   危殆 ← position_agg ≥ CRITICAL_THRESHOLD
   潜伏 ← τ < incubation
   其余 ← 由 sign(trend_backward) 与 position_agg 分段        // 因果:只读过去(F2)

position_agg(t) = max over d∈D of position_d(t)               // 合成量,规则十 / F5

last_effective_treatment = last( 处置 where polarity = causal ∧ Offset 与 Base 异号 )  ,若存在
                         = onset_tick                                                     ,若从未有过对因处置
      ⚠️ 哨兵必须**显式**。缺了它,「从没被治过」的病人这一项为空,
         `(t − last_effective_treatment)` 无定义 → **死亡判定整条短路**
         —— 而「从没治过」恰恰是 F4 最需要覆盖的情形。
      ⚠️ **对无对因手柄的病种(P0:痢疾 / 破伤风 / 心衰 / 伤寒),哨兵恒生效**
         ⇒ 过了 TREATMENT_WINDOW 即满足「未获有效处置」⇒ **越阈必死**(用户裁定,见铁律一)。
```

> ⚠️ **判定顺序退化的修正(2026-09-14 复核,blk #2)**。原稿按
> 「潜伏 → 危殆 → 昏迷 → 死亡」列出,实现为 `if/else if` 时 `危殆` 先命中 ⇒ **昏迷/死亡成死代码**。
> **今按严重度降序(死亡 → 昏迷 → 危殆 → 潜伏 → 其余)重写**;或等价地按互斥阈值带判定。
> 这是因为 `CRITICAL < COMA < DEATH`(校验 9),三者本可组成互斥带,但**顺序仍须写死**以免实现者自由发挥。

> ⚠️ **plateau / 急性保持型下 `position_agg` 恒为 1 的处置**(复核 minor #13)：
> 这两型 `Base ≡ A_peak`,若 `SCALE_病种 = A_peak` 则 `position ≡ 1`。
> ① **死亡可达性**：若 `DEATH_THRESHOLD = 1` 且保守舍入使 `position = 1 − ulp < 1`,
>   则死亡**永不可达**。**修正:校验 9 强制 `DEATH_THRESHOLD < 1`**,把理论满格留给上界。
> ② **过度治疗把 plateau 压成痊愈**:原稿允许 —— 但因 **毛地黄极性已定为「对症」(blk #2)**,
>   plateau 型**没有对因手柄**,`clamp` 的 0 下界对其**不被触发** ⇒ 该路径已封闭。

**为什么放弃求根**:`Noise` 破坏单调性,`Offset` 在 `t = tickᵢ` 处引入导数跳变 ——
二分可能失效,**或收敛到错误的根**。9 的状态转移本来就是 tick 离散的,在采样点判阈值足够。
⚠️ **`FIXED_ITER` 保证的是「确定终止」,不保证「收敛到正确根」—— 固定迭代只解决确定性,不解决正确性。**

**铁律一的实现(死亡必须被挣得)有四个必须写死的条件:**

| 条件 | 防的是什么 |
| ---- | ---- |
| `self_limit = false` | 自限性病也「时间到就死」—— 那是铁律一的伪装违反 |
| `last_effective_treatment` 只认 **`polarity = causal`** 的处置 | 对症药**刷新死亡窗口**会让玩家用柳树皮「续命」—— **伪治疗** |
| `last_effective_treatment` 为空时**取 `onset_tick` 哨兵** | 「从未被治过」的病人这一项若无定义,死亡判定整条短路 —— **而「见死不救」正是它要覆盖的情形** |
| 无对因手柄的病种,哨兵恒生效 ⇒ **越阈必死** | P0 痢疾 / 破伤风的既定设计后果(用户裁定)—— **不是缺陷,是铁律二的牙齿** |
| 自然痊愈是终态,位置已降 | 死亡条件自然不满足 —— **明写,勿加特判**;**但带 `relapse.*` 的病种不入痊愈**(R3.3 注) |

### F5 多人多病合成(2026-09-14 复核新增 · blk #6 · D-8-6)

```
对病人 p,身上病/伤集合 D = { d₁ … dₙ }:

  position_d(t)   = clamp( Progress_d(t) / SCALE_d, 0, 1 )          // 各 d 独立(F1 / F2)
  position_agg(t) = max_{d ∈ D} position_d(t)                       // 取大(用户裁定)
  trend_agg(t)    = 由 position_agg 的时间导数符号给出               // 合成后再取趋势

  【compounds 显式加成】对每条 compounds 规则 r = (target, when, bonus):
     if  when.component ∈ D
        ∧  position_{when.component}(t) ≥ when.min_position
        ∧  该条件已持续 ≥ when.min_duration
     then  Progress_{r.target}(t) += bonus.Δ_progress
           (或 bonus.Δ_rate 乘到 target 的上升速率 —— 二选一,由数据声明)

  九态机判定(F4)吃的是 position_agg(t),不是任一个 position_d(t)。
```

> **为什么合成只在出口**:各 `d` 的病程**必须独立**(否则「治好了关节、心脏也跟着好」——
> 恰是 R3.4 明令禁止的医学错误)。**合成只发生在 ①8 的读数 ②9 的阈值判定两处。**
> **`compounds` 的加成是「向目标病种的 Progress 加一项」**,不是在聚合量上加 ——
> 这样共病恶化对**目标病种自己的曲线**可见,也保持了「取大」的语义。
>
> **禁环**:校验 10 拒绝 `A→B→A`;`min_duration` 用 tick 计数(整数,确定性)。
> **触发条数上限一层** —— 不做传递闭包(避免复杂度失控)。

## Edge Cases

| 情况 | 处理 | 理由 |
| ---- | ---- | ---- |
| **病人在潜伏期**(体征未显) | 8 诊断**读不到任何东西** —— 这是**正确行为**,不是失灵。**机制:`τ<incubation ⇒ Progress ≡ 0`(噪声被抑制)** | 潜伏对 8 不可见的机制实现;也让 34 公卫(P1a)有对象。**原稿未抑制噪声 ⇒ `Progress` 可为正,读得出非中性体征 —— 已修**(blk #9) |
| **豁免类病种(空体征)** | 病人**照常走潜伏 → 发病 → 迁延**,但 8 侧读数**全通道中性**;`lethal=false`,永不濒死 | R3.6 —— 「系统内外一致」,不产生濒死/正常的矛盾读数 |
| **玩家在病程中途离开** | 病程继续走(规则五)。他回来时 8 诊断看到的是**另一个人** | Player Fantasy 锚点二:脉是会变的 |
| **病人自然痊愈,玩家从未现身** | **合法**。`self_limit = true` 的病自己会好 | 铁律一的配套:**不开方不等于杀人** |
| **玩家丢下病人、病人死亡** | **不发生** —— 铁律一允许它发生,但代价**不在 9 这一层** | ⚠️ **待裁决 D-9-A**:代价归属挂到 **31 声誉 / 47 精神压力** 设计时再定(见 Open Questions) |
| **同一病人多种伤情 / 多种病** | 各 `d` **独立走自己的 `Progress`**;**读数与阈值判定用合成量 `max`(取大)+ `compounds` 显式加成** | 规则十 / F5 —— **原稿写「不叠加、不合并」,与旗舰共病线矛盾,已改**(blk #6 · D-8-6) |
| **病与伤复合**(如刀伤 → 感染) | 走 `compounds[]` 的**触发规则**(`when` 条件满足才施加 `bonus`),不是独立注册条目 | R2.2:感染是「伤的走向」;`compounds` 今有触发语义(F5) |
| **人被打到生命归零 vs 病死** | 前者登记为 **`INJ_COMA`(不是死亡)**;后者**可以死** | C1 + 铁律二:「医者不杀」≠「医者无敌」 |
| **复发与处置偏移重叠** | **取大(`⊔`)不取和** | 相加会让病情假性叠加(F1) |
| **`relapse_interval` 配成 0 或负** | **注册表写入时拒绝** —— 否则病人**每 tick 复发一次** | 值域校验(规则九)。构建期报错,不是运行期意外 |
| **越阈值恰好落在 tick 边界** | 在**采样点**上判定,取**先到者**;不做插值 | F4 只判定不插值 —— 插值会引入浮点与不确定性 |
| **玩家睡过一整季(时间跳跃)** | 走 `CatchUp`,复杂度 O(类 A 边界),**不重放 tick** | 规则二/F3 的设计红利 |
| **病人所在区块被卸载 / 玩家传送离开** | **无特殊路径** —— 在场与不在场同一条路径(规则五) | 没有「冻结」这个概念,故没有这条边界 |
| **存档跨版本,病种 id 已被删改** | 事件流里找不到 id → **该条病史保留为「不明病症」,不静默丢弃、不报错崩溃** | 病史是玩家的记录,不可被版本更新夺走 |
| **34 公卫订阅时病人刚好死亡** | 聚合事件在**下一 tick 边界**统一广播;死亡已计入 | 聚合是 tick 离散的,不追求即时性 |
| **玩家对已痊愈的病人再开方** | 允许但无害:处置写入病史,`Progress` 已归位,`Offset` 无效果 | 不惩罚误诊之外的动作;惩罚不是 9 的职责 |
| **玩家用对症药给危重病人「续命」** | **无效** —— `last_effective_treatment` **只认对因处置** | 否则柳树皮可以刷死亡窗口,那是**伪治疗**(F4) |
| **联机时两人同时治疗同一病人**(P1b) | 事件是**世界级**的,按全序 `(Tick, Patient, Seq)` 结算 | ADR-005:事件必须可全序 |
| **想加第 9 个 P0 病种** | **拒绝** —— P0 病种硬上限 ~8(`systems-index.md` §8) | 上限是风险控制,不是建议 |
| **玩家自己在疫区出入不做防护** | 玩家也是一个 `PatientState`,走**完全相同的病程** | 52 规则九「你自招的升级」的机制接口 |
| **定点运算溢出** | `Fix` 的中间乘法落 Q32.32;**溢出即 bug,不是边界** —— 由单元测试守住 | ADR-005 的 `Fix` 边界值测试 |

> ⚠️ **本表中「玩家丢下病人、病人死亡」一行仍是唯一未结案的一条** —— 其余均为已定裁决。
> 「丢下病人」不是一个可以靠 9 独自惩罚的行为:**9 只负责让病程继续走**,
> 要不要为它扣声誉、加精神压力,是 31 / 47 的语义,不是模拟的语义。

| `IEventSink` | `void Append(in SimEvent e)` | 事件写入点散落各系统 → P1b 改所有产事件处 | 本地 `List<SimEvent>`;ADR-008 扩展为按 Kind 路由 |
| `IIdAuthority` | `PatientId Next()` | 用运行时 instance id → 联机 seed 分叉,重写病种 | 主机单调计数器;21a 尚需 `ItemInstanceId Next()`(TR-itemdb-019) |
| `IVitalsQuery` | `VitalsDto GetVitals(PatientId p)` | **唯一的浮点出口**(F0 纪律);绕过它 = 浮点泄漏进 sim 层 | 门面内 `Fix.ToFloat()` |
| `IEventAuthority` | `bool IsAuthority { get; }` · `EventRollResult Roll(in RollRequest r)` | 掷骰权归属(ADR-007 §一)**第六抽象点**,P0 恒 true | 本地占位;52 消费 |
| `SimEvent` | `{ long Tick; PatientId Patient; long Seq; EventKind Kind; EventPayload Payload; }` | 事件不带逻辑 tick / 不可全序 → 回放无法检测乱序 | 值 struct,可全序 `(Tick, Patient, Seq)` |

**三条实现铁律**(与 ADR-005 `Implementation Guidelines` 同源):

1. **`Fix` 不定义到 `float` 的隐式转换。** 这是刻意的 —— 唯一出口是 `IVitalsQuery` 门面内的显式 `ToFloat()`。
2. **sim 层类型放独立程序集,零 `UnityEngine` 引用**(规则七)。**双门判据**(ADR-005,2026-09-15 补):
   **门 A** —— 独立 asmdef 且**显式设置 `"noEngineReferences": true`**(Unity 默认向 asmdef 注入
   `UnityEngine.dll`,不设则「零引用」**静默假通过**,unity-specialist #2);
   **门 B** —— EditMode 反射测试断言 sim 程序集**不引用** `UnityEngine.*` / `Unity.Mathematics` /
   `Unity.Collections`,**不含**对 `Math.Exp` / `Pow` / `Sqrt` / `Log` / `Abs` 的 IL 调用,且类型签名
   **不出现** `float` / `double`。**只有门 A 不够**:`System.Math.Exp` 在 `System.Runtime` 里,
   asmdef 隔离拦不到(报告 E-1 的盲区)。对应 AC-5(组一)。
3. **`SimEvent` 必须可全序**且**带载荷**,否则联机回放无法检测乱序、且 F1/F4 的求值参数无处安放。
   **全序键以 ADR-006 Amendment C 为准**:跨流 `(Tick, StreamPriority, Patient, Seq)`
   (病史流 < 病例流),单流内 `(Tick, Patient, Seq)` —— 本行 P0 形态的「可全序 `(Tick, Patient, Seq)`」
   在 37 病例流存在后即不足,见 ADR-008 §二。

> ⚠️ **`SimEvent` 的形状是 ADR-005 的债,不是 9 的**(2026-09-14 复核,blk #3)。
> ADR-005 定义的 `SimEvent{Tick, Patient, Kind}` **装不下全序**(无 `Seq`)、
> **也装不下载荷**(`病种_id / 处置_id / 施予者 / polarity / Offset / τ_half` 无处放);
> 它同时与规则六的事件元组**对不上**(复核:network / unity / systems / qa 四方同指)。
> **✅ 已兑现(2026-09-14)**:`ADR-006 Amendment A` 把上表形状落盘为权威定义,
> ADR-005 正文已就地修正并加前向指针 —— 见 §Debt Register **D-9-D**。

> ⚠️ **换 authority 会重排 id ⇒ 改写全部病程**(network-programmer #3)。
> 若新主机的 `IIdAuthority` 计数器归零,`PatientId` 撞号 ⇒ `hash(world_seed, patient_id)` 得同一 seed;
> 或按 id 重枚举则**所有 `patient_seed` 变 ⇒ `Noise(t)` 跳变 ⇒ 病程改写**。
> **✅ 已裁决(2026-09-14)—— 取「计数器 + 高水位可重构」,不是 hash 派生。**
> 三条硬不变量(`ADR-006 Amendment B`):
> 1. **计数器永不复位为 0**;
> 2. **任何权威变更后 `next = max(全部已知 patient_id) + 1`** —— 由事件流**重构**,不作独立快照;
> 3. **终态折叠行必须保留 `patient_id`**。
>
> **⚠️ 第 3 条是本轮复核新发现的漏洞**:原折叠元组 `(onset, 病种_id, patient_seed, outcome, t_end)`
> **丢掉了 `patient_id`**,而折叠丢弃流位置、`patient_seed` 又是单向哈希 ⇒
> 高 id 病人全部折叠后 `max(patient_id)` **不可重构** ⇒ id 复用 ⇒ **两个病人共写一份病程**。
> **该失败不崩溃、不回放失配,只表现为「病程悄悄变了」。** ADR-005 已就地补上该字段。
>
> **原文「hash 派生而非计数器派生」的说法已废除** —— 它让「出生上下文」既要唯一
> (唯一就必然含序号)又要无状态,自相矛盾;等于把计数器藏进哈希输入里。见 D-9-E。

## Tuning Knobs

> **本节所有默认值均为 `*待定*`** —— 数值由用户裁定。
> 这里交付的是**旋钮清单 + 安全区间 + 耦合警告**:「往哪拧会动到谁」。
> 逐病种的旋钮在**注册表**里逐条填(R1.3 schema);本节是**全局旋钮 + 跨旋钮约束**。

### 一、时间基准

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `TICK_SECONDS` | **全案唯一 tick 长度**。改它 = 9 / 5 / 25 / 7a 四份文档同时失效 | **必须 > 0**;且便于 `⌊GameClock / TICK_SECONDS⌋` 无漂移的取值 | `*待定*` |

> ⚠️ **`TICK_SECONDS` 是本节最贵的一个旋钮。** 它已登记 `entities.yaml`(constants),
> 因为 **7a / 5 / 25 必须与 9 取同一个值**。**定它之前先问这三家** —— 事后改 = 重算所有病史时间戳。

### 二、病程曲线(逐病种 · R1.3 schema)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `incubation` | 潜伏期长度 · **8 诊断在此期间读不到** | `≥ 0`;**外伤类通常 = 0** | `*待定*` |
| `A_peak` | 峰值病情(**决定 `SCALE_病种` 的下限**) | `> 0` | `*待定*` |
| `τ_rise` | 上升快慢 | `> 0`。**越大越缓** | `*待定*` |
| `τ_peak` | 达峰时刻 | **必须 `> incubation`** —— 否则 F1 分段区间倒置 | `*待定*` |
| `τ_fall` | 下降快慢 | `self_limit = true` 时**必填** `> 0`;`plateau` 时忽略 | `*待定*` |
| `self_limit` | 是否自愈(**铁律一的护栏**) | bool。**与 `plateau` 互斥** | `*待定*` |
| `plateau` | 是否不降不愈(迁延) | bool。**与 `self_limit` 互斥** | `*待定*` |
| `SCALE_病种` | **`position` 的归一化分母** —— ⚠️ **同时是 9 自己的状态机变量**(危殆/昏迷/死亡全由 `position` 越阈判定) | **必须 `≥ A_peak`**;`> 0` | `*待定*` |

> **`SCALE_病种 ≥ A_peak` 是硬约束,不是建议。** 若 `SCALE < A_peak`,`position` 会**永久钉在 1.0**,
> 玩家看到的重病永远是「满格」—— 趋势读数失真,8 诊断的难度阶梯塌掉。

### 三、复发(仅疟疾类病种)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `relapse_interval` | 两次复发间隔 | **必须 `> 0`** —— 写入期拒绝 0 或负(见 Edge Cases) | `*待定*` |
| `A_rel` | 复发峰值 | `> 0`;`≤ A_peak` 时复发更轻 | `*待定*` |
| `τ_rel_fall` | 复发衰减 | `> 0` | `*待定*` |

> **三字段同生共死**:`relapse` 块出现时三个必须齐全(R1.3 校验三)。
> **`A_rel` 与 `A_peak` 的大小关系是叙事旋钮** —— `A_rel < A_peak` 时复发是「余烬」,
> `≥` 时是「你以为好了,其实是它藏起来了」。**《他回来了》的力度就拧在这里。**

### 四、噪声与读数

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `σ` | **病情波动 + F3 保守带宽度**(一个旋钮两处受力) | `≥ 0`。**越大 → CatchUp 扫描越多** | `*待定*` |
| `N` | 噪声查表分辨率 | 整数,`> 0` | `*待定*` |
| `W` | `trend` 的差分窗口(`trend` 中心 / `trend_backward` 单侧) | `> 0`,**须为偶数**(取 `W/2`) | `*待定*` |
| `TREND_EPS` | **`trend` 死区** —— `\|trend\| < TREND_EPS` 判「持平」 | `> 0`。**防 Q16.16 量化抵消把 plateau 段判成随机抖动** | `*待定*` |

> ⚠️ **`σ` 是本节唯一「一动动两处」的旋钮。** 它同时是病情噪声**和** F3 保守带宽度 ——
> 调大让病程更「活」,代价是离线补算更慢。**这是刻意的耦合,不是缺陷**:
> 噪声越大,边界越难闭式定位,保守带**就该**更宽。但它意味着**调 σ 时必须同时看性能**。

### 五、阈值(状态转移 · 铁律一的落地)

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `CRITICAL_THRESHOLD` | 进入**危殆** | **`< COMA_THRESHOLD`**(三者必须单调)`∈ (0,1]` | `*待定*` |
| `COMA_THRESHOLD` | 进入**昏迷**(C1 登记点) | **介于 CRITICAL 与 DEATH 之间** | `*待定*` |
| `DEATH_THRESHOLD` | **死亡门** | **`> COMA_THRESHOLD`** 且 **`< 1`** —— **不得取 1**:保守舍入会让 `position = 1−ulp < 1`,死亡永不可达(校验 9) | `*待定*` |
| `TREATMENT_WINDOW` | **处置窗口** —— 最后一次有效对因处置后多久算「放弃」 | `> 0`。**这是铁律一的时间维度** | `*待定*` |

> **三阈值的单调性是硬约束**:`CRITICAL < COMA < DEATH`。任何倒置都会造出一个
> 「先死后昏迷」的状态机 —— 构建期应直接拒绝。
> **`TREATMENT_WINDOW` 是最敏感的一个**:太短 → 玩家稍一离开病人就死,**违反铁律一**;
> 太长 → 死亡几乎不可能达成,**铁律二的悲剧面消失**。**它同时是 D-9-A(见死不救代价)的物理下限。**

### 六、性能与确定性

| 旋钮 | 影响 | 安全区间 / 约束 | 默认 |
| ---- | ---- | ---- | ---- |
| `FIXED_ITER` | 二分定位的**固定迭代上限** | **正整数**。只保证「确定终止」,**不保证收敛到正确根** | `*待定*` |
| `ε_PRUNE` | **复发脉冲剪枝门** —— 峰值低于它后续脉冲全部忽略 | `> 0`。**把复发型病种的边界数从「随离线时长线性」降为常数**(F3) | `*待定*` |
| `boundary_mode` | **每病种**:能否闭式求解 | enum `monotone` / `scan`。**默认 `monotone`,配错了要显式认领 `scan`** | **P0 8 项全 `monotone`**(2026-09-13 定,见 OQ-5) |

> **`FIXED_ITER` 的正确性依赖 `σ`**:保守带内才二分,`σ` 越小带越窄、迭代越少。
> **固定迭代数量本身就等于引入了「最多扫这么多步」的截断** —— 这是刻意的:
> **宁可误差有界,不要迭代次数不定**(那会让不同机器跑出不同迭代数 → 破坏 ADR-005 的逐位一致)。

### 七、旋钮耦合总表(实现前必读)

| 你若拧这个 | 会牵动 | 怎么发现拧过头了 |
| ---- | ---- | ---- |
| `TICK_SECONDS` | 5 / 25 / 7a 全部时间戳 | 存档打开后病程对不上 |
| `σ` | F3 补算耗时 | 离线一个月的存档读盘变慢 |
| `A_peak` | 必须同步 `SCALE_病种` | `position` 长期贴 1.0 |

| `TREATMENT_WINDOW` | 铁律一 ↔ 铁律二的平衡 | 病人要么必死,要么必活 |
| `A_rel` vs `A_peak` | 《他回来了》的力度 | 复发玩家感觉不到 / 感觉像第一遍 |

> **9 自己不做任何渲染。** 它是**数据核心** —— 本节规定的是
> **它必须吐给表现层的「通道契约」**,不是它的美术需求。表现归 13 病人 AI / 8 诊断 / 42 拟物 UI。
> **这一节存在的理由**:若不在这里锁死「体征只能通过哪些通道外显」,
> 不同系统的实现者会各自发明一套,拟物 UI 的硬约束(支撑原则二)就从内部被架空。

### 一、铁律:9 的输出**不含任何可直接显示的量**

| 9 吐出的 | 禁止直接变成 | 必须经由 |
| ---- | ---- | ---- |
| `position`(0–1) | 血条 / 百分比 / 数字 | 8 诊断的**感知反馈映射表** |
| `trend`(带符号) | 上升 / 下降箭头 | 13 的**行为表现**(坐立不安 / 安静躺着) |
| `signs[]`(词表) | 图标 / 标签 | 拟物渠道:面色 · 语声 · 姿态 · 呼吸 · 触感 |
| 病程状态(九态) | 状态图标 | 病人**自己的动作与台词** |

> ⚠️ **这是支柱「无血条」在 9 这一侧的强制点。** `Player Fantasy` 的反幻想段已写死:
> 「玩家永远不会看到『病人:42 / 100』」。**本表是那句话的机制护栏** ——
> 任何把 `position` 直连 UI 的实现都是违规,应当在 code review 拦下。

### 二、体征 → 感知通道映射(P0 五通道)

> 9 定义**通道清单**,8 诊断定义**每个体征走哪个通道、阈值在哪**。
> **9 只保证「体征是离散词」,不保证「体征长什么样」** —— 后者是美术与 8 的事。

| 通道 | 承载的体征族(示例,词表归 8) | 关键约束 |
| ---- | ---- | ---- |
| **面色** | 苍白 · 潮红 · 发黄 · 发青 | 需要皮肤 shader 支持;昼夜光照下**必须仍可辨** |
| **语声** | 有力 · 虚弱 · 含糊 · 不语 | 与 42 对话系统共用;**是音频需求** |
| **姿态** | 坐起 · 半卧 · 蜷缩 · 不动 | 归 13 的动画状态机 |
| **呼吸** | 平稳 · 急促 · 浅慢 · 停顿 | **唯一可以「不看也能听出来」的通道** |
| **触感** | 发热 · 发凉 · 湿冷 | 与 10 急救动作的触诊交互绑定;VR 模式下是主通道 |

> **呼吸是 P0 最重要的通道。** 它同时走视觉(胸腔起伏)**和**音频(喘 / 咳),
> 让「你在隔壁房间也能察觉病人变坏」成立 —— 这是 Player Fantasy 锚点一
> (「世界不为你暂停」)唯一能不依赖 UI 的外显方式。

### 三、音频需求(归 42 / 音频,此处只登记 9 的接口)

| 需求 | 说明 | 归谁 |
| ---- | ---- | ---- |
| **病人呼吸层** | 随病情状态切换的呼吸音(平稳 → 急促 → 浅慢 → 停顿) | 音频设计;9 只提供状态量 |
| **咳嗽 / 呻吟** | 由 13 触发,不由 9 触发 —— **9 不产事件给音频,只产状态** | 13 → 音频(✅ ADR-016 §六:属 13 的**表现层映射**,不经 sim) |
| **无「提示音」** | ⚠️ **禁止**用 UI 音效提示「病人状态变化」 | **9 的硬约束** |
| 昏迷 / 死亡的听觉差异 | 呼吸停顿 vs 呼吸停止 —— **必须能被听出来,但不许用音效硬报** | 音频 + 动画 |

> ⚠️ **「无提示音」是本节最容易违反的一条。** 一旦加了「叮」的一声表示病人转危,
> 就把 9 变回了一个**报警器** —— 玩家不再需要判断,只需要听提示。
> **这是对支柱一「判断为骨」的直接破坏**,比数值错误严重得多。

> ✅ **2026-09-15 ADR-018 已把本表四条全部机械化。** 44 与 42 同构(只触发 / 只渲染),
> **无提示音铁律**由白名单断言守住(**AC-44-09,BLOCKING** —— sting 类 cue 被构建期拒收);
> 呼吸层 / 咳嗽呻吟走 `AudioCueDto`(`CueId` + `Tier` + `Intensity`),9 **只产状态量、发 cue**,
> 不产音频资源(与 AC-21 一致);音频事件表走 ADR-014 烘焙管线。
> 9 的 F2 投影与 44 的 cue 生成是**两条独立路径**(44 读 9 状态 → 发 cue,不经 sim)。

### 四、9 **不**需要的东西(负面声明)

- ❌ **不需要 9 自己的 UI 层或渲染层** —— 它没有屏幕
- ❌ **不需要病灶可视化**(如「感染区域」高亮)—— 那是 8 诊断的产出
- ❌ **不需要病程图表 / 曲线预览** —— 违反拟物铁律
- ❌ **不需要专门的「疾病特效」** —— 体征走**注册的通道集合**(§二 列 P0 五通道)

> ⚠️ **9 不设「通道数上限」**(2026-09-14 复核修正,blk #12)。
> 原稿写「体征走上面五通道,**没有第六条**」—— 这与 **D-8-2**(8 要求 9 增列
> 检验 / 病史 / 舌脉等**非物理证据通道**)正面冲突:8 已裁定 9 须为这些通道供数。
> **修正:五通道是 P0 的【现状】,不是【上限】;通道集合归 8 诊断拥有,9 只出 `signs[]` 数据。**

## UI Requirements

> **本节的绝大部分内容是「不做什么」。** 9 是**唯一一个以负面声明为主的系统** ——
> 因为它的输出**全都不许被玩家直读**。
> **正向需求只有一条**:为 8 诊断的**脉案**提供数据。

### 一、铁律:没有「疾病 UI」

| 禁止 | 理由 |
| ---- | ---- |
| ❌ **病人状态列表 / 名册** | 「世界不为你暂停」的反面 —— 一列表就把人变成了待办事项 |
| ❌ **病情进度条 / 百分比** | 反幻想段已写死:不是血条 |
| ❌ **患者计数 / 疫区红点** | 34 公卫(P1a)可以有**生态层**呈现,但那是**村落视角**,不是诊断视角 |
| ❌ **疾病名录 / 图鉴** | 知识应来自 30 技能与学习,**不是来自一张表** |
| ❌ **复发倒计时 / 预警** | 复发之所以成立,正因为**玩家不知道它要来** |

> ⚠️ **「没有名录」这条与 30 技能直接相关。** 如果有一个疾病图鉴可以查,
> 「判断」就退化成了「查表」—— 玩家不再需要望闻问切。**知识必须被挣得。**

### 二、正向需求:脉案(唯一 UI 接口)

| 需求 | 说明 |
| ---- | ---- |
| **数据供给** | 9 向 8 诊断提供 `position` / `trend` / `signs[]`;**脉案的呈现归 8 与 42** |
| **门槛在 8,不在 9** | 9 无条件给出真值;**能不能读出来**(`READ_FLOOR(Skill_诊断)`)是 8 的判定 |
| **手柄可导航** | 脉案是焦点导航界面(`technical-preferences.md` 硬约束)—— 无指针也能读 |
| **无 hover-only** | 同上 —— 所有脉案交互必须有非指针路径 |

> ⚠️ **「门槛在 8,不在 9」是一条重要的职责边界。** 9 不知道玩家技能多少 ——
> 若 9 也开始按技能过滤,**同一份病史在两台机器上会读出不同的 `Progress`**(技能等级不同),
> **直接破坏 ADR-005 的逐位一致**。**9 给真值,8 决定玩家能看到多少。**

### 三、VR 模式下的特殊性

| 需求 | 说明 |
| ---- | ---- |
| **触诊是主通道** | VR 急救动作中,`触感` 通道(发热 / 发凉)通过手柄震动传达 |
| **无平面 UI 投影** | VR 里不做脉案浮窗;体征仍走五通道 |
| **晕动症约束** | 病人状态变化**不得触发镜头效果**(`technical-preferences.md`:VR 不承担开放世界移动) |

## Acceptance Criteria

> 分组对应本系统六层结构。**每条都是 QA 可判 pass/fail 的判据**,不写「感觉对不对」。

> **分级(2026-09-14 复核新增)**:每条标注 **[L]**(逻辑 / 可在 EditMode 单测)

### OQ-5 · `boundary_mode` 的默认值 —— ✅ **已定(2026-09-13)**

**R3 定后回填:P0 全部 8 项 = `monotone`。`scan` 是留给 P1a 的钉子。**

理由 —— F3 的类 A 边界共三类,**每一类在 P0 都有闭式解**:

| 类 A 边界 | 闭式 |
| ---- | ---- |
| 潜伏 → 发病 | `onset + incubation` |
| 达峰 `τ_peak` | `onset + tau_peak` |
| 复发(第 k 次) | `onset + relapse_interval × (k + 1)` |

> ⚠️ **原稿这一行写的是「好转 / 迁延分界 = 单峰曲线的导数零点」—— 那是错的**(2026-09-14 复核,blk #1)。
> 两段指数拼接的曲线**没有内部导数零点**:上升段单调升、衰减段单调降,**唯一的「峰」在
> `τ = τ_peak`,是一个已知参数(不是求根得来的)**。原稿把它描述成「求零点」会误导实现者去写求根器。
> **今改为直接登记 `τ_peak`(闭式,`O(1)`)。** 归一化 `R_rise` 消除了原稿在此处的跳变,
> 使 `τ_peak` 成为一个真正的连续分段点。

> **⚠️ 唯一的真问题是 `DIS_MALARIA`(唯一带 `relapse.*` 的病)。**
> 若把病程写成 `Base + Relapse` 的**匿名求和**,叠加处会出现**不属于任何具名脉冲的极值** ——
> 那就要在超越方程上求根,退化成 `scan`。
> **故本设计定死一条**:`relapse.*` 块定义的是**具名脉冲**(自己的 `interval` / `a_rel` / `tau_fall`),
> 复合病程是**具名脉冲的 join,不是匿名求和** ——
> 每个脉冲的上升/峰值/衰减都有自己的闭式,故 `DIS_MALARIA` **仍是 `monotone`**。
> **这条要求已由 R1.3 的 `relapse.*` schema 保证**(三个字段必填),不是新增约束。

**什么时候才需要 `scan`**(留给 P1a):某病种的 `natural_progress`
**无法用 R1.3 的参数族表示**(如多峰、阶跃式自然史、非线性复发模式)。
**届时显式认领 `scan`,接受性能代价** —— 默认 `monotone` 不变(配错了要声明,防静默退化)。
