## 1. 概述 Overview

关卡 / 遭遇系统定义**"一个病例怎么从敲门走到收束"**。本作的"关卡"不是地图、不是迷宫，而是**一场诊疗的全过程**：一个病人（或一家人）带着一场病来找上队伍，玩家要做的不是"打到关底"，而是**在固定主线节拍的骨架上，自由地把能收集的信息、能照看的人、能下的判断做完，再回到主线把这场病了结**。系统只负责**编排**——它把既有系统当作乐器：用**对话系统**承载"问与听"，用**证候系统**承载"辨"，用**战斗系统**承载"治"，用**队伍系统**承载"谁在场、谁看得见"。本系统不发明新的医学或叙事机制，它只回答三个问题：**这一关有哪些节拍、哪些可自由探索、做错了要付出什么代价**。

> **快速索引** — 形态 = **混合**（病例主线 + 探索节点）· 编排 = **主节拍固定 + 小节自由** · 失败 = **软失败（累积代价）**（切片不设病人死亡，预留硬失败接口）· 范围 = **只做单病例关**（疫情博弈只留单向接口）· 节拍种类 = 诊 / 问 / 治 / 变 / 结。

## 2. 玩家幻想 Player Fantasy

**"我不是在推图，我是在一个病人身上花掉一个真正医者的时间。"**

玩家要体验的，是一个医者在一场病面前的**两种专注的切换**。一种是被推着走的：病人的病情不等他，主线的关键节点（病势传变、家属催逼、同行质疑）会在**固定的节拍**上找上门来，无论他准备好没有——这是**医者在时间压力下的责任**。另一种是他主动挣来的：在主线允许的间隙里，他可以**走到病家的后院**看看水缸、**多问一句**病人的起居、**翻开**案头那本旧医案——这些**可自由探索的节点**不推剧情，却常常藏着一条关键证候、一句掏心的话、或者一个能少走弯路的判断。本作最重的体验就长在这个缝隙里：**"主线催我，我却还想再看一眼"**——玩家在自己选择停留的每一刻里，亲手把"敷衍的看诊"变成"郑重的看诊"。

这份专注的反面，是**代价的重量**。本作不惩罚"死"，而惩罚"**拖**"与"**错**"：一次误诊不会让病人当场咽气，却会让他的正气一截截地掉；一次迟疑的转诊不会判负，却会让病势悄悄传变。玩家不会看到"游戏结束"，他会看到**病历上一行行累积的恶化**，到收束时算成一笔总账——**"我把他救回来了，但我让他多受了三天罪"**。这种"救回来了，但没救好"的余味，比任何死亡惩罚都更像一个医者的愧疚。

**情绪目标**：主线催促下的紧迫（时间不等人）· 自由探索的郑重（多看的每一眼都算数）· 累积代价的愧疚（救回来了，但没救好）· 收束时的豁然（这场病，我读明白了）。

## 3. 详细规则 Detailed Rules

### 3.1 系统定位与数据边界

| 上游 / 下游系统 | 从本系统取用 | 本系统不负责 |
|---|---|---|
| 战斗系统 `combat-system.md` | 遭遇节点（治段）的进入/退出、病人配置、病机 stages 编排、胜利条件（治段的）、评级结算 | 出牌、CTB、伤害结算、四诊规则、辨证 |
| 队伍系统 `party-system.md` | 出战编成（在关卡边界落定）、资源池初值、聚散状态、羁绊矩阵 | 编成规则本身、资源池核算 |
| 对话系统 `dialogue-system.md` | 问段 / 探段的对话场景、`beatId`、心声 / 发问、产物（碎片/顿悟/BondDelta/flag） | 对白文本、知识门/关系门判定 |
| 证候系统 `status-syndrome.md` | 病机 stages 表、传变阈值、状态组合、病种标签、单镜型数据形态 | 证候向量、匹配系数、状态效果本身 |
| 成长系统 `progression-system.md` | 评级 → IP_gain、顿悟事件的触发位、标签按卷引入的节奏 | 图谱结构、连线、IP 核算 |
| 任务 / 剧情流程系统（#7，待建） | 病例关卡的"主线节拍表"、剧情锚点 | 跨关卡的叙事编排（卷与卷的连接） |
| 疫情资源博弈系统（#9，待建） | **单向接口**：本系统把"升级/移交"的病例数据交出去（见 §3.7） | 群体疫情的模拟（**不在本系统实现**） |

> **边界声明**：本系统**不判证、不结算伤害、不写对白**。它只**编排节拍**（何时进诊、何时可探、何时进治、何时结算）与**累积代价**（软失败如何记账）。它像一张**病历**：记录这场病的时间轴与转归，却不替医生下药。

### 3.2 病例关卡数据结构 Case Schema

一个**病例关（Case）**是关卡系统的最小完整单元（一个病例 = 一条主线关）。数据结构：

```
Case:
  id:           case_v{n}_{slug}          // 如 case_v2_mother
  volume:       int 1..10                  // 所属卷（技能即剧情）
  patients:     [ Patient ]               // 主要病人 + 次要病人；同场实体总数 ≤ 6（见 §4.8 实体预算校验）
  mainBeats:    [ MainBeat ]              // 主节拍（固定顺序，见 3.3）
  exploreNodes: [ ExploreNode ]           // 探索节点（自由顺序，见 3.4）
  hardFail:     HardFailContract          // 硬失败接口（切片不实现，见 3.6）
  epidemicHook: EpidemicHook | null       // 升级移交疫情系统的单向接口（见 3.7）
  budget:       Budget                    // 时间/资源预算（见 §4.5）

Patient:  { id, vitalQi: {cap, current}, statuses: Set<StatusId>, isMain: bool }   // 正气条宿主
MainBeat: { beatId, kind: 诊|问|治|变|结, order: int,                 // 主节拍（固定序）
            dialogueSceneId: string | null,                          // 该节拍承载的对话场景（父子引用，见下）
            gating: Gate | null,                                      // 进入门槛（见 §4.2）
            onComplete: [ Effect ] }                                  // 完成后的效果
ExploreNode: { nodeId, kind: 探|问, location: string,                 // 探索节点（自由序）
              yields: [ Yield ],                                      // 产出（证候/碎片/羁绊/flag）
              optional: bool, onceOnly: bool }                        // 是否可选、是否一次性
```

- **主要病人**：病例的"目标病人"，其正气归零（若实现硬失败）触发硬失败；竖直切片**不实现**硬失败（见 §3.6）。
- **次要病人**：背景患者（家属、同住者）；其状态只影响**评级与剧情**，不触发判负。
- **切片"正气下限钳到 1"作用于全部病人（主要 + 次要）**：切片中**任何病人**在治段正气归零都被钳到 1，故 `combat-system.md` §5 的"主要病人死亡判负"**与**"次要病人死亡判负但允许转诊"**两条路径在切片中均不可达**（与"切片不设病人死亡"一致）。
- **`beatId` 与对话节拍是父子引用、非共用命名空间**：关卡的 `MainBeat.beatId`（如 `case_v2_mother_T1`）与对话系统的**对话节拍 `beatId`**（`dialogue-system.md` §3.3 / §5，如 `dlg_v2_mother_ask1`）是**两个粒度**——一个 `治` 主节拍可承载多个对话场景。`MainBeat` 通过 `dialogueSceneId` **引用**其承载的对话场景；去重/存档各用**自己的** `beatId` 表，跨系统以 `dialogueSceneId` 关联（**不**假定同一张去重表）。

#### 3.2.1 章层结构 Chapter Schema（含「叙事关」与「章层遭遇」）

`Case`（§3.2）只覆盖**有病例的关**。但一个**章**可能**没有病例**（**纯叙事章**，如卷一 序章·归舟），且两类章都可挂**章层遭遇**（如旁观遭遇）。故补齐章层结构：

```
Chapter:
  id:          string                 // ★ 与 quest-system.md §3.1 的 ChapterRequest.chapterId **同一命名空间**
                                      //    （唯一真源在 #7）；实例形如 vol1.prologue，见 design/levels/vol-01.md §2.1
  displayName: string
  volume:      int 1..10
  type:        叙事关 | 病例关         // 决定 case 是否可为空
  case:        Case | null            // 病例关：非空；叙事关：必须为 null
  encounters:  [ Encounter ]          // 章层遭遇（两类章皆可挂，可空）
  entryGate:   Gate | null            // 章层进入门槛（词汇见 §4.2；卷级门槛见 quest-system.md §3.8）

Encounter:                             // 章层遭遇（当前仅「旁观」一种）
  id:            string                // 如 spect_v1_old_doctor
  kind:          旁观                   // 现仅「旁观」（combat-system.md §3.10）；其余类型预留
  ctb:           bool                   // ★ 是否实例化战斗循环：false = 叙事旁观 / true = 战斗旁观（§3.10）
                                        //   卷一 A-2 = true（真跑 3 回合 CTB）；卷二"回看" = false
  script:        [ ScriptBeat | ScriptedTurn ]   // 固定演出脚本：ctb=false → ScriptBeat（叙事节拍）；ctb=true → ScriptedTurn（CTB 回合，逐回合钉死出牌，非 AI）
  playerControl: none                   // 旁观遭遇恒为 none（ctb=true 时回合推进亦不受玩家影响）
  skipAllowed:   bool                   // 是否允许整段跳过
  failMode:      none                   // 旁观遭遇恒无可失败
  yields:        [ Yield ]              // **白名单：只允许 flag**（不产评级 / IP / 碎片）
                                        // ★ flag 是**点亮事件**；"跳过时未看过"由**该 flag 缺席**表达，不写 `flagSet(id, false)`
  focusPoints:   [ FocusPoint ] | null  // 纯叙事注视点，**不产任何 yield**

ScriptBeat:  { order: int, act: 诊|辨|治|叙事, actor: string, content: string }
ScriptedTurn: { order: int,                 // ctb=true 的 CTB 回合序号（= 行动回合，非"叙事节拍"）
                actor: string,               // 出牌者（如 老郎中）
                act: string,                 // 该回合的动作（如"取麻黄"）；★ 推进信号之一
                cardId: string,              // ★ 出的牌（如 麻黄 / 杏仁 / 甘草）——见下"剧本专用牌"
                mainAxis: string,            // ★ 该牌主靶轴（如 表里:表）；配置校验据此判 M（§3.10）
                target: string,              // 目标（如 病人）
                narration: string }          // ★ 该回合的自白（判断 + 用药依据）；推进信号之二
FocusPoint:  { id, label, text }         // 如"看老郎中的手""看药柜"
```

- **★ `ScriptedTurn` 承载"逐回合出牌"（2026-09-12 增，修 `ScriptBeat` 无法携带出牌数据的缺口）**：`ScriptBeat`（诊 / 辨 / 治 / 叙事 + `content`）只能承载**叙事节拍文本**，**装不下**"哪一回合出了哪张牌、该牌主靶轴为何"——而 `combat-system.md` §3.10 的"战斗旁观"**必须**有这些字段才能**真跑** CTB 与被配置校验。故 `ctb = true` 的脚本**改由 `ScriptedTurn[]` 承载**：每个回合 = 一 `ScriptedTurn`，**必带** `act` + `narration`（`combat-system.md` §3.10 的"回合推进信号"要求），**并带** `cardId` / `mainAxis` / `target` 供结算与校验。
- **★ 剧本专用牌（NPC 牌不进玩家牌池）**：`ScriptedTurn.cardId` 指向的牌若**不在玩家牌池**（如 A-2 的麻黄 / 杏仁 / 甘草——它们是**老郎中的药**，玩家从未拥有），其定义**随脚本内联或存于剧本档**，**不注册进玩家牌池 / 医道图谱**。其 `mainAxis` / `P` 只在**该遭遇的结算档**内生效。**推论**：A-2 的三味药**不产出任何可获取牌**——它们只是"别人打的牌"（`combat-system.md` §3.10）。

- **`ctb` 决定是否真跑战斗（2026-09-12 增，A-2 起）**：`ctb = true` 时**真跑 CTB**——逐回合出牌、逐回合结算 `ΔE`，但**玩家零输入**、**数值不上屏**（呈现层与结算层分离）。`ctb = false` 时三节拍纯叙事（原定义）。**变体内部规则见 `combat-system.md` §3.10**（含"战斗旁观不产 `revealed` → 永不出 `M = 1.5`"的强校验）。**但"不结算 `Rating` / IP、不计入 `Progress`"对两模式一视同仁**——`ctb = true` **不等于**它是一场"治段"（不绑 `MainBeat(治)`）。

- **章 id 命名空间唯一**：`Chapter.id` **即** `quest-system.md` §3.1 `ChapterRequest.chapterId` / `ChapterResult.chapterId`，也是其 §3.8 `chapterDone(cid)` 的入参——**同一个字符串**，本系统**不另立前缀**。实例：`vol1.prologue`（**不是** `ch_v1_prologue`）。
- **叙事关**（`type = 叙事关`）：`case` **必须为 `null`**（无病例即无主节拍、无探索节点、无治段）；`failMode = none`；**本系统不产出其评级**——评级由任务系统 #7 按剧情完成度给出（§4.5 末段）。**配置校验拒绝**给叙事关配 `case` 或主节拍。
- **章层遭遇不是主节拍**：`Encounter` **不在** `MainBeat.kind ∈ {诊, 问, 治, 变, 结}` 之内，**不计入** `Progress`（§4.1），**不结算** `Rating`——它是**章层**的演出单元，与病例的节拍编排**正交**。
- **`ScriptBeat.act` 的 诊 / 辨 / 治 是叙事节拍，不是 CTB 回合**：三者对齐 `combat-system.md` §3.9 的三段，但**术语不得与 §4.1 的行动「回合」混用**。**`ctb = true` 时脚本改由 `ScriptedTurn[]` 承载**（见上；`combat-system.md` §3.10 的"战斗旁观"），该序列里的"回合"**才是** CTB 行动回合——**同一脚本内的"叙事节拍（诊/辨/治）"与"CTB 回合"两套计数不得混称**。
- **旁观遭遇的行为规则由 `combat-system.md` §3.10 定义**：本系统只负责**编排它何时出现、是否 `ctb`、可否跳过、产出什么 flag**，不重复定义其内部演出与数据合法性校验规则。
- **跳过语义**：跳过**不改变**用于推进链的 flag（**链完整性优先**），但"是否真看过"的 flag **仅在"未跳过"时点亮**——跳过时该 flag **缺席（未点亮）**，而**不是**写一个 `flagSet(x, false)`。理由：`yields` 白名单是 `flagSet` **事件**（只表达"点亮"），布尔否定由"事件是否发生"承载（**缺席即假**），以免引入 `flagSet(id, bool)` 的新签名。

### 3.3 主节拍（固定顺序）Main Beats

主节拍是病例的**骨架**——关键病例推进点，**顺序固定**，不可跳过，不可乱序。五种主节拍：

| 种类 | 符号 | 内容 | 是否含战斗 | 玩家能动 |
|---|---|---|---|---|
| **诊** Diagnose | `D` | 初诊 / 复诊：四诊揭示证候（交证候系统），或进入"治段"前的最终辨证 | 否（四诊是战斗内动作，见下） | 诊段投入四诊的顺序与取舍 |
| **问** Inquire | `Q` | 关键对话（问诊家属、病家内情、同行会诊）：交对话系统 | 否 | 听谁的心声、发问谁 |
| **治** Treat | `T` | **战斗遭遇**：进入战斗系统，辨证施治 | **是** | 编成、出牌、四诊（战斗内） |
| **变** Turn | `V` | 剧情转折：病情传变、家属催逼、同行介入 | 否（剧情段） | 通常无（叙事段） |
| **结** Settle | `S` | 收束：结算评级、判转归、产出顿悟 | 否 | 无（结算） |

- **顺序固定**：`mainBeats` 按 `order` 严格升序执行；**玩家不能跳过主节拍**（主节拍是"必须面对的"），但可在主节拍之间**插入探索节点**（见 3.4）。
- **治段 = 战斗遭遇**：`治` 节拍是**唯一**进入战斗系统的节拍。它把病人配置、病机 stages、编成结果交给战斗系统，收回一个**战斗结果**（病邪残余、正气保有、评级、错治/峻剂次数），再喂回给关卡的代价累积（见 §4.4）。
- **诊段的四诊**：初诊/复诊的"四诊"**不是**战斗内动作，而是**对话系统**承载的叙事段（`dialogue-system.md` §3.3）——它产出**部分证候揭示**作为**预置信息**（喂给后续治段），但**不掷骰**（问诊的 90% 只在战斗内的"问"诊法出现，见 §3.5 与 `status-syndrome.md` §4.7）。
- **变段的传变**：`变` 节拍可触发**剧情强制传变**（病机的 `stageIndex` 前进，重置已揭示轴）——复用 `status-syndrome.md` §4.4 的传变规则，**确定性、无随机**。
- **章层遭遇不在五种主节拍之列**：旁观遭遇等 `Encounter`（§3.2.1）是**章层**演出单元，**不是**主节拍——不计入 `Progress`、不结算 `Rating`（见 §3.2.1 与 `combat-system.md` §3.10）。

### 3.4 探索节点（自由顺序）Explore Nodes

探索节点是病例的**血肉**——玩家在主节拍之间可**自由探索**的节点，顺序自由、可选、多数一次性。

- **位置与解锁**：探索节点挂在**主节拍之间**的"间隙"上；只有当前主节拍完成后，其后的间隙才解锁（玩家不能跳到未解锁的间隙）。
- **★ 自由探索窗口（辨证窗口 · rev g 新增，承 N4）**：`问 Q` → `治 T` 之间的间隙是本作的**核心自由探索窗口**——玩家的**"看一看、再问一句"**就发生在这里，决定治段手里握着哪些已知证候（`revealed` 轴）。为**保证窗口存在**，配置期强校验如下：
  - **凡 `case` 含 `治` 节拍者，`问` 与 `治` **之间必须存在至少一个间隙**；`mainBeats` 不得让 `Q` 与 `T` 的 `order` 相邻而无间隙。**违者配置非法**（与 §4.8 实体预算同为配置期强校验）。
  - **窗口内容**：挂在该间隙上的探索节点（`探` 揭示证候轴 / `问` 产 flag 与碎片）由关卡配置给全；窗口**本身上下不设回合上限**（玩家可把该间隙的节点探完，或不探直接推进——`§3.4 可跳过` 仍成立）。
  - **为什么强制**：`combat-system.md` §4.3 的 `M = 1.5`（对证）档与悖证判定都以 `revealed` 为前提。**若窗口缺席，`revealed` 恒为空 → 卷一永不出现 `M = 1.5`、"探不探"的权衡整条失效**（即 N4 所指：`ex_v1_m_4` / `ex_v1_m_5` 无处可挂）。故窗口不是"建议有"，而是**本系统对战斗系统可玩性的硬承诺**。
  - **与 `诊 D` 的分工**：`诊` 节拍产出的证候揭示是**预置信息**（§3.3），**不替代**窗口——`诊` 只覆盖配置指定的一小部分轴；窗口里的 `探` 节点是玩家**主动**去补的其余轴。
  - **怠慢交互**：窗口内连续结算 ≥ `neglectThreshold` 个节点而不推进 `治`，按 §4.4 记**怠慢**——"病人在等，你还在看"正是本系统的核心张力（§2 玩家幻想）。
- **种类**：
  - **探（察看）**：到某个地点（后院、厨房、病家卧房）察看，产出**证候线索**（揭示某轴的一个极）、**环境 flag**（如"水缸生苔 → 湿邪"）——确定性，无随机。
  - **问（闲谈）**：与次要角色（家属、邻居、药铺伙计）闲谈，交对话系统，产出**点拨碎片**、**BondDelta**、**剧情 flag**。
- **产出（Yield）**：探索节点的产出全部是**既有系统的输入**——证候线索喂证候系统、碎片喂成长系统、BondDelta 喂队伍系统、flag 喂任务系统。**本系统不消化产出，只负责"什么时候给"。**
- **可跳过**：探索节点**可选**——玩家可以不探任何节点，直接推主线。但探索节点藏着**少走弯路的信息**（证候线索、关键 flag），不探则后续治段更难（信息更不全）——**"探不探"是玩家的权衡**（时间 vs 信息），见 §4.5。
- **一次性**：多数探索节点 `onceOnly = true`（看过即消耗，防刷）；少数（如"复诊"）可重复。

### 3.5 随机性边界：本系统零随机 Randomness Boundary

- **本系统不引入任何新的随机源**。全作**唯一**的随机源是**战斗内"问"诊法的 90% 准确率**（`status-syndrome.md` §4.7），且它只发生在**治段**（战斗）内。
- **诊段（对话系统的问诊）不掷骰**：初诊/复诊的"问"是**对话**（队友之间、医者与家属之间），不是战斗内的四诊"问"诊法；它产出的是**确定性的剧情事实**（"病人说怕冷"是剧情写死的），不含随机。
- **探索节点不掷骰**：探节点的产出是**配置写死的**（这个后院的水缸一定生苔），不是"随机掉落"。
- **战斗内的问诊**：治段进入战斗后，战斗内的"问"诊法（`status-syndrome.md` §3.4 / §4.7）才引入 90% 随机——**那是战斗系统的事，本系统只把战斗当作黑盒调用**。
- **结果**：给定（编成、已揭示信息、玩家选择），**关卡的全部节拍结果与代价累积都是确定性的**——唯一的不确定性只在战斗内的"问"诊法，且那是既有系统的既有规则。

### 3.6 失败语义：软失败 + 硬失败接口 Failure Semantics

- **软失败（切片默认）**：单次失误**不直接判负**，而是**累积代价**。代价以三种形式累积（见 §4.4）：
  1. **病人状态恶化**：错治伤正、峻剂损正、病机 drain——病人的正气保有率下降。
  2. **时间 / 资源损失**：病势传变（治疗窗口缩短）、耐药/紊乱上升（牌效衰减）。
  3. **关系变化**：错治或怠慢累积 → 病家信任度下降（喂任务系统，影响剧情分支与后续病例）。
  **切片不设病人死亡**——病人的正气**下限钳到 1**（不归零），故**永不触发"正气归零判负"**（战斗系统 §3.1 的判负路径在切片中不可达）。
- **硬失败接口（预留，不实现）**：为后续接入预留**接口契约**，切片**不实现**（见 §4.6 的接口定义）。契约规定：若某关配置 `hardFail.enabled = true`，则病人正气归零时**不钳到 1**，触发硬失败回调（如"主要病人死亡 → 关卡判负"）。**本系统只定义接口的形状，不实现其逻辑。**

### 3.7 疫情博弈的单向接口 Epidemic Hook

- **只做单病例关**：本系统只覆盖**单个病例**关卡；**群体疫情（#9 疫情资源博弈）不在本系统实现**。
- **单向接口**：本系统只负责**把病例"升级/移交"给疫情系统**的**数据出口**，不负责疫情系统的逻辑。当一个病例满足**移交条件**（如"该病机带 `d_epidemic` 标签且病家出现 ≥2 名次要病人"），本系统产出一个 **`EpidemicHandoff`** 数据包（见 §4.7），交给疫情系统（#9，待建）。**疫情系统如何处理、是否升级为群体疫情，由 #9 决定**——本系统只"递出去"，不"管后续"。
- **切片范围**：竖直切片（卷 1–3）**只递数据包，不实现疫情系统的接收端**——`EpidemicHandoff` 只作为**占位数据**产出并记录，供后续 #9 接入。

## 4. 公式 Formulas

### 4.1 主节拍进度 MainBeatProgress

```
Progress(case) = 已完成主节拍数 / 主节拍总数
                = |{ b ∈ mainBeats : b.completed }| / |mainBeats|
```

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| mainBeats | list | 5–9 个 / 关 | 主节拍（诊/问/治/变/结），顺序固定 |
| completed | bool | — | 该主节拍是否已完成 |
| Progress | float | [0, 1] | 关卡进度（0 = 未开始，1 = 已收束） |

**示例**：某关主节拍 = [诊, 问, 治, 变, 治, 结]（6 个）；玩家已完成 [诊, 问, 治] → `Progress = 3/6 = 0.5`。
**预期输出范围**：[0, 1]；单调递增（主节拍不可回退）。

### 4.2 主节拍进入门槛 Gate

部分主节拍有**进入门槛**（Gate）——玩家须先满足条件才能推进。门槛是**确定性的**（无随机）：

```
Gate(b) = 所有 gating.conditions 皆满足
condition 种类：
  revealed(axis)          → 该轴已被揭示（证候系统）
  flagSet(flagId)         → 某剧情 flag 已点亮（对话/探索产出）
  heardWall(char)         → 已听过某角色的「wall 层」心声（对话系统关系门产出的事件）
  eventSeen(eventId)      → 某对话 / 关卡事件已被经历
  poolHas(side)           → 本场牌池含某侧资源（队伍系统，见 §4.3）
```

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| condition | expr | — | 确定性布尔条件 |
| Gate | bool | — | 所有条件满足才放行 |

> **口径钉死（羁绊阈值唯一真源）**：关卡 Gate **不直接比较羁绊数值**（**不存在** `bondGE(char, N)` 这种条件）。"信任"一律由**对话系统的关系门**判定（`dialogue-system.md` §3.7：表层 0 / `mid` 50 / `wall` 75），并以**事件**（`heardWall` / `flagSet`）暴露给关卡层。这样全篇只有**一处**羁绊阈值逻辑（对话 §3.7），关卡层只**读事件、不读数值**，避免两套阈值语义在同一数值（如 50）上打架。

**示例**：某"治"节拍的 Gate = `revealed(寒热)`（须先取得**寒热这一轴**的信息才能下药；★ **但教学期禁用此类门槛**，见下"门槛提示口径"）；某"问"节拍的 Gate = `heardWall(陆九针)`（须先听过陆九针那条只有 Bond ≥ 75 才浮现的心声，才会说出关键内情）——注意此门槛的**判定者是对话系统**，关卡只检查"那条心声是否已被听过"这一事件。
**未满足门槛**：该主节拍**不可推进**；系统提示**只给"还没做过什么"**（如"巷口那位，你还没问过""陆九针还没把话说透"）——**不给"还没辨明什么"**。逐字口径见下块。

> **★ 门槛提示口径（2026-09-12 增；承 `vol-01.md` §2.7 临床层边界 / 甲b 约束③；`onboarding-system.md` §3 规则六之真源）**
>
> **规则：门槛未满足时，提示只说"玩家还没做过什么"（动作 / 未探的节点 / 未问的人），绝不说"角色还没辨明什么"（证候结论 / 辨证判断）。**
>
> | | 示例 |
> |---|---|
> | **允许**（动作 / 地点 / 人） | 「巷口那位，你还没问过。」·「院里的水缸，你还没细看。」·「陆九针还没把话说透。」 |
> | **禁止**（证候结论 / 辨证判断） | 「尚未辨明寒热。」·「须先辨明寒热才能下药。」·「证候未明。」 |
>
> - **为何禁**：① **辨证之法是刻意留下的缺口**——**一级教学弧**的全部落点是"玩家看见现象、**说不出**怎么从现象走到判断"（`vol-01.md` §1.3 一级 / §2.4）。说出"尚未辨明寒热"**等于替玩家做了那步推理**，把缺口当场填上。② **术语禁令**——"寒热 / 表里 / 虚实"是中医术语，章 B 人间层**禁用**（`vol-01.md` §3.8），门槛提示**同受限**（承甲b 文本约束③「禁机制提示」）。③ **不损本条初衷**——"确定性的教学引导"仍成立，只是引导**动作**而非**结论**：玩家知道"该去问巷口那位"，仍须**自己**从回答里得出"是寒"。
> - **`revealed(轴)` 类门槛的提示**：**指向可探索节点，不点轴名**——其补全路径**必然**是某个 `探` / `问` 节点（见下"★ 补全路径的唯一承载"），故提示节点**既完整、又无泄露**。
> - **★ 教学期禁用 `revealed(轴)` 门槛（序–卷三主节拍）**：教学期主节拍 Gate **一律只 gate 动作**（`flagSet` / `eventSeen` / `heardWall` / 节点进度）。**理由**：`revealed` 门槛 = **强制探**，而卷一的教学弧**恰恰长在"未探"分支上**——`vol-01.md` §1.3 **二级教学弧**（"我赢了，可我不知道我为什么赢"）的锚点 **甲a**、以及 **D13 裁决的唯一文本落点 甲b**，**都要求玩家停在"未探寒热"**。把 Gate 压在 `revealed(寒热)` 上 = **同时抹掉二级教学弧与 D13**（**范例**：`vol-01.md` §3.3 `T1` 门槛取 `flagSet(vol1.mother.history_told)`〔已问过〕而**非** `revealed(寒热)`——后者会使**甲a / 甲b 两支不可达**；**乙a 仍可达**）。**卷四起解禁**（**汇通图开放** = `progression-system.md` §3.7；教学期结束）。此条为**配置期强校验**。
> - **★ 依据范围（2026-09-12 更正）**：硬据**目前只在卷一如实成立**（唯一已写成的关）。⚠️ **本条的旧理由"序–卷三玩家不持有四诊牌、拿不到 `revealed`"已作废**——`vol-01.md` §3.4 实证 探 / 问 节点**确实产 `revealed`**（`ex_v1_m_1` / `ex_v1_m_3` → `revealed(寒热)`，`ex_v1_m_4` → `revealed(虚实)`），且四诊在**卷二**解锁（`progression-system.md` §3.7）、**非**卷三。**真正的理由是"强制探会消灭未探分支"**（见上）。序 / 卷二 / 卷三的教学弧**尚未写成**，属**待证**——其 `revealed` 门槛须**逐例登记论证**（内容层不得自行设定，见 `vol-01.md` §8 硬约束 1 / 4）。
> - **★ 适用范围（2026-09-12 增，关闭范围洞）**：本禁令覆盖**全部两处 Gate 挂载点**——① `MainBeat.gating`（§3.2）；② **`Chapter.entryGate`**（§3.2.1）。**不只是主节拍 Gate**。`ExploreNode` 现无 Gate 字段（§3.2 结构，只有 `optional` / `onceOnly`），故不在范围内；**若将来给 `ExploreNode` 加 Gate，本禁令一并覆盖**（同一 `revealed(axis)` 判定，同一理由）。配置期校验须遍历两处。

> **★ 补全路径的唯一承载（rev g · 承 N4）**：`revealed(axis)` 类门槛的补全，**必须**由 §3.4 的**自由探索窗口**（`问 Q` → `治 T` 间隙）上的 `探` 节点承载。因此配置期同时强校验：**凡某 `治` 节拍的 Gate 含 `revealed(a)`，且该轴在更早的 `诊`/`问` 节拍中未被预置揭示，则该关必须在 `Q`→`T` 间隙里给出至少一个产 `revealed(a)` 的 `探` 节点**——否则该关的 Gate 在合法流程下**不可满足**，配置非法。这一条把 N4 的"节点无处可挂"从**运行时报错**提前为**配置期拒绝**。

> **★ 补全路径必须是确定性的（2026-09-12 增 · 全卷次）**：`revealed(a)` 门槛的补全路径**必须**由**确定性**手段承载（**探 / 闻 / 望 / 切**），**不得以 问诊 为唯一路径**。**理由**：问诊是**唯一随机源**（`status-syndrome.md` §4.7，accuracy `0.90`），且未命中时给出的是**"错报"——相邻极或降 1 级强度，玩家无法直接分辨真伪**。若某轴的唯一补全路径是 问诊，则该门槛**受运气把关**：玩家可能"问了、也过了门槛"，却基于**错报**出手，直接违反核心承诺「失误是选择的结果，不是运气的结果」（`combat-system.md` §4.3）与 §3.4「教学段一律零随机」。**配置期校验**：凡 `revealed(a)` 门槛，其补全路径集合中**至少一条**的 `method ≠ 问`。**注**：卷一无 `revealed` 门槛，故本条在卷一无实例化约束；其对序–卷三的实际分量随各卷教学弧写成而兑现。

### 4.3 本场牌池与战斗型（引用 `party-system.md` §4.7 / `combat-system.md` §4.10.1）

```
牌池 P = (∪ 出战者 singles) ∪ (可用「通」)
has_R = ∃ card ∈ P : cost.type = 剂量
has_H = ∃ card ∈ P : cost.type = 气机
has_R ∧ has_H → 双核；仅 has_R → 速攻型；仅 has_H → 持守型；空池 → 配置拒绝
```

- **本系统只消费**战斗型判定结果（用于"治"节拍的难度提示），**不重新定义**。
- **编成在关卡边界落定**：进入关卡时，玩家在编成交界（由队伍系统托管）选定出战编成；**进入关卡后不可换编**（`party-system.md` §3.7）。

### 4.4 软失败代价累积 Cost Accumulation

软失败的代价以**三通道**累积，喂给最终评级（§4.5 复用战斗评级）与剧情：

```
① 正气保有率 VitalRate = 收束时 主要病人正气 / 主要病人正气上限
                          （切片中正气下限钳到 1，故 VitalRate > 0 恒成立）

② 病势恶化度 ShiftCount = 本关发生的传变次数（含剧情强制传变 + 战斗内传变）
                          每次传变 → 治疗窗口缩短、已揭示轴重置

③ 信任变化 TrustDelta = Σ 错治次数 × (−5) + Σ 怠慢次数 × (−3) + Σ 正确决断 × (+2)
                        错治 = 悖证触发次数（战斗系统 §4.3b）
                        怠慢 = 见下「怠慢定义」（自包含，不依赖他节）
                        正确决断 = 满足 Gate 后「当拍推进」主节拍的次数
                        信任度喂任务系统（#7），影响剧情分支
```

**怠慢定义（自包含）**：某主节拍在其 Gate 已满足后，玩家**连续结算 ≥ `neglectThreshold` 个探索节点**仍未推进该主节拍 → 记 **1 次怠慢**（每超过 `neglectThreshold` 的整数倍再记 1 次）。语义：「病人的处置条件已备齐，你却先忙别的」。

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| VitalRate | float | (0, 1] | 正气保有率（切片中 > 0） |
| ShiftCount | int | 0–4 | 传变次数（越多越糟） |
| 错治次数 | int | 0–6 | 悖证触发次数（战斗 §4.3b） |
| 怠慢次数 | int | 0–6 | 门槛已满足却连续延宕的计数（见上） |
| neglectThreshold | int | 2（见 §7） | 连续结算多少探索节点记 1 次怠慢 |
| TrustDelta | int | −30 – +10 | 信任变化（喂任务系统） |

**聚合顺序（钉死）**：三通道**独立累积**，不互相乘算；最终评级由战斗系统的 `Rating`（§4.5）主导，本系统的三通道只作为**剧情与后续关卡的输入**（TrustDelta 喂任务系统、VitalRate 喂后遗症判定）。
**预期输出范围**：VitalRate ∈ (0, 1]；ShiftCount ∈ [0, 4]；TrustDelta ∈ [−30, +10]（下界 = 6×(−5) + 0 + 0；上界 = 0 + 0 + 5×(+2)）。

### 4.5 关卡评级与顿悟点（引用 `combat-system.md` §4.7 / `progression-system.md` §4.5）

```
战斗评级 Rating（治段）= 由战斗系统结算（combat §4.7）
关卡 IP_gain = IP_base × Rating × (1 + 首次通关加成)    （progression §4.5）

IP_base = f(关卡难度)         // 随卷次与病例复杂度配置，见 §7
```

| 变量 | 范围 | 来源 | 说明 |
|---|---|---|---|
| Rating | 0–1 | combat §4.7 | 战斗评级（治段的结算） |
| IP_base | 2–8 | 关卡配置 | 随卷次递增（progression §4.6） |
| 首次通关加成 | 0 或 0.5 | progression §4.5 | 首通 +50% |

**示例**：某关 `IP_base = 5`，治段 `Rating = 0.9`〔rev h 口径〕，首通 → `IP_gain = 5 × 0.9 × 1.5 = 6.75 → 7 IP`。
- **无治段的关**（纯叙事关）：若关卡无"治"节拍，则 `Rating` 由**任务系统**（#7）按剧情完成度给出，本系统不结算。

> **★ `IP_base` 重校（rev h 登记，承 `combat-system.md` §4.7 D12 裁决）**：D12 给「回合效率」定平台函数 **`Eff = clamp(R_ref / R_actual, Eff_min, 1.0)`** 后，`Rating` 的取值带**整体上移**（旧口径"回合效率 = 0.5"→ 卷一`Eff ≡ 1.0`，六子支**各 +0.10**）。`IP_gain = IP_base × Rating` 是**线性**的，故**同一段玩法的 `IP_gain` 会随之上移 ~10–20%**。**处置**：
> - **`IP_base` 的 2–8 区间暂留**（progression §4.6 尚未定死各关取值），但**配套伸缩规则**：`IP_base_new ≈ IP_base_old × (Rating_old 均值 / Rating_new 均值)`——使"同一段玩法产出的 IP 总量"与旧口径对齐，避免**评级口径变更**误当成**成长加速**。
> - **本文件不结算 `Rating`**，只搬运——重校的**权威落点**在 `progression-system.md` §4.5 / §4.6（IP 曲线）。本行**登记该连带项**，待 progression 侧与本卷数值同批确认。
> - **示例口径**：上例 `Rating = 0.9`（rev h）对应旧口径的 `0.8`（`0.8 + 0.10 = 0.9`）——**同一段玩法**，`IP_gain` 由 `6 IP` 变 `6.75 IP`，正是需重校的部分（若要保持 6 IP，`IP_base` 应落 `5 × 0.8/0.9 ≈ 4.4`）。

### 4.6 硬失败接口契约 HardFailContract（预留，切片不实现）

```
interface HardFailContract:
  enabled:     bool                     // 切片恒为 false
  onHardFail:  (patient: Patient) -> void   // 病人正气归零时回调
  condition:   patient.vitalQi.current ≤ 0 ∧ patient.isMain

切片行为（enabled = false）：
  patient.vitalQi.current = max(patient.vitalQi.current, 1)   // 下限钳到 1，永不归零

后续接入（enabled = true，不在切片实现）：
  病人正气 ≤ 0 → 不钳 → 触发 onHardFail(patient) → 关卡判负
```

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| enabled | bool | false（切片） | 硬失败开关（切片恒关） |
| onHardFail | fn | — | 硬失败回调（切片不实现） |

**切片承诺**：`enabled = false` → 病人正气**下限钳到 1** → **永不触发**"正气归零判负"（战斗 §3.1 的判负路径在切片中不可达）。接口契约**只定义形状**，供后续接入，**不在切片实现**。

### 4.7 疫情移交数据包 EpidemicHandoff（单向接口）

```
EpidemicHandoff:
  caseId:        CaseId                  // 来源病例
  diseaseTags:   Set<TagId>              // 病种标签（须含 d_epidemic 才移交）
  patientCount:  int                     // 本关病人总数（主要 + 次要）
  severity:      float                   // 平均 VitalRate（越低越重）
  timestamp:     VolumeTick              // 移交时的剧情时点

移交条件（确定性）：
  handoff ⟺  diseaseTags ∋ d_epidemic  ∧  patientCount ≥ 2
```

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| diseaseTags | set | — | 病种标签（须含 `d_epidemic`） |
| patientCount | int | 1–2（切片） | 本关病人总数；上限受 §4.8 实体预算约束 |
| severity | float | (0, 1] | 平均正气保有率（越低越重） |

**示例**：某关含 `d_epidemic` 病机、2 名病人 → 移交条件满足 → 产出 `EpidemicHandoff` 数据包，交疫情系统（#9）。**本系统只产出，不处理。**

### 4.8 实体预算校验 Entity Budget（配置期强校验）

**本条回应 `party-system.md` §6 的联调待办**（4 医者 + 2 病人 + 1 病机 = 7 会超 `combat-system.md` §3.1 的 ≤6 实体/场预算）：

```
同场实体数 Entities(关) = |出战医者| + |病人| + |病机|
硬约束：Entities(关) ≤ 6        // 与 combat §3.1 / status §4.9 的 ≤6 实体预算一致
配置校验：任一关若 Entities > 6 → 配置期拒绝（关卡表非法）
```

| 变量 | 范围 | 来源 | 说明 |
|---|---|---|---|
| 出战医者 | 1–4 | 队伍编成（`party-system.md` §4.1，`PartySize = min(4, 可编成人数)`） | 关卡边界落定 |
| 病人 | 1–2 | 本关配置 | 主要 1 + 次要 ≤1（切片） |
| 病机 | 1 | 本关配置 | 单病例关**单病机** |
| Entities | ≤6 | 校验式 | 超限即配置非法 |

**示例**：4 医者 + 2 病人 + 1 病机 = 7 > 6 → **配置期拒绝**：该关须减 1 名病人（`patientCount=1`）或提示玩家减 1 名医者。切片默认病例配置为 **3–4 医者 + 1 主要病人（+0~1 次要病人）+ 1 病机**，故常落在 ≤6 内。
**与 §4.7 的关系**：`EpidemicHandoff.patientCount` 的取值受本条上限约束（切片 1–2）；疫情系统（#9）若需更大规模，走其**自身**的实体调度预算，不扩张本系统的单关上限。

## 5. 边界情况 Edge Cases

| 场景 | 会发生什么 | 理由 |
|---|---|---|
| **主节拍门槛未满足**（如还没问过病人怕冷怕热就想下药） | 该主节拍**不可推进**，系统提示**玩家还没做过什么**（如"巷口那位，你还没问过。"）；玩家须先通过探索节点或对话补全 | 门槛是确定性的教学引导（§4.2）。**提示只给动作、不给证候结论**——禁"尚未辨明寒热"（§4.2「门槛提示口径」） |
| **探索节点全部跳过**（玩家直推主线） | **允许**——主线节拍不依赖探索节点的产出即可推进；但玩家会**信息更不全**（证候未揭示、flag 未点亮），后续治段更难 | "探不探"是权衡（§3.4） |
| **探索节点产出与主线门槛冲突**（如探索已揭示寒热，但主节拍门槛要求"辨明寒热"） | 探索节点的证候揭示**计入**门槛——`revealed(寒热)` 看的是**证候系统的实际状态**，不限于主节拍内的揭示 | 信息是全局的（§3.4） |
| **病人在治段正气归零** | **切片**：正气下限钳到 1（不归零），战斗**不判负**，战斗继续；评级因正气保有率低而下降 | 切片不设病人死亡（§3.6） |
| **次要病人在治段正气归零** | **切片**：同样**钳到 1**——`combat-system.md` §5 的"次要病人死亡→判负但允许转诊"路径在切片中**不可达**（切片对所有病人一律不判负） | 切片关闭判负路径（§3.6） |
| **同一结算中病邪归零、病人正气也归零** | **切片**：正气钳到 1（不归零），故**不触发**战斗 §5 的"同刻双归零判负"；判胜 | 切片关闭判负路径（§3.6） |
| **剧情传变重置已揭示轴、恰使某"治"节拍 Gate 回退为不满足** | **不构成死结**：①配置校验强制——凡有「传变重置轴 + 依赖该轴的 Gate」的关，**必须**在传变之后安排至少一个可**重新揭示该轴**的探索节点或"问"节拍，否则该关配置**非法**；②运行时若玩家已过传变、Gate 不满足，系统按①给出的补全路径提示**那个可重新揭示的节点**（如"院里的水缸，你再细看一遍。"），**不得**说"需重新辨明寒热"（§4.2「门槛提示口径」）；③`Progress` 的**单调递增**只约束**主节拍**已过者不回退，**不约束** `revealed` 轴状态——二者是不同量（§4.1 / §4.2） | 防止"门槛永远补不齐"的死结（§3.3 / §4.2） |
| **编成为单核（缺一只眼睛）遭遇单镜型病机** | 治段进入战斗后，由**战斗系统**处理（`combat-system.md` §4.10.4：四诊返回"无显著证候"或病邪免疫）；玩家可**转诊**（退出战斗，回编成界面换人重进） | 战斗系统兜底（§3.3） |
| **转诊（退出战斗重进）** | **允许**：退出治段 → 回编成界面 → 换编成 → 重进治段；**不判负、不累积代价**，但**病势已传变的状态保留**（传变不重置） | 医疗语境的合理逃逸（§3.3 / combat §5） |
| **探索节点的"问"产出顿悟事件** | 顿悟事件喂成长系统（`progression-system.md` §3.6），若玩家已备好两端节点 → 免费生成一条「通」；若未备好 → 顿悟挂起 | 探索的额外奖赏（§3.4） |
| **主节拍之间无可探索节点** | 该间隙**无探索节点**，玩家只能直接推进主节拍——**正常**，探索节点不是每关都有 | 节奏控制（§3.4） |
| **关卡中途存档 / 退出** | 在**主节拍边界**或**探索节点结算后**落盘；战斗中途不可存（战斗系统 §5）；中途退出视为**未结算当前节拍** | 状态一致性 |
| **剧情要求队员在关卡中途离队** | **推迟到关卡边界**执行（`party-system.md` §5）；战中不撤人 | 状态一致性 |
| **移交给疫情系统的数据包，疫情系统未实现** | 数据包**产出并记录**（存档），但**无接收端**——切片中它只是一个**占位**，供后续 #9 接入 | 单向接口（§3.7） |
| **硬失败接口被误开启**（enabled = true） | 配置校验**拒绝**：切片版本 `enabled` 必须为 false；尝试设为 true 会触发配置错误 | 切片不设硬失败（§3.6） |
| **探索节点 onceOnly = false 被反复刷** | 少数可重复节点（如"复诊"）的产出**去重**：同一 `nodeId` 的碎片 / flag **只发一次**（按 `nodeId` 去重），BondDelta 受单场上限约束 | 防刷（§3.4 / dialogue §5） |
| **病家信任度降至极低** | TrustDelta 喂任务系统（#7），可能触发**剧情分支**（病家转而求助同行）；本系统只产出数值，不判分支 | 软失败的关系代价（§4.4） |
| **章层旁观遭遇被跳过** | **允许**：整段演出跳过；其**用于推进链的 flag 照常点亮**（链完整性优先），但"是否真看过"的 flag **不点亮**（**缺席 = 未看过**，不写 `flagSet(x, false)`） | 跳过改变的是"理解厚度"，不是"事实"（§3.2.1） |
| **给叙事关（`case = null`）配了病例或主节拍** | 配置校验**拒绝**：叙事关的 `case` 必须为 `null`、主节拍概念上为空 | 结构一致性（§3.2.1） |
| **章层遭遇的 `yields` 含评级 / IP / 碎片** | 配置校验**拒绝**：`Encounter.yields` 为**白名单，只允许 flag** | 旁观遭遇不产出成长资源（§3.2.1 / `combat-system.md` §3.10） |
| **注视点（`FocusPoint`）被当作产出节点** | **拒绝**：注视点是**纯叙事**，不产任何 flag / 碎片 / 数值 | 防"看风景"被当成探索（§3.2.1） |

## 7. 调参旋钮 Tuning Knobs

| 旋钮 | 当前值 | 安全范围 | 增大影响 | 减小影响 |
|---|---|---|---|---|
| **每关主节拍数** | 5–9 | 4–12 | 关卡更长、结构更复杂 | 关卡更短、节奏更快 |
| **每关探索节点数** | 2–6 | 0–10 | 自由探索空间大、信息更全 | 线性推进、探索感弱 |
| **探索节点产出密度**（证候线索/碎片/flag 的比例） | 各 1/3 | — | （内容旋钮，非数值） | — |
| **主节拍门槛严格度**（Gate 的条件数） | 0–2 条件 / 节拍 | 0–4 | 更多前置要求、教学引导强 | 门槛宽松、自由度高 |
| **信任变化系数**（错治 −5 / 怠慢 −3 / 正确 +2） | −5 / −3 / +2 | −10..0 / −5..0 / 0..+5 | 软失败的关系代价重 | 关系代价轻、更宽容 |
| **怠慢阈值** `neglectThreshold` | 2 | 1–5 | 更宽容（需更久延宕才记怠慢） | 更严苛（易触发怠慢扣分） |
| **传变对评级的惩罚**（ShiftCount 是否影响 Rating） | 否（Rating 由战斗系统独立结算） | — | （是否让传变额外扣评级，默认否） | — |
| **IP_base（关卡难度）** | 2–8（随卷递增） | 1–12 | 成长加速 | 成长放缓、更依赖剧情顿悟 |
| **硬失败开关** `hardFail.enabled` | **false（切片锁定）** | false（切片）/ true（后续） | （后续：启用病人死亡判负） | （切片：恒关） |

## 8. 验收标准 Acceptance Criteria

- [ ] **主节拍顺序固定**：`mainBeats` 按 `order` 严格升序执行；尝试跳过或乱序被拒绝（守卫检查）。
- [ ] **主节拍进度单调递增**：`Progress = 已完成 / 总数`，取值 [0, 1]；示例（6 节拍完成 3）→ 0.5（§4.1）。
- [ ] **主节拍门槛确定性**：Gate 的所有条件（`revealed` / `flagSet` / `heardWall` / `eventSeen` / `poolHas`）皆确定性判定，无随机（守卫检查）。
- [ ] **门槛不含羁绊数值**：Gate 定义中**不存在** `bondGE(char, N)` 这类直接比较羁绊的条件；"信任"一律经对话关系门以事件（`heardWall`）暴露（守卫检查，§4.2）。
- [ ] **门槛未满足则不可推进**：尝试推进一个门槛未满足的主节拍被拒绝，并提示**玩家还没做过什么**（守卫检查）。
- [ ] **★ 门槛提示只说动作、不说证候结论（rev k 增）**：提示文本**不出现** `尚未辨明` / `须先辨明` / `证候未明` 类**辨证结论字样**；`revealed(轴)` 类门槛的提示**指向可探索节点**而非轴名（文案守卫检查，§4.2「门槛提示口径」）。
- [ ] **★ 教学期无 `revealed(轴)` 门槛（rev k 增 · rev k+1 理据更正）**：序–卷三主节拍 Gate **不含** `revealed(axis)` 条件（一律只 gate `flagSet` / `eventSeen` / `heardWall` / 节点进度）；卷四起解禁（**汇通图开放** = `progression-system.md` §3.7）。**违者配置期拒绝**（配置校验，§4.2）。**理据**：`revealed` 门槛 = 强制探，会抹掉"未探"分支上的二级教学弧（甲a）与 D13 落点（甲b）。**依据范围**：硬据目前只在卷一如实成立；序 / 卷二 / 卷三的 `revealed` 门槛须**逐例登记论证**（§4.2「依据范围」）。
- [ ] **★ `revealed(a)` 门槛的补全路径不含唯一 `问`（rev k+1 增）**：凡 `revealed(a)` 门槛，其补全路径集合中**至少一条** `method ≠ 问`（探 / 闻 / 望 / 切）。理由：`问` 是唯一随机源（`status-syndrome.md` §4.7），唯一 `问` 路径 = 门槛受运气把关（配置校验，§4.2「补全路径必须是确定性的」）。
- [ ] **探索节点自由顺序**：玩家可在主节拍之间的间隙**自由**探索节点，顺序不限；探索节点产出（证候线索 / 碎片 / flag）正确喂给对应系统（守卫检查）。
- [ ] **探索节点可跳过**：玩家可不探任何节点直接推主线；主线节拍不依赖探索节点产出即可推进（守卫检查）。
- [ ] **探索节点一次性**：`onceOnly = true` 的节点探索后**不可再探**；`onceOnly = false` 的节点产出按 `nodeId` 去重（守卫检查）。
- [ ] **诊段四诊不掷骰**：初诊/复诊的"问"是对话系统的叙事段，产出确定性剧情事实；**不含**战斗内"问"诊法的 90% 随机（守卫检查）。
- [ ] **本系统零随机**：除战斗内"问"诊法（战斗系统托管）外，关卡的全部节拍结果与代价累积皆确定性（回归测试：同输入连测 100 次，输出一致）。
- [ ] **软失败：病人正气下限钳到 1**：切片中**所有病人（主要 + 次要）**正气**永不归零**；战斗的"主要病人死亡判负"与"次要病人死亡判负"两条路径**均不可达**（守卫检查，§3.2 / §5）。
- [ ] **同刻双归零不判负**：切片中"病邪归零 + 正气归零"时，正气钳到 1，判胜（守卫检查）。
- [ ] **代价三通道独立累积**：VitalRate / ShiftCount / TrustDelta 各自独立，不互相乘算；示例数值可核算（§4.4）。
- [ ] **怠慢可核算**：`怠慢次数` 按 §4.4 自包含定义（Gate 已满足后连续结算 ≥ `neglectThreshold` 个探索节点记 1 次）；`TrustDelta` 下界 −30 / 上界 +10 可由公式推出（守卫检查 + 用例）。
- [ ] **实体预算校验**：任一关 `|出战医者| + |病人| + |病机| ≤ 6`；示例（4+2+1=7）在**配置期**被拒绝（守卫检查 + 配置用例，§4.8）。
- [ ] **传变不造成 Gate 死结**：含"传变重置轴 + 依赖该轴的 Gate"的关，配置期强制存在可**重新揭示**该轴的补全路径；否则配置非法（守卫检查，§5）。
- [ ] **★ 自由探索窗口存在（承 N4）**：凡 `case` 含 `治` 节拍者，`问 Q` 与 `治 T` **之间必有间隙**；`Q` 与 `T` 的 `order` 相邻而无间隙的配置被**配置期拒绝**（守卫检查，§3.4）。
- [ ] **★ `revealed` 门槛有可挂载的补全节点（承 N4）**：凡某 `治` 节拍 Gate 含 `revealed(a)` 且 `a` 未在更早节拍预置揭示者，该关**必须**在 `Q`→`T` 间隙给出至少一个产 `revealed(a)` 的 `探` 节点；否则配置非法（配置用例，§4.2）。**⚠️ 本 AC 在卷一不可测**——卷一无任何 `revealed` Gate（§4.2「教学期禁用」，序–卷三），仅作为**配置层用例**成立；其首个真实实例须待序 / 卷二 / 卷三的关写成。**易混点**：`ex_v1_m_4` → `revealed(虚实)=虚` 使「补液·支持」可取 `M=1.5`（`combat-system.md` §4.8 六子支）是**节点→`M`**的实例，**不是**节点→**Gate**的实例（`ex_v1_m_4` 不是任何 Gate 的条件），不可当作本 AC 的卷一实例。
- [ ] **硬失败接口预留**：`hardFail.enabled` 在切片中恒为 false；尝试设为 true 被配置校验拒绝（守卫检查）。
- [ ] **疫情移交单向接口**：满足移交条件（`d_epidemic` 标签 + patientCount ≥ 2）时产出 `EpidemicHandoff` 数据包；数据包含全部必需字段；**本系统不调用疫情系统的任何接口**（守卫检查）。
- [ ] **转诊不判负**：玩家在治段退出战斗（转诊）→ 回编成界面换人 → 重进治段；**不判负、不累积代价**，但传变状态保留（守卫检查）。
