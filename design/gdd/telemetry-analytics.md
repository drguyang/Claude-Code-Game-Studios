## Overview

**51 是全案唯一回答「判断层到底好不好玩」的仪器。** 它交出一件事:**一条只读的分析通道**。

**① 一个只读读数器。** 51 订阅 ADR-005 / 008 / 009 已确立的三条逻辑流(病史 / 病例 / 世界),
**只读不写**。它不向三流追加一个字段、不成为第四个 `IEventSink` 写入者。它做的全部工作是:
**把流里已经存在的事件,按 `Kind` 与 `Tick` 聚合成本地指标。**

**② 一组可重算的指标。** 判断准确率(病例流 `JudgmentRecorded` / `JudgmentRevised`)、
误诊分布、跳过率、熟练度成长、难度曲线(三流的时间分布)、局内时长与节律(`Tick` 序列)——
每一项的真源都已在流里(ADR-019 §一)。**若某个量不在流里,处置是先问「它是否本就该进流」
(ADR-009 三问判据),而不是给 51 加一条旁路采集** —— 旁路会造出「事件流之外的第二个真源」。

**③ 一条本地出口。** 输出只落两处:**本地文件**(供离线分析)与**开发者调试视图**
(仅 Development Build)。**无网络、无第三方 SDK、无玩家可见统计 UI**(ADR-019 §二 / §五)。

**51 住在边界层,不是模拟的一部分。** 它不进 sim 程序集(不污染门 A)、不写三流(不污染真源)、
不出厂(隐私面因「无出厂」而结构性满足,ADR-019 §四)。它**只渲染数据给人看,永不持有游戏状态**
—— 与 42 / 44 同构,是呈现 / 分析侧的同一条纪律。

**它是 instrument(仪器),不是 subsystem(子系统)。** 全案没有第二个系统为「测量」而生 ——
51 的存在,是为了让支柱一那句「判断为骨」从声明变成可验证的事实。

## Player Fantasy

**51 没有玩家幻想。它是纯基础设施 —— 玩家感受不到 51,只感受到「被它改进过的游戏」。**

玩家永远不会看到一张统计图、一个仪表盘、一行「本周误诊率」的弹窗。ADR-019 §五 明写
**P0 无玩家可见统计 UI**;若日后需要,那属于 **42 拟物 UI 框架**的一项新呈现需求,
须另立案,不属 51。

51 服务的不是玩家,是**设计者**。它的「用户」是坐在编辑器前、想看清判断层到底哪里卡住的人。
因此本节的措辞对象是团队而非玩家 —— 这也是全案**唯一**一节 Player Fantasy 直书「无」的系统。

> **口径注**:「无幻想」≠「无价值」。51 的价值是**间接**的 —— 它把「好不好玩」从一个主观争论
> 变成一组可回放、可复现的数字,使支柱一的验证闭环成立。这属于**间接价值**,不是玩家可感知的幻想。

## Detailed Design

### Core Rules

**R1 — 51 只读,不写。** 51 的唯一输入面是 `ITelemetrySource`(三条流的只读订阅)。
**不存在**任何向三流 / 存档写入的代码路径;51 不是第四个 `IEventSink` 写入者。
判据:`grep` 不到任何 `IEventSink.Append` 的 51 调用点(ADR-019 §三 / AC-19-04)。

**R2 — 51 不埋点。** 想测的量必须**已可从事件流重算**。若某个量无法重算,
处置是**先问「它是否本就该进流」**(走 ADR-009 三问判据),而**不是**给 51 加一条旁路采集 ——
旁路会造出「事件流之外的第二个真源」。这是 51 与「AAA 式遥测」的根本分野(ADR-019 §一)。

**R3 — 51 住边界层。** 51 的程序集**不进 sim 程序集**(门 A `"noEngineReferences": true`),
且**不引用 sim 程序集以外的任何引擎程序集**。它是**工具**,不是模拟的一部分 ——
放进 sim 会给门 A 增加一个与模拟正确性无关的引用面(ADR-019 §三)。

**R4 — 51 零出厂。** 构建产物与运行期**无任何网络上报调用**;无第三方分析 / 崩溃上报 SDK。
接口层**不存在** `Upload()` / `Send()` / `Post()`(ADR-019 §二 / AC-19-02)。

**R5 — 51 无玩家可见 UI。** 输出只落**本地文件**与**开发者调试视图**(仅 Development Build)。
若日后需要玩家可见统计界面,那是 **42 拟物 UI 框架**的新呈现需求,须另立案(ADR-019 §五)。

**R6 — 51 不写回数值。** 输出为**只读数据 / 报告**;不自动改 `assets/data/*.json`、
不输出「建议把 X 改成 Y」。51 交付**数据**与**可操作的观察结论**,**不交付调好的数值**
(ADR-019 §六 / AC-19-07)。

**R7 — 指标是整数。** `JudgmentMetrics` 的全部字段为整型(计数用 `int`,时点用 `Tick`),
**无 `float`**。承 ADR-006 的边界纪律(定点域边界禁浮点)。

**R8 — 重算是纯函数(唯一可测性锚点)。** 指标 = `Fold(stream)` —— **给定同一条事件流,
重算必得同一组指标**。51 不依赖墙钟、不依赖帧序、不依赖执行次数。
这使 51 的指标可进 ADR-012 的**黄金夹具**(单元级哈希)对拍。

**R9 — 指标按需重算,不是常驻采集。** 51 在两种入口被调用:
① **局内增量读取**(调试视图:订阅增量事件,维护滚动指标);
② **离线完整重算**(给定一次回放的完整三流,折叠出指标)。
**两种入口共用同一个折叠函数** —— 增量入口只是「边读边折」,不是第二套算法。

**R10 — 51 不解释因果。** 51 报告**发生了什么**(误诊率、跳过率、难度曲线的形状),
**不报告为什么**。归因是设计判断,需要人对照医学语义与实际手感,不是统计量的函数(ADR-019 §六)。

**R11 — 指标定义必须写成「可复算的谓词」。** 每一条指标在 Formulas 节给出
**精确的计数口径**(数哪些 `Kind`、以什么为一次事件、边界如何取),使两个实现者得到同一数字。
凡是口径含糊到「大概」「主要看」的,都不算一条已定义的指标。

**R12 — 51 的输出可空。** 任何输入流为空(新局 / 无病例 / 无世界事件)时,
指标返回**零值而非报错** —— 「没有数据」是合法状态,不是异常。

### States and Transitions

51 是**无状态工具 + 一次重算生命周期**。它不持有跨调用的游戏状态(§Summary);
下表描述**单次重算**的状态机。

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| **Idle** | 已挂载,未重算 | 程序集加载 / 上一次 Emit 完成 | 收到一次 `Compute()` |
| **Reading** | 正在只读订阅 / 折叠三流 | `Compute()` 被调用 | 三流读到尽头(`Fold` 返回) |
| **Computed** | 指标已在内存(未落盘) | 折叠完成 | 触发一次 Emit |
| **Emitted** | 已写本地文件 / 已刷新调试视图 | `ITelemetrySink` 调用返回 | 自动回到 Idle |
| **Faulted** | 流不一致(如 `Tick` 回退 / `Seq` 断号) | 折叠期校验失败 | **中止,不产出指标**(不静默出半份数据) |

**合法转移**:`Idle → Reading → Computed → Emitted → Idle`。
**异常转移**:`Reading → Faulted`(校验失败)。**Faulted 不可自愈** —— 须重新发起 `Compute()`,
由 `Idle` 重入。**禁止**从 `Computed` 直接跳 `Idle`(会丢一次未落的指标)。

## Formulas

> **共同记号**:三流合并序列 `E`,按全序键 `(Tick, StreamPriority, Patient, Seq)` 排序(ADR-006 / 008 / 009)。
> `Kind(e)` / `Tick(e)` / `Payload(e)`;流 `s ∈ {病史, 病例, 世界}`。
>
> **整数纪律(R7)**:全部指标字段为整数(计数 `int`,时点 `Tick`)。**率一律以「(分子, 分母) 整数对」承载**;
> 仅当需要单一标量时按 `Q16.16 = (num << 16) / den` 导出,并**显式附加舍入**:
> `ROUND_HALF_AWAY_FROM_ZERO((num << 16) / den)`(ADR-006 唯一舍入;`(num << 16) / den` 在 C# 是**截断**
> 除法,本身不含舍入 —— **必须由显式舍入函数包住**)。
> **分母为 0 时报「分母 0」,不报 0、不除零**(E-2)。
>
> **纯函数(R8)**:每条指标 = `Fold(E)` —— 不读墙钟 / 帧序 / 执行次数;同流同值,可进 ADR-012 黄金夹具。
>
> **边界注(与 53 的分工)**:51 报**测量结果**(准确率是多少),**不判后果与责任**
> —— 那是 53 医疗后果与责任的裁量(`case-system.md:164` 规则五:「37 不判定它对不对,正确性是 #53 的裁量」)。
> 51 用 `CaseClosed.disease_set`(模拟真值)与玩家落笔做比较,这是**测量**,不是**归责**。

### F1 判断准确率(结果与过程两个正交量,分开报)

```
Scorable     := { c : ∃ CaseClosed(c) }                     // 一次 = 一个立案病例
case_id(c)   := CaseOpened(c) 的 (Tick, Patient, Seq)        // 跨流配对键(F-37.2)
D(c)         := Payload(CaseClosed(c)).disease_set           // 真值,唯一来源(ADR-008 §三)
J(c)         := 满足 case_id = case_id(c) 的【全序最后一条】
                JudgmentRecorded / JudgmentRevised 的 judgment ; 无 ⇒ ∅
F1a Accuracy     := |{ c ∈ Scorable : J(c) == D(c) }| / |Scorable|          // 结果指标
F1b RevisionRate := |{ c ∈ Scorable : ∃ JudgmentRevised(c) }| / |Scorable|  // 行为指标
```

- **计数口径**:数 `CaseClosed` 为「一次」;`==` 为**集合相等**(含空集 `∅ == ∅`,即「无病且判无病」= 判对)。
  判断记录类事件**永不折叠**(ADR-008 §六)⇒ 恒可重算。
- **⚠️ 全序最后一条的折叠回写(R1 自举)**:`J(c)` = 全序最后一条判断事件 —— 但全序键
  `(Tick, StreamPriority, Patient, Seq)` 不含 `case_id`,**跨病例共病时**(同一 `Patient` 有多个
  `case_id` 并存,ADR-008 §六「病例流不折叠」)单凭键**无法定位**「属于 `c` 的最后一条」。
  ⇒ 定位方式必须由**上一级(选 `case_id`)传递**:Fold 逐条推进时**先把每条判断事件经
  `case_id` 落进对应 `c` 的槽位**(`case_id` 取自事件自身载荷,跨流配对键 F-37.2 在**读侧**按
  事件内字段配对,不依赖全序),**槽位覆盖写 ⇒ 最后一条自然胜出**。**实现路径唯一**:
  逐条推进选 `case_id` → 写槽 → 覆盖;**不存在**「先选键再在键内找最后一条」的双层实现
  (那会退化为键内不排序时的实现依赖)。判定点 = `AC-51-B3` 的逐事件重放对拍。
- **为什么「改写」≠ 误判 —— 二者正交,四种组合都存在**:

  | | 未改写 | 改写过 |
  |---|---|---|
  | **判对** | 一次到位 | 自纠成功 |
  | **判错** | 从未察觉 | 改了仍错 |

  改写度量的是**过程**(是否在查验自己的判断 / 怀疑与自纠),准确度量的是**结果**;
  同一终态可由两条路径到达。把改写折进准确率会**惩罚自我纠正**,
  与 `AC-8-29` / `AC-37-20`「**改写次数永不进计分**」正面冲突 ⇒ **改写率必须单列**。
  (`diagnosis-system.md:756` 明写「改写不是可疑行为,是好的临床行为」—— 51 作为仪器**必须能看见它**,
  否则「好的临床行为」在数据上不可见。)
- **输出域**:两者 ∈ [0,1](以整数对承载)。
- **边界压测**:`|Scorable| = 0` ⇒ **不可定义**(报 `0/0`,非 `0`);分子 > 分母与负值按构造不可能。
- **⚠️ 字段语义前置**:`JudgmentRevised.judgment` 存的是**新值**还是**被替掉的旧值**?
  已裁(**2026-09-16,用户**):**存新值** ⇒ 取「**全序最后一条胜**」。
  依据 `diagnosis-system.md:746` 的槽位语义(病名栏是**单一当前值** + 可被看见的**痕迹**,非增量日志)。
  **ADR-008 未明写此点** ⇒ 残留义务:`case-system.md` 须将此语义写进 37 侧(见 `OQ-51-8`)。

### F2 误诊分布(混淆矩阵)

```
M[t][j]         := |{ c ∈ Scorable_single : truth(c) = t ∧ judged(c) = j }|
Scorable_single := { c ∈ Scorable : |D(c)| ≤ 1 ∧ |J(c)| ≤ 1 }
```

- **形状**:(`|病种枚举| + 1`)² 的**整数**矩阵。
  行 `t` = 真值病种 ∪ 哨兵「无病」(`D = ∅`);列 `j` = 判断病种 ∪ 哨兵「未落笔」(`J = ∅`)。
- **⚠️ 对称哨兵(`≤ 1` 而非 `= 1`,2026-09-18 修复)**:谓词取 `|D| ≤ 1 ∧ |J| ≤ 1`。
  `|J| ≤ 1` 保住「未落笔」列(`|J| = 1` ⇒ 该列恒空);**对称地** `|D| ≤ 1` 保住「无病」行
  (`|D| = 1` ⇒ 该行恒空)——「无病且判无病」`D=∅ ∧ J=∅`(最干净的一类判对)与「误开方」
  `D=∅ ∧ J={j}`(真值无病却落笔病名)会**整类消失**。放宽后 `M[无病][未落笔]` 非恒 0,
  F1 恒等式三项**严格成立**(见「与 F1 的关系」);`N_comorbid`(`|D| ≥ 2 ∨ |J| ≥ 2`)
  恰好是 `Scorable_single` 的补集,「不静默丢」纪律不变(J 侧的结果集取法见
  「与 F1 的槽位一致性」注 —— 同一 `≤ 1` 语义)。
  **「未落笔」列非平凡** —— 它数的是「结案时真值已知但玩家从未落笔」的病例
  (`|D| ≤ 1 ∧ J = ∅`,含无病 `D=∅` 与单病种 `D={t}` 两态)。这正是 `≤ 1`(而非 `= 1`)的理由:
  若写 `|J| = 1`,则该列**恒空**,矩阵丢掉一整类真实信号。
- **与 F1 的关系(不重复折叠,但**不是**同一分子)** —— 恒等式须分三项,**但**漏掉中间一项正是最容易犯的错:

  ```
  F1a 分子 = Σ_{t ∈ 病种枚举} M[t][t]        // D={t} ∧ J={t} ⇒ 判对
           + M[无病][未落笔]                  // D=∅  ∧ J=∅  ⇒ ∅ == ∅ 也判对(见下「陷阱」)
           + N_matched_comorbid               // |D| ≥ 2 ∧ D == J ⇒ 判对但进不了矩阵
  ```
  `N_matched_comorbid ⊆ N_comorbid` —— 差额**须**由桶解释,**不允许无桶解释的静默差额**。

  > **⚠️ 陷阱(本式最容易写错处)**:`D = ∅ ∧ J = ∅` 判**对**,但它在矩阵里落在
  > **(行「无病」× 列「未落笔」)**,**不在对角线上**(两个哨兵按构造是不同的行 / 列)。
  > 若写成「对角线 = F1a 分子」,会**系统性少算「无病且判无病」的全部病例** ——
  > 而那恰恰是最干净的一类正确判断。`M[无病][未落笔]` 这一项**必须显式加回**。
- **不可归类时必须显式计桶**(整数,**绝不静默丢弃** —— 静默丢弃会悄悄缩小分母):
  - `N_comorbid` —— `|D| ≥ 2 ∨ |J| ≥ 2`(共病集合对映不到单格,F-37.3 一案进多组);
    其**判对子集** `N_matched_comorbid`(`D == J`)须**单独计数**(F1a 恒等式的第三项);
  - `N_open` —— 无 `CaseClosed`(E-7);
  - `N_unmappable` —— `judgment` 未携带病种枚举。
- `N_unmappable > 0` 是**字段缺口信号**:按 R2 走 **ADR-009 三问判据**评估
  「判断病名是否本应作为枚举进流」,**不给 51 加解析器**(旁路 = 第二个真源)。
- **⚠️ 与 F1 的槽位一致性**:`Scorable_single` 的 `|J(c)| ≤ 1` 在**结果集**上取(玩家在病例存续期
  的**最终**判断 = 一条),不约束中间改写次数(E-8 只计一次改写史)。`JudgmentRevised.judgment`
  **存新值**(2026-09-16 已裁)⇒ 结果集的最后一元 = 槽位**最后的**新值 ⇒ `Scorable_single`
  的 `|J|` 以**槽位内容**计(`∅` 或单元素),**不因改写史增稠**。判定点 = `AC-51-B3` 对拍。
- **⚠️ 纪律**:F2 的输出**含真值病种** —— 正是 `AC-37-15` 对玩家隐藏之物。
  51 之所以安全,**仅因** R5(无玩家可见 UI)+ R4(零出厂)同时成立;
  任一被破坏,F2 即成规则九漏洞。**这是一条承重边界,不是装饰。**

### F3 跳过率(支柱一的直接读数)

```
Opportunity  := |{ a ∈ 动作实例事件 : Payload(a).resolution ∈ {Played, Skipped} }|
Skip         := |{ a : resolution = Skipped }|
SkipByChoice := |{ a : resolution = Skipped ∧ cause = 玩家选择 }|      // 与降级强制分开
SkipRate     := Skip / Opportunity                                   // 整数对
```

- **「一次」** = 一个「手段对应动作实例」;源流 = **病史流** —— 跳过把结算从「手技」切到
  「判断 + 熟练度」,改变病人状态 ⇒ 是**模拟态**,ADR-009 Q1 已定其进流。
- **分母 = 可跳过机会数 = 该动作族「提供了小游戏」的实例数**
  (`game-concept.md:196`「每个动作都**必须有跳过路径**」)。
  **不是**独立 skip 流,**不许**用「病例数」之类代理凑。
- **分子分母是同一事件族被一个枚举位切分** ⇒ 构造上保证 `0 ≤ 分子 ≤ 分母`,不存在来源错配。
- **必须分开报 `SkipByChoice` 与降级强制**:ADR-001 的降级路径(网络降质 / VR / 无障碍)造成的跳过
  **不是**支柱一的失败。合并会把一次网络差的会话误读成「小游戏没人玩」
  (`game-concept.md:615` 登记的风险是「玩过三遍后开始全部跳过」——**另一回事**)。
- **边界**:`Opportunity = 0` ⇒ 不可定义(报 `0/0`);`NotOffered`(无小游戏的动作)**不入分母**,
  否则率被稀释。
- **⚠️ 输入前置(跨系统义务)**:若 10 的动作事件**只**记 `Skipped` 而不记 `Played` / `cause`,
  则分母与原因分离**不可得** ⇒ **不凑代理**。已裁(**2026-09-16,用户**):
  **登记为 10 的 GDD 义务**(见 §Dependencies 未定依赖 · `OQ-51-9`)。

### F4 熟练度成长

```
Practice(skill, W)   := |{ g : g.skill = skill ∧ Tick(g) ∈ W }|      // 增量:练了多少次
NoveltyMix(skill, W) := ( N_new, N_repeat, N_stale )                 // 按新颖度枚举计数
**F4 ΔLevel 语义订正(2026-09-18)**:`Level_end − Level_start` —— `Level_end` = **读流终点**(= 折叠终点)的成长事件所携带的 `Level`;**绝不读取玩家当前 / 存档现值**(那会把 `ΔLevel` 变成「玩家状态」的函数而非「重放」的函数,R8);`Level_start` = 窗口起点**前最后一个已知值**;`Level` 携带点 = **成长事件**(§Dependencies `O-27-8`/`OQ-51-9` 同型:对侧回填义务)。
GrowthRate(skill, W) := Practice(skill, W) / |W|                     // 速率:次 / Tick
```

- **51 不重算 `XP_gain = BASE × K_difficulty × K_novelty`。** 那是 **30 的定点域算术**;
  重算 = ① 破 R7 的整数纪律,② 造出**第二个真源**(违「唯一真源」)。51 只折**已发出**的量。
- **新颖度分布是回答「判断层好不好玩」的主指标** —— `skill-system.md:319` 的设计意图是
  「**靠刷不可能到 60**」(重复病例需 32,000 次 vs 新病例约 2,100 个病名);
  `N_stale / Practice` 走高即**刷**的信号。
- **边界**:`W` 内无事件 ⇒ 全 0(合法);事件**未携带 `Level`** ⇒ `ΔLevel` 报**不可得**,
  **不报 0**(报 0 会被误读成「没涨」);`ΔLevel` **不读玩家当前 / 存档现值**(见上注,
  取法 = 纯读流 ⇒ R8 成立)。

### F5 难度曲线(三流滑窗密度)

> **registry 名**:`difficulty_curve_window_density`(`entities.yaml` 已登记,2026-09-16 —— 故 5 时间天气 /
> 17 采集若复用同一形状,**窗口口径必须同源**;`W` / `S` / `t_0` 三个旋钮同属该登记项)。

```
Dens_s(t_k)   := |{ e ∈ E : Kind(e) ∈ s ∧ t_k ≤ Tick(e) < t_k + W }| ,   t_k = t_0 + k·S
WindowCoverage := ( CoveredTicks, SpanTicks )          // 窗口覆盖记账
CoveredTicks  := |⋃_k [t_k , t_k + W)|                 // 各窗并集的长度
SpanTicks     := Tick_max − Tick_min
```

- **三流各一条序列,不合并为单一标量** —— 三流密度语义不同
  (病例 = 判断负载 / 病史 = 病人处置负载 / 世界 = 建造掉落活动)。R10:51 报**形状**,不报**因果**。
- **窗口半开 `[t_k, t_k + W)`** —— 边界只取一次,防同 `Tick` 事件双计(与 F2 的「不重复折叠」同源纪律)。
- `W` / `S` / `t_0` **全部 `*待定*`(用户裁定)**;形状固定 = **定宽窗整数计数**。
- **`S > W` 时窗间留空须记账** —— 由 `WindowCoverage = (CoveredTicks, SpanTicks)` 承载:
  `CoveredTicks < SpanTicks` 即表示存在**未覆盖的 Tick 区间**,读报告者据此知道曲线有洞。
  **不记账而只报密度 = 把「没测」伪装成「测得 0」**(与 E-3 的「不掩盖」同一纪律)。
- **输出域**:非负整数;上界由 `PATIENT_APPEARANCE_CAP`(9,✅ **24** —— 2026-09-20 `OQ-8` 结案,51 不自定义上界)与三流有界性
  (ADR-008 §六 / ADR-009 §六)封顶。
- **边界**:`W < 1` ⇒ 退化,**构建期 / 加载期硬失败**(非运行期退化、非静默取默认值);
  `S > W` ⇒ 合法,须记账(上式);事件数 < `W` ⇒ 单窗仍定义;空流 ⇒ 全 0(R12)。

### F6 局内时长

```
SessionSpan := Tick_max − Tick_min ,   Tick_min := min Tick(e) ,  Tick_max := max Tick(e)
```

同时报 `Tick_min` / `Tick_max` / `|E|`,使 `SessionSpan` **可审计**(可被独立复算)。

### F7 节律(只用整数序统计量)

```
Δ_i      := Tick(e_{i+1}) − Tick(e_i) ,  i = 1 … n−1              // 整数,≥ 0
节律      := ⟨ Δ_median, Δ_MAD, Δ_min, Δ_max, GapCount ⟩
Δ_median := Δ_(⌈n/2⌉)                     // 排序后【上中位数】,1-indexed,确定取法(禁插值)
Δ_MAD    := median( |Δ_i − Δ_median| )    // 整数中位数绝对偏差
GapCount := |{ i : Δ_i > GAP_THRESHOLD }| // GAP_THRESHOLD *待定*
```

- **禁方差 / 标准差**(`sqrt` + 除法 ⇒ 浮点)。离散度**只用整数序统计量**。
- 中位数取**上中位数**(`⌈n/2⌉`)而非插值 —— 两个实现者必须得同一个数(R11);
  此处为叙述对照,实现一律引用 `F7` 的**定义公式**(`Δ_median := Δ_(⌈n/2⌉)`,1-indexed),**不引用本节散文**。
- `Δ_i = 0` 合法(同 `Tick` 多事件);大 `Δ` = 静默段;
  `GapCount` 是「突发性」的整数读数,与 `Δ_MAD` 互补。
- **边界**:`n < 2` ⇒ 无 `Δ` 序列 ⇒ 全部字段报**不可定义**。
  **⚠️ `n = 1` 时 `Δ_MAD` 不是 0,是「无意义」** —— 不得报 0(报 0 会被读成「节律完全均匀」)。
  `n = 2` ⇒ `Δ_MAD = 0`(合法)。

## Edge Cases

### 组 A —— 空 / 稀疏输入(合法,不得报错)

- **E-1 三流皆空**(新局,一局未跑)。全部指标返回**零值**,状态 `Computed`(非 `Faulted`)。
  「没有数据」是合法状态(R12)。
- **E-2 分母为零**(如零次判断 → 判断准确率)。**不产生 `NaN` / 除零** ——
  按 Formulas 的统一编码,输出整数对 `(0, 0)` + **显式「分母 0 / 未定义」标记**
  (率一律以 `(num, den)` 承载 ⇒ 分母 0 自然落在 `(0,0)`,**不需要哨兵值**);
  **不报 `0/1`、不报标量 `0`**(那会被读成「准确率 0%」,与「无法定义」混淆)。
- **E-3 样本不足**。指标存在但样本量低于 `TELEMETRY_MIN_SAMPLE` 时,
  报告**照常产出但标注「样本不足」** —— **不隐藏、不四舍五入掩盖**(见 Tuning Knobs)。

### 组 B —— 流完整性(异常,`Faulted`)

- **E-4 `Tick` 回退**(后读到的事件 `Tick` 小于前一条,违反跨流全序)。
  折叠期校验失败 → `Faulted`,**中止,不产出指标**(不静默出半份数据)。
- **E-5 `Seq` 断号**(同一 `(Tick, StreamPriority, Patient)` 内的 `Seq` 不连续)。
  同 E-4:校验失败 → `Faulted`。断号意味着**流被截断或损坏**,指标不可信。
- **E-6 病例流引用不在病史流中的 `Patient`**。跨流全序要求成员一致 ——
  不一致即 `Faulted`(而非静默跳过,那会**悄悄缩小分母**)。

### 组 C —— 病例生命周期缺口(语义边界)

- **E-7 病例已 `JudgmentRecorded` 但未 `CaseClosed`**(真值未揭示)。
  该判断**不计入**判断准确率的分母(真值未知,无法判对错),但**计入「未结案病例数」**。
  口径由 Formulas 固定,防「未结案 ⇒ 故意拉高准确率」的错觉。
- **E-8 同一病例多次 `JudgmentRevised`**。改写是**行为**,每次改写计一次改写史
  (非多次「判断」)。**一次病例的「落笔」只算一次**。
- **E-9 跳过与判断并发**(玩家跳过后又落笔)。二者**独立计数** ——
  跳过率的分母与准确率的分母**不共享**(否则互相污染)。口径见 Formulas。

### 组 D —— 离线重算的输入异常

- **E-10 存档来自不同 `ConfigVersion`**(ADR-010 §七 版本比对不符)。
  **不静默重算** —— 报告标注**版本不匹配警告**(ADR-014:`ConfigVersion` 派生自内容哈希);
  版本不符 ⇒ 回放可能不符 ⇒ 指标可能有偏。
- **E-11 回放被截断(部分三流)**。离线重算时若流不完整:
  **要么拒绝(要求完整流),要么产出并标注「部分指标」** —— 由 `OQ-51-4` 邻域的导出策略定,
  但**禁止**把部分流当成完整流静默出数。
  **⚠️ 导出策略(2026-09-18 增注)**:`OQ-51-4` 裁定的两条路径对「部分流」语义不同
  —— **人读文本**(允许产出并标注「部分指标」,读取者自行判断)/ **机器可解析**(严格语义,
  建议拒绝,防下游脚本被部分数据污染)。**两条路径对应 `AC-51-D8` 的「要么…要么…」两个分支**;
  单条 ADVISORY 断言「不静默」已覆盖两义,无需在裁定前强行二分。

### 组 E —— 环境 / 越界请求

- **E-12 `Release` 构建里的调试视图**。调试视图**仅存在于 Development Build**;
  Release 构建里该入口**不存在**(编译期剔除或运行期硬禁),**不得**是「有按钮但点了没用」。
- **E-13 玩家可见统计界面的越界请求**。**拒绝并转 42** —— 那是 42 的新呈现需求,
  须另立案(ADR-019 §五)。51 不得自行加看板 / 图表。
- **E-14 「帮我调节数值」的越界请求**。**拒绝** —— 51 只出数据与观察,不写回 `assets/data/`,
  不输出「建议把 X 改成 Y」(ADR-019 §六 / AC-19-07)。
- **E-15 联机非主机侧被要求出指标**。**拒绝** —— 非主机不执行 `Step`,读不到完整流
  (见 `OQ-51-5`);硬跑会得到空 / 截断指标。51 默认只在**主机**或**离线(从主机存档)**运行。

### 组 F —— 规模 / 性能

- **E-16 超长回放**(数小时 / 海量事件)。折叠须**内存有界**(流式折叠,不整表载入)
  或**明确接受内存换时间**。二者由 Tuning Knobs 定,但**不得**因规模而改变指标数值(R8)。

## Tuning Knobs

> **硬约束**:本表全部数值 `*待定*` —— **数值由用户自己调**,本 GDD 只交付**旋钮的存在、位置与副作用**。
> 与 ADR-019 §六 一致:51 让旋钮的**方向**更可见,**不替用户转**。

| 旋钮 | 作用 | 类型 / 单位 | 安全范围 | 调整的副作用 |
|------|------|-----------|---------|------------|
| `W` | F5 难度曲线滑窗宽度 | `Tick` | **`*待定*`**(须 ≥ 1,构建期拒绝 0;同源登记 `difficulty_curve_window_density`,`entities.yaml`) | 大 ⇒ 曲线平滑、掩盖突发;小 ⇒ 尖峰噪声 |
| `S` | F5 滑窗步长 | `Tick` | **`*待定*`**(可 > `W` ⇒ 窗间留空,须记账) | 小 ⇒ 密、成本高;大 ⇒ 漏窗 |
| `t_0` | F5 首窗起点 | `Tick` | **`*待定*`** | 影响全部窗的对齐;改它 ⇒ 指标数值变(R8 仍成立 —— 同 `t_0` 同值) |
| `GAP_THRESHOLD` | F7 「静默段」的整数阈值 | `Tick` | **`*待定*`**(≥ 0) | 小 ⇒ 处处算 gap;大 ⇒ `GapCount` 恒 0(退化为无信息) |
| `TELEMETRY_MIN_SAMPLE` | E-3 「样本不足」的标注门槛 | `int`(计数) | **`*待定*`** | **仅影响标注,不影响数值** —— 低于它照常出数,只加警示 |
| `GROWTH_WINDOW` | F4 成长统计窗口 | `Tick` | **`*待定*`** | 大 ⇒ 成长被平均掉;小 ⇒ `N_stale/Practice` 抖动 |
| `FOLD_MEMORY_MODE` | E-16 折叠的内存策略(流式 / 整表) | 枚举 | **2 值,非数值** | 流式 ⇒ 内存有界、略慢;整表 ⇒ 快、内存随流长。**两者不得改变指标数值(R8)** |

**不是旋钮的东西**(写下来防误调):

- **`Accuracy` / `SkipRate` / `RevisionRate` 等指标数值本身** —— 它们是**测量输出**,
  不是可调参数。**任何「把准确率调高一点」的需求都是错的**(那是改游戏,不是改仪器)。
- **`Scorable` 的口径**(∃ `CaseClosed`)—— 属**规则**,不属旋钮。改它会让历史数据不可比。
- **`ROUND_HALF_AWAY_FROM_ZERO`**(ADR-006 唯一舍入)—— 属**域纪律**,不属旋钮。
- **默认全关**:51 **无「开关」** —— 无上报开关、无采样率、无实验分组。
  ADR-019 §二 / §三 已定:没有可开关的东西(因为不出厂)。**加一个开关就是加一个出厂面。**

**旋钮的落地位置**:`assets/data/telemetry_analytics.json`(作者态,走 ADR-014 两阶段烘焙管线,
运行期读 `*.cooked`)。**⚠️ 51 只读它,永不写回**(R6 / AC-19-07)。
