## Overview

**医馆即机器(24)是「位置即逻辑」的规则层:** 玩家在 23 模块化建造的槽位骨架里摆放家具
(布局),24 把这份布局**解析成房间与情境**,再把情境换算成**效果乘数**,喂给 9 与 21a
(恢复速度修正 · 炮制成药率)以及 1 的移动情境上限(`CONTEXT_TABLE` 房间格乘数)。它是
`game-concept.md:381`「红石逻辑」的机械侧:玩家摆零件,零件就会运转 —— 运转规则归本 GDD。

24 **拥有且只拥有三样东西**:

1. **房间析出**:从 23 的 `structure_at(cell) → module_id + orientation`(规则五,23 出布局)推导
   「哪些格构成一个房间、这个房间是什么、有什么属性」;
2. **`CONTEXT_TABLE`**:房间格 → 情境乘数(邻接判定 = 整数格离散规则,ADR-015 §五 —— **非物理 /
   非 NavMesh**);`K_CONTEXT_MAX` 由本表派生,交付系统 1(玩家控制器的 `O-2`);
3. **`EnvMod` / `EquipMod` 的产出**:情境乘数汇总为 9 的恢复速度修正(`EnvMod`,可为负 —— 例如
   传染病区与普通病房相邻 → 交叉感染风险,21a 的 F1 可读)与 21a 的炮制/制作修正(`EquipMod` / `EnvMod`)。

它**不**拥有:槽位骨架与占用真相(23)· 医馆房间格定义(6,只提供格)· 数值效果本身(9 / 21a
只收乘子)· 任何呈现(42)· 建造件物品(21a / 20)。**9 不感知医馆本身** —— 24 只把乘子交给 9,
不把「房间」的语义泄漏出去(`disease-simulation.md` 集群 B2 已裁)。

**P0 范围口 = `systems-index.md:575`:只做单房间评分**(多房间邻近约束 → P1a)。P0 里医馆的
「红石逻辑」是**一个房间内部的评分** —— 房间怎么摆家具、邻近格怎么互相修正;跨房间的
交叉污染(传染病区邻普通病房)在 P1a 展开(`game-concept.md:380` 的完整邻近矩阵)。这是
`game-concept.md:420`(P0 叙事钩子《他回来了》)在机械侧的最小兑现:布局抉择 = 无对错的空间判断题。

> **权威件**:ADR-015 §五(整数格邻接判定)。**实现细节不在本 GDD** —— 24 的规则落盘后,
> 网格对齐口径由 ADR-015 负责。

## Player Fantasy

**「一间从茅草屋长起来的医馆 —— 我摆的每个零件都会运转,而我怎么摆,暴露了我怎么理解医学。」**(承 23 的 Player Fantasy 锚点 · `game-concept.md:389` Expression)

三条,层层加深:

1. **我为布局纠结。** 手术室挪过来,术后感染率降了,但床位就少了(`game-concept.md:93`:
   玩家会为布局纠结)。在有限地块里满足一堆互相冲突的邻近约束 = 空间解谜:每动一处,
   代价和收益同时出现,没有白捡的优化。

2. **改布局 → 立刻给我不同读数。** 每一次挪动都改变某个数值(感染率 / 恢复 / 成药率),玩家
   **看得见**。不是「放好了等结果」的放置 —— 是**我改了这台机器的一处,读数当场变了**
   (可见因果,不是连续运转:布局不动,读数也不动 —— ADR-005 的无状态纪律使然)。

3. **医馆的演变 = 我的整体观的演变。** 只懂还原的玩家会建诊室 → 药房 → 手术室的流水线
   (把身体当机器修);开始有整体观的玩家会想病人住的地方会不会影响他好起来(`game-concept.md:397`)。
   随辨证熟练度上升(**P1a**),「疗愈」侧的价值被玩家自己的眼睛重新定价 —— 布局不是装饰,
   是表达。

> **P0 兑现分层(评审口径,同 23)**:P0 只做**单房间评分**(`systems-index.md:575`),幻想只兑现
> 层 1 与层 2 的前半(布局纠结 + 单房间内的可见因果);层 2 后半(跨房间交叉污染)与层 3
> (整体观表达)归 **P1a**(多房间邻近 + 辨证重估价)。P0 的钩子 = **「这一种看法有尽头」**
> (`game-concept.md:420`《他回来了》):玩家先把布局做好、验收单房间运转,再在 P1a 撞上
> 「还有另一种看法」。

## Detailed Design

### Core Rules

**P0 管线**:**单连通块**内部,布局 → 情境 → 乘子,五条规则。

- **规则一 —— 房间析出(布局读取,`structure_at` 只读):** 24 从 23 的 `structure_at(cell) → module_id
  + orientation` 读取**只读布局**;不写占用、不持有任何占用真相(23 的所有权不动摇,规则五)。
  房间 = 一个**连通的家具格集**(邻接 = 整数格 `ABS(dx)+ABS(dy) == 1`,4 邻接,非物理 / 非 NavMesh,
  ADR-015 §五);「房间」没有独立的全局 id —— 它由布局 + 房间定义**派生**(P1a 才需要跨房间命名)。
  - **格分类(2026-09-17 复核,阻塞 2):** `S` 的成员**仅** `type(c) ∈ FURN_TYPES` 的格。
    **外壳格(壁 / 地基 / 房顶,23 的 `BakedInitial`)与空地板格 = 非格** —— **不计分、不参与连通**。
    墙因此**天然隔断**:隔着墙的两件家具本就不是 4 邻接(无需额外判定)。**敞开空间的家具簇仍是合法房间**
    (P0 不要求围合 —— 与「零件摆对就运转」一致)。**禁围合检测 / 禁 flood-fill 几何算法**(纯整数派生)。
  - **单连通块前提(2026-09-17 复核,阻塞 1):** **布局须恰好析出 1 个连通家具格集**;
    ≥ 2 块 ⇒ **整份布局 = `ROOM_NONE`(0,0)**(EC-24-07)。**为什么不是「各块求和」**:求和通道**本身就是
    跨房间项** —— `EnvMod` 可负,把病房的负值加进手术室的正值 = 正是 P1a 的 `ROOM_INTEROP` 交互;
    P0 不许偷偷兑现它。**全零是**可修复、可诊断**的失败态**(移走散件即恢复),而非最块的静默选择
    (后者会让「加一格悄悄删掉另一个房间的分」这类不可见 bug)。⇒ 单块下 `n = |S|` 的 int64 界(F-24-1)原样成立。
- **规则二 —— 房间定义与类型判定:** 房间的**定义 = `ROOM_TABLE`**(**24 拥有**,与 `CONTEXT_TABLE` /
  `ADJ_TABLE` 同族评分规则数据;**非**关卡工具产物 —— 医馆由玩家建造,房间定义不可能是固定世界几何。
  经 ADR-014 烘 `clinicmachine_room.json`,**不登记 ADR-022 §三 导出契约**。2026-09-17 复核订正:
  原写 `world_room.json`(关卡工具产出)为**误挂**,已删),声明房间类型的判定谓词(如「床 ≥ 2 ∧ 有手术台」);
  房间类型 ⇒ 该房间承担的效果 **(Eq 评分,见 F-24-1)**。未满足任何房间类型 ⇒ `ROOM_NONE`(不产生效果乘子)。
  - **判据语言允许「邻接子句」(2026-09-17 复核,阻塞 5 —— 幻想承重):** 谓词可含
    **基于同一整数 4 邻接的邻接子句**(如「手术台 **邻接** 无菌柜 ≥ 1」),使**房间身份与布局互相牵制** ——
    否则「位置即逻辑」在 P0 是**装饰性**的,空间题退化为「先满足计数据词、再对 `ADJ_TABLE` 爬山」。
    **烘焙 schema 须校验邻接子句的引用的 `type` ∈ `FURN_TYPES` 且方向确定性**(同 `adj_sum` 的 +x/+y 单向查法)。
- **规则三 —— `CONTEXT_TABLE` 房情境乘数:** 房间类型 → 情境(如「手术室 · 无菌」);情境 → 效果乘数
  (`EQ`)。`CONTEXT_TABLE` 是 24 的**表**(与 23 的 `module_id` 目录区分),`K_CONTEXT_MAX`(= 
  `max(CONTEXT_TABLE 的 K_speed)`)由本表派生,交付系统 1(玩家控制器 `O-2`);**裸常数禁止**(系统 1 的
  `player-controller-and-movement.md` F-1-8 已订正)。本表**独立于** `TERRAIN_TABLE`(6 的地貌表)。
- **规则四 —— `EnvMod` / `EquipMod` 产出(整数域,禁 float):** 24 输出两个乘子 ——
  - `EnvMod`:情境乘数汇总(可为负,疾病 9 的 `EnvMod` 环境调制 · 可负来自 21a 的 `ENV_MOD_MIN`;
    负表示「交叉污染 / 环境劣化」);
  - `EquipMod`:器具档位汇总(接 21a 的 `EQUIP_MOD_CAP`;房间内的可操作器具(丹房 / 手术台)提供)。
  两个乘子 **均整数定点**(Q16.16 或 int,与 21a 的 F1 一致);**禁 float 写 sim**。
- **规则五 —— 乘子交付(消费方只收乘子,不感知医馆):**
  - `EnvMod` → 9(`disease-simulation.md` F4 照护判定**不读** `EnvMod` —— 集群 B2 ;它只调制恢复速率);
  - `EquipMod` / 部分 `EnvMod` → 21a(`item-database.md` F1 的 `EnvMod`/`EquipMod` **运行时入参**,可负);
  - `K_CONTEXT_MAX` → 1(`player-controller-and-movement.md` `O-2` / F-1-8)。
  **消费方的效果语义归消费方,24 不读结果**(23 规则五的单向无环)。

### States and Transitions

**24 没有自有状态机 —— 它是纯函数派生(ADR-005 的「无状态 = 可重放」)。** 24 唯一的“状态”
是**布局**(23 持有,随 `Structure*` 事件流变),以及**乘子**的终点(9 / 21a / 1 持有)。24
本身既无持久状态、也无逐级状态机:

- 输入 `structure_at`(23 布局)变化 ⇒ 24 重导出 `EnvMod` / `EquipMod` / `K_CONTEXT_MAX`;
- 布局不变 ⇒ 乘子不变(纯函数,输入不变输出不变);
- 同一布局在会话内重放(加载 / CatchUp)⇒ 乘子**逐位一致**(无内部缓存、无语境隐藏状态)。

> **缓存是允许的优化(= 表现层 Memoize),不是状态:** 若实现层缓存房间析出 / 乘子,须以
> `Structure*` 事件为失效键(ADR-002 / 45 的 `IReplayPipe` 通知),且缓存只改性能不改结果
> (`AC-24-04` 断言:缓存前后的求值逐位一致)。

**逐级状态归属表**(哪些“状态”该由谁持有):

| “状态” | 持有者 | 形态 |
|--------|--------|------|
| 布局(占用真相) | 23(事件流真源) | `Structure*` 事件 |
| 房间析出/乘子 | **24 纯函数输出(不持有)** | 派生态,重放期重建 |
| `EnvMod` / `EquipMod` | 9 / 21a 消费 | 入参(整数定点) |
| `K_CONTEXT_MAX` | 1 消费 | 表派生上界 |

## Formulas

**域纪律(2026-09-17 落盘)**:全部乘子 = **Q16.16 raw**(`1.0 = 65536`);`tier` 为 **int 计数**
(ADR-006 D-21-17,不入 `Fix` 解析集);**禁 float / 禁 `sqrt`**(ADR-015 §五)。输入 = 23 的
`structure_at(cell) → (module_id, orientation)` **只读**(规则一);输出 = `EnvMod` / `EquipMod` → 9 / 21a,
`K_CONTEXT_MAX` → 1(规则五)。三条公式均为**纯函数**,由世界流 `Structure*` 事件重建(派生态,
States and Transitions 节)。

**公共定义(F-24-1 / F-24-2 共用)**:
- `S` = 房间**连通家具格集**(规则一)。**恰好 1 个连通块**是前提;≥ 2 块 ⇒ 整份布局 `ROOM_NONE`(EC-24-07)。
  未匹配任何房间类型 ⇒ `ROOM_NONE` ⇒ **输出中性 `(0, 0)`**,不产生乘子(规则二基例,EC-24-01 / EC-24-02)。
- **`S` 成员判据 = `type(c) ∈ FURN_TYPES`**;外壳格(23 的 `BakedInitial`)与空地板格 = **非格**,不计分、不连通(规则一)。
- `type(c)` ∈ `FURN_TYPES` · `tier(c)` ∈ [0, `TIER_MAX`](0 = 无档)。
- **邻接和(整数 4 邻接,每条边恰好计数一次)**:
  `adj_sum = Σ_{c∈S} [ (c+ex) ∈ S → w(type(c), type(c+ex)) ] + Σ_{c∈S} [ (c+ey) ∈ S → w(type(c), type(c+ey)) ]`
  只查 +x / +y 两方向(基向量 `(1,0)` / `(0,1)`,ADR-015 §五);`w(a,b) = ADJ_TABLE[a][b]`
  (**无序对、可负、缺失 = 0**);O(2n) 整数比较。→ 兑现 **`O-23-4`**(P0 最小邻接判定)。
  ⚠️ **对称性必须由烘焙 schema 硬保证(2026-09-17 复核,阻塞 3/6):** 查法是**几何固定**的单向查
  (`w(type(c), type(c+ex))`),若作者只填 `(药柜,便器)` 忘了 `(便器,药柜)`,则**镜像 / 旋转后的同一布局
  会算出不同分**(静默、与方向相关的失败)。⇒ **烘焙期 schema 断言 `∀a,b: w(a,b) == w(b,a)`,不等 = 构建失败**
  (`throw`,承 AC-24-05/08 的失败通道);「无序对」不再是作者纪律,而是**门**。

### F-24-1 —— EnvMod:线性加权和 + 双钳制

```
env_score = base_env(room_type) + Σ_{c∈S} e_env(type(c)) + adj_sum
EnvMod    = clamp(env_score, ENV_MOD_MIN, ENV_MOD_MAX)
```

| symbol | type | range | 描述 |
|--------|------|-------|------|
| `base_env(room_type)` | Fix | [ENV_MOD_MIN, ENV_MOD_MAX] | 房间基础环境(CONTEXT_TABLE,规则三) |
| `e_env(type)` | Fix | [−`C_max`, `C_max`] | 单件家具环境贡献,**可负**(FURN_TABLE;污染 / 劣化)。`C_max := max|e_env|` over FURN_TABLE |
| `adj_sum` | Fix | `2n·[−max(|W_MIN|,W_MAX), +max(|W_MIN|,W_MAX)]` | 邻接修正(公共定义;`n = |S|`) |
| `EnvMod` | Fix | [ENV_MOD_MIN, ENV_MOD_MAX] | 交付 9 的恢复速度修正(可负) |

**输出范围**:clamp 后**严格 ∈ [ENV_MOD_MIN, ENV_MOD_MAX]** —— **复用 21a 常量,2026-09-17 用户裁定**
(单一出处,不新造 `ENV_MOD_CAP`)。极端(堆叠污染)被 clamp 压顶,越界从意外变**规格**(EC-24-03)。
**int64 算术域前置**:`max|env_score_raw| ≤ |base_env| + n·C_max + 2n·Φ`,其中 **`Φ := max(|W_MIN|, W_MAX)`**
—— ⚠️ **2026-09-17 复核订正**:原界写 `2n·W_max` **不健全**(`W_MIN < 0`,最坏负向 = `2n·|W_MIN|`;
若 `|W_MIN| > W_max` 则原界低估)。⇒ 烘焙 schema 须断言 **`|W_MIN| ≤ W_max`**(否则改 `Φ` 定义);
量纲依赖格数上界 `n_max` → **6 复核点**(6/24 调表抬高 `LATTICE_SIZE` 下界)。
**ENV_MOD_MIN < 0 是承重前提(2026-09-17 复核)**:若 21a 把 `ENV_MOD_MIN ≥ 0`,则「满污染但已匹配房间」
的 clamp 结果 = `0` = **恰等于 `ROOM_NONE` 的中性值**(EC-24-02),9 / 21a **无法区分「空 / 中性 / 最差」**。
⇒ **向 21a 登记 `ENV_MOD_MIN < 0` 为约束**(只登记口径,**不指定数值** —— 数值归用户)。
**算例**(药房 4 格):药柜 `+12000`、研磨台 `+8000`、烘干架 `+6000`、便器 `−20000`;邻接 研磨台↔烘干架
`+4000`、药柜↔便器 `−12000`;base = `30000` ⇒
`env_score = 30000 + (12000+8000+6000−20000) + (4000−12000) = 28000`(≈ 0.427,未越界)⇒ `EnvMod = 28000`。

### F-24-2 —— EquipMod:器具档位求和 + 单钳制

```
equip_score = Σ_{c∈S, tier(c)>0} tier(c)
EquipMod    = clamp(equip_score × 65536, 0, EQUIP_MOD_CAP)    # int 升 Q16.16
```

| symbol | type | range | 描述 |
|--------|------|-------|------|
| `tier(c)` | int | [0, TIER_MAX] | 器具档位;0 = 无档,不计入(ADR-006 D-21-17) |
| `equip_score` | int | [0, n·TIER_MAX] | 档位求和(**求和堆叠语义,2026-09-17 用户裁定**) |
| `EquipMod` | Fix | [0, EQUIP_MOD_CAP] | 交付 21a 的制作 / 炮制修正 |

**输出范围**:clamp 后 ∈ [0, EQUIP_MOD_CAP](21a 常量)。档位求和 ⇒ 堆叠感直接,cap 钝住边际(EC-24-03)。
⚠️ **运算域(2026-09-17 复核,阻塞)**:`equip_score × 65536` 在 **int32 下于 `equip_score > 32767` 溢出**
(而 `n·TIER_MAX` 上界未定,OQ-24-5)。⇒ **须在 int64 域求积后再 clamp**;烘焙 schema 追加断言
**`n_max × TIER_MAX < 2^31`**(与 `ENV_MOD_*` 同批)。
**算例**:tier `2+1+1+0 = 4` ⇒ `equip_score = 4` ⇒ `EquipMod = 262144`(4.0,若 < cap)。

### F-24-3 —— K_CONTEXT_MAX:表上界交付

```
K_CONTEXT_MAX = max(CONTEXT_TABLE 的 K_speed)   → 交付 1(F-1-1a / O-2)
```

| symbol | type | range | 描述 |
|--------|------|-------|------|
| `K_speed` | Fix | > 0,无量纲 | 房间格情境乘数(CONTEXT_TABLE,规则三) |
| `K_CONTEXT_MAX` | Fix | 表派生 | 1 消费的速限上界(玩家控制器 F-1-8 / `O-2`) |

**不是公式内 clamp**:循环定义不自证 ⇒「输出 ≤ K_CONTEXT_MAX」落**烘焙期 schema / CI 校验**
(ADR-014 管道,表条目值域检查),不进本公式;表条目越界 = 构建失败(EC-24-03)。

### P1a 预留 —— F-24-4 乘性协同(不落 P0)

多房间邻近 / 情境叠加(`ROOM_INTEROP`,EC-24-06)时,正情境走**乘性层**、负情境走**加性扣除层**
(乘性结构天然不能过零,须拆层以兼容 EnvMod 可负):

```
# ❌ 原式(2026-09-17 复核废止 —— 量纲错 + 溢出):
#   EnvMod = clamp(round_r(base_env × Π_{j∈C+}(1+m_j) / 65536) − Σ_{j∈C−} n_j, ...)
#   k 个因子只除一次 65536 = 量纲错;k≈3 时 base_env≈6.5e4 × 1.3e5³ ≈ 1.4e20 > 9.2e18 溢出 int64。

# ✅ 逐因子折叠(每步归一,k 无关、无溢出):
acc = base_env
for each j ∈ C+:  acc = round_r(acc × (1+m_j) / 65536)     # 每步回 Q16.16
EnvMod = clamp(acc − Σ_{j∈C−} n_j, ENV_MOD_MIN, ENV_MOD_MAX)
```

P0 单房单情境下本族无区分度,**不实现**;此处仅立取舍证据(`m_j` 正情境因子 · `n_j` 负情境幅值,
定值归用户)。**逐因子折叠**同时消解溢出与量纲(k 个因子 = k 次归一,而非 1 次),
`round_r` = ADR-006 的单一舍入模式 `ROUND_HALF_AWAY_FROM_ZERO`。
