## Overview

本库是**跨屏交互模式的唯一次级登记处**(次级 = 权威仍在 ADR;本库负责「模式如何在屏间复用」)。
它不定义焦点算法(那归官方桥 + `FocusController`,ADR-011/013 已裁)也不定义游戏状态
(42 / 44 只渲染,ADR-013 §9 C3)。

**收录判据(三选一即立案)**:
1. 已被某份 **Accepted ADR** 或 **Approved GDD** 点名,且**跨 ≥2 屏**复用;
2. 是**无障碍承诺的执行体**(即删掉它 Standard 档位失效);
3. 违反它会产生**静默失败**(如双栈焦点、状态经音频播报)。

**每条模式的字段**:意图 → 权威源 → 呈现规格 → 键鼠路径 → 手柄路径 → VR 路径 → 反例(何为破) → 消费者 → 落点文件。

## Patterns

### P-01 · 单栈焦点门(Focus Single-Stack Gate)

- **意图**:手柄导航只有一个真源,避免「同一扳机两栈各动一次焦点」。
- **权威源**:ADR-013 焦点单栈门 · 接口归 ADR-011,**呈现归 42/R-6**;`AC-42-A5` 的 `SetFocusGate` / `IsFocusActive`。
- **呈现规格**:焦点移动**不自实现算法** —— 走官方桥 `NavigationMoveEvent` + `FocusController`;两栈共用同一 `EventSystem`,**禁双 EventSystem / 双输入模块**。
- **键鼠路径**:指针不受门约束(指针不产生 `NavigationMoveEvent`)。
- **手柄路径**:门 = 开则 UI Toolkit 栈收,关则 UGUI world canvas 栈收;**不存在两栈同时收**。
- **VR 路径**:P1a;VR 必须 world canvas(ADR-013 裁定 ①),届时门恒关。
- **反例(何为破)**:一个 action 资产里同时留自建导航源 → 官方桥与自实现并存 = 同键双触发(3 的 :128 已点名的失败模式)。
- **消费者**:全部纸面界面(脉案 39 / 出诊箱 20 / 地图 6 / 存档位 7b / 教学 48)。
- **落点**:门状态由 42 持有(不持游戏状态),切换时机见 `skeuomorphic-ui.md` 规则四。
- **状态**:✅ 已裁 · ⚠️ **未 spike**(ADR-013 §6.6 假设 6 = 半可信;运行时手柄焦点为前置门)。

### P-02 · 纸面近景模态(Paper Closeup Modal)

- **意图**:读纸面信息时把世界**装进口袋**,而不是叠一层 HUD。
- **权威源**:ADR-013(UGUI 补 world/XR)+ ADR-020 §五(相机只读不持状态,自建 `ICameraRig`)。
- **呈现规格**:枚举 `ModalId`(`ADR-009 §三` 同款「骨架先行,载荷归系统」纪律)—— 已知具名:`ModalId.PaperCloseup48`(48 的 ⑱ 式近景);39 脉案页(42 §UI Requirements 表内档位 P0)。
- **键鼠路径**:开 / 关 = 单一 toggle action;指针在纸面内直接取物。
- **手柄路径**:开 = 同一 toggle;**关 = 焦点必须能回到进入前的载体**(背包格 / 地图标记)—— 断头 = P-04 破。
- **VR 路径**:不做(承 ADR-020 ③:VR 不承担开放世界移动;纸面阅读 = 平面专属,P1a 重议)。
- **反例**:用相机滤镜 / 后处理表达「进入模态」= 破 ADR-020 §六(镜头效果不得用于报状态)。
- **消费者**:39 · 48 · 6(纸质地图)· 20(出诊箱)· 11(方笺 —— ⚠️ 见下 Gaps G-1)。
- **状态**:✅ 48 渲染形态已裁(2026-09-21 · 等比纸本近景,42 UI Toolkit,见 `design/ux/paper-closeup-48.md`);39 脉案近景 = 同族形态(本 pattern 族默认);✅ **第七员登记已落(2026-09-21 第二十八批「42 修订轮」· `ADR-013 §十-B`)—— `AC-42-F1` 点名自此七项,`ModalId` 含 `PaperCloseup48`**(OQ-48-8 / OQ-C1 结案;本行即该 spec §15 预登记的随批回写)。

### P-03 · 意图事件化(Intent-as-Event)

- **意图**:玩家「想做什么」以**全整数意图事件**进流;判定与结算归主机。
- **权威源**:ADR-011 **Amendment B**(F1 改判)· ADR-009 §七(拾取三段式)· ADR-005(病史流唯一真源)。
- **呈现规格**:客户端聚合为**一条** `EmergencyAttempt` 类事件;连续位置 / 速度 / 朝向**永不**进流(AC-20-03,判据 = 载荷字段类型的反射断言,非 grep)。
- **键鼠路径**:直读通道触发(急救 <50ms 的 `L_input` 预算路径,**不穿过 42 的 UI 事件栈**)。
- **手柄路径**:同一 action 资产,`bindings overrides` 换绑不换语义。
- **VR 路径**:急救小游戏 VR 模式同构(站定式;手势 → action)。
- **反例**:① 客户端上报 `JudgeResult`(= 把流的内容交给客户端诚实性做保,改一个枚举值即伪造满 potency);② 逐帧同步输入。
- **消费者**:10 急救 · 4 交互 · 20 库存 · 23 建造。
- **未结**:**`OQ-10-9`** —— `EmergencyAttempt` 走 ADR-001 第二 QoS 通道会**丢**,而它是判定输入 ⇒ 须 ADR-001 一次窄修订(归 45 的 GDD 轮,P1b 前)。

### P-04 · 双导航等价(Dual-Navigation Parity)

- **意图**:手柄没有指针,所以**每个指针可达的交互都有一条焦点路径**;这是可玩性级要求,不是优化。
- **权威源**:`technical-preferences.md` Platform Notes(「拟物 UI 必须同时支持键鼠与手柄导航」)· `TR-concept-008` · `accessibility-requirements.md` §Motor。
- **呈现规格**:焦点顺序由**语义方**定,不由渲染方定 —— 例:脉案焦点顺序由 8 定(面色 → 语声 → 姿态 → 呼吸 → 触感 → 病名 → 置信度,`skeuomorphic-ui.md:1176`),42 只渲染。
- **键鼠路径**:指针 = 焦点的**快捷方式**,不是另一套交互模型。
- **手柄路径**:完整;含**长按**类交互须给焦点可达的等价(或按 P-06 / L-2 的口径说明为何不给)。
- **反例**:任何「只能拖拽」的交互(建造摆放 23 当前有此风险,见 Gaps G-2)。
- **状态**:✅ 裁 · ⚠️ 未验(逐屏走查在 QA 计划「手柄焦点无断头」行)。

### P-05 · 设备图标随活动输入切换(Prompt Rebinding)

- **意图**:屏幕上的按键提示永远是玩家**此刻**用的设备。
- **权威源**:`input-system.md` 四项裁定之一 —— **3 只给 `iconKey`,呈现归 42 / 48**。
- **呈现规格**:键鼠 / 手柄 / VR 三套绑重(ADR-011);`iconKey` 是字符串键,不是精灵引用。
- **反例**:渲染层自己订阅设备事件(= 42 持状态,破 ADR-013 §9 C3)。

### P-06 · 无提示音 / 无提示色报状态(No-Sting Rule)

- **意图**:游戏的反馈全部 diegetic —— 医者的判断依据是病人,不是 UI。
- **权威源**:AC-44-09(音频触发源 ∈ 行为反馈白名单,禁 sting / jingle / ducking / 素材切换报状态)· ADR-020 §六(同一铁律的视觉侧)· ADR-013 §9 C3。
- **呈现规格**:状态变化只经 8 的体征通道 / 脉案落笔 / 世界内物理表现传达。
- **手柄 / 键鼠路径**:无差异 —— 该模式不产生「提示」,故无提示可达性问题。
- **反例**:疗效达成时放一段音乐 = 直接破。
- **无障碍副作用**:本模式使模板中「audio-only 信息的视觉指示」一项**结构性满足**(见 `accessibility-requirements.md` §Cognitive)。

### P-07 · 体征读数进脉案不进 HUD(Diegetic Vitals)

- **意图**:无血条、无小地图;读数必须**主动去读**,且落笔即成事件。
- **权威源**:ADR-013 · 8 的 `UI-8.0` / `UI-8.1` · ADR-008(读数 / 落笔 / 改写史三类判断记录 Kind)· `disease_id` **不进呈现层**(AC-37-15 `PresentationDtoGuard` 递归反射扫描)。
- **呈现规格**:UI 只读 `VitalsDto`(float —— 唯一浮点出口,ADR-016 §一 13 例外注)。
- **反例**:任何把 `disease_id` 或「病名」直接显示在屏上 = 破拟物铁律 + AC-37-15 BLOCKING。

### P-08 · 意图拾取与宽容半径(Forgiving Intent Pickup)

- **权威源**:ADR-009 §七(拾取判定 = 意图事件 + 当下判距 + 宽容半径)· `interaction-system.md`。
- **意图**:离屏拾取被**拒**(不是崩溃、不是静默成功);判距用 sim 格,不用表现态坐标。
- **反例**:用 `OnTriggerEnter` 回调直接写流 = 破 ADR-020 §四(位移纯表现态)。

### P-09 · 本地即时呈现 · 权威异步(Local-First Presentation)

- **权威源**:ADR-011 Amendment B(本地判定**降级为预表现**;主机 `Append` + 发号 `Seq` 才为真)。
- **呈现规格**:预表现与权威结果的收敛窗口 = 一个 tick(`TICK_SECONDS = 0.05`,OQ-25-8 已裁 20 Hz)。**不得**把 `L_input` 与 `L_eval` 重并成一个「端到端 < 50 ms」(该禁令见 `tests/README.md` 与 OQ-25-8 ②)。
- **反例**:等主机回包才动动画(手感死)或本地结果直接当真(可伪造)。

### P-10 · 无障碍设置本地化(Local-Only Accessibility Settings)

- **权威源**:`design/accessibility-requirements.md` §Matrix 联机行 · `OQ-A2`。
- **意图**:字号 / 缩放 / 倍率 / 字幕是**每端本地态**,不进三流、不跨端同步。
- **反例**:把倍率写进 `SimEvent`(污染真源,且与 ADR-019 §三「不成为第四个写入者」同理)。
- **状态**:⚠️ 断言已立,**守卫落点待 ADR #2**(边界程序集)。
