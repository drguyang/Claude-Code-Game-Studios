## 三、机械门的判据(四条)与它们的靶

| # | 判据 | 打的是什么 |
|---|---|---|
| **C1 新撞号** | 某 ID 被 ≥2 文件「定义」且不在基线 ⇒ 红 | **本次的病因本身** |
| **C2 基线不得扩大** | 基线 ID 不得被第三个文件再定义 | 老问题不许变大 |
| **C3 基线不得陈旧** | 基线 ID 必须**仍**是撞号 | 将来真改名后基线会腐烂成永久掩护 |
| **C4 空集守卫** | 扫到 0 条定义行 ⇒ 红 | 路径写错时 C1 在空集上恒绿(F4 空洞正控) |

### 「定义」怎么认(不靠语义)

- GDD 表行:`| **AC-20-01** | **[A]** | ...`
- ADR 校验清单:`- [ ] **AC-20-01(BLOCKING)**:...`

⚠️ **`## GDD Requirements Addressed` 整节跳过**。这条不是预防性设计,是**实测逼出来的**:
首版原型逐行扫,把 `adr-033:444` 回写表的 `| **AC-23-02** | ...` 误判成第二处定义,
凭空造出第 18 个「撞号」。⇒ 修法是**结构性的**(那一节按定义就是引用别人的 AC),
不是给 AC-23-02 加白名单。
