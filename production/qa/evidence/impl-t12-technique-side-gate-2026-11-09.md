## 1. 甲:门此前只朝一个方向看

T7 的 `technique_coverage_test` 断言「**每一行病种 / 伤情**都有技法归宿,或有具名豁免」。
**反方向没有任何东西管**:没有一条判据问过「每一门技法有没有病种用它」。

⇒ T11 量出「技法 1 覆盖 0 行」时,**全库没有一处会响**。它绿着,不是因为它没问题。

### 做法

| 件 | 内容 |
|---|---|
| `Gameplay.Boot/TechniqueCoverageExemptions.cs` | **具名豁免清单**(技法 id → 理由),今日只有技法 1 一条 |
| `DrawSurfaceAudit.EvaluateCoverageGate(coverage, exemptions)` | 纯函数,返回**两个方向**的差集 |
| `CoverageGateResult` | `UnexcusedGaps`(零覆盖且无豁免)/ `StaleExemptions`(有豁免但已覆盖) |

**判据写成集合相等,不是包含** —— 两个方向都是静默失效面:

- 只查「零覆盖 ⊆ 豁免」⇒ 豁免表可以无限长大而没人管;
- 只查「豁免 ⊆ 零覆盖」⇒ 新出现的零覆盖技法无人处理。

### 为什么豁免表是**生产代码**

它是**具名缺口清单**,不是测试夹具。放在生产面 ⇒ 补数据的人打开 `Gameplay.Boot` 就能看到
它还欠着什么;判据(集合相等)在夹具侧执行。这与 T7 的 `UndeclaredByDesign` 同一形态。

## 2. 乙:规则行的三类源 id 此前无门

T9 的规则行有三个源 id,词表分属三个系统:

| 源 | id | 词表 | 归属 |
|---|---|---|---|
| `Poi` | `poi_id` | `world_poi.json` | 6 |
| `Event` | `event_key` | `52_event_pool.json` | 52 |
| `Case` | `disease_id` | `disease_registry.json` | 9 |

写错一个 ⇒ 规则**永不命中**,且**完全静默**:没有报错、没有日志,表现只是「这局没学到东西」。
T9 只给**技法 id** 那一侧上了门(写者闭集 + 用例),这三侧一条都没有。

### 做法

`Gameplay.Boot/TechniqueUnlockRuleValidator.cs` —— 纯函数,零 I/O:

```csharp
IReadOnlyList<string> Validate(rules, poiIds, eventKeys, diseaseIds);
```

违例串带规则下标与源种类,便于定位。

**为什么是校验器而不是构建期门**:规则表今日住**代码常量**(`TechniqueUnlockRules.Default`),
没有构建期阶段可挂。若将来外部化成 baked artifact,本校验器**原样复用**在 binder 里。

## 3. 判据(7 条)

| # | 判据 | 判别力 |
|---|---|---|
| 1 | 零覆盖技法集 **恰好等于**豁免集(两方向都空) | 新增零覆盖技法没人管 / 豁免陈旧 ⇒ 红 |
| 2 | 每条豁免理由非空 | 空白理由 = 悄悄把门堵上 |
| 3 | 豁免 id ∈ 处置轴 `actions[]` | 悬空豁免(拼错 id)⇒ 红 |
| 4 | **门的谓词有牙**(负控):零覆盖+无豁免 ⇒ 报 gap;有豁免 ⇒ 不报;已覆盖+有豁免 ⇒ 报陈旧 | 谓词写坏 ⇒ 红 |
| 5 | 生产规则表零违例 | 见下,**今日空真** |
| 6 | **校验器有牙**:三类坏 id 各报一条 + **正控**(真存在的 id 不报) | 永远报违例的空实现 ⇒ 红 |
| 7 | null 词表 / null 规则 ⇒ 抛 | 空集与「没给表」混用 ⇒ 红 |

### 3.1 第 5 条今日是**空真**(写在明面上)

`TechniqueUnlockRules.Default` 为空 ⇒ 零规则 ⇒ 零违例。夹具**显式断言表为空**并把这句话写进
失败报文:「规则表今日为空 ⇒ 下面这条是**空真**,不是『查过没问题』。填了第一行之后,
请删掉本条断言,让下一条真正起作用」。这样「空真」不会被人读成「已验证」。

### 3.2 第 6 条为什么必须有正控

只写负控(坏 id ⇒ 报一条)的话,一个「**永远报违例**」的实现也会绿 —— 它连正控都过不了。
正控 = 同一批词表里**确实存在**的 id 必须零违例。
