NavMesh 烘焙成本;**Feature / MEDIUM**),而 **13 与 27 均无 GDD** —— 属「Feature 层缺口」,

## Context

### Problem Statement

R-14 原文:「**AI 架构**(13 病人 AI 只读 DTO + NavMesh;27 敌人 AI;开放世界 + 动态建造的
NavMesh 烘焙成本)| Feature | MEDIUM | 13 / 27」。它把三件不同层次的事压在一行:

1. **确定性边界**:13 只读 DTO 已由 ADR-005 / ADR-009 定形,但**敌人行为是否可重放**从未裁决 ——
   这是与 ADR-005「事件流唯一真源」直接相冲的缺口;
2. **寻路载体**:ADR-015 §五 已判「sim 走整数导航格查表,NavMesh 仅表现态」,但**格从哪来、
   算法住哪、两套网格怎么对齐**未定(ADR-015 自己在 Related 里留了「寻路形态待定」);
3. **NavMesh 成本**:动态建造下的 tile 更新成本 —— 这是**表现层预算项**,与确定性无关,
   但被原文与上两项混写。

**不裁决的代价**:敌人 AI 是 P0 垂直切片的一部分(`game-concept.md:611` 格斗线 + 敌人 AI 进 P0)。
若行为决策的实现形态事后才发现与确定性模型相冲,等于重写 AI 层 + 与其耦合的 25 / 52 / 37。

### Requirements

- **行为决策 deterministic 可重建**:同一事件流 + 同一版本化烘焙数据 ⇒ 同一 AI 行为,逐位一致。
- **表现态自由**:动画 / 插值 / 绕障 / 视觉打磨**不得回流进 sim**(禁 sim 反推表现)。
- 敌人**可受伤、可昏迷**,与既有非致命模型**同一套**,不新开生命模型。
- 13 **只读**,并提供 37 所需的**在场病人视图**;13 的**表现映射**(非真值)归 13。
- 27 提供遭遇原型给 52,并满足「**不锁定玩家**」的可脱离要求。
- **动物 AI 预留 P1a 驯化接口**(跟随 / 归属 / 命令)。
- 运行期**零第三方 AI 库**;行为可在编辑器期可视化编辑(策划可改,不必写代码)。

## Decision

**裁决:AI 层分层** —— 行为决策 = sim 侧整数派生态(不进流、可重建),逻辑位姿逐 tick 整数推进,
表现态位姿单向受其驱动;**敌人复用 9 的伤情模型**;**感知输入 = 粗粒度整数格**(跨格写世界流事件);
**行为程序编辑器期编辑、构建期烘焙为整数数据**;**sim 寻路走烘焙整数导航格,NavMesh 仅表现态**;
**13 出只读在场病人视图**(结清 37 的「契约暂定」);**动物 AI 的 P1a 驯化接口本次定型**。

### 一、AI 层分层:行为决策进 sim,运动表现态

| 层 | 内容 | 数值 | 谁持有 | 进流? |
|----|------|------|--------|-------|
| **决策层(sim)** | 行为程序求值(敌意 / 逃逸 / 目标选择 / 包抄) · **逻辑位姿**(格坐标 + 朝向枚举) · 整数导航格的路径推进 · 感知视图 | **整数**(`WorldPos` / 枚举 / `Fix` 仅限非空间量) | sim 程序集(门 A) | **否**(派生态) |
| **运动表现层** | 连续位移 / 插值 / NavMesh 绕障 / 动画状态机 / 音效触发 / 黄铜读数条 | `float` 任意 | 场景 + MonoBehaviour | **否**(纯表现) |

- **AI 决策是派生态,不是事件。** 依 ADR-009 §一 Q1 的判据推广(ADR-015 §二):
  AI 决策**无玩家-authored 历史**,由外生源**确定性重建** ⇒ 归**派生态** ——
  **不进流、不存档、加载 / 重放期重建**。**进流的是效果,不是决策**:
  敌人受伤 / 昏迷(经 §二 的 9 模型)· 遭遇开始 / 结束 —— **判定结果进流、判定过程不进流**
  (与 ADR-009 同构)。
- **逻辑位姿在 sim,表现位姿受其单向驱动。** `LogiPose = (WorldPos Cell, byte Facing)`,
  逐 tick 整数推进(沿 §五 的路径步进);表现层把 `LogiPose` 映射成连续位姿
  (插值 / 绕障 / 动画)。**反向不可信** —— 禁从 `Transform.position` 反推逻辑格
  (`adr-015:157` 的同一条纪律)。
- **重建三源不变量(本 ADR 的核心)**:AI 决策可重建的**充要条件**是
  **其全部输入 ∈ {事件流, 版本化烘焙数据, 二者的纯函数}**。
  任何第四个来源(表现态位置 · 墙钟 · `UnityEngine.Random` · 未版本化的场景几何)
  都是**静默不可重建通道**,进 Forbidden Patterns。

> **为什么不是「AI 全量进 sim」**(Alternative 3):那要求寻路也走定点整数自研,
> 成本极高,且与本作「AI 不是核心玩点」的定位不符。
> **为什么不是「AI 整体表现态」**(Alternative 2):那会让敌人行为成为「不可重放的第三类状态」,
> 迁移 / 中途加入时敌人状态无法重建,与 ADR-005 的「事件流唯一真源」张力最大。

### 二、敌人实体:复用 9 的伤情模型(id 空间语义扩大)

- **裁决(用户裁定①)**:敌人 = **可受伤实体**,其**生命 / 伤情 / 昏迷状态住 9 的伤情注册表**,
  与病人**同一套模型**。**不新开第二套生命模型** —— 25 已把「生命归零」登记为 `INJ_COMA`
  (`disease-simulation.md:497`),非致命模型(归零 = 昏迷,晾着不死)**自动适用于敌人**,
  无需重写。`skill-system.md:394-395` 的「人形敌人被误杀**不可能发生**」由此获得实现侧保证。
- **归属划分**(本 ADR 定型):
  - **27 拥有**:行为程序 · 遭遇原型定义(人形 / 野兽)——「来了怎么动」;
  - **9 拥有**:伤情 / 生命 / 昏迷**状态**(`INJ_*` 词表)——「伤成什么样」;
  - **52 拥有**:要不要来 / 来多少 / 来多强 —— 不涉及行为;
  - **42 拥有**:黄铜读数条的呈现(读 `VitalsDto`,与病人同一只读通道)。
- **id 空间语义扩大(对 ADR-006 Amendment B 的注记)**:敌人实体经 `IIdAuthority` 发放 id,
  **与病人共用同一 id 空间与同一高水位** —— 这样 ADR-006 Amendment B 的
  「`next = max(id) + 1` 由事件流重构」**依然成立**,不需要第二套计数器。
  **须同步注记**:Amendment B 终态折叠行保留的 id 字段,其语义从「病人 id」扩为「受伤实体 id」;
  折叠谓词**不适用**于敌人行(折叠只作用于病史流的病人真源)。
- **敌人伤情事件的流向**:敌人是**世界实体**,其伤情 / 昏迷状态变化**落世界流**(第三条流),
  **不污染病史流**(病史流是病人真源)。**逐 `Kind` 形状归 25 的 GDD** ——
  本 ADR 只定「住哪条流」这一定性,不越界定 `Kind` 名字与载荷。

### 三、感知输入 = 粗粒度整数格(禁读表现态位置)

- **裁决(用户裁定②)**:敌人决策所需的玩家信息 = **粗粒度整数格坐标 + 粗枚举状态**,
  作为 **sim 事实**存在。**玩家跨格时写一条世界流事件**(`ActorCellEntered` 家族),
  频率 = **格穿越率**(低频),不随帧率、不随移动距离连续产生 ——
  满足 ADR-009 的事件流有界性纪律。
- **为什么必须进 sim**:表达态位置走 ADR-001 的**第二 QoS 通道**(unreliable latest-value),
  其**到达时序不确定** ⇒ 若 AI 决策读它,决策不再是 tick 上的确定性函数,
  主机与客户端的敌人行为会分叉,§一 的「行为决策可重建」当场破产。
- **表现态位置通道不变**:高频连续位置仍走第二 QoS(表现层平滑 / 插值用),**禁用于 AI 决策**。
  两条通道**用途分离、互不替代**。
- **感知的其余分量同样整数化**:格距用**整数格距**(禁 `sqrt`;需要比较时用平方和比较)、
  视线用**逻辑层阻挡格查询**(禁 `Physics.Raycast` / NavMesh 采样 —— `random-events.md:438-439` 的纪律)。
- **粗枚举状态**(如玩家是否在战斗中 / 是否濒危)**取自 sim 真值**(9 的 `VitalsDto` 语义侧),
  不由表现层推断。

### 四、行为载体:编辑器期行为树 → 构建期烘焙为整数数据

- **裁决(用户裁定③)**:行为在**编辑器期**以行为树 / 状态机**可视化编辑**,
  **构建期烘焙为整数数据**(`assets/data/ai_[name].json` → `*.cooked`,**完全走 ADR-014 的管线**)。
  运行期是**自研的整数决策器**(数据驱动解释烘焙产物),**运行期零第三方行为树库**。
- **与 ADR-014 同构**:作者态(可视化编辑,富格式)/ 出货态(烘焙整数数据,零解析器)。
  行为程序是**版本化烘焙数据** ⇒ 进 §一 的「重建三源」,并**纳入 ADR-014 §Validation 的陈旧门**
  (源改了没重烘 = 构建失败,不是运行期幻觉)。
- **承载数值纪律**:行为程序中的**空间量**是 `WorldPos` 整数格 / 枚举;
  **非空间量**(如仇恨值 / 威胁权重)是 `Fix`(Q16.16)或 `int`;
  **禁 `float` 字段**(ADR-006)—— 与数据管线同一套校验。
- **策划可改,不必写代码**:改行为 = 改编辑器期资源 + 重烘,不进代码评审。
  这是选此载体(而非纯代码)的主要理由。
- **候选第三方编辑器须评估**(Verification ③):若第三方工具的导出 / 烘焙链路不可用,
  **退回自研数据表载体**(状态机 / 效用函数表)—— 退回**不改变本裁决的确定性形态**,
  只改作者态工具。

### 五、寻路:sim 走整数导航格,NavMesh 仅表现态

- **裁决(用户裁定④)**:兑现 **ADR-015 §五** ——
  - **sim 侧**:在**烘焙的整数导航格**(`可走 / 阻挡 / 代价`)上跑**确定性整数寻路**
    (`WorldPos` 格上的 A*;**JPS / 预烘流场为可选优化**,仅在性能实测不达标时启用,且**必须保持整数与确定性**);
  - **表现层**:`NavMeshAgent` + 动态 `NavMeshObstacle`(carving)只负责**把逻辑路径变成好看的连续位移**
    (绕障 / 平滑 / 转向)。
- **两套网格的分工与对齐**:逻辑导航格**由关卡工具产出**(ADR-015 §一 的逻辑层,与地形 / 建造槽位同源),
  NavMesh 由**视觉层地形 + 建造体**烘焙。两者**必须一致到「可走性判定不矛盾」**;
  漂移由关卡工具的一致性检查兜住(承 ADR-015 §Validation 的两层一致性检查)。
- **漂移的处置方向是单向的**:表现层偏离逻辑路径 ⇒ **表现层 snap / 修正**;
  **禁** sim 跟随表现层(那是 float 入 sim)。
- **动态建造的成本是表现层预算**:建造落位 / 拆除后 NavMesh tile 失效重烘(承 ADR-015 §四 的脏块失效)
  是**帧时 / 内存预算项**,与确定性无关 —— 与 R-10 的原始成本问号同属一类,
  须在进实现时实测(Verification ②)。**P0 可用粗化策略**(tile 尺寸 / 更新节流)兜住预算。

### 六、13 病人 AI:只读通道 + 表现映射归属 + 对 37 的在场视图

- **只读通道不变(承 ADR-005 / ADR-009)**:**13 只读不写**(`disease-simulation.md:497`)——
  13 读 `IVitalsQuery.GetVitals() → VitalsDto`(唯一浮点出口),**不得回写病史流**。
- **「只读」的边界澄清(解 `:1116` 与 `:497` 的口径张力)**:「只读」禁的是**回写 sim 真值**
  (病史 / 病例 / 世界三流),**不禁表现层输出**。13 **拥有表现映射**:
  姿态 / 动画状态机 / 咳嗽呻吟的触发 → 音频(44)—— 这些是**表现层产物**,不是 sim 事件。
  **分工**:8 拥有**体征语义**(signs 词表),13 拥有**行为与表现映射**,9 拥有**真值**。
- **13 ↔ 37 的在场病人视图(用户裁定④,结清 `case-system.md:473` 的「契约暂定」)**:
  13 暴露**只读**视图 `IPresentPatients`(在场病人的 `PatientId` + `WorldPos` 格 + 粗状态枚举),
  **37 只读它立案**;13 **不感知 37**(单向,不构成环)。
  **为什么这次定形,而 ADR-008 B-2 当时拒绝预留**:B-2 拒绝的理由是「为一个**至今没有 GDD、
  没有消费者**的系统保留扩展位」——**此处消费者已存在**(37 已立案且明写需要它)。
  与 B-2 的教训一致,不是矛盾。
  **不改既有字段**:视图是**新增只读接口**,ADR-008 的 `opened_tick` / `anchor_case` 语义不动
  (符合 `adr-008:319-323`「以追加新字段方式引入」的约定)。

### 七、动物 AI:本次定型 P1a 驯化接口形状

- **裁决(用户裁定③)**:`game-concept.md:647` 明写「P0 的动物行为 AI **须为其留接口**
  (跟随 / 归属 / 命令),否则 P1a 要重写 27」—— 本次**定型接口形状**,**P0 不实现**。
- **形状**:`ITameable`(可驯化标记 + 归属 `OwnerId` + `TameState` 枚举)+
  **命令通道复用行为程序**(`Follower / Guard / Stay` 作为**行为程序可表达的目标态**,
  **不新开第二条命令通道** —— 避免「命令」变成 sim 之外的第二真源)。
- **P0 交付**:接口 + 数据字段占位(动物实体的 `OwnerId = None`),**无驯化行为**。
  **P1a 交付**:28(#28 捕获 · 驯化 · 取材与护卫)实现驯化与命令,27 无需重写。
- **范围债显式记账**:驯化 / 护卫仍属 **P1a 范围债**(`game-concept.md:642-647` 已记)。

### 八、与 52 随机事件导演的接口(结清 TR-randomevents-028 / 029)

- **27 → 52 的数据**:遭遇原型(人形:兵痞 / 山匪 / 溃兵;野兽)—— **27 定形状,52 读**
  (`random-events.md:966`)。原型定义是**版本化烘焙数据**(§四)。
- **「遭遇体不锁定玩家」= 27 的接口要求(AC-52-16 的落地)**:27 的行为程序**必须**支持
  「已接触但可脱离」的状态 —— 遭遇体**不得**实现为硬锁定仇恨(不可脱战)。
  这是 27 侧的实现约束,52 只声明它必须存在。**P0 的兵痞原型须首先满足此条**。
- **52 与 13 的交互(TR-randomevents-028)**:52 的医疗事件注入经 **37** 落地
  (52 定何时 / 37 定是什么病,规则二-A),**病人实体的在场由 13 供**(§六 的只读视图)——
  52 **不直接驱动 13**。三者关系:**52 触发立案 → 37 立案 → 13 提供在场实体**。

### 九、性能预算与规模

- **每 tick AI 决策 = 整数运算**,预算按「**敌人数量 × 决策频率**」给:
  - **决策节流**:非近距 / 非战斗态敌人**降频决策**(LOD 式的决策频率衰减),
    离屏 / 远区可**冻结**(逻辑位姿不推进);
  - **冻结不改变判定**(承 ADR-015 §四 的「驻留与否不改变判定结果」)—— 解冻后从
    事件流 + 烘焙数据重建,结果一致。
- **P0 规模上限按最小切法定**:27 只留**一个**原型(兵痞)(`systems-index.md:534`),
  决策数 = 遭遇规模 × 低频;**架构不为「多原型」预置复杂度**。
- **承 R-11(是否 DOTS)**:AI 决策的**批量规模**是 R-11 的关键数据点。
  本 ADR **不上 DOTS**(sim 侧纯整数 C# 已足),但**决策器保持「批处理友好」形状**
  (值 struct · 无引用类型状态 · 无虚调用热点),使 R-11 若判「上 DOTS」时,
  **决策器可平移而不重写**。
- **NavMesh 动态更新成本**(§五)是表现层预算,与本节 sim 预算分账。

## Alternatives Considered

### Alternative 1: sim 决策 + 表现层 NavMesh(采用)

- **Pros**:确定性最强(决策可重建、可对拍)· 表现层完全自由 · 与 ADR-005 / 009 / 015 全部自洽 ·
  运行期零第三方 · 与「掉落身份进流 / 位置表现」同构,不是新范式。
- **Cons**:两套网格要对齐(但有 ADR-015 §Validation 的一致性检查垫底)· 逻辑位姿积分要自研。
- **采用理由**:用户裁定②④。

### Alternative 2: AI 整体表现态(敌人动作不回放,主机为准同步)

- **Pros**:成本最低,实现最自由,无需 sim 侧寻路。
- **Cons**:敌人行为成为**不可重放的第三类状态**,与 ADR-005「事件流唯一真源」张力最大;
  迁移 / 中途加入时敌人状态无法重建;联机下敌人行为在主机 / 客户端分叉且**无法察觉**。
- **否决理由**:用户裁定②;且这是本项目反复拒绝的**静默失败**模式。

### Alternative 3: AI 全量进 sim(含位移逐位可重放)

- **Pros**:确定性最强,联机最简。
- **Cons**:寻路也必须是定点整数自研,**不能用 NavMesh / PhysX**;自研成本极高;
  与本作「AI 不是核心玩点」的定位不符;收益(逐位位移)本作**不需要**。
- **否决理由**:用户裁定②(分层),成本 / 收益不对称。

### Alternative 4: 直接用 Unity Behavior 包(不作烘焙层)

- **Pros**:官方包、无需自研运行期解释器。
- **Cons**:其运行期时序**不保证逐位**、难进 sim 整数域;属 post-cutoff API(知识空白);
  第三方运行期依赖与 `technical-preferences.md` 的候选依赖纪律相悖。
- **否决理由**:用户裁定③ —— 作者态 / 出货态分离。

### Alternative 5: 纯自研代码 + 数据表(不用可视化编辑器)

- **Pros**:零新依赖,最符合仓库既有纪律。
- **Cons**:策划改行为要写代码或直接改表,**无图形化编辑**;行为复杂度上升后维护成本高。
- **未采用但作为退回路径**:若 §四 的候选第三方编辑器评估不合格(Verification ③),
  **退回此形态** —— 确定性形态不变,只改作者态工具。

### Alternative 6: 27 自持独立生命 / 状态注册表

- **Pros**:敌人语义不污染 9 的病人模型。
- **Cons**:两套生命模型并存 ⇒「归零 = 昏迷」要写两遍(非致命承诺的**双实现漂移**风险);
  敌人状态住哪条流另需裁决;`max(id)+1` 高水位重构要第二套计数器。
- **否决理由**:用户裁定① —— 复用 9 的伤情模型(25 已把归零登记为 `INJ_COMA`,模型本就在那里)。

### Alternative 7: 敌人决策直读表现态玩家位置

- **Pros**:零新增同步事实(玩家位置本就走在第二 QoS 通道上)。
- **Cons**:决策不再是 tick 上的确定性函数(到达时序不确定)⇒ 直接推翻 §一 的「决策可重建」;
  主机 / 客户端敌人行为分叉。
- **否决理由**:用户裁定② —— 粗粒度整数格进 sim。

## Consequences

### Positive

- **R-14 的三个层次被拆清**:确定性边界(§一)· 实体归属(§二)· 寻路载体(§五)各归其位,
  NavMesh 成本被明确划为**表现层预算**,不再与确定性混写;
- **AI 决策获得与 ADR-009 / ADR-015 同一套判据** —— 「派生态」分类自然承接,
  不需要为新系统发明新范式;
- **非致命模型零成本适用敌人**:25 已登记 `INJ_COMA`,§二 只是把它接到第二个实体类别;
- **13 ↔ 37 的「契约暂定」结清** —— 37 立案有确定接口,第 4 个月的 37 实现不再悬空;
- **动物 AI 的 P1a 重写风险消除** —— `game-concept.md:647` 的前置要求被兑现;
- **策划可改行为而无需写代码**(§四),且改完走 ADR-014 的陈旧门,不引入静默漂移;
- **R-11 获得输入**:决策器的批量规模是「是否 DOTS」的关键数据点,§九 保证可平移。

### Negative / Costs

- **两套网格的维护与一致性检查**:逻辑导航格与 NavMesh 必须一致到「可走性不矛盾」,
  这是新增的编辑期纪律(承 ADR-015 §Negative 的同一类成本);
- **逻辑位姿积分自研**:sim 侧要走整数路径步进,不能直接吃 `NavMeshAgent` 的输出;
- **新增一类事件**(`ActorCellEntered` 家族)与一条只读接口(`IPresentPatients`)——
  需与 ADR-009 的三流路由表、ADR-008 的字段约定对齐;
- **ADR-006 Amendment B 的 id 空间语义扩大**须同步注记(病人 → 受伤实体),
  折叠谓词须明确**不适用于敌人行**;
- **行为程序的烘焙链路是新增工具面**(编辑器 → 烘焙 → 陈旧门),作者态工具若选第三方还须评估;
- **P0 只做兵痞一个原型** —— 架构不预置多原型复杂度,但**多原型的行为程序表达能力须在 P1a 前验证**。

### Neutral

- 本节引入的 `LogiPose` / `Intent` / `PerceptionView` 等形状是**新增接口**,不改既有 ADR 的结论;
- DOTS 仍待 R-11 裁决 —— 本 ADR 只保证**可平移**,不预判结论。
