## Overview

敌人 AI(27)决定**遭遇体来了之后怎么动**:在追击、包抄、逃跑、可脱离之间切换,沿着世界的整数格移动,并与玩家、地形、玩家自己盖的墙发生关系。

而它**不决定**这些:

- **不决定来不来、来多少、来多强** —— 归 **52 随机事件导演**(`random-events.md`,ADR-016 §八)。
- **不决定伤成什么样** —— 敌人与病人**共用 9 的同一套生命 / 伤情 / 昏迷模型**(ADR-016 §二);
  生命归零登记为 `INJ_COMA`(昏迷,不是死亡),这是支柱二「医者不杀」的实现侧保证。
- **不拥有任何呈现** —— 黄铜读数条归 **42**(读 `VitalsDto`,与病人同一只读通道);
  敌人受伤呻吟的音归 **44**。

27 拥有的是**行为**:行为程序(作者期手写数据表、构建期烘焙为整数数据,ADR-016 §四)、**敌意状态机**、
**整数导航格上的确定性寻路**(ADR-016 §五)、**感知视图**(玩家的粗粒度整数格,ADR-016 §三)。

**它是这场游戏的敌人,不是它的主题。** 战斗在本作是「医疗的到达成本」而不是独立体验关卡
(`game-concept.md:794` —— 「遭遇与动物模型」注)—— 所以 27 的设计目标不是「打起来好玩」,
而是**「挡得住、读得懂、可以不打」**:敌人要有存在感与威胁,但**永远可以被绕开、被制服、被脱离**
(AC-52-16)。P0 只交付**一套行为程序 × 两类参数行(兵痞 / 野兽)**(ADR-016 §九 ——「单原型」指
**行为程序的表达能力上限**,不是实体种类数;见规则五的口径澄清)。

**归 27 的不是「战斗」,是「动」** —— 伤害数值、武器线、命中判定全归 25(`systems-index.md:362`);
27 只消费 25 的结果。

## Player Fantasy

三层,由外到内。

**直接层 —— 「它看得见我,我也看得懂它。」**
遭遇发生后,敌人不是一堵会跟着你平移的墙。它有状态,而且**状态是读得出来的**:
它正在逼近(追击)、它正在找角度(包抄)、它退开了(逃逸 / 可脱离)。
玩家应该能在**几秒内**判断出「现在能不能走」「要不要打」——
因为**它的行为本身就是读数**,不需要 UI 告诉他。它挂在你身上的那条黄铜读数条归 42,
但**它的犹豫、它的绕路、它的退却**是 27 给的。

**直接层之下的不杀感 —— 「我打赢了,但地上躺着的是个人。」**
这是本作对英灵神殿最关键的一处改写:你把一个人打倒了,**他没有死**。
他躺在那儿,**晾着也不会死**(支柱二,D1=甲)。你要面对的不是「击杀数」,
而是一个倒下的、还可能被你救起来的、之后可能再来的**人**。
27 在这里的职责是**不破坏这件事的体感**:敌人归零的瞬间**不能读作死亡**
(不能播死亡动画 / 不能淡出 / 不能让尸体消失),它必须读作**「不动了」**——
一个可处置的真值状态,而不是一个消失的实体。

**基础设施层 —— 「他们追不上我,因为我改过这个世界。」**
玩家在自己造的墙后面,**AI 走不进来** —— 因为 27 的寻路读的是 23 合成的 `EffectiveWalkable`
(ADR-016 §五 补注),玩家放置的每一个模块**当场改变敌人的可走空间**。
「位置即逻辑」在这里闭环:**你盖的东西真的挡住了人**,不只是挡了视线。

**反幻想(27 明确不做的)**:

- **不做硬锁定的追杀。** 遭遇体**不得**实现为「不可脱战」——
  追到天涯海角、没有脱战路径,是**明令禁止**的(AC-52-16)。
  玩家永远可以走开,代价是「目标没完成」,不是「被系统按着头打」。
- **不做「越远越强」。** 本作是**固定世界**(ADR-015),不是英灵神殿的同心圆难度。
  强度随**玩家当前状态**走,归 52 的 `StrengthRaw`(`random-events.md` F1)——27 不掺和。
- **不做读数的敌人。** 敌人**不能**读玩家的连续位置来决策(ADR-016 §三)——
  它读的是粗粒度整数格,这意味着**它会「看不见」你半格**。
  这不是缺陷,是本作对「AI 眼里的世界」的定义:**它和你看到的世界一样,是格子**。
- **不做多套行为程序。** P0 **只有一套**(ADR-016 §九)—— 兵痞与野兽走同一套决策器,
  差别全在**参数行**里,代码里没有 `isBeast` 分支(CD-2 口径澄清,见规则五)。
  **架构不为「将来加二十种敌人」预置复杂度** ——
  为不存在的敌人写的抽象,是这批代码里最贵的一种债。

## Detailed Design

### Core Rules

> 27 的规则分五组:**读取**(它怎么知道你在哪)· **行为**(它做什么)· **移动**(它怎么走)·
> **伤害与身份**(它和 9 / 25 的关系 —— 伤情真值归 9,动作表共读 25)· **输出**(它写什么)。
> 与 13 同法:27 的绝大多数边界**不是本 GDD 新立的,是 ADR-016 强加的** ——
> 本节的职责是把它们落到可实现的口径上。

#### 一、读取:27 只读三源,且都不是表现态

**规则一 · 27 的输入恰好三个来源。** 承 ADR-016 §一 的**重建三源不变量**:

| 来源 | 具体是什么 | 谁拥有 |
|---|---|---|
| **世界流事件** | `ActorCellEntered`(玩家格)· `Structure*` 三件套 · `PoiStateChanged` · 敌人自己的伤情事件 | 1 / 23 / 6 / 9 |
| **版本化烘焙数据** | 遭遇原型定义(`ai_enemy.json`)· 整数导航格(`world_nav_{chunk}`) | 27 / ADR-022 |
| **二者的纯函数** | `EffectiveWalkable` 合成 · 整数格距 · 视线格查询 | 23 / 27 |

**任何第四来源都是静默不可重建通道**(ADR-016 §一):表现态位置 · 墙钟 ·
`UnityEngine.Random` · 未版本化的场景几何 —— 一律**进 Forbidden Patterns**。

**规则二 · 感知输入 = 玩家的粗粒度整数格,禁读表现态位置。**
27 读的是**最近一条 `ActorCellEntered` 里的 `cell`**(ADR-020 §四),
**不是** `Transform.position`。理由承 ADR-016 §三:表现态位置走 ADR-001 第二 QoS
(unreliable latest-value),**到达时序不确定** ⇒ 读它则决策不再是 tick 上的确定性函数,
主机与客户端行为分叉。

> **这条的可感后果(不是缺陷,是设计)**:玩家在**格内移动**时,敌人读到的位置**不变** ——
> 它会在你跨到下一格之前朝旧格走。**敌人眼里的世界是格子**。这个「半格盲区」是
> **本作对 AI 感知的定义**,不是精度不足。玩家能观察到它,也能利用它(贴着格边绕)。

**规则三 · 格距比较用整数,视线用逻辑层阻挡格查询。**
格距用**整数平方和**比较(`dx² + dy² + dz²`),**禁 `sqrt`**;**禁** `Physics.Raycast` ·
**禁** NavMesh 采样(ADR-016 §三 —— 两者都读表现态几何)。视线 = 整数格上的
**Bresenham 式格步进**,逐格查 `EffectiveWalkable`。

**规则四 · 粗枚举状态取自 sim 真值,不由表现层推断。**
27 能读到的「玩家在做什么」只有粗枚举(在战斗中 / 是否濒危),**来源 = sim 真值**,
不是从动画或输入推断(ADR-016 §三)。

#### 二、行为:六态敌意状态机 · 单套程序 × 两类参数

**规则五 · P0 兵痞的敌意状态机恰六态**(2026-09-17 用户裁定)。
**态即读数** —— 玩家能从敌人的动作**读出差在哪个态**,不需要 UI(§Player Fantasy 直接层)。
态表见 §States and Transitions。

**规则六 · 单套行为程序 × 两类参数。**(2026-09-17 用户裁定,PR-27-1)
P0 的遭遇池含**人形(兵痞)与野兽**两类(`random-events.md:394`),但 27 **只实现一套行为程序**;
两者的差异**全部落在烘焙数据的参数上**,不落在代码分支上:

| 参数 | 兵痞(人形) | 野兽 |
|---|---|---|
| **`entity_kind`** | `EntityKind.Human = 0` | `EntityKind.Beast = 1` |
| **`down_class`** | `DownClass.Healable = 0` | `DownClass.Salvageable = 1` |
| 可变包抄 | ✔ | ✘(`flank_enabled = false`) |
| 可变士气 / 逃逸 | ✔(`morale_enabled = true`) | ✘(**不因士气逃**) |
| 攻击动作来源 | **25** 的武器线 | **25** 的兽类攻击 |
| 可驯化(`ITameable`) | ✘ | ✔(规则十九) |
| 归零后果 | `INJ_COMA`(昏迷,**可救治**) | 见规则十六 |

> **`entity_kind` / `down_class` 是「身份」不是「分支」**(2026-09-17 用户裁定)。
> 二者是**烘焙参数行上的整数枚举**,**不是 `if (isBeast)`** —— 决策器读到它们只用于
> **写输出**(规则十六 / 规则二十),**不改变任何转移或公式**。**禁**任何
> `if (entity_kind == Beast) { …不同的决策… }` —— 那正是规则六要消灭的东西。
> **分离两个枚举的理由**:`entity_kind` 是「这是什么」(实体分类),
> `down_class` 是「归零后走哪条下游」(处置路径)。两者**P0 恰好同值对齐**,
> 但**不合并** —— 否则 P1a 若出现「可救治的野兽」(驯化中的熊)就无法表达,
> 而合并后的枚举没有第三个值可用。**判据:一个枚举答一个问题。**

> **口径澄清(已回填 ADR-016 §九,2026-09-17)**:ADR-016 §九 的「P0 只留**一个**原型(兵痞)」
> 指的是**行为程序的表达能力上限**(一套数据集 / 一个决策器),**不是实体种类数**。
> 一条 `if (isBeast)` 分支会**同时**违反本裁定与 §九 的「不为多原型预置复杂度」;
> 而**同一套程序读不同参数行**两样都不违反。**本裁定不改变 P0 池** ——
> 52 的 P0 池仍是「兵痞 + 蛇 / 熊 / 狼 / 野狗」(`game-concept.md:794` 不动)。

**规则七 · 行为程序是版本化烘焙数据**(ADR-016 §四)。
作者态:**手写 `assets/data/ai_enemy.json`**(2026-09-17 用户裁定 —— P0 **不引入**编辑器期行为树工具,
退回 ADR-016 §四 的 Alternative 5「自研数据表载体」;**六态机 + 参数行不需要 BT 编辑器**,
砍掉工具即消掉 ADR-016 唯一一条 post-cutoff 悬置与整条工具链义务);出货态:ADR-014 两阶段烘焙 →
`ai_enemy.cooked`。**运行期是自研整数决策器解释烘焙产物,零第三方行为树库**。
**源改了没重烘 ⇒ 构建失败**(ADR-014 的陈旧门),不是运行期幻觉。

**规则八 · 行为程序里禁 `float`。** 空间量 = `WorldPos` 整数格 / 朝向枚举;
非空间量(仇恨值 / 威胁权重 / 士气) = `Fix`(Q16.16)或 `int`(ADR-016 §四 + ADR-006)。

**规则九 · 决策是派生态,不进流。** 承 ADR-009 §一 Q1 判据 + ADR-016 §一:
**效果进流,决策不进流**。敌人受伤 / 昏迷(经 9)· 遭遇开始 / 结束(规则十七)进流;
「它决定包抄左边」不进流 —— 加载 / 重放期由三源重建。

**规则十 · 决策频率按 LOD 节流;节流判据只用 sim 量,且冻结确实改变位姿。**(ADR-016 §九)
非近距 / 非战斗态敌人**降频决策**;**远区**(判据 = sim 量 `d2 > DECIDE_RADIUS²` ∧ `¬in_combat`)可**冻结**(逻辑位姿不推进)。
**冻结期不推进 `LogiPose`、不累积 `acc`** ⇒ 解冻后的位姿与「从不冻结」的运行**必然不同**
(`LogiPose` / `acc` / `path_cursor` 是**积分量**,不是 tick 的纯函数 —— 冻结即少积分)。
**这不是 bug,是可重放的 sim 真值**:解冻 tick 从三源**重新求值当前值**,**不补算**冻结期间的欠账
(EC-27-21)。**判据只用 sim 量** —— 「离屏」是**相机事实**(表现态),永不进流;
若用作冻结依据,客户端无法重算主机的调度,`ActorCellEntered` 序列将分叉(ADR-016 §一 第四来源禁则)。**故不采用「离屏」**。

**规则十一 · 「可脱离」是状态机的对等态,不是特例。**(AC-52-16 的落地)
「玩家已接触但选择不接战」**必须可达**。故 `Disengage` 是六态之一,且**进入条件必须包含
「玩家离开了接触范围」这一条与「我方战败」并列**。**禁**「不可脱战」的硬锁定仇恨 ——
这是承重约束,不是平衡旋钮(§反幻想第一条)。

#### 三、移动:路径在 sim,位移在表现

**规则十二 · 27 的寻路输入 = 23 合成的 `EffectiveWalkable`。**(ADR-016 §五 补注)
**不是**静态烘焙 `Nav` 原件:

```
EffectiveWalkable(cell) := Nav[cell].walkable ∧ ¬Overlay.blocked(cell)
```

23 是唯一合成点;**27 只读合成结果**(`modular-building.md` F-23-1)。
玩家放置的墙 / 家具**当场改变敌人的可走空间** —— 这是 §Player Fantasy 基础设施层的机制落点。

**规则十三 · 路径重规划由 27 侧轮询触发,23 无 push 义务。**(ADR-016 §五)
**失效判据**:当前路径的格集 ∩ `Overlay` 新 blocked 格 ≠ ∅ ⇒ **下 tick 重规划**。
27 **不自建** blocked 格集、**不监听** `Structure*` 事件来维护副本 ——
**直接轮询 `EffectiveWalkable`**(第二真源风险,同 13 的规则三纪律)。

**规则十四 · sim 走整数导航格 A*,表现层走 NavMesh。**(ADR-016 §五)
sim 侧在**烘焙的整数导航格**(可走 / 阻挡 / 代价)上跑**确定性整数寻路**
(`WorldPos` 格上的 A*);表现层 `NavMeshAgent` + 动态 `NavMeshObstacle`(carving)
只负责**把逻辑路径变成好看的连续位移**。
**漂移的处置方向是单向的**:表现层偏离逻辑路径 ⇒ **表现层 snap / 修正**;
**禁** sim 跟随表现层(那是 float 入 sim)。

**规则十五 · 逻辑位姿在 sim,表现位姿受其单向驱动。**
`LogiPose = (WorldPos Cell, byte Facing)`,逐 tick 整数推进。
**禁**从 `Transform.position` 反推逻辑格(ADR-016 §一;`adr-015:157` 同条纪律)。

#### 四、伤害与身份:复用 9,不新开第二套

**规则十六 · 敌人 = 可受伤实体,生命 / 伤情 / 昏迷状态住 9 的注册表。**
**不新开第二套生命模型**。25 已把「生命归零」登记为 `INJ_COMA`

#### 五、输出:两个 Kind,写者分工

**规则二十 · 27 写世界流恰好两个 Kind;遭遇的开始归 52。**(2026-09-17 用户裁定)

| Kind | 写者 | 载荷 | 何时 |
|---|---|---|---|
| `EncounterStarted` | **52** | 遭遇原型 id + `spawn_anchor` 解析出的格 + 参与者 id 集 | 52 的 `EventArrived` 同 tick 派生 |
| `EncounterEnded` | **27** | 遭遇 id + 结束原因枚举(脱离 / 全倒地 / **超时**) | 27 判定遭遇真的结束 |

> **为什么 Ended 归 27 不归 52**:52 决定**来不来**(ADR-016 §八),
> 但「遭遇什么时候真的结束」(脱离成功 / 全员倒地 / 玩家走远)是 **27 的状态** ——
> **52 不持有它,写不出它**。写作分工 = 状态所有权分工,同 ADR-021 的判据。

**规则二十之二 · 遭遇级硬时限 `ENCOUNTER_TIMEOUT` 是 `reason=超时` 的唯一机械定义。**(2026-09-18 用户裁定 [甲])
`reason=超时` **不是**状态机的第六种结束条件 —— 它的机械定义是:
```
EncounterEnded{reason=超时} ⟺ Tick − EncounterStarted.tick ≥ ENCOUNTER_TIMEOUT
```
- **触发与敌人当前状态无关**:任何非已结束的遭遇,自 `EncounterStarted` 起超过
  `ENCOUNTER_TIMEOUT` tick 未结束,27 即写 `EncounterEnded{reason=超时}` ——
  纯兜底清理,防「玩家从不去 / 遭遇永久悬挂」。
- **与「脱离」正交**:脱离 = 敌人**主动离场**(`DisengageIf` → `EncounterEnded{reason=脱离}`);
  超时 = 遭遇**过期**。同一遭遇**只写一次 `EncounterEnded`**(AC-27-24 的可写集恰 = {`EncounterEnded`});
  谁先到谁触发,先写者生效,另一路径**不再写**。
- **结束 ≠ 实体消失**(承 EC-27-12 / 规则十六):到点后敌人仍留场,走自己的 `Patrol`,
  玩家再靠近可重新进入 `Alert` —— 超时只是**战术关系**过期,不是实体终止。
- **量级归 `OQ-27-7`**(计时器组,与 `NODE_BUDGET` 同批标定)。**安全范围**:
  `ENCOUNTER_TIMEOUT > DISENGAGE_DELAY`(否则未接战遭遇会在超时与脱离两条路径间产生**竞态**)。
- **AC-27-35 判据的落实**:① 三值可达(脱离 = 不接战;全倒地 = 打完;超时 = 遭遇级硬时限)
  ② 超时路径的判据 = **遭遇开始后的 tick 计数**(§States 二 的「每 tick 检查」纪律,
  非事件驱动 —— 承 EC-27-22 同型)。

**规则二十一 · 27 不写第二条 `ActorCellEntered`。**(2026-09-17 用户裁定,PR-27-3)
`ActorCellEntered` 的 **`Actor` 命名只是留口**(ADR-009 Amendment G 已注明);
**P0 只有玩家发**。敌人的逻辑格是**纯派生态** —— 由三源逐位重建,**不进流**。
> **后果,显式记账**:联机时客户端的敌人格**完全靠确定性重算**(不靠事件回放),
> 这正是 ADR-016 §一「行为决策可重建」的**核心考验** ——
> 若重算会分叉,那是**决策器确定性有 bug**,不是「该给敌人加事件」。
> 加事件会**掩盖**这个 bug 而付出带宽与有界性代价,故不采纳。

**规则二十二 · 27 不做读数条、不做音效、不持有 UI。**
黄铜读数条的呈现归 **42**(读 `VitalsDto`,与病人同一只读通道,ADR-016 §二);
敌人的音归 **44**。27 交付**触发**与**信号**,不交付呈现(承 ADR-013 §9 C3 / ADR-018 §一)。

### States and Transitions

> 27 有四层状态,**只有第一层是 27 自己拥有的状态机**;后三层是输入或派生。
> 与 13 同法:分层的目的是让「谁拥有什么」在表上一眼可读。

| 层 | 状态 | 谁拥有 | 进流? |
|---|---|---|---|
| **① 敌意状态机** | 六态(下表) | **27** | ❌ 派生态 |
| **② 逻辑位姿** | `LogiPose = (WorldPos Cell, byte Facing)` + 路径游标 | **27** | ❌ 派生态 |
| **③ 伤情 / 生命 / 昏迷** | `INJ_*` 注册表状态 | **9**(25 负责登记归零) | ✔ 世界流 |
| **④ 遭遇生命周期** | 进行中 / 已结束 | 52(开始)/ 27(结束) | ✔ 世界流(规则二十) |

#### 一、敌意状态机(27 拥有,P0 六态)

| 态 | 玩家读到的 | 进入条件 | 退出 |
|---|---|---|---|
| `Patrol` | **在走它的路** —— 沿导航格巡游,不朝你 | 默认态 / 遭遇开始 | 感知到你 → `Alert` |
| `Alert` | **停下了,转头了** —— 面向你,不动 | `Visible` ∧ `d2 ≤ R_ALERT²`(F-27-1 分档) | `d2 ≤ R_CHASE²` ∧ `PathExists` → `Chase`;`¬Visible` ∨ `d2 > R_ALERT²` 持续 `ALERT_TIMEOUT` → `Patrol` |
| `Chase` | **直线朝你来** | **`Visible` ∧** `d2 ≤ R_CHASE²` ∧ `PathExists(e → p)` | `d2 ≤ R_CONTACT²` → `Engage`;`¬Visible` ∨ `d2 > R_ALERT²` 持续 `CHASE_TIMEOUT` → `Alert`;`DisengageIf` 成立 → `Disengage` |
| `Flank` | **不直线来,绕了** —— 走侧向路径 | `Chase` 态 ∧ `flank_enabled` ∧ `∃ ally ≠ self : ally.State = Engage` | 到位(`d2 ≤ R_CONTACT²`)→ `Engage`;`¬Visible` ∨ `d2 > R_ALERT²` 持续 `CHASE_TIMEOUT` → `Alert`;**`∃ ally : Engage` 不再成立**(全员脱离)→ `Chase`;**且** `FLANK_TIMEOUT` 到点仍未到位 → `Chase`(防绕圈) |
| `Engage` | **贴身了** —— 出手 | `d2 ≤ R_CONTACT²` ∧ **有攻击手段**(25 给) | `d2 > R_CONTACT²` 持续 `DISENGAGE_DELAY` → `Chase`;`DisengageIf` 成立 → `Disengage` |
| `Disengage` | **退了** —— 背对你走开 | **`DisengageIf` 成立**(F-27-2 / F-27-5 —— **单一谓词,非本表另立**) | 脱离成功(`d2 > R_ALERT²` 持续 `DISENGAGE_DELAY`)→ 遭遇结束(`EncounterEnded{reason=脱离}`);被追及(`Visible` ∧ `d2 ≤ R_CHASE²`)→ `Chase` |
| `Down`(非态,见下) | **不动了** | 9 的伤情真值:生命归零 | — |

> **本表的「进入条件」列不是新规格,是公式的投影** —— `Disengage` 的进入条件**恰等于**
> `DisengageIf`(F-27-2 与 F-27-5 的并集),**不在此处重复写第二遍谓词**。
> 这与 §Core Rules 规则五「态即读数」同构:表描述**玩家读到的**,公式描述**机器算的**,
> 二者必须同源 —— 抄第二遍就会分叉(这是 23 / 24 首轮评审的原型缺陷)。
> **不存在 `Down` 的进入条件** —— 它不是 27 的态(见下)。
>
> **`Visible` 项在 `Chase` 进入条件里是承重项**:F-27-1 的 `Band` 分档本身只算 `d2`,
> 是状态机的进入条件把 `Visible` 串起来 —— 少了它,敌人会**隔着墙直线追你**
> (而 `PathExists` 只保证「有路」,不保证「看得见」)。

> **`Flank` 在 P0 单人遭遇里可能永远不触发** —— 因为它要求「已有同伴在 `Engage`」。
> 这**不是死代码**:P0 池里兵痞可以成组出现(`random-events.md` 的强度轴),
> 且 `flank_enabled` 是**数据参数**,野兽行置 false。
> **禁**为「P0 只来一个」而删掉它 —— 那是把内容配置写死进状态机。

> **`Disengage` 的三条进入条件是本表的承重项**(完整谓词在 F-27-2 / F-27-5,此处不复写)。
> 前两条(士气崩 / 失去接触超时)在讲「谁赢了」,
> **第三条(`PathFailed` 持续宽限期)在讲「它进不来」** —— 不涉及胜负。
> 三条合起来才是 **AC-52-16 在状态机上的落点**:玩家可以**从头到尾不接战**,
> 遭遇仍会自行结束。**「这件事可以不发生」才是支柱二在敌人侧的体现**。

**`Down` 为什么不是第七态** —— 它不是 27 的状态,是 **9 的真值**(规则十六)。
27 在 `Down` 期间的职责**只是表现回放**(倒在地上的姿态 / 停止一切决策 / 不再移动),
**不参与任何判定**(是否存活 / 能否被救 / 是否苏醒,全归 9 / 10)。
把这层真值放进 27 的状态机 = 第二真源,当场违反 ADR-016 §二。

#### 二、感知事件表(态的驱动源)

| 输入 | 来源 | 驱动的转移 |
|---|---|---|
| `ActorCellEntered`(玩家) | 世界流 | `Patrol → Alert`(`Alert` 态下重算格距) |
| `d2 ≤ R_CHASE²` ∧ `Visible` | 27 自算(整数平方和)**+ F-27-1 分档** | `Alert → Chase` |
| `¬Visible` ∨ `d2 > R_ALERT²` 持续 `ALERT_TIMEOUT` | 27 自算(**逐 tick 计时**) | `Alert → Patrol` |
| `¬Visible` ∨ `d2 > R_ALERT²` 持续 `CHASE_TIMEOUT` | 27 自算(**逐 tick 计时**) | `Chase` / `Flank` → `Alert` |
| `d2 ≤ R_CONTACT²` | 27 自算 | `Chase` / `Flank` → `Engage` |
| `d2 > R_CONTACT²` 持续 `DISENGAGE_DELAY` | 27 自算 | `Engage → Chase` |
| `Visible` ∧ `d2 ≤ R_CHASE²`(被追及) | 27 自算 | `Disengage → Chase` |
| `d2 > R_ALERT²` 持续 `DISENGAGE_DELAY`(脱离成功) | 27 自算 | `Disengage` → **遭遇结束**(`EncounterEnded{reason=脱离}`) |
| `DisengageIf`(F-27-2 `morale_enabled ∧ Morale < MORALE_BREAK`;F-27-5 三条) | 27 自算 | 任一态 → `Disengage` |
| 路径失效(∩ `EffectiveWalkable` 新 blocked ≠ ∅) | 27 轮询 23 | **不换态**,下 tick 重规划(规则十三) |
| 敌情真值变化(自己受重伤 / 同伴倒地) | 世界流(9) | 士气重算 → 可能 `→ Disengage` |
| 生命归零 | 世界流(9) | 一切态 → `Down`(非态,表现回放) |

> **表中「持续 `X` 」是本表唯一的计时语义**:全部计时器**每 tick 检查**(见下死区注),
> **不是**「收到下一个事件时才算超时」。

**全部 `27 自算` 行的量都是 tick 上的纯函数**(`d2` / `Visible` / `Morale` / 超时计数),
**无一读表现态** —— 这是 §Core Rules 规则一 的三源不变量在转移表上的落实,
也是 AC-27-02 的反射断言能覆盖的范围。

> **注意 `Alert` 存在一个「无事件」的死区风险**:`ActorCellEntered` **只在跨格时发**
> (规则二)→ 玩家**站在格内不动**时,27 **不会收到任何新事件**。
> 这**不是 bug**,但**要求超时逻辑必须由 tick 驱动而非事件驱动** ——
> 否则「玩家站住不动」会让敌人在 `Alert` 态**永久卡住**。
> **实现纪律**:`ALERT_TIMEOUT` / `CHASE_TIMEOUT` 的计时器**每 tick 检查**,
> **禁**写成「收到下一个事件时才算超时」。

#### 三、遭遇生命周期(与 52 的边界)

```
52 EventArrived (tick T)
   └─► 同 tick 派生 EncounterStarted        [写者 = 52]
         └─► 27 从烘焙原型实例化敌人,进入 Patrol
               └─► … 六态机循环 …
                     └─► 27 判定结束 → EncounterEnded   [写者 = 27]
```

- **`EncounterStarted` 与 `EventArrived` 同 tick**:52 决定来,27 实例化 ——
  **中间不隔 tick**,否则「事件已降临但敌人还没出现」成为一个可观察的真空窗。
- **结束原因是枚举**(脱离 / 全倒地 / 超时),**不是布尔** —— 51 的回放分析需要区分
  「玩家逃了」与「玩家打完了」(ADR-019 §一:回放即数据记录)。
  **`reason=超时` 的机械定义 = 遭遇级硬时限 `ENCOUNTER_TIMEOUT`**(规则二十之二):任何遭遇
  自 `EncounterStarted` 起超过该时限未结束,27 即写超时 —— 纯兜底清理,防遭遇永久悬挂。
- **`EncounterEnded` 不等于敌人消失**:倒地的敌人仍在世界里(规则十六),
  可被 10 救治 / 28 捕获。**「遭遇结束」是战术关系的结束,不是实体的结束。**

## Formulas

> **域纪律**:本节全部公式在**整数 / 定点域**求值(ADR-005 / ADR-006)。
> 空间量 = `WorldPos` 整数格;非空间量 = `Fix`(Q16.16)· `int`。
> **零 `float` / 零 `sqrt`**(ADR-016 §三)。
> **全部常量值 = 待裁**(`OQ-27-1…7`)—— 本 GDD 只交付公式与变量表,不替用户拍定值。
> ⚠️ **`OQ-27-7`(计时器 / 搜索预算组)与其余六条不同**:它有**正确性面**
> (`NODE_BUDGET` 太小 ⇒ 假阳性失败;`FLANK_TIMEOUT < CHASE_TIMEOUT` ⇒ 包抄卡死),
> **须在写 A\* 与状态机之前定量级**,不能推迟到调参轮。

> **同 tick 内多敌人的求值顺序必须钉死(2026-09-18 重开评审补)**:27 的决策是**逐实体**的
> (同遭遇内每个敌人各自跑六态机)。同 tick 内多实体共享的读量(`d2` / `Visible` /
> 士气同伴计数 / `PathExists` / 世界流事件)在求值顺序未定义时会**取决于实现者的迭代序**
> —— 与 F-27-1 的 `Band` 行序是**同一类静默缺陷**(ADR-006 D-21-26 谱系)。
> **钉死为**:
> ```
> 27 的 step(按 tick):
>   ① 按 actor_id 升序逐个求值每个敌人的六态机(纯函数,读上 tick 快照;
>      互斥转移 → 同一 tick 内无链式反应)
>   ② 遭遇级检查(ENCOUNTER_TIMEOUT 到点 → EncounterEnded{reason=超时})
>   ③ 写本 tick 的输出(EncounterEnded)
> ```
> **`actor_id` 升序是承重选择**(27 侧确定性;与 13 / 25 的 id 空间共用,ADR-006 Amendment B):
> 迭代序必须**完全由 sim 量决定**,禁止暴露字典序 / 数组序 / 实例指针序。
> **每 tick 快照读**:`d2` / `Visible` / `Morale` 同伴计数 / `PathExists` 全部取**上 tick 落盘值**,
> 一个敌人本 tick 的转移**不改变**同 tick 另一敌人的读量 —— 无链式反应(否则求值序进入转移本身,
> 可重放性依赖实现顺序)。
> **同 tick 两条 `EncounterEnded` 互斥**:恰一条(AC-27-24 的可写集 + 规则二十之二的「只写一次」)。

### F-27-1 —— 感知分档(格距判定,**禁 sqrt**)

```
d2      := (px − ex)² + (py − ey)² + (pz − ez)²        // 整数平方和,WorldPos 各分量
Visible := d2 ≤ R_VIS²  ∧  LineOfSight(e, p) = true

Band(e) := Patrol   if  ¬Visible ∨ d2 > R_ALERT²
           Alert    if  Visible ∧ d2 ≤ R_ALERT² ∧ ¬ChaseReady
           Chase    if  Visible ∧ d2 ≤ R_CHASE² ∧ PathExists(e → p)
Flank   := Chase ∧ flank_enabled ∧ (∃ ally ≠ e : ally.State = Engage)
```

> **`Band` 的求值顺序即优先级:自上而下,首个为真者胜(互斥,非并列)。**
> **`ChaseReady` 是 `Chase` 行的谓词**:`d2 ≤ R_CHASE² ∧ PathExists` ——
> 它把人从「已分档」里摘出来,使 `Alert` 与 `Chase` **不可能同时为真**。
> **原稿的三行是并列条件 ⇒ 当 `R_CHASE < R_ALERT`(合法且常见)时,
> 同时落进 `Alert` 与 `Chase` 两行 ⇒ 分档结果取决于实现者的行序**。
> 这是**静默**缺陷(AC 全绿,行为随机),故在公式里定死顺序,
> **不留给实现者选**。**禁**任何「按带宽重叠做加权」的变体 ——
> 那是把一处确定性问题改成一枚举重问题。

| 变量 | 类型 | 含义 | 安全范围 |
|---|---|---|---|
| `R_VIS` | `int` 格 | 视线半径(硬上限;超出即不可见) | ≥ `R_ALERT` |
| `R_ALERT` | `int` 格 | 警戒半径 | `R_CHASE ≤ R_ALERT ≤ R_VIS` |
| `R_CHASE` | `int` 格 | 追击半径 | ≥ `R_CONTACT` |
| `R_CONTACT` | `int` 格 | 接触半径(进入 = 贴身) | ≥ 1 |

**关系式(构建期断言)**:`R_CONTACT ≤ R_CHASE ≤ R_ALERT ≤ R_VIS` —— 四值**必须单调**。
**破了会怎样**:非单调 ⇒ 存在「进了追击半径但仍在警戒半径外」的格,
该格上敌人**永不进入 `Chase`** ⇒ 一个**看得见却不追**的静默死区。

**`d2` 在 int64 域求值**(承 24 的 B6 教训):`WorldPos` 是 `(i32,i32,i32)`,
两个 i32 分量的差平方在 int32 域**会溢出**(`|Δ| > 46341` 即溢出)。
**全部中间量用 int64**,仅最终比较用同一类型。

> ⚠️ **原稿把 int64 界的断言对象写成 `R_VIS` —— 这是错的。**
> `d2` 的溢出风险来自**坐标差的量程**(世界尺度),**不是**感知半径:
> 一个 `d2` 的加法链是 `(px−ex)² + (py−ey)² + (pz−ez)²`,三项**各自**可达
> `|Δ|²`。`R_VIS` 只是**比较阈值**,它对中间量**零约束** ——
> 把 `R_VIS < 46341` 写成断言,既拦不住真正的溢出,又给了一个**虚假的安全感**。
> **正确的断言对象 = 世界坐标量程**(`W`):
> **构建期断言** `3 × (2W)² < 2^63`(即 `2W < 2^30.5` ⇒ `W < 7.6e8`)。
> **未定前**按 ADR-015 §三 的 `i32` 上界保守取 `W ≤ 2^30`;
> 超出则 `throw`,**不在运行期 clamp**(clamp 会把溢出变成**静默的错误格距**)。

`LineOfSight(e, p)` = 整数格上的 **Bresenham 步进**,逐格查 `EffectiveWalkable(cell)`;
**任一中间格不可走 ⇒ 视线被挡**(规则三)。**禁** `Physics.Raycast`。

> **为什么 `d2` 用平方而非开方**:开方引入无理数 ⇒ 定点近似 + 舍入 ⇒ 跨平台不逐位
> (ADR-012 的黄金夹具会当场抓到)。**比较两次方是等价的**,且**整数精确**。
> 这也是 13 的做法(`patient-ai.md` F-13.3),两系统共用同一纪律。
>
> **`PathExists` 是本式唯一的图查询**:它由 F-27-7 的 A* 给出
> (`A*(e → p, EffectiveWalkable)` 返回非空路径),**单 tick 至多求值一次**,
> 结果**缓存到 `path_cache`**(F-27-7 §缓存策略)—— 否则每个敌人每 tick
> 一次全图 A* 会把 ADR-016 §九 的预算吃掉。

### F-27-2 —— 士气(驱动 `Disengage` 的唯一量)

```
Morale := clamp( MORALE_BASE
                 + Σ_{t ∈ ThreatTypes(self)} w_threat[t] × MORALE_K
                 + w_peer × (nearby_allies − downed_allies)
                 − w_hurt × HurtLevel(self)
                 , MORALE_MIN, MORALE_MAX )
```

| 变量 | 类型 | 含义 | 安全范围 | 定义处 |
|---|---|---|---|---|
| `MORALE_BASE` | `Fix` | 基础士气 | `MORALE_MIN < base ≤ MORALE_MAX` | 参数行 |
| `w_threat[t]` | `Fix` | 各类威胁的权重(**下标域见下**) | 逐类型独立 | 参数行 |
| `MORALE_K` | `Fix` | 威胁权重 → 士气的换算系数 | > 0 | 参数行 |
| `w_peer` | `Fix` | 同伴影响系数 | > 0 | 参数行 |
| `w_hurt` | `Fix` | 自身伤重影响系数 | > 0 | 参数行 |
| `MORALE_BREAK` | `Fix` | 崩溃阈值 | `MORALE_MIN < BREAK < MORALE_BASE` | 参数行 |
| `MORALE_MIN` / `MORALE_MAX` | `Fix` | 钳制上下界 | `MIN < 0 < MAX` | 参数行 |
| `HurtLevel(e)` | `int` 档 | **自身伤重档位**(整数,非浮点) | `[0, HURT_LEVEL_MAX]` | **9**(见下) |
| `nearby_allies` | `int` 计数 | 同遭遇内**未倒地**的同伴数 | ≥ 0 | 27 自算(见下) |
| `downed_allies` | `int` 计数 | 同遭遇内**已倒地**的同伴数 | ≥ 0 | 27 自算(见下) |
| `ThreatTypes(e)` | 集合 | `e` 当前感知到的威胁类型集 | 有限 | 27 自算(见下) |

> **原稿把上表末四行留在公式里不定义 —— 那是 `HurtLevel` / `nearby_allies` /
> `downed_allies` / `w_threat` 下标域四个符号的无主状态**(参考实现必须凭空发明它们)。
> 现逐项定死,且**每一项都有明确的第一所有者**:

**① `HurtLevel(e)` ∈ `[0, HURT_LEVEL_MAX]` = 9 的伤情真值的整数投影。**
`HURT_LEVEL_MAX` 是**参数行上的整数**(建议 3,值由用户定 —— 见 `OQ-27-2`)。
**映射由 9 定义**(它是伤情的所有者):由逐伤情 bar 的 `position` 折叠成档,
**27 只读投影值,不自己算伤重**(规则十六 —— 27 累加伤情 = 第二真源)。
**未受伤 = 0**。**`HurtLevel` 不是 27 的派生量** ⇒ 它的定义与落地**由 9 的公开查询承载**
(`QueryHurtLevel(actor_id)`,2026-09-17 25 的 R17 回填已落 `disease-simulation.md` F4 节)。
⚠️ **措辞订正(承 25 · S2 改判 + R17)**:原稿两处口径均已作废 ——
① 「由伤情事件的**严重度枚举**折叠」(实为**逐 bar `position` 折叠**,严重度枚举是注册表静态字段不是逐次伤害量);
② 「必须由 **25 的伤情事件载荷**承载」(25 的载荷只带 `magnitude` + `dose_seq`,**不带档位**;
归 9 折叠)。`O-27-3` 的「25 提供载荷」半边随 R2 已结,**本边的兑付 = 9 侧落字,不再是 25 的账**。

**② `nearby_allies` / `downed_allies` = 同遭遇内的同伴计数,由 27 自算。**
**「同遭遇内」= 同一 `encounter_id`** —— 这是唯一的成员定义,
**不是**「半径 N 格内的所有敌人」(那会把两个无关遭遇的敌人算成同伴,
且引入一个没有来源的半径常量)。**「倒地」的判据 = 该同伴的 9 真值为归零**
(`Down` 的表现回放已开始),**不是**「它在 `Disengage` 态」。
⇒ **计数是 tick 上的纯函数**(遭遇成员集 + 各自 9 真值),满足三源不变量。

**③ `w_threat[t]` 的下标域 = `ThreatType` 枚举(封闭、有界)。**
**定义在 27 侧,值在参数行**(承 ADR-021 §三 的「骨架先行、载荷归系统」纪律)。
P0 值域**刻意取粗**(4 项),因为**数值归 25**:

| `ThreatType` | 触发 | P0 |
|---|---|---|
| `Melee` | 玩家进入 `R_CONTACT` 且 25 报近战武器线 | ✔ |
| `Ranged` | 玩家持有远程武器线(25 报) | ✔(P0 池无远程敌人,但**玩家可能持** ⇒ 值域须在) |
| `Outnumbered` | `nearby_allies = 0` ∧ 玩家 `in_combat` | ✔ |
| `BeastTerrified` | 对手是野兽且己方为兽(兽类之间的畏惧) | ✔ |

> **`ThreatType` 是封闭枚举不是开放字符串**,且**项数上界须构建期断言**
> —— 见下溢出纪律。**`BeastTerrified` 不在 P0 池里被触发**(P0 无兽对兽遭遇),
> 但**枚举值保留** —— 去掉它不会省任何东西,而加回来要改烘焙 schema。

**`Disengage_if` 的唯一出处 = 本节**(F-27-5 **不复写这一条**)。

```
Disengage_if_morale  :=  morale_enabled ∧ Morale < MORALE_BREAK
```

**全式在 int64 域求积后再 clamp**(承 24 的 B6 教训):`Σ` 是**有限项和**
(项数 = `|ThreatType|` + 2 = 6),**项数上界须在构建期断言**
(`2 × |ThreatType| × |w_threat|_max × MORALE_K < 2^63`),否则静默溢出。
**`Morale` 的比较也在 int64 域**(`Fix` 的 raw 值),**禁**先转 `float` 再比。

**`morale_enabled` 与 `flank_enabled` 为何是两个门**:规则六的表中,
野兽 `morale_enabled = false` ⇒ 本式短路 ⇒ 野兽**永不因士气逃逸**;
而 `flank_enabled` 只关**包抄**(F-27-1 的 `Flank` 行)。
**两条行为两个门,同一张参数表** —— 用一个门管两条行为会让
「不会包抄但会逃的敌人」无法表达(而那是 P1a 想要的原型)。

> ⚠️ **`MORALE_BREAK < MORALE_BASE` 是承重条件,不是平衡旋钮。**
> 若 `BREAK ≥ BASE`(例如作者手滑把 BREAK 调高),
> **每个敌人在遭遇开始的那一 tick 就立刻 `Disengage`** ⇒ 遭遇永远不发生,
> 而 AC 会**全绿**(「可脱离」确实可达)。⇒ 见 §Edge Cases EC-27-02。

### F-27-3 —— 决策频率(LOD 节流)

```
in_contact := d2 ≤ R_CONTACT²

DecisionPeriod(e) := DECIDE_PERIOD_NEAR   if  in_combat ∨ d2 ≤ R_ALERT²
                     DECIDE_PERIOD_FAR    if  ¬in_combat ∧ d2 ≤ DECIDE_RADIUS²
                     FROZEN (∞)           if  d2 > DECIDE_RADIUS²

Skip := (Tick − e.last_decision_tick) < DecisionPeriod(e)
```

| 变量 | 类型 | 含义 | 安全范围 | 定义处 |
|---|---|---|---|---|
| `DECIDE_PERIOD_NEAR` | `int` tick | 近距决策周期 | ≥ 1(tick) | 参数行 |
| `DECIDE_PERIOD_FAR` | `int` tick | 远距决策周期 | ≥ `DECIDE_PERIOD_NEAR` | 参数行 |
| `DECIDE_RADIUS` | `int` 格 | 冻结半径 | ≥ `R_ALERT` | 参数行 |
| `in_combat` | `bool` | **本敌人是否在战斗中** | — | 27 自算(见下) |
| `last_decision_tick` | `int` tick | 上次真正决策的 tick | ≤ `Tick` | 27 实体字段 |

> **`in_combat` 的定义**(原稿未给,是本节第一个悬空符号):
> **`in_combat(e) := e.State ∈ {Chase, Flank, Engage}`**。
> **不含 `Alert`**(站定张望不是战斗)、**不含 `Disengage`**(正在退,不该拖住 LOD)。
> ⇒ **`in_combat` 是 27 自己状态的纯函数**,不读任何外部标志位。
> **这消掉了「战斗态」作为第四来源的入径** —— 它看起来像外部真值,
> 实际由状态机自推。
> ⚠️ **注意 `in_combat` 与 `engaged_with_player`(F-27-5)是两个不同的量**:
> 前者是**本敌人的状态机态**(策略层,3 个态),
> 后者是**接触关系**(几何层,`d2 ≤ R_CONTACT²` 的窗口化)。
> 原稿混用二者,故在 F-27-5 就地分清(见彼处注)。

**`FROZEN` 的语义是「不推进逻辑位姿」,不是「不计算」** —— 冻结的敌人
**仍在状态机上**,只是 `DecisionPeriod = ∞` ⇒ 永不到点 ⇒ 位移与转移都不发生。
**解冻不产生补算**:不是「把冻结期间欠的决策补上」,而是**从三源重新求值当前 tick 的值**。

> ⚠️ **原稿此处写「(ADR-016 §九:冻结不改变判定结果)」—— 该引用是误植,已删。**
> ADR-016 §九 的原文是「**冻结不改变判定**」,其语境是 **ADR-015 §四 的加载期驻留**
> (格子常驻与否不影响结果);把它搬到 **运行期 step 跳过**上不成立 ——
> 跳过 step 就是**少积分**,`LogiPose` / `acc` / `path_cursor` 三者都不是 tick 的纯函数。
> **冻结确实改变位姿** —— 这是 §Core Rules 规则十 已定的立场
> (`F-27-3` 只负责**何时**跳过,`规则十` 负责**跳过的后果**)。
> **二者是同一件事的两处表述,必须一致**;AC-27-04 / 05 按规则十 的口径改写(见彼处)。

> **`DECIDE_RADIUS ≥ R_ALERT` 是承重条件**:若 `DECIDE_RADIUS < R_ALERT`,
> 则存在「已进入警戒半径但决策被冻结」的格 ⇒ `Alert` 态**永不推进** ⇒
> 敌人**定在原地转头看你**,却永远不追。**看得见的静默 bug。**

> **⚠️ 冻结 / 解冻与 `FROZEN` 的边界**:冻结期**`acc` 不累加**(规则十)。
> 若不冻结 `acc`,解冻的第一 tick 会**一次性吐出**冻结期间攒下的全部 `ENEMY_SPEED`,
> `while` 循环把敌人**瞬移若干格** —— 而那几格**从未被 `EffectiveWalkable` 查过**。
> **这与 EC-27-04 的隧穿同型,但触发路径不同**(EC-27-04 是速度配置错,
> 这里是**加速器状态管理错**),故单列 **EC-27-23** 且 AC-27-05 显式点名「冻结 / 解冻」。

### F-27-4 —— 逻辑位姿步进(定点累加器,防跳格)

```
LogiPose 每 tick:
  if  ¬Moving(e):            // 冻结 / Down / Alert / Engage 静止 → 见下
      acc := acc             // 不累加、不清零(规则十:冻结期 acc 冻住)
  else:
      acc := acc + ENEMY_SPEED                   // Fix;ENEMY_SPEED = 格/tick
      while acc ≥ FIX_ONE:
         acc     := acc − FIX_ONE
         cell    := Path[path_cursor + 1]        // 沿整数路径前进恰好一格
         path_cursor := path_cursor + 1
  Facing := DirFrom(cell, Path[min(path_cursor + 1, |Path| − 1)])
```

| 变量 | 类型 | 含义 | 安全范围 |
|---|---|---|---|
| `ENEMY_SPEED` | `Fix` (格/tick) | 逐 tick 沿路径推进的格速 | `0 < v ≤ ENEMY_SPEED_MAX` |
| `acc` | `Fix` | 累加器(余数)**住敌人实体** | `[0, 1)` 恒成立 |
| `FIX_ONE` | `Fix` | 1.0 的定点表示(`65536`) | 常量 |
| `Moving(e)` | `bool` | 本 tick 是否推进位移 | 见下 |

> **`Moving(e)` 的定义**(原稿缺,是第二个悬空符号):
> **`Moving(e) := ¬Frozen(e) ∧ ¬Down(e) ∧ e.State ∈ {Patrol, Chase, Flank, Disengage}`**
> —— `Alert`(站定张望)与 `Engage`(贴身出手,位置交给 25 的战斗)在此态**不推进逻辑位移**。
> ⇒ **`acc` 在这两种态下也不累加**:否则敌人在 `Engage` 打十 tick 后一脱离,
> `acc` 攒满 ⇒ 下次 `Moving` 的第一 tick **瞬移一格**。
> **这与 F-27-3 的冻结同一类错误,故合并为同一条纪律**:
> **`acc` 只在 `Moving` 为真的 tick 里前进;`Moving` 转假时 `acc` 保持,不归零。**

**为什么用累加器而不是「每 tick 走 `ENEMY_SPEED` 格」**:
`ENEMY_SPEED` 是 `Fix` ⇒ 若直接乘,格子坐标会**变成小数** ⇒ 逻辑位姿不再是整数格 ⇒
`WorldPos` 的整数性当场破产。累加器把**小数部分留在 `acc` 里**,
**格坐标永远整数**(ADR-015 §三)。

**防跳格不变量(构建期断言)**:`ENEMY_SPEED < FIX_ONE`(即 < 1 格/tick)。
**破了会怎样**:`ENEMY_SPEED ≥ 1` ⇒ `while` 循环**单 tick 前进 ≥ 2 格** ⇒
敌人**穿过玩家的墙** —— 而 23 的 `EffectiveWalkable` 查的是**格**,
跳过的格**根本没被查过**。**隧穿**(与系统 1 的 `AC-1-02` 同型,但这里更容易犯,
因为 AI 的速度是策划直接调的旋钮)。

**`acc` 不变量(构建期断言)**:`0 ≤ acc < FIX_ONE` **恒成立**(EC-27-23)。
**破了会怎样**:`acc` 落在 `[FIX_ONE, ∞)` ⇒ `while` 循环同 tick 连走多格 ⇒ **隧穿**;
`acc < 0` ⇒ `Path` 越界读(F-27-7 §`path_cursor` 的边界处理)。
**两处都在构建期 `throw`**,不在运行期 clamp。

### F-27-5 —— 脱离判定(AC-52-16 的机械落点)

```
engaged_with_player := (d2 ≤ R_CONTACT²)          // 几何关系,不是状态机态

DisengageIf :=
    Disengage_if_morale                                    // ← 唯一定义在 F-27-2
  ∨ (¬engaged_with_player ∧ (Tick − last_contact_tick) ≥ DISENGAGE_DELAY)
  ∨ (PathFailed(e → p) ∧ (Tick − last_path_tick) ≥ PATH_FAIL_GRACE)
```

| 变量 | 类型 | 含义 | 安全范围 |
|---|---|---|---|
| `DISENGAGE_DELAY` | `int` tick | 失去接触后多久开始脱离 | ≥ 1 |
| `PATH_FAIL_GRACE` | `int` tick | 无路可走的宽限期(防瞬态抖动导致秒退) | ≥ 1 |
| `engaged_with_player` | `bool` | **几何上的接触关系**(`d2 ≤ R_CONTACT²`) | — |
| `last_contact_tick` | `int` tick | 上次 `engaged_with_player` 为真的 tick | ≤ `Tick` |
| `last_path_tick` | `int` tick | 上次 `PathExists` 为真的 tick | ≤ `Tick` |
| `PathFailed(e→p)` | `bool` | `¬PathExists(e → p)`(A* 空路径,F-27-7) | — |

> **🔴 本节与 F-27-2 的门分裂是本 GDD 最高信号的缺陷,已就地修死。**
> **原稿**:F-27-2 用 `morale_enabled` 管士气逃逸,而 F-27-5 的第二个析取项
> 复写了一遍 `(Morale < MORALE_BREAK ∧ flank_enabled)` ——
> **同一件事用了两个不同的门** ⇒ 同一份文档里两条「`Disengage` 的唯一谓词」互相矛盾
> (`morale_enabled=true, flank_enabled=false` 时,一个说逃、一个说不逃)。
> 而原判据(原稿 AC-27-10,**今 AC-27-11**)只取 P0 两行(两门同值)⇒ **全绿**。
> **这是静默缺陷的教科书形态。**
> **修法(单一出处)**:士气项**只在 F-27-2 定义一次**(`Disengage_if_morale`),
> **F-27-5 只引用不重写**。⇒ 门分裂在结构上不可能再发生。
> **AC-27-11 随之改为 2×2 叉乘**(见彼处)—— 只有叉乘能在**不依赖人眼**的前提下
> 抓住「两个门管一条行为」。

**第一条(`¬engaged_with_player`)是 AC-52-16 的机械实现** ——
它**不以「谁赢」为条件**,只以「**是否还在接触**」为条件。
**玩家从未接战 ⇒ 从来不是 `engaged_with_player` ⇒ 计时器一直跑 ⇒ 到点即脱离。**
这正是支柱二要的那件事:遭遇**可以自行结束**,不需要玩家「打赢」。

> **`engaged_with_player` 是几何量,`in_combat` 是状态量 —— 二者刻意不合并。**
> 前者幂等于 player 的**距离窗口**(`d2 ≤ R_CONTACT²`),
> 后者幂等于**本敌人的状态机态**(`State ∈ {Chase, Flank, Engage}`,F-27-3)。
> 原稿在 `Engage` 的退出条件里写「玩家脱离接触」而没给谓词 ——
> 现由本表统一为 **`¬engaged_with_player` 持续 `DISENGAGE_DELAY` ⇒ `Engage → Chase`**
> (§States 一 表的 `Engage` 行已是此口径)。
> **合并二者会造出一个 choke point**:所有脱离判定都变成状态机查询,
> 而「玩家走开了」是**玩家侧的事实**,不该依赖敌人自己的态。

> **`PATH_FAIL_GRACE` 存在的理由**:若玩家用墙把敌人彻底围死,`PathFailed` **恒真**。
> 没有宽限期 ⇒ 敌人**转身就走**(行为上合理但读起来像"卡住了就凭空放弃")。
> 有宽限期 ⇒ 敌人**先在墙外转几圈**,再退 —— 玩家读到的因果是
> 「**它进不来,所以走了**」,而不是「贴图卡了」。**这是表现正确性,不是平衡。**

### F-27-6 —— 目标选择(P0 单人形式 + `target_policy` 扩展点)

> **本式整体是 2026-09-17 用户裁定的新增项。** 原稿**没有任何目标选择规则** ——
> 参考实现必须凭空发明「追谁」,而这是一个**影响确定性**的判定
> (两个人格同时可见时选谁,决定了后续全部轨迹)。即使 P0 是单人,该规则也必须存在。

```
Target(e) :=
    argmin_{c ∈ Candidates(e)}  d2(e.Cell, c.Cell)          // 最近格距(整数平方和)
    tie_break:  lowest actor_id                             // 严格决胜键

Candidates(e) := { p : p 是玩家侧行动者 ∧ Visible(e, p) }
                 ∪ { a : a 是敌对关系中的另一实体 }          // P0 空集
```

| 项 | 类型 | 含义 |
|---|---|---|
| `Candidates(e)` | 集合 | 本敌人**当前可选**的目标集(**受 `Visible` 过滤**) |
| `tie_break` | 规则 | **格距全等时取 `actor_id` 最小者** |

> **`tie_break` 是规则的一部分,不是实现细节。** 没有它,
> 「两个等距目标」的场景下 A* 的移动方向取决于**容器遍历顺序**(实现相关)
> ⇒ 跨平台不逐位 ⇒ AC-27-01 会抓,但抓到的现场**无法定位到根因**。
> **`lowest actor_id` 与 ADR-006 Amendment B 的 id 发放同源**:id 是单调计数器,
> 故决胜键**稳定且可重构**(不依赖内存地址 / 创建顺序)。

> **P0 的 `Candidates` 恒为单元素**(只有一个玩家行动者)—— 本式在 P0 的
> **可观察行为**等价于「追玩家」。**那为什么还要写?**
> 因为**规则必须存在**:P0 与 P1b 的差别不该是「有没有目标选择代码」,
> 而是**同一个决策器读到不同的候选集**。⇒ 这正是规则六「单套程序 × 多套参数」的同构。

**扩展点(命名,不实现)**:**`target_policy`** —— 烘焙参数行上的一个枚举,

| 值 | 语义 | P0 |
|---|---|---|
| `NearestVisible` | 上式的默认形式(本项目 P0 唯一取值) | ✔ **唯一实现** |
| `LowestVitality` | 选体征最弱者(群集狩猎的野兽) | ✘ **P1a 预留** |
| `LastAttacker` | 选最近攻击自己的(复仇行为) | ✘ **P1a 预留** |

> **`target_policy` 是「命名一个口子」,不是「实现一个多态」。**
> P0 **只有 `NearestVisible` 一条分支**,其余两值**在烘焙 schema 里合法但无实现**
> —— 读到非 `NearestVisible` 值 ⇒ **构建期 `throw`**(陈旧门同法:
> 数据声明了一个本构建不支持的能力 ⇒ 硬失败,而不是静默退回默认)。
> **这防的是**:作者在 P0 数据里手写 `"target_policy": "LastAttacker"`
> 而运行期静默按最近者跑 —— 一个**只有靠行为日志才能发现**的静默失败。

### F-27-7 —— 整数导航格 A*(确定性规格)

> **原稿只写「跑确定性整数寻路」,无一处规格** —— 而 A* 的**每一处**
> 都可以是确定性的或不是(启发式是否含 `sqrt` · 平局如何破 · 节点上限 · 缓存何时失效)。
> **「确定性 A*」不是一个规格,是一个愿望**;本式把它落成规格。

```
A*(s, g, EffectiveWalkable) →
  open   := 最小堆,键 = (f, h, cell.Z, cell.Y, cell.X)   // ← 全整数,无浮点
  f(c)   := g(c) + h(c)
  g(c)   := Σ cost(step)         // 逐格累加,整数
  h(c)   := OCTILE(c, g)          // 见下 —— 整数,零 sqrt
  cost(step) := STEP_COST         // 常量,整数(不做地形代价 —— P0 无地形差)
  expand_limit := NODE_BUDGET     // 构建期断言 > 0(P0 值见 OQ-27-7)

  if  |expanded| ≥ NODE_BUDGET  ⇒  return ∅      // 「路径失败」,非异常
```

| 变量 | 类型 | 含义 |
|---|---|---|
| `open` 的堆键 | 5 元整数元组 | **决胜键 = `(f, h, Z, Y, X)` 全序** —— 保证扩展顺序唯一 |
| `h(c)` | `int` | **OCTILE 距离 × `STEP_COST`**(整数近似,见下) |
| `cost(step)` | `int` | 单步代价(**P0 常量**;`EffectiveWalkable` 不给代价,F-23-1 只给布尔) |
| `NODE_BUDGET` | `int` | 单次 A* 的节点扩展上限 ⇒ 超限返回**空路径**(= `PathFailed`) |

**`OCTILE(c, g)`** —— 整数八向距离近似(`D = 1`, `D2 = 1414/1000` 量级的整数比例):

```
dx, dy, dz := |c − g| 各分量
m1 := min(dx, dy, dz);  m3 := max(dx, dy, dz);  m2 := dx+dy+dz − m1 − m3
OCTILE := STEP_COST × (m3 + (D2·m2)/1024 + (D1·m1)/1024)     // 全整数,禁 sqrt
```

> **为什么不直接用 `d2` 当启发式**:`d2`(欧氏平方)**不是**八向格上的可采纳启发式
> (它低估得太多 ⇒ 退化成 Dijkstra ⇒ 扩展数爆掉,直接撞 `NODE_BUDGET`)。
> **为什么不用 `sqrt(d2)`**:引入无理数 ⇒ 舍入 ⇒ 跨平台不逐位(ADR-012)。
> **OCTILE 是整数比例近似**,`h` 与 `g` 同量纲(都是 `STEP_COST` 的倍数),
> 且 **`h` 略欠估** ⇒ A* 仍最优,扩展数可控。

**缓存策略**(`path_cache`,住敌人实体):

| 项 | 规则 |
|---|---|
| **何时重算** | ① `Path` 为空 ② 路径 ∩ 新 blocked ≠ ∅(规则十三)③ `Target(e)` 变了(F-27-6)④ 每 `REPLAN_PERIOD` tick 兜底 |
| **何时**不**重算** | 目标格不变 ∧ 路径未失效 ∧ 未到兜底周期 ⇒ **零 A* 调用** |
| **`path_cursor` 在重算时** | **保留当前位置索引**:重算后**从新路径中找离当前格最近的节点**作新游标(禁清零 —— 清零等于把敌人**瞬移回路径起点**) |
| **重算失败时** | `path_cursor` **不动**,敌人**沿旧路径走完剩余部分**(F-27-5 的 `PathFailed` 计时同时启动);⇒ 不会原地僵直(EC-27-07) |

> **`path_cursor` 的重算保持是承重项**:它把「重规划」从**位置事件**降级为**路径事件** ——
> 玩家在敌人前方盖墙时,敌人**不会因为重算而向后退**。少了这条,
> 每次 `StructurePlaced` 都会把敌人**往回拽一格**(视觉上像被磁铁吸)。

**`NODE_BUDGET` 的作用**:把「寻路失败」变成一个**有界的返回值**(空路径),
而不是一个**无界的卡顿**。它是 ADR-016 §九 的「敌人数量 × 决策频率」预算里
**唯一与地图大小挂钩的项**,故必须显式受限且可断言。

> 「不做」和「做」一样是规格,不写就会被实现期各自发明)。

### 一、数值与分档病态

| # | 情形 | 处置 | 谁不做 |

| `R_ALERT` | `int` 格 | `[R_CHASE, R_VIS]` | 警戒半径(停下转头) | < `R_CHASE` ⇒ `Chase` 不可达,敌人永不追 |
| `R_CHASE` | `int` 格 | `[R_CONTACT, R_ALERT]` | 追击半径 | < `R_CONTACT` ⇒ `Engage` 不可达,贴身却不打 |
| `R_CONTACT` | `int` 格 | ≥ 1 | 贴身半径 | 0 ⇒ 永不 `Engage` |

> **四值同调**:改任意一个都可能破单调;**烘焙器对每个参数行独立校验**。
> 调大 `R_VIS` 而不同调 `R_ALERT` 是**最常见的作者错误** —— 断言会当场拦下。
>
> **A24 联动(2026-09-18 二轮登记)**:`R_CONTACT` 与 25 侧 `combat_actions.json`
> (`HumanEnemy` / `Beast` 行)的 `RANGE_CELLS` 有**跨文档约束** ——
> `RANGE(default_attack(e)) ≤ R_CONTACT(e)`,烘焙期**两表同批可见**、违反即
> **构建期硬失败**(25 侧 `AC-25-5-12` 断言);`RANGE ≪ R_CONTACT` 为**告警登记**方向。
> 27 侧义务 = **烘焙器把两表同批可见**,不新增运行期接口(规格依赖,承 `O-27-10`)。

### 一之二、超时与包抄(§States 二 / F-27-1)—— `OQ-27-7`

| 旋钮 | 类型 | 安全范围 | 影响了什么 | 破了会怎样 |
|---|---|---|---|---|
| `ALERT_TIMEOUT` | `int` tick | ≥ 1 | 警戒态无目标多久回落 `Patrol` | 太大 ⇒ 敌人**永久张望**;0 ⇒ `Alert` 帧内闪过,玩家读不到「它注意到我了」 |
| `CHASE_TIMEOUT` | `int` tick | ≥ 1 | 追击 / 包抄态失去可见多久回落 `Alert` | 太大 ⇒ 敌人**隔着墙追你很久**(虽不至于永追,但违反 AC-52-16 的体感);0 ⇒ 一拐弯即放弃 |
| `FLANK_TIMEOUT` | `int` tick | ≥ `CHASE_TIMEOUT` | 包抄多久未到位则改走直线 `Chase` | 0 ⇒ 包抄无意义(帧内退回);太大 ⇒ **绕圈不打**,玩家读作卡住(EC-27-16) |

> **三值都是「每 tick 检查」的计时器**(§States 二的死区注),
> **不是事件驱动** —— 「玩家站住不动」不发新事件,事件驱动会永久卡死(EC-27-22)。
> **`FLANK_TIMEOUT ≥ CHASE_TIMEOUT` 的理由**:让包抄**至少有机会完成一次**
> (否则 `Flank` 会在到位前就被 `Chase` 的失目标计时弹回)。

### 二、士气(F-27-2)—— `OQ-27-2`

| 旋钮 | 类型 | 安全范围 | 影响了什么 | 破了会怎样 |
|---|---|---|---|---|
| `MORALE_BASE` | `Fix` | `(MORALE_MIN, MORALE_MAX]` | 基础士气(越接近 `BREAK` 越易逃) | ≤ `BREAK` ⇒ 开局即逃(EC-27-02) |

> 但它**抹掉了兵痞与野兽的核心差异**。故在 §Edge Cases 之外单列此注 ——
> 它是**内容设计决策**伪装成的一个系数。

### 三、移动与步进(F-27-4)—— `OQ-27-3`

### 四、决策 LOD(F-27-3)—— `OQ-27-4`

### 五、脱离(F-27-5)—— `OQ-27-5`

| 旋钮 | 类型 | 安全范围 | 影响了什么 | 破了会怎样 |
|---|---|---|---|---|
| `DISENGAGE_DELAY` | `int` tick | ≥ 1 | **失去接触**后多久开始脱离(**同时用于 `Engage → Chase` 与 `Disengage → 结束` 两处**,F-27-5 / §States 一) | 太大 ⇒ AC-52-16 体验上落空(敌人粘着);太小 ⇒ 擦身而过即脱战,遭遇读作 bug |
| `PATH_FAIL_GRACE` | `int` tick | ≥ 1 | 无路可走的宽限期 | 0 ⇒ 被围死瞬间凭空放弃(EC-27-07 的表现失败) |
| `REPLAN_PERIOD` | `int` tick | ≥ 1 | 兜底重规划周期(F-27-7 §缓存策略 ④) | 无此项 ⇒ 路径永不因**目标漂移**而更新(只在被墙截断时更新) |

> **`DISENGAGE_DELAY` 在两处的语义必须一致**(都是「失去接触后容忍多久」)——
> 若实现者给 `Engage → Chase` 与 `Disengage → 结束` 各写一个常量,
> 就会出现「脱离接触 3 tick 后敌人退出 `Engage`,但 5 tick 后才真的开始退」
> 这类**玩家可感知的迟滞**。**单一定义、两处引用**(门分裂教训的同型防御)。

### 五之二、A* 预算与启发式(F-27-7)—— `OQ-27-7`

| 旋钮 | 类型 | 安全范围 | 影响了什么 | 破了会怎样 |
|---|---|---|---|---|
| `NODE_BUDGET` | `int` | ≥ 1 | 单次 A* 的节点扩展上限;超限返回空路径(= `PathFailed`) | 太小 ⇒ **明明有路却报无路** ⇒ 敌人在开阔地也脱离(AC-52-16 **假阳性**);太大 ⇒ 单 tick 寻路耗时无界(ADR-016 §九 预算失控) |
| `STEP_COST` | `int` | ≥ 1 | 单步代价(P0 常量,`h` 与 `g` 同量纲) | 0 ⇒ `f` 恒等,退化为 BFS;≥ `NODE_BUDGET` 量级 ⇒ `h × 路径长` 的 int64 求积须重核上界 |

> **`NODE_BUDGET` 太小是比太大更危险的失败**:它是**假阳性**——
> 敌人在完全通畅的地形上「以为」无路可走,触发 `PATH_FAIL_GRACE` 并**扬长而去**,
> 而玩家读到的因果是「**它莫名其妙地放弃了我**」(与 EC-27-07 的正当放弃无法区分)。
> ⇒ **AC-27-26 断言「开阔地长路径可达」**(性质测试,不锁具体地图)。

### 五之三、遭遇级硬时限(规则二十之二)—— `OQ-27-7`

| 旋钮 | 类型 | 安全范围 | 影响了什么 | 破了会怎样 |
|---|---|---|---|---|
| `ENCOUNTER_TIMEOUT` | `int` tick | **`> DISENGAGE_DELAY`** | 遭遇自 `EncounterStarted` 起的**最长存活时长**;到点 → `EncounterEnded{reason=超时}`(纯兜底清理,防「玩家从不去 / 遭遇永久悬挂」) | 无此项 ⇒ 玩家永远不去时遭遇**永久悬挂**,`EncounterEnded` 永不写(AC-27-35 的超时值不可达);≤ `DISENGAGE_DELAY` ⇒ 未接战遭遇在「超时」与「脱离」两路径间**竞态**(谁先触发不确定) |

> **与 52 的预告窗口正交**:52 的预告窗口(玩家「去不去」的决策期,`random-events.md`)在
> `EncounterStarted` **之前**;`ENCOUNTER_TIMEOUT` 从 `EncounterStarted` 起计,**在遭遇开始之后**。
> **与 EC-27-10 的脱离路径正交**:脱离 = 敌人**主动离场**(`DisengageIf`);超时 = 遭遇**过期**;
> 同一遭遇只写一次 `EncounterEnded`,谁先到谁触发(规则二十之二)。

### 六、可调与不可调的边界

**不可调(承重约束,写死在代码里,不是旋钮)**:

| 项 | 为什么不可调 |
|---|---|
| `R_CONTACT ≤ R_CHASE ≤ R_ALERT ≤ R_VIS` | 单调性是**正确性**,不是手感(EC-27-01) |
| `MORALE_BREAK < MORALE_BASE` | 同上(EC-27-02) |
| `ENEMY_SPEED < FIX_ONE` | 隧穿是 sim 正确性问题(EC-27-04) |
| `DECIDE_RADIUS ≥ R_ALERT` | 同上(EC-27-03) |
| `0 ≤ acc < FIX_ONE` | `acc` 越界 ⇒ 同 tick 连走多格 ⇒ 隧穿(EC-27-23) |
| **`Disengage_if_morale` 只在 F-27-2 定义一次** | F-27-5 重写它 = 门分裂(本 GDD 首轮评审的最高信号缺陷) |
| **`Band` 求值顺序 = Patrol → Alert → Chase** | 顺序是**正确性**:并列条件会让分档结果取决于实现者的行序(F-27-1) |
| **`acc` 只在 `Moving(e)` 为真的 tick 前进** | 否则 `Engage` / 冻结期间攒下的 `acc` 会在恢复时一次吐出(EC-27-23) |
| 「不锁定玩家」 | **AC-52-16 的硬要求**,是支柱二在敌人侧的落点 |
| 「单套行为程序 × 两类参数」 | ADR-016 §九 的承重前提(规则六)· `entity_kind` / `down_class` / `target_policy` 只影响**输出与下游**,不影响转移 |
| 「每 tick 检查的超时计时器」 | 事件驱动超时 ⇒ 玩家站住不动即永久卡死(EC-27-22) |

**可调(表现层,不影响 sim)**:动画过渡时长 · 转身角速度 · 逼近音的音量与节奏
—— 这些是 27 发给 42 / 44 的**参数**,不进 sim,不受 ADR-005 / 006 约束。

### 二、呈现层必须遵守的三条(27 的契约)

**① 归零 = 「不动了」,不是「死了」。** 这是支柱二在呈现层的硬要求
(`game-concept.md:210`:敌人「永不因你的攻击而死」)。**禁**:
死亡动画 · 尸体淡出 · 实体销毁 · 血液飞溅的量级升级。
**必须**:倒地姿态 + **呼吸层仍在**(与 13 的昏迷态同法,承 44 的 `AC-44-10`
「禁音效硬报」)。

> **为什么这是 27 的契约而不是 42 / 44 自己的品味**:42 / 44 拿到的是
> **整数语义的 `EnemySignalDto` / cue**,它们**看不出**这是敌人还是病人 ——
> 若 27 把倒地信号标成「已清除」,呈现层会**忠实地**播成死亡。
> **语义的区分必须发生在 27 这一侧**(它是唯一知道实体种类的地方)。
>
> **⚠️ `down_class = Salvageable` 不能改表现**:野兽归零的**表现约束与人形完全相同**
> —— 仍是「不动了 + 呼吸层」,**不是**可猎取物的高亮 / 可交互提示。
> 取材是 **28 的 P1a 动词**,不是**倒地瞬间**的视觉状态;
> 把「可取材」画在倒地那一刻,等于**在 P0 交付一个 P1a 的承诺**
> (`down_class` 在 P0 只服务「下游归谁」的**逻辑路由**,不服务表现)。

**② 半格盲区必须可见。** 敌人朝旧格移动时(规则二),呈现层**照实播** ——
**禁**让它「平滑跟随」玩家的真实连续位置。表现层的插值只发生在
**逻辑格之间**,不发生在「逻辑格与实际位置之间」。
> 若呈现层擅自追随真实位置,**玩家会看到一个追踪精度远超 sim 的敌人** ——
> 那既违背 ADR-016 §一(表现态不可反推逻辑),也让玩家学到错误的感知模型。

**③ `Down` 态的敌人不做任何主动表现。** 无转向 · 无寻找目标 · 无动作 ——
**决策完全停止**(§States 的 `Down` 注)。表现层若有 idle 动画,选**最静止的那一档**。

### 三、无障碍

承 ADR-013 的无障碍取向。27 侧的**具体义务**:

- **敌人状态不得只靠颜色传达** —— 六态的读数必须**同时**有姿态 / 动作差异
  (§Player Fantasy 直接层的「态即读数」本身就是这条的兑现)。
- **「可脱离」必须在任何设置下都可达** —— 它不依赖视觉提示
  (玩家不需要「看到脱战按钮」,他只需要走开)。
