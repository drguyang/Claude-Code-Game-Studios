## Overview

随机事件导演是**一个不生产内容、只决定内容何时降临的系统**。它持有四个轴 ——
**内容**(抽到什么)· **时机**(什么时候抽)· **强度**(来多强)· **密度**(还能来多少)。
骨架全档通用,每一档只是**往内容池里注入更多东西**。

它存在的理由是**一个缺口**:概念 L161「出诊途中可能遇敌/遇险」与
`concept-benchmark.md:46` 的「世界事件 ✅ 沿用结构」都要求有个系统拥有
**「事件的触发与强度」**,而全系统表里没有 —— 27 敌人 AI 只管**行为**(追击 / 包抄 / 逃跑)。

它同时承担本作对《英灵神殿》的**一处关键改写**:英灵神殿的进度锁是**杀怪**,
本作的进度锁是**行医**。盯上你的人不是因为你强,是因为你**有用**。

> **边界一句话**:52 决定**「要不要来、来多少、来多强」**,不决定**「来了做什么」**。

## Player Fantasy

玩家不该感觉到「有个系统在刷怪」。他该感觉到的是**这世界是活的,而且它在找你**。

三个锚点:

1. **门外有人** —— 出诊路上被拦住:「先生,救救我爹。」
   **事件的第一情绪不是危险,是「有人来了」。** 这是本作与《英灵神殿》最根本的差异 ——
   那边的世界只会来打你,这边的世界也会来求你。P0 的**机会档**就是为这一条立的。
2. **先听见,后看见** —— 狗吠、马蹄、锣声、远处一片哭喊。**预告制**让每个事件都有前奏,
   而这个前奏**正好是拟物 UI 能画出来的东西**(视觉锚点支撑原则二)。
3. **你做了什么,世界就回什么** —— 你救过一个逃犯,官兵后来上了门。
   随机事件因此不是骰子,是**因果**(规则九)。

> **反幻想**:这不是「刷怪塔」也不是「事件农场」。玩家**永远不会**看到
> 「今日事件:3 / 5」这样的计数。**事件一旦可被计算和刷取,它就不再是世界的一部分。**
>
> ⚠️ **「不可被计算」是 UI 层的否定声明,不是模拟层的约束**(2026-09-14 复核补)。
> 模拟层恰恰相反 —— ADR-005 要求它**逐位可计算、可回放**(见 `§确定性契约`)。
> 两者不冲突:数值必须确定,**呈现必须不透明**。任何把本条读成「抽取过程可以不确定」的实现都是错的。

## Detailed Design

### Core Rules

**规则一:一个导演,四个轴。**
```
时机轴 → 抽池(内容轴,按 key 过滤) → 强度轴定档 → 密度轴查预算 → 生成
```
即:`EventRoll = 抽一(ContentPool × 时机权重 × 进度锁过滤 × 历史乘子)`
**抽池在先,定档在后** —— 强度轴**不参与**抽取(见 F1 注:`强度系数` 若进乘子
会被归一化约去,且与「抽到什么」无关)。完整定义见 **F1**。

> **⚠️ 时机轴的落点(二轮复核补 2026-09-15)** —— 原文四个轴里**只有时机轴没有公式**,
> 而 F1 却以「预算窗口开启时」起头,窗口从未定义(三名专家独立命中)。
> **定义如下,不引入新系统**:
> ```
> 预算窗口   = 一个 TICKS_PER_DAY(与 5 时间天气的日边界同值;DC-3)
> 窗口起点   = tick % TICKS_PER_DAY == 0
> 窗口内评估 = 由 tick 推进回调驱动,每个子区间求值一次(无每帧轮询;AC-52-40)
> ```
> - **一个预算窗口 = 一天**,窗口内至多抽 `WINDOW_SIZE` 条(见 F1 步骤①)。
> - **子区间长度 `ROLL_INTERVAL`**(`N × TICKS_PER_DAY` 的整数分之一)决定「隔多久看一眼」,
>   是**旋钮**(见 Tuning Knobs)。它**不**改变日预算,只改变事件的**铺开程度**。
> - **`ContextMult`(规则六之二)乘在子区间的抽取上** —— 即「这一眼里各档的相对权重」,
>   故它**不**是 F1 步骤② 的 `W_i` 乘子,而是**档配额权重**的来源之一。
> - **dwell time(在某地停留多久)不进任何输入** —— 见 AC-52-28。

**规则二:导演不生产内容,只调度。** 内容由各系统**注入**:

| 注入方 | 注入什么 | 档 |
| ---- | ---- | ---- |
| **27 敌人 AI** | 人形遭遇(兵痞 / 山匪 / 溃兵)与野兽 | P0 |
| **37 病例系统** | **医疗事件模板**(原型疫情 / 急召出诊 / 药材短缺) | P0 |
| **34 公卫与疫情** | 疫情事件 | P1a |
| **35 时代事件** | **篇章窗口**(有脚本,非随机) | P1a |
| **36 NPC 与村落** | 求诊 · 交涉 · 流民 | P1a |
| **45 网络层** | 联机协作事件 | P1b |

**池条目 schema(52 持有的全部形状 — 不含任何内容字段):**

| 字段 | 类型 | 含义 |
| ---- | ---- | ---- |
| `key` | int | 条目主键。**整数**,非字符串(抽取结果的确定性依赖整数比较) |
| `W_base` | **int** | 基础权重(最小单位个数)。**不是 `Fix`** —— 同 D-21-17 的口径 |
| `档` | enum | 威胁 / 机会 / 反应 / 灾难(**属且只属**一档,规则三) |
| `spawn_anchor` | enum | 事件发生地。**全枚举**:`CLINIC_FRONT` / `TRAVEL_PATH` / `GATHER_POINT`(P0)· `SETTLEMENT` / `BIOME_REGION`(P1a)—— 见规则十一后注。*(2026-09-15 改名:原为 `anchor` —— 与 ADR-008 病例流的 `anchor` 字段**同名异型**(这里是生成点枚举,那里是立案上下文)。架构复核 C-2 裁定拆名,本项取 `spawn_anchor`。)* |
| `触发方式` | enum | **`随机` / `脚本`** —— **默认「随机」**;`脚本` 条目**不进抽池**,由注入方定义触发条件、52 只决定何时进入窗口(见规则十一的三案链裁决) |
| `cause_flag` | string? | 规则九的因果标记(如 `JH_ESCAPEE_SHELTERED`)。非空 = 该条目受历史乘子影响 |

> **52 不拥有任何内容字段** —— 上表没有「病种」「症状」「敌人类型」。
> **内容由注入方填,52 只持有 key、权重与调度元数据。** 这是规则二的可执行化。

> **边界铁律**:`35 时代事件不是随机的` —— 它是**有脚本的篇章**,
> 52 只决定它**何时进入窗口**,不决定它发生什么。这是 52 不吞并 35 的理由。
>
> #### ✅ 52 ↔ 37 的归属裁定(2026-09-14)
>
> **问题**:规则二说「导演**不生产内容**,只调度」,但 P0 池现在必须有医疗内容
> (见 §规则十一 的断口注)—— 那么**医疗事件的内容归谁**?
>
> **裁定**:**52 拥有「池条目与调度」,37 拥有「医疗内容」。**
>
> | | **52 随机事件导演** | **37 病例系统** |
> |---|---|---|
> | **拥有** | 池**条目** · 时机 / 强度 / 密度四轴 · 预告形态 | 病例的**内容与语义**(病种、体征、三案链) |
> | **它做什么** | 决定「**要不要来、来多少、来多强**」 | 决定「**来了是谁、是什么病**」 |
> | **它不做什么** | **不定义任何病例内容**(不写病种、不写症状) | **不管何时触发**(那是 52 的轴) |
>
> **这不动摇规则二** —— 52 依然是零内容的生产者:`W_base` 注册表里那条医疗事件的
> **内容字段由 37 填**,52 只持有**一个 key 与权重**。
> 与 27 的关系**同构**:52 决定遭遇来不来,27 决定遭遇来了怎么动。
> **37 决定医疗事件来了是什么病,52 决定它何时降临。**
>
> ⚠️ **P0 的这层接口现在只有 52 这一侧** —— 37 的 GDD 尚未撰写(`systems-index.md` §2 #37:
> 「未开始」)。**37 落笔时必须兑现本表的三条边界**,否则 P0 的医疗事件源会退化成空条目。

**规则三:四个情绪档。** 每条事件**属且只属**一档 —— 这保证内容池不会一边倒。

| 档 | 情绪 | 玩家的选择 |
| ---- | ---- | ---- |
| **威胁** | 来打你的 | 打 / 逃 / 绕 |
| **机会** | 来给你的 | 接 / 不接 |
| **反应** | 世界对你有意见 | 应对 / 无视 |
| **灾难** | 来了就改变地貌与人口 | 尽力 / 撤退 |

> ⚠️ **P0 的灾难档由脚本条目承担**(原型疫情,`触发方式 = 脚本`)——
> 故 **P0 的随机池里灾难档可以为空,但四档的「内容归属」不可为空**。
> 构建期校验的是「四档各有至少一条条目(**随机或脚本皆可**)」,见 AC-52-01。

**规则四:强度轴随「玩家状态」,不随空间。**
《英灵神殿》用「离世界中心越远越强」;本作是**固定世界**(`concept-benchmark.md:60`),
空间纵深轴失效。改为:
- **P0**:随**玩家当前状态**(带药量 · 时段 · 相关技能 · 是否独行)
- **P1a**:随**声誉 + 生态区**

**⚠️ 上限帽(2026-09-14 复核补,用户裁定)**:强度**不得**单纯随「你看起来值得抢」上涨 ——
否则「刚采完药 + 技能 0 + 独行」恰好落最高档;失败后再掉药、掉 5% 熟练度 →**同档更难**,
且玩家**读不出为什么**,这正是否定反幻想(「有系统在刷怪」)的体感来源。故:

```
StrengthTier = clamp( Σ(归一化后的 PlayerState × 权重) , MIN_tier , MAX_tier )
StrengthCap  = min( StrengthTier , f(最高格斗线, 急救) )        ← 上限帽
```

`f(...)` 是玩家**硬实力**的代理:带药多只会让**事件更多**(你看起来值得抢),
不会让它**强过你打不过的量级**。**掉药掉熟练度后,帽子随之下降** —— 正反馈闭环成立。

> **归一化是硬要求**:`CarryLoad`(整数计数,可达 10²–10³)若与 `RelevantSkill`(1–60)、
> `SoloFlag`(0/1)同量级入加权和,会以 1–2 个数量级**淹没**后两者。
> 各项必须先除归一常数到 `[0,1]`(见 F1)。
> **P1b 注意**:`SoloFlag` 在联机时改为**队伍规模**(1–4),**语义漂移** ——
> 该旋钮须在 P1b 重新标定,不得沿用 P0 权重。

> **深水线归属(2026-09-14 复核补)**:`concept-benchmark.md` 断裂② 要求 P0 给一条
> **看得见的**难度曲线(采集衰减 + 季节)。**52 不接这条轴的坐标分量** ——
> 它的强度输入是**玩家侧**的,深水线是**空间/内容侧**的,归 **5 时间天气 · 17 采集**
> (见 §Dependencies,已登记归属)。

**规则五:进度锁 = 行医进度。**
《英灵神殿》的 key = 杀 Boss;本作的 key = **声誉 / 救人数 / 生态区解锁**。
**这是对《英灵神殿》最重要的一处改写** —— 你越有名,来找你的人越多,
而**大多数不是来打你的,是来求你的**;同时盯上你的人也变多变强(**有名是把双刃**)。
接 #31 声誉与支柱四(制度性权限)。

> ⚠️ **进度锁挂「处置结果」,不挂「诊断正确」(二轮复核补 2026-09-15 —— 承自 `game-concept.md:269-271` + `systems-index.md:369`)。**
> 这是上游早已落盘的裁决,而**52 此前未认领** —— 而「救人数」恰恰是最容易被实现成
> 「诊断正确才算救活」的那个词。**一旦如此实现,误诊会软锁进度,而玩家不自知**,
> 同时背叛支柱一(判断为骨)与支柱四补注。
> **故 `KeyGate` 的一切来源(声誉 / 救人数 / 生态区)**:
> **只读 8 的诊断读数,不作对错判定;判定归 37 / #53 的处置结算。**
> 52 **不得**引入任何「诊断正确性」字段(AC-52-03 的类型扫描守门)。
>
> ⚠️ **机制现状(诚实记账,二轮复核)**:P0 **无声誉系统(#31 属 P1a)**,
> 故 `ReputationMult[档]` 与 `KeyGate` 在 P0 **无输入源**(等价恒为 1 / 恒放行)。
> **规则五的幻想在 P0 不生效** —— 见 §承重问题与 Open Questions。

**规则六:密度预算。** 每 `TICKS_PER_DAY` 有事件数上限,超预算不刷 —— 防刷。
(原文写「每日 / **每次出诊**」两个分母,**已择一**:分母 = 日。见 F2。)
**脚本条目(三案链)不参与预算。**
**超预算直接丢弃,不排队、不延后** —— 但**规则六之三**的「医馆内压制」是**唯一例外**,
且其延后**以当日为界**(见下)。

**规则六之二:时机轴认识上下文(ContextGate)。** *(2026-09-14 复核补;2026-09-15 二轮修正语义)*

核心循环要的是「**出诊途中**可能遇敌/遇险」,而纯随机间隔会让事件在**医馆里**刷出 ——
那会打断本作核心的「静」段(读脉案 = 判断层的前提),且刚打完一场立刻刷第二场。

```
ContextMult[档]:  在出诊路径上  × CONTEXT_TRAVEL      (num ≥ den,即 ≥ 1;机会/威胁档皆抬)
                  在医馆地块内  × CONTEXT_CLINIC      (威胁档 = 0;机会/反应档保留)
                  战斗结算后    × CONTEXT_COOLDOWN    (短冷却窗内 = 0,全档)
```

> **⚠️ 二轮复核(2026-09-15)—— 三处口径修正:**
>
> **① `ContextMult` 乘在「档配额权重」上,不是乘在 `W_i` 上。**
> 原文把它与 `TODMult` / `HistoryMult` 并列写成逐条乘子,但**它只依赖 `档` 与玩家上下文**,
> 与「具体哪一条」无关 —— 写在步骤② 会在档内被归一化约去(与 `ReputationMult` 同一个陷阱)。
> **故它进步骤① 的 `档配额权重[档]`**。
>
> **② `≈ 0` 必须写成 `= 0`,不得用「约等于」**(ADR-006:定点域不许浮点近似)。
> 医馆内威胁档 = **硬 0** —— 这同时是 AC-52-29 可测的前提。
>
> **③ 「出诊路径」是导演侧布尔谓词,不是几何区域(二轮 blocking 之一)。**
> **`出诊路径` 在仓库中不是已定义实体**,且 **P0 无地图(#43 属 P1a)**。
> 故定义:
> ```
> 在出诊路径上 ≡ (玩家有活跃的出诊目标) 且 (玩家不在医馆地块内)
> ```
> 两个分量都是**导演侧可读的布尔状态**:**医馆地块占用**由 **23 建造 / 24 医馆**提供
> (与规则十的「无人」判据同源);**出诊目标**由任务/事件源提供。
> **不得**实现为 NavMesh 路径查询或场景几何判定 —— 那会让两台机器**独立求值**同一事件
> 而结果不同(静默分叉,同 DC-1 警告)。
>
> **⚠️ 联机归属(P1b)**:`ContextMult` 读的是**队伍**状态而非某个玩家的状态
> (「任一玩家在出诊路径上」即为真),否则四名玩家四个位置,世界级事件的时机无定义。

**医馆不是绝对安全区** —— 机会与反应档照常来(「门外有人」正是锚点①);
只有**威胁档**在医馆内被压制。**这是有意的**:让家成为「判断」的场所。

**规则六之三:医馆内的威胁档「延后」以当日为界。** *(2026-09-15 二轮新增 —— 兑现 AC-52-26 与 AC-52-29 的冲突裁决)*

> **⚠️ 冲突背景**:F2 与边界表明写「**不排队、不延后**」(防雪崩式袭击),
> 而首轮的 AC-52-29 要求「延后且预算不丢弃」。**两条 BLOCKING 不能同时成立** ——
> 延后**本身就是一个队列**。**用户裁定(2026-09-15):当日内延后,跳日作废。**

```
若 威胁档到期 且 玩家在医馆地块内:
    该抽取被 ContextMult = 0 压制,不生成
    记入 DeferredThreatSlot(当日有效,有界)
    当玩家离开医馆地块(当日之内)→ 立即补发该威胁事件(消费当日预算)
    若跨过 TICKS_PER_DAY 边界仍未补发 → 该 slot 作废,不结转
```

- **为什么是「当日作废」**:F2 的防雪崩承诺是硬约束 —— 结转会把跨日累积的
  威胁一次性倾泻,正是 F2 要防的东西。
- **`DeferredThreatSlot` 当日有界**(至多 `DEFER_MAX` 条,见 Tuning Knobs)——
  防止玩家整日在医馆内把当日威胁全攒起来、出门一次全触发。
- **它消费的是「当日」预算**:补发时若当日预算已耗尽,则**丢弃**(与 F2 同规则)。
- **持久化归属**:该 slot 是**跨 tick 状态**,须进事件流(见 DC-4 与 ADR-007)——
  否则主机迁移会静默丢失或重复补发。

**规则七:医馆可被损毁,但知识不可被夺走。** *(**P1a** — 2026-09-14 复核修正)*

> ⚠️ **裁决 2026-09-13(用户选 B:可摧毁)**。
>
> ⚠️ **分档修正(2026-09-14 复核)**:本条整段为 **P1a**。
> 理由:P0 威胁档 = 兵痞劫道 + 野兽(规则十一),**均不打建筑**;围困医馆是 **P1a 条目**。
> 且损毁类事件的护栏①要求「玩家有时间回防」,而 **P0 无地图(#43 属 P1a)** ——
> 玩家凭什么知道回防?**P0 落不了这条承诺。**
> **P0 版本只保留一句**:「**医馆在 P0 不可被损毁**(围困 / 灾难档 P1a 才解锁)」。
> **F3 与相关的 AC 一并标注 P1a。**

事件**可以**损毁医馆。这给建造以真实的 stakes,也合乱世史实
(战乱中诊所被烧被抢是那个时代真实发生的事)。但**必须**配齐下面四条护栏,
否则它会反噬第一审美(Expression):玩家花数小时的建造被骰子抹掉 → 玩家干脆少建
→ Expression 反而崩掉。

1. **预告制** —— 任何威胁医馆的事件**必须先有预告**(规则八),玩家有时间回防
2. **分级损毁** —— 不是二值的毁 / 不毁(见下表)
3. **可修复** —— 损毁可在原地修补,材料可回收
4. **知识永不失** —— **脉案、已学的动作、已解锁的知识、技能等级永不被随机事件夺走**

**第 4 条不是新规矩** —— 它是概念 `game-concept.md:308`《玩家死亡与代价》的原话兑现:
「**不掉:已解锁的动作、已学的知识、已写的脉案**」。
*(⚠️ 二轮复核修正:原文误引为「概念 L270」;L270 是「进度挂处置结果」那条 —— 同样相关,但不是本句出处。)*
**医馆可以烧,但你是带着知识走出去的。** 这保住了 Expression 的连续性:
房子是身外物,医术不是。

| 损毁等级 | 触发 | 后果 | 恢复 |
| ---- | ---- | ---- | ---- |
| **受损** | 围困战败 / 火灾蔓延 | 家具与墙受损,功能下降 | 就地修补,材料部分回收 |
| **摧毁** | 特定灾难(溃兵焚烧 / 地动) | 建筑体需重建 | **图纸保留、地基保留**;重建更快 |
| **焚毁** | 灾难档最高级,稀有 | 医馆全失 | **脉案与技能全数保留**;从零重建 |

**规则八:预告制**(借自《英灵神殿》的 raid 公告语)。
任何事件**先有名有预告**,绝不突袭。预告必须走**拟物通道**(支撑原则二)——
狗吠、马蹄、锣声、远处一片哭喊、药铺里突然安静下来。**不报数字。**

**规则九:你自招的升级**(借自《我的世界》的不祥之兆 → 劫掠)。
部分事件不是骰子来的,是**你做过的事**招来的。让随机事件有**因果**:

| 你做过的事 | 招来什么 |
| ---- | ---- |
| 救过一个逃犯 / 窝藏伤员 | 官兵上门盘查 |
| 在某村公开用西药治好重病 | 保守医家联名告你 / 医闹 |
| 拒绝过某军阀的征召 | 被针对的遭遇强度上升 |
| 在疫区出入而不做防护 | **你自己染病**(接 9) |

**⚠️ 机制落地(2026-09-14 复核补 —— 原文有表无机制,是本轮 blocking 之一)**:

因果**不是**「另开一条触发路径」(那会被规则六的「预算耗尽直接丢弃」静默吞掉,
且「你救过人,今天预算用完」是最刺眼的反幻想)。它落在 **F1 的乘子**里:

```
HistoryMult_i = clamp( 1 + HIST_W[ cause_flag_i ] , 1 , HIST_MULT_MAX )
                ( cause_flag_i 为空 ⇒ HistoryMult_i = 1 )
```

- **`HIST_W[flag]`** 是每个历史标记的权重增量(P0 标量,`Fix`,可 0)。
  救过逃犯 → `HIST_W[JH_ESCAPEE_SHELTERED] > 0` → **官兵盘查条目的权重被抬起**。
- **它抬的是「哪一条被抽到」,不是「来不来」** —— 因果仍然是概率性的,
  但**可观测**:预告线索必须能读出「这是冲你来的」(见下)。
- **乘子是对应的、非全局的** —— 只作用于该 `cause_flag` 关联的池条目,
  **不作用于全池**(否则会像旧 F1 的全局乘子一样被归一化约去,见 F1 注)。
- **⚠️ 二轮复核修正(2026-09-15)**:原文写 `Π(1 + HIST_W[flag]) over 玩家历史标记集`
  —— 那是**对玩家全部 flag 连乘**,与紧邻的「只作用于该 `cause_flag` 关联的条目」**自相矛盾**
  (连乘会把**无关条目**也抬起,AC-52-17 当场失效),且**无界**(20 个 flag × 1.0 ⇒ `2²⁰`,
  以 int64 raw 溢出击穿 DC-2 的定点域)。**已改为「单次查表 + `HIST_MULT_MAX` 钳位」。**

**因果可见性是硬要求。** 预告线索里必须带一条 `cause_clue_key`,由 **42 拟物 UI**
渲染成可读的世界细节(官兵的口音/腰牌、对方指名道姓)。
**「读得出这是冲你来的」= 因果成立**;读不出就是随机,规则九当场失效。

**规则十:疏忽触发**(借自《我的世界》的幻翼 —— 三天不睡)。
长期不管某事,世界来提醒你:
- 医馆连续多日无人 → 药材被窃 / 药圃荒芜 / 病人转投别家
- 长期不出诊 → 声誉下降,有人上门抱怨

> **✅ 两处补裁(2026-09-14 复核)**
>
> **① 规则十 受规则八约束吗?—— 受。** 「药材被窃 / 药圃荒芜」是**损毁类后果**,
> 而规则七护栏①要求损毁类**必须先有预告**。**故规则十的每一条都走预告通道**
> (门外的动静、药圃里被踩过的痕迹)。原文未裁定,与护栏①显式冲突,已修。
>
> **② 「无人」怎么判?** 检测源 = **医馆地块占用**,由 **23 建造 / 24 医馆** 提供
> (非 52 自算);窃取目标 = **20 库存**;荒芜载体 = **23 建造件**。
> **「无人」的定义**:玩家角色不在医馆地块内 —— **在门口也算有人**,睡着了不算。
> 该判据进 AC(见 §Acceptance Criteria)。
>
> **③ 时间量纲**:「多日」= `N × TICKS_PER_DAY`,接 `ITickProvider`(见 §确定性契约)。

> #### ✅ 三处裁定(2026-09-14 复核,用户裁定)
>
> **① 「事件是调味」与「四档齐全」不矛盾 —— 矛盾在把「频率」与「内容」塞进了同一句话。**
>
> | | **何时来**(频率) | **来的是什么**(内容) |
> |---|---|---|
> | **性质** | **调味** —— 可以缺席 | **核心玩法的原料** —— 不可缺席 |
> | **P0 要求** | 密度预算封上限;**一次没遇到也合法** | **四档齐全,不能有整档为「—」** |
>
> 原文「事件是调味不是驱动」说的是**频率**,却被读成了**内容**。已切分。
> 「P0 必须可通关」的意思是**主线不依赖随机事件**,不是「Boss 可以是彩票」。
>
> **② 三案链(原型疫情)移出抽池,归 37 确定触发。**
>
> 原设计把 P0 的「拼图样 Boss」挂在**灾难档随机**上,同时又说「一次没遇到也合法」
> —— **两者不能同时成立**(支柱四的承重墙不能靠彩票)。
>
> **裁定**:三案链作为**脚本条目**挂在 52 的注册表里(`触发方式 = 脚本`),
> 由 **37 病例系统**定义触发条件(如「连续三日同症候」),**52 只决定它何时进入窗口**。
> **这与 #35 时代事件同构** —— 52 只开窗口,不决定内容。
> **⚠️ 这不动摇 52↔37 的既有裁定**:池条目与调度仍归 52,医疗内容仍归 37;
> 变的只是**该条目的触发从骰子变成脚本**。
>
> **③ `spawn_anchor` 是 P0 必需,不是 P1a 装饰。**
> 池条目的 `spawn_anchor` 决定**事件在哪生成**。
> 「兵痞**劫道**」「**半路**拦你求救的村民」语义上全是**路上**事件 ——
> 没有 spawn_anchor,它们会在医馆院内刷出,空间可信度一次崩掉。
>
> **`spawn_anchor` 全枚举**(2026-09-15 二轮复核补全 —— 原文只列 P0 三项,
> 而 P1a 已列「流民涌入 / 疫病爆发 / 地动」,**无一项能落在 P0 三项里** ⇒ 枚举不完备):
>
> | `spawn_anchor` | 含义 | 解析归属 | P0 |
> | ---- | ---- | ---- | ---- |
> | `CLINIC_FRONT` | 医馆门前 / 院内 | 24 医馆地块边界 | ✓ |
> | `TRAVEL_PATH` | 出诊路径上 | 导演侧谓词(规则六之二) | ✓ |
> | `GATHER_POINT` | 采集点 / 资源点 | 17 采集 | ✓ |
> | `SETTLEMENT` | 聚落内 / 聚落口 | 36 NPC 与村落 | P1a |
> | `BIOME_REGION` | 生态区全域(无定点) | 6 世界与生态区 | P1a |
>
> **解析纪律**:`spawn_anchor` → 世界坐标的解析**必须确定性**(同一 `EventRollSeed` + 同一
> 世界状态 ⇒ 同一生成点),不得用 `UnityEngine.Random` 或 NavMesh 采样
> (NavMesh 在 IL2CPP 下跨平台不保证逐位一致 —— 见 DC-1)。解析算法归属见 **DC-4**。
> **构建期校验**:每条池条目的 `spawn_anchor` 必须是上表成员,否则报错(AC-52-42)。
>
> **✅ 2026-09-15 · ADR-015 定型**:上表的「解析归属」(24 / 17 / 6)现在全部落在**逻辑层整数数据**上 ——
> 医馆门前锚点 / 采集点集 / 生态区多边形都是 `WorldPos` 整数格;`SETTLEMENT` 同属 36 的逻辑层数据。
> 解析因此退化为**整数查表**,自然满足本段的「禁 NavMesh 采样」纪律(`random-events.md:438-439`)。
> **坐标类型**已定(`WorldPos` = i32 × 3,`ADR-015 §三`);**逐枚举值的解析规则**(如 `TRAVEL_PATH` 的
> `SPAWN_AHEAD_DIST` 前方偏移向量形状)仍归 DC-4 与 24 / 17 的接口细化。

> #### ✅ 「事件必须可拒绝或绕开」—— 从建议升为机制(2026-09-14 复核)
>
> 原文自认:「既然一半压力是战斗,这条就不能是软性建议」—— **但它既无机制也无 AC**。
> P0 无潜行、无替代路线,**回避动词根本不存在**,威胁档只有「打」或「弃」。
>
> **裁定:两条独立路径,都必须有 AC。**
> - **可拒绝** —— 预告窗口内不前往 = 事件不降临,记为**避险**(已有状态机支持)
> - **可绕开** —— 抵达现场后可选择**不接战**而完成其他目标(先救人 / 绕行),
>   遭遇体**不锁定玩家**;这是 **27 敌人 AI** 的接口要求,52 只声明它必须存在
>
> **锚点②(先听见后看见)在此处兑现** —— 预告窗口就是「拒绝」的操作窗口。

> #### ⚠️ P0 医疗事件模板(**须由 37 补 · 2026-09-14 对标复核**)
>
> **原 P0 池的问题**:威胁档全是战斗,机会 / 反应 / 灾难三档**要么空要么与行医无关**
> —— 核心动词「判」在 P0 唯一的事件源里**缺席**,而 8 诊断是全案唯一「不知道好不好玩」的
> 承重系统。**承重墙没有承重对象。**(详见 `systems-index.md` §5 #52 注)
>
> **本表已把三类医疗事件模板挂进 P0 各档**(括号内为注入方 37),它们同时是:
> 52 的池内容 · 37 的三案链载体 · 8 的「拼图样」原料 —— **一份内容,三处用**。
>
> ⚠️ **上表的中文条目是「占位 + 归属」,不是最终内容** ——
> 每条的具体形态(病人是谁、症候如何、可拒绝 / 可绕开的路径)由 **37 病例系统**定义,
> 且**须逐条考据后落盘**(支柱五)。

> **「四档齐全」的准确口径**(2026-09-14 修正):**P0 的四档必须都有内容** ——
> 但**灾难档由脚本条目承担**(原型疫情,触发方式=脚本),故
> **P0 的随机池里灾难档可以为空,内容不可为空。**
> 构建期校验的是「四档各有至少一条条目(**随机或脚本皆可**)」。

> **P0 的机会档 : 威胁档 = 1 : 1**,指的是**运行期配额比**(= `档占比[机会] : 档占比[威胁]`),
> **不是池条目计数比**。*(⚠️ 2026-09-15 二轮复核修正:原文未点明分母,读者会按池条目数理解 ——
> 而 P0 池里机会档 3 条、威胁档 2–5 条,取决于粒度 ⇒「1:1」当场不成立。
> 见 AC-52-02 的改写:它必须断言**运行期配额**,不断言池条目数。)*
> **P1a 起非战斗(机会 + 反应) : 战斗 = 1 : 1** —— 保留《英灵神殿》的生存建造骨架手感,
> 医学层是差异化增量而非替换。
>
> **⚠️ 机制(2026-09-14 复核补 —— 原文只有裁决,无公式、无 AC)**:
> **池先验占比 ≠ 运行期配额。** 一个 8 事件的夜晚可以全是威胁,1:1 当场失效。
> 故改为**预算窗口内按档无放回配比抽取**:先按 `档占比[]` 决定本窗口各档各抽几条,
> 再在每档内部按 `W_base × 时机权重` 加权抽取。
> **配额对玩家不可见**(不破反幻想:永远不显示「今日事件 3/5」)。
>
> **代价(明说)**:既然一半压力是战斗,**「事件必须可拒绝或绕开」就不能是软性建议** ——
> 否则一半的随机压力会变成不可回避的战斗,直接违反支柱一(判断为骨)。
> **该要求已有机制与 AC**(见上文裁定)。

## Determinism Contract(确定性契约)

> **本节是 2026-09-14 复核新增。** 原文全文对随机源、定点域、tick 源**零提及** ——
> 而 52 是全案**唯一既是随机数消费者、又是事件生产者**的 P0 系统。
> 链条是 `21a(数据) → 52(掷骰) → 9(模拟)`:21a 堵了自己的出口,9 堵了自己的门,
> **52 就是中间那段敞开的管子**。
>
> **⚠️ 二轮复核修正(2026-09-15)**:原文声称 DC-1…DC-4「由 ADR-005 / ADR-006 直接推出,
> **不是新裁决**」—— **该声称有两处为假**,已改正:
> - **DC-1 的 `WorldSeed`** —— 它的生成时机与持久化归属**在两份 ADR 中均未定义**。
>   52 原文单方面断言「存档创建时生成一次」,那是 **7a 持久化**拥有的跨域决定。
>   **2026-09-15 已裁决(ADR-007 §二 + ADR-010 §一)**:7a 生成一次,`WorldSeed` 进存档头,
>   非 `SimEvent`;跨版本原样保留。
> - **DC-1 的 `IEventAuthority`** —— ADR-005 定义的抽象点**恰为五个**
>   (`ITickProvider` / `IEventSink` / `IIdAuthority` / `IVitalsQuery` / `SimEvent`)。
>   `IEventAuthority` 是**第六个**,由 52 引入。**这是新裁决,不是推出。**
>   **已登记为 ADR-007 的正式条目。**
>
> 其余(定点域、tick 源、事件流归属)才是 ADR-005 / ADR-006 的直接推论。

### DC-1 随机源(唯一)

```
WorldSeed            ← 7a 生成一次 · 进存档头(ADR-007 §二 · ADR-010 §一)
EventRollSeed(win, tier, ordinal) = SplitMix64( WorldSeed, win, tier, ordinal )
      win     = 预算窗口起点 tick(== tick % TICKS_PER_DAY == 0 的那个 tick;DC-3)
      tier    = 档 id(威胁 / 机会 / 反应 / 灾难 的整数序)
      ordinal = 「本窗口本档内的第几次抽取」,从 0 起,n 由主机随预算推进递增
```

> **⚠️ 二轮复核修正(2026-09-15)—— 原文的 `EventRollSeed(t, k)` 表达不了 F1 的加权抽取。**
> `k` 是**池条目 key**,而**抽中之后才知道 key** —— 种子不可能依赖结果。
> 原文的 `(t, k)` 实为「给定条目的确定性随机数」,**与抽样无关**;
> 一个 `argmax_i SplitMix64(t, k_i)` 的实现**能通过 AC-52-06 却完全无视权重**(不满足 F1)。
> **故改为 `(win, tier, ordinal)`,与具体条目解耦。** 正确算法见下。

**加权抽取必须走「累计分布 + 二分/线性游走」(CDF walk):**

```
给定:档内候选集 {i},各自 W_i(F1 步骤②)
S = SplitMix64( EventRollSeed(win, tier, ordinal) )         // 64 位无符号整数
C = Σ_i W_i                                                  // 已判非零(ΣW_j = 0 走 Edge Cases)
r = S mod C                                                  // 落在 [0, C) 内的整数
遍历 i(按 key 升序,确定性):
    若 r < W_i          → 抽中 i,结束
    否则 r -= W_i
```

- **游走顺序必须由 `key` 升序钉死** —— 否则两台机器用不同迭代序会抽出不同条目。
- **余数取模 `mod C`** —— `C` 可能非 2 的幂,故用 `mod` 而非位掩码;`S` 是 64 位无符号。
- **一次抽取只消费一个 `ordinal`** —— 该窗口该档的第 n 次抽取用 `ordinal = n`。

**掷骰的全部输入必须持久(二轮 blocking 之一):**

`EventRollSeed` 只依赖 `(WorldSeed, win, tier, ordinal)`,这三者都能从事件流重构。
但 **`W_i` 的构成输入**同样必须能从流重构,否则主机迁移会静默改变分布:

| 输入 | 归属 | 持久化方式 |
| ---- | ---- | ---- |
| `WorldSeed` | ADR-007 / ADR-010 | **存档头**(非 `SimEvent` —— ADR-007 §二 · ADR-010 §一) |
| `win` / `tier` / `ordinal` | 52 | **进事件流**:每次抽取写一条「抽取记录」`SimEvent` |
| 已用预算 / 已消费的 ordinal | 52 | 同上(由抽取记录重构) |
| `DeferredThreatSlot`(规则六之三) | 52 | 同上(见 DC-4) |
| 历史标记集(规则九) | 52 | **进事件流**(每条 flag 变更 = 一条 `SimEvent`) |
| `MIN_tier` 进度缩放 | 52 | 派生自进度;进度本身已在流中 ⇒ 可重构 |

> **失败模式仍是静默的**:若上述任一输入只活在可变导演对象里(不进流),
> 主机迁移后 `HistoryMult` / 已用预算静默改变 ⇒ **抽出不同事件,不崩溃,回放对不上**。
> 这正是 ADR-006 要杀的那一类分叉。**AC-52-46** 守门。

- **唯一 RNG = SplitMix64(整数哈希),无状态** —— 与 9 的 `patient_seed` 同源同法。
- **禁止 `UnityEngine.Random`**(全局单例状态,27/13 任何一处调用都会推进同一全局流
  ⇒ 抽取结果取决于**调用次序**)、禁止 `System.Random`。
- **逐次抽取不持 PRNG 状态** —— 每次抽取由 `(win, tier, ordinal)` 重新派生,可重放、可中途加入。
- **P0 即预留 `IEventAuthority`**(主机掷骰、客户端只播)—— 与 ADR-005
  「主机唯一执行 Step / CatchUp」同构。**P1b 只是接上,不是新写。**(该接口为新裁决,见 ADR-007。)

> **失败模式是静默的**:若用 `UnityEngine.Random`,两台机器抽出**不同事件** →
> 生成**不同病人** → `IIdAuthority` 分配序列错位 → **`patient_seed` 全变** →
> **病史事件流从第一条起永久分叉**。不崩溃、可能仍自洽,但 ADR-005 的核心裁决在这一环失效。

### DC-2 定点域(全量)

- **F1 / F2 / F3 的全部数学在整数定点域**(int64 / Q16.16),标 `Fix`。
- **`W_base` 是 `int`,不是 `Fix`** —— 它是**最小单位个数**(同 D-21-17)。
- **乘子不得写成浮点字面量**:`TODMult` 等一律写**分子/分母**或整数倍率。
  > ⚠️ **二轮复核修正(2026-09-15)**:原文写「旋钮表 `>1` / `(0,1)` 的写法正面违反 ADR-006,
  > **已改**」—— **那句「已改」为假,当时表格根本没改**。**本轮才真正改掉了**(见 Tuning Knobs
  > 的「类型」列:全量 `Fix(分子/分母)` 或 `int`,且「安全范围」列不再用 `>1` / `(0,1)` /
  > `≈ 0` 这类浮点区间记号,改写成整数域可判定的形式)。**AC-52-08 守门。**
- **clamp 走整数 Min/Max**;**舍入模式统一 `ROUND_HALF_AWAY_FROM_ZERO`**
  (禁 `Math.Round` 的默认 ties-to-even)。
- **`Fix` 不可经 Unity 内置序列化器承载** —— 凡承载 `Fix` 数据者**只能**落 `assets/data/*.json`
  并经 `FixParse` 读入。**禁止把 `Fix` 写进 ScriptableObject / `.asset`**
  (序列化器会静默跳过 readonly struct 的私有 `long` ⇒ 全池权重归零,不报错)。
  > ⚠️ **二轮复核修正(2026-09-15)—— 禁令挂错了数据集**:
  > - **池条目 schema(规则二)零 `Fix` 字段**(`W_base` 是 `int`),故「内容池禁 SO」
  >   并非本禁令的适用对象;
  > - **真正承载 `Fix` 的是 Tuning Knobs 表**(`TODMult` / `HIST_MULT_MAX` / `CONTEXT_*` /
  >   `W_strength[*]` / `SALVAGE_*` / `DAMAGE_MIN` / `档占比` 等)。
  > - 禁令的**真正依据是 D-21-13**(`Fix` 不可经 Unity 序列化器),不是 DC-2 本身。
  > - **它不取消 Addressables 授权** —— 数据仍走 Addressables(`technical-preferences.md`
  >   已批准),只是**文件格式为 `assets/data/*.json`,经 Addressables 以 `TextAsset` 载入**,
  >   而非 `.asset` / ScriptableObject。**json 不是「绕过 Addressables」,而是它的承载格式。**
  > - ⚠️ **2026-09-15 ADR-014 调和**:上句「经 Addressables 以 `TextAsset` 载入」的**字面**
  >   已被 ADR-014 修正 —— 运行期载入的是**构建期烘焙产物**(`*.cooked`),作者态 JSON 在烘焙后
  >   **不上构建**(它是源,不是产物)。**意图(Addressables 承载 · 数据外置 · 经 `FixParse` 读入)
  >   完全保留**;仅「运行期读 JSON 文本」这一层改为「运行期读烘焙产物」。

> **为什么乘性链比加法链更危险**:`item-database.md:628` 已警告「float 累加顺序会翻转
> `≤ 上限` 判定」。52 的链是**乘法 + 加权和 + 一次 clamp 边界比较**,
> 一次翻转就改「遭遇强度」→ 改「战斗结果」→ 改 `INJ_COMA` 是否入流 → **事件流分叉**。

### DC-3 时间量纲(接 `ITickProvider`)

- **全案 tick 唯一来源 = `ITickProvider`**;`ITickProvider.CurrentTick`。
- **禁止 `Time.time` / `Time.deltaTime` / 协程 / `InvokeRepeating` / 墙钟 / 帧数。**
- **「日」= `TICKS_PER_DAY` 常量**,与 5 时间天气的日边界**同值**。
- **`预告窗口时长` 的单位是 tick**(原文未定单位,是最贵的一个悬空旋钮)。
- **F2 的「每日预算」按 tick 边界重置**,不按墙钟。

### DC-4 事件流归属

- **52 的「事件降临」是一条 `SimEvent`**(新 `EventKind`),走主机 `IEventSink.Append`。
- **52 只发事件,不改任何状态** —— 病人的创建与 `patient_id` 分配**唯一归主机 9**
  (防 ADR-006 Amendment B 的 id 复用漏洞)。
- **损毁等级由事件流派生,不另存** —— 否则违 ADR-005 规则六(存档存事件流)。

> **⚠️ 二轮复核补(2026-09-15)—— 四处形状必须钉死,否则两个实现者会分叉:**

**① `Seq` 与 `Patient` 的取值(接 ADR-006 Amendment A)**

`SimEvent` 的形状以 ADR-006 为准,含 `{ Tick, Patient, Kind, Seq, Payload }`:

| 字段 | 事件降临 | 抽取记录 | `DeferredThreatSlot` 变更 | 历史标记变更 |
| ---- | ---- | ---- | ---- | ---- |
| `Tick` | 生成 tick | `win` | 变更 tick | 变更 tick |
| `Patient` | **`PatientId.None`(哨兵)** | `None` | `None` | `None` |
| `Kind` | `EventArrived` | `EventRolled` | `ThreatDeferred` / `ThreatDeferralCleared` | `HistoryFlagChanged` |
| `Seq` | 主机 `Append` 时分配 | 同 | 同 | 同 |
| `Payload` | `{ event_key, tier, spawn_anchor, cause_clue_key? }` | `{ win, tier, ordinal, chosen_key }` | `{ slot_index, event_key }` | `{ flag_id, new_value }` |

> **`Patient` 哨兵是硬要求**:世界级事件**不属于任何病人**。ADR-006 的 `SimEvent` 有
> `PatientId` 字段,而 52 的事件是**世界级**的 —— 若实现在这里塞一个「最近的病人」
> 或 `default(PatientId)`(可能 = `0`,而 `0` 是合法 id),会污染 `IIdAuthority` 的高水位,
> 并违反 ADR-006 Amendment B(「`max(patient_id)+1`」会读到伪造的 `0`)。
> **必须有一个显式的 `PatientId.None` 哨兵值,且它不参与高水位重构。**

**② `Seq` 由主机在 `Append` 时分配并持久化(ADR-006 Amendment A)**

52 **不自分配 `Seq`** —— 它在 `IEventSink.Append` 的**背后**由主机分配(与 `patient_id` 同权属)。
这保证「同 tick 内多条事件」的全序稳定。

**③ `spawn_anchor` → 世界坐标的确定性解析**

`spawn_anchor` 是枚举(规则十一后注),但**生成点**是坐标。解析规则:

```
解析(spawn_anchor, EventRollSeed(win, tier, ordinal)) → 世界坐标
- CLINIC_FRONT   → 24 医馆的「门前锚点」(由 24 定义的单点,非采样)
- TRAVEL_PATH    → 玩家当前出诊目标路径上的「前方偏移点」
                   (前方偏移距离 = SPAWN_AHEAD_DIST,见 Tuning Knobs;旋钮)
- GATHER_POINT   → 17 采集定义的点集,按 key 升序取第 (S mod 点数) 个
- SETTLEMENT / BIOME_REGION → P1a
```

> **禁止 NavMesh 采样 / 物理射线 / `UnityEngine.Random` 抖动** —— 三者在 IL2CPP
> 跨平台下**不保证逐位一致**,而生成点差异会传导到病人生成位置 → 影响 9 的病程
> → **事件流分叉**。**「前方偏移」是导演侧算出的固定向量,不是碰撞体查询。**
> *(这正是二轮 blocking #4 的共位威胁修正 —— 见规则六之二与 `[level]` 的联合裁决:
> 路径谓词 **+** 前方偏移,两者都要。)*

**④ 事件条目的写入时序**

一次「降临」在流中产生的条目**恰好一条** `EventArrived`(不是「预告一条 + 降临一条」)。
预告是**导演侧状态**(不进流,可本地重算);只有**状态变更**(降临 / 延期 / flag 变更 /
预算消费)才进流。这条口径防止事件流被预告噪声撑爆。

> **`Payload` 是值类型纯数据** —— 不得含引用 / `GameObject` / 委托(ADR-005 规则七)。
> 大小上界须进构建期断言(见 Tuning Knobs 的 `EVENT_PAYLOAD_MAX_BYTES`)。

## Formulas

### F1 事件抽取(**P0 · 二轮复核再修 2026-09-15**)

```
EventRoll:
  ① 预算窗口开启时,定本窗口各档配额(无放回):
       档配额权重[档] = 档占比[档] × ReputationMult[档]
       配额[档]       = 最大余数法把 WINDOW_SIZE 个名额分给四档(见下)
  ② 对每个配额,在该档内按权重抽取:
       W_i = W_base_i × TODMult_i × HistoryMult_i
       W_i = 0  若 KeyGate_i 未通过
       抽中概率  p_i = W_i / Σ W_j        (Σ W_j = 0 时见 Edge Cases)
  ③ 抽中后定档:StrengthTier(见下),并被 StrengthCap 钳位
  ④ 过密度预算 → 生成
```

**⚠️ 乘子必须是「对单条」的,不能是任何范围内的常量。**
若 `TODMult` 等是全池同一个标量 `k`,则 `p_i = w_i·k / Σ(w_j·k) = w_i/Σw_j` ——
**`k` 恒被约去,对分布零作用**。

> **⚠️ 二轮复核补(2026-09-15)—— 首轮修法无效,已重做。**
> 上述「约去」结论**同样适用于「档级常量」**:步骤② 是**档内**抽取,档内 `档` 恒定,
> 故任何 `档` 的函数在 `p_i` 中**照样被约去**。首轮把 `ReputationMult` 从
> 「全池标量」改成「按档非对称」**并未修复该缺陷** —— 它只是换了个作用域。
> **故 `ReputationMult[档]` 移入步骤①**(乘在**配额**上),见下。
> *(这正是二轮 blocking #1:文档当时写着「已修」,而机制仍然失效。)*

**档配额分配(最大余数法 / Hamilton —— 二轮复核新增):**

```
WINDOW_SIZE                        // 本窗口最多抽几条(int 常数,见 Tuning Knobs)
总权重 = Σ_档 档配额权重[档]        // 整数
若 总权重 = 0        → 本窗口 0 条(不掷骰、不报错)
商[档] = WINDOW_SIZE × 档配额权重[档] / 总权重      // 整数除法
余[档] = WINDOW_SIZE × 档配额权重[档] % 总权重
待补名额 = WINDOW_SIZE − Σ 商[档]
把 待补名额 依次补给 余[档] 最大者;平局 ⇒ 按 **档序**(威胁 < 机会 < 反应 < 灾难)
```

- **平局必须由规则裁决,不得由实现者自选** —— 否则两台主机会确定性地分叉。
- **被跳过档的配额重分配**:若某档因 `ΣW_j = 0`(见 Edge Cases)无法消费其配额,
  该空缺**在同一窗口内**按余数顺序补给其他档;若四档皆 `ΣW_j = 0`,本窗口 0 条。

**内容权重构成:**

| 变量 | 类型 | 含义 | 来源 |
| ---- | ---- | ---- | ---- |
| `W_base[event]` | **int** | 事件的基础权重(最小单位个数) | 内容池(21a 形状) |
| `TODMult_i` | `Fix` | **逐条**昼夜修正(夜 → **威胁档**条目 ↑;其他档恒 1) | 5 时间天气 |
| `HistoryMult_i` | `Fix` | **逐条**历史修正(规则九);只作用于 `cause_flag` 匹配的条目 | 52 自身的历史标记集 |
| `KeyGate_i` | bool | 进度锁过滤(未达 key 的条目**权重 = 0**) | 声誉 / 救人数 / 生态区(P1a) |
| `档占比[档]` | **int[4]** | 四档的配额**占比**(见规则十一之裁定) | 内容池配置 |
| `WINDOW_SIZE` | **int** | 每预算窗口的抽取条数上限 | 见 Tuning Knobs |

**`ReputationMult` 的修正(二轮复核 2026-09-15 —— 首轮修法无效,已重做):**

```
ReputationMult[档] = { 机会: R_opp, 反应: R_react, 威胁: 1, 灾难: 1 }
                     ↑ 乘在 档配额权重[档] 上(**步骤①**),不是乘在 W_i 上
```

- **为什么必须在步骤①**:步骤② 是档内抽取,档级常量会被归一化约去(见上注)。
  乘在**配额**上,声誉改变的是「**本窗口来几条**」—— 这正是规则五的幻想
  「你越有名,来找你的人越多」。**改的是条数,不是哪一条。**
- `R_opp` 与 `R_react` 是**两个独立参数**,由 31 的声音值共同驱动(两者同升)。
- **P1a**;P0 无 31 ⇒ 恒为 1(等价于不生效)。AC-52-20 守门。

**规则九的历史乘子(二轮复核修正 —— 原文对全部 flag 连乘,与紧邻散文矛盾):**

```
HistoryMult_i = 1 + HIST_W[ cause_flag_i ]        若 cause_flag_i 为空 ⇒ 1
HistoryMult_i = clamp( HistoryMult_i , 1 , HIST_MULT_MAX )      // 整数 Min/Max
```

- **是「查一次表」,不是「对全部 flag 连乘」** —— 原文写 `Π(1 + HIST_W[flag]) over 玩家历史标记集`,
  但 `:234` 同时要求「只作用于该 `cause_flag` 关联的池条目」。两者不能同时成立
  (连乘会让**无关条目**也被抬起,AC-52-17 当场失效)。**已改为单次查表。**
- **`HIST_MULT_MAX` 是硬上界** —— 原文无界(20 个 flag × 1.0 ⇒ `2²⁰`),
  会以 int64 raw 溢出击穿 DC-2 的定点域。见 Tuning Knobs。

**强度轴**由 `PlayerState` 而非距离决定(各项**先归一化到 `[0,1]`**):

| 变量 | 类型 | 归一化 | 含义 |
| ---- | ---- | ---- | ---- |
| `CarryLoad` | int | `clamp(CarryLoad / CARRY_CAP, 0, 1)` | 当前携带的药量(药多 → 事件**更多**,但**不强过你的量级** —— 见 `StrengthCap`) |
| `RelevantSkill` | int | `clamp(RelevantSkill / SKILL_CAP, 0, 1)` | 相关技能等级(格斗线 vs 遭遇;诊断 vs 病情)。**权重为正** |
| `SoloFlag` | bool→int | 原样(0/1) | 是否独行。**P1b 改队伍规模(1–4),须重新标定** |
| `EcoTier` | enum | **查表**,非序数 | 生态区(P1a)。**P0 权重恒为 0** |
| `Reputation` | int | `clamp(Reputation / REP_CAP, 0, 1)` | 声誉(P1a)。**P0 权重恒为 0** —— 兑现规则四「P1a 强度随声誉」,原文的强度表缺此行使该承诺无落点 |

> **⚠️ 归一化后必须钳到 `[0,1]`(二轮复核补)** —— 原文只写「先归一化」而未钳,
> 则 `CarryLoad > CARRY_CAP` 或技能超限时该项恒 `> 1`,与声明范围矛盾。
> **`CARRY_CAP ≤ 0` / `SKILL_CAP ≤ 0` / `REP_CAP ≤ 0` 进构建期拒绝表**(否则除零)。

```
StrengthRaw  = Σ( 归一化(PlayerState 各变量) × W_strength[变量] )     // Fix
StrengthTier = clamp( RoundHalfAwayFromZero(StrengthRaw) , MIN_tier , MAX_tier )
StrengthCap  = min( StrengthTier , f(最高格斗线, 急救) )              // 上限帽(规则四)
```

> **⚠️ `Fix → int` 的舍入必须显式命名(二轮复核补)**:`StrengthRaw` 是 `Fix`,
> 档位是 `int`。原文未指定舍入 ⇒ 算例里玩家丙 2.50 可被实现为 3 或 2,**整整差一档**。
> **统一走 `ROUND_HALF_AWAY_FROM_ZERO`**(ADR-006 §三),**先舍入后钳位**,不得颠倒。

**⚠️ `MIN_tier` 是全局常数,不是「地板砖」**:若 `MIN_tier` 高于新玩家算出的 `StrengthRaw`,
clamp 会把它**向上**拉 —— 规则四当场失效。故 **`MIN_tier` 随进度缩放**
(见 Tuning Knobs),且**构建期校验 `MIN_tier ≤ MAX_tier`**。

> **⚠️ 缩放必须同时动两端(二轮复核补)**:若只抬 `MIN_tier` 而不动 `MAX_tier`,
> 满级玩家的 clamp 宽度收敛到 0 ⇒ `StrengthTier` 恒为定值,**强度轴当场死亡**。
> **构建期断言 `MAX_tier − MIN_tier ≥ 1`**,对任意玩家状态成立。

**Output Range:** `MIN_tier` 到 `MAX_tier`(整数档位)。
**P0 的 `EcoTier` / `Reputation` 权重恒为 0** —— 固定世界无空间纵深(`concept-benchmark.md:60` 的验证点);
P0 亦无声誉系统。

**Worked example(算例 —— 二轮复核改为整数域,原文以浮点书写违反 DC-2):**

> 下列数值**只为演示算式走向**,不是标定值;真值归用户(见 Tuning Knobs)。
> 记号:`Fix` 以 Q16.16 整数书写(`1 = 65536`),仅为可读起见以小数值标注。

```
设定:CARRY_CAP = 500, SKILL_CAP = 60
W_strength[CarryLoad] = 2, W_strength[RelevantSkill] = 3, W_strength[SoloFlag] = 1
MIN_tier = 1, MAX_tier = 5

玩家甲:CarryLoad=10, 短兵=2, 独行
  StrengthRaw = 2×(10/500) + 3×(2/60) + 1×1 = 0.04 + 0.10 + 1.00 = 1.14
  → Round → 1 → clamp → StrengthTier = 1
  ⚠️ 0.04 与 0.10 被 SoloFlag 的 1.00 淹没 —— 归一化**仍不够**,
     故 W_strength 必须按量级标定;这是「无上限帽会出事」的数值证据。
     **AC-52-24 因此要求「移除任一变量后档位变化 ≥ 1」,而不是「可观测地变化」。**

玩家乙:CarryLoad=480, 短兵=40, 不带独行标记
  StrengthRaw = 2×0.96 + 3×0.667 + 0 = 1.92 + 2.00 = 3.92
  → Round → 4 → clamp → StrengthTier = 4
  → StrengthCap = min(4, f(短兵 40, 急救 10))

玩家丙:玩家乙刚被打倒 —— 掉药(CarryLoad→150)、短兵 →38
  StrengthRaw = 2×0.30 + 3×0.633 = 0.60 + 1.90 = 2.50
  → Round(2.50) = 3(ROUND_HALF_AWAY_FROM_ZERO)→ StrengthTier = 3
  ← 帽子随实力下降,闭环成立
```

### F2 密度预算(**P0**)

```
EventBudgetPerDay = clamp( BASE + ΣMod , 0 , BUDGET_MAX )
```

| 变量 | 类型 | 含义 | 默认 |
| ---- | ---- | ---- | ---- |
| `BASE` | int | 每日基础事件数 | *待裁* |
| `Mod_Eco` | int | 生态区修正 | *待裁* |
| `Mod_Rep` | int | 声誉修正(P1a) | *待裁* |
| `BUDGET_MAX` | int | 硬上限(防「N 人重新打开刷怪洪流」) | *待裁* |

> **⚠️ 三处修正(2026-09-14 复核)**:
> ① **下钳 0** —— 原文 `BASE=0, ΣMod=−1` 会得到**负预算**,低于声明范围却无钳制。
> ② **「联机人数」项已删** —— 它与「事件是世界级的、按**队伍共享**预算」冲突:
> 若该项为正,N 人反而重新打开被共享预算封堵的洪流。**联机不抬高预算。**
> ③ **分母 = `TICKS_PER_DAY`**,不是「日 / 每次出诊」二选一(规则六已修)。
>
> **超预算的事件直接丢弃,不排队** —— 排队会导致「雪崩式袭击」,那不是设计意图。
> **⚠️ 例外一**:`触发方式=脚本` 的条目(三案链)**不参与密度预算**(见规则十一裁定)。
> **⚠️ 例外二**:规则六之三的 `DeferredThreatSlot`(**仅威胁档 · 仅医馆内 · 仅当日**,
> 有界 `DEFER_MAX`)—— 这是**唯一**被裁定的「延后」,且**跨日作废、不结转**。
> 二者之外,不存在任何队列(AC-52-26 / AC-52-29 / AC-52-48 守门)。

### F3 损毁与重建成本(**P1a** — 2026-09-14 复核改为 P1a,见规则七)

```
RepairCost  = Σ( 受损件.base_cost × DamageRatio ) − SalvageValue
SalvageValue = Round( Σ( 受损件.base_cost × DamageRatio ) × SALVAGE_RATE )   // ← 先求和,再乘,最后舍入一次
                                                  ↑ 二轮修正:不得逐件舍入后相加(双重舍入)

RebuildCost_mark  = FullCost_mark × ( 1 − SALVAGE_RATE )     // 摧毁档
RebuildCost_razed = FullCost_mark × ( 1 − SALVAGE_RATE_RAZED )  // 焚毁档(回收率更低)
```

| 变量 | 类型 | 含义 | 安全范围 |
| ---- | ---- | ---- | ---- |
| `DamageRatio` | `Fix(分子/分母)` | 单件损毁比例 | **`DAMAGE_MIN ≤ num/den < den`**(上界不含 1),`DAMAGE_MIN > 0` |
| `SALVAGE_RATE` | `Fix(分子/分母)` | 摧毁档材料回收率 | **`0 < num < den`** —— **不含 1** |
| `SALVAGE_RATE_RAZED` | `Fix(分子/分母)` | 焚毁档回收率 | **`0 < num/den < SALVAGE_RATE`** |
| `FullCost_mark` | int | 该建筑件的完整建造成本 | ≥ Σ(受损件.base_cost) |
| `base_cost` | int | 部件基础成本 | ≥ 0 |

> **⚠️ `FullCost_mark` 与 `Σ base_cost` 的关系(2026-09-15 二轮补 —— 原文未定义此关系)**:
> **`FullCost_mark = Σ(该建筑件全部部件.base_cost)`** —— 即**整件的全损成本**,
> 不是「受损件的成本」。这是 `RebuildCost` 与 `RepairCost` 唯一可能的共同量纲。
> **构建期断言** `FullCost_mark ≥ Σ(受损件.base_cost)`。
>
> **否则 AC-52-34 是伪断言**:若两者取同一个 `Σ`,则 `DamageRatio = 1` 时
> `RepairCost = FullCost_mark × (1 − SALVAGE_RATE) = RebuildCost_mark` ——
> **恒等,而原文断言严格 `<`**,永不成立。见 AC-52-34 的改写。

> **⚠️ 四处边界退化(2026-09-14 复核 + 用户裁定)**:
> ① **`SALVAGE_RATE` 范围由 `(0,1]` 改为 `0 < num < den`(不含 1)** —— 含 1 时
> `RebuildCost = FullCost × 0 = 0`,**重建免费**,焚毁档失去全部 stakes,
> 且玩家可反复故意焚毁刷布局。
> ② **`DamageRatio = 1` 曾使 `RepairCost = FullCost > RebuildCost`** ——
> **「修不如拆」,维修被严格支配**,与「就地修补」承诺相悖。**已补 `SalvageValue` 回收项**;
> 且 `DAMAGE_MIN > 0` 保证 `DamageRatio = 0` 时不会「零成本复原」。
> ③ **焚毁档原无成本式** —— 已补 `RebuildCost_razed`。
> ④ **材料是整数计数** —— 乘 `SALVAGE_RATE` 的舍入走 **`ROUND_HALF_AWAY_FROM_ZERO`**(ADR-006);
> **先算 `SalvageValue` 的整体值再相减,不得逐件舍入后相加**(双重舍入,二轮补)——
> 逐件舍入会在 `base_cost = 1` 的小件上击穿 `DAMAGE_MIN > 0`(免费维修)。
>
> **⚠️ 构建期拒绝**:`SALVAGE_RATE = 0`(「可修复」承诺破产)、`SALVAGE_RATE = 1`(重建免费)、
> `SALVAGE_RATE_RAZED ≥ SALVAGE_RATE`、`MIN_tier > MAX_tier`、`预告窗口时长 ≤ 0`、
> `DAMAGE_MIN ≤ 0`、`FullCost_mark < Σ(受损件.base_cost)`。
> (完整拒绝表见 §Tuning Knobs —— 二轮收口后为 17 条。)

**Variables 表** —— 全部数值待用户裁定(见 Tuning Knobs)。

## Edge Cases

| 情况 | 处理 | 理由 |
| ---- | ---- | ---- |
| **玩家在预告窗口内离开事发区域** | 记为**避险**,事件结束,**不惩罚** | 支柱一:你总能选「先救人」 |
| **事件抽中但密度预算耗尽** | **直接丢弃**,不排队、**不跨日结转**。**唯一例外** = 规则六之三的 `DeferredThreatSlot`(**仅威胁档 · 仅医馆内 · 仅当日**) | 防雪崩式袭击;当日内的延后是有界例外,不构成雪崩 |
| **事件已进入 `DeferredThreatSlot`,`TICKS_PER_DAY` 边界跨过** | **作废,不结转**;次日预算从 0 重算 | 防止跨日累积倾泻(与 F2 同口径) |
| **医馆无人时被围困** | 事件照常发生;按规则七**分级损毁**;**脉案与技能不受影响** | 知识永不失 |
| **玩家在医馆内被围困** | 进入防守 / 救治的取舍(同在场的病人要不要先撤) | 判断为骨 |
| **疫情事件与 #35 篇章窗口重叠** | **篇章优先**;随机事件让位 | 篇章是脚本,不可被骰子挤掉 |
| **玩家反复在同一生态区刷事件** | 密度预算封堵;且事件**不给经验** | 双重封堵 |
| **「你自招的升级」被玩家抱怨「凭什么」** | **不是 bug** —— 因果必须**可见**(预告线索里要能读出「这是冲你来的」) | 规则九 | 
| **一个事件同时命中两档** | **不允许** —— 每条事件属且只属一档 | 规则三 |
| **联机时多人各自触发** | 事件是**世界级**的,不是玩家级的;按队伍共享预算(P1b) | 一致性 |
| **玩家故意用灾难档事件刷材料** | 灾难档**不产出可刷取的战利品** —— 产出是叙事与**权限** | 支柱四 |
| **P0 期间玩家一次都没遇到事件** | **合法**。P0 的事件是**调味**不是**驱动**,不能因没遇到而卡住主线 | P0 必须可通关 |
| **`SALVAGE_RATE = 0` / `预告窗口时长 = 0` / `MIN_tier > MAX_tier`** | **构建期报错** | 三者分别违反「可修复」、支柱一、F1 的 clamp 良定义 |
| **ΣW_j = 0(档内全部条目权重归零)** | **该档跳过本轮配额,不掷骰**;不报错 | 除零的显式退化路径(S5)。`KeyGate` 全封或全档 `TODMult=0` 都会触发 |
| **脚本条目(三案链)与随机条目同时到期** | **脚本优先**;随机条目让位(与「篇章优先」同构) | 脚本是不可被骰子挤掉的内容 |
| **医疗事件(37)的处理经验** | **完全归 30 管辖,52 不承诺封堵** —— 原「事件不给经验」的防刷论证来自**战斗**事件,不适用于医疗事件(处置病人**必然**驱动 30) | 防刷只剩密度预算一层;重复病种的冷却归 30 的新颖度加权 |
| **玩家在医馆内且威胁档到期** | `ContextGate` **压制**并记入 `DeferredThreatSlot`(**当日有效**);**当日内**离开医馆 ⇒ **立即补发**;**跨日未补发** ⇒ **作废,不结转**(规则六之三) | 家 = 判断场所;但延后必须有界,否则 F2 的防雪崩承诺破产 |
| **玩家连续多日在同一区域停留** | 密度预算封顶;**且抽取输入的 `t` 不含 dwell time** —— 「停留」在数学上进不了权重 | 原 AC「频率收敛而非上升」不可测,已改为这条**结构性**判据 |
| **预告窗口内玩家正在战斗** | 预告**照常发出**(可感知),窗口计时**不暂停**;战斗是玩家自选的代价 | 规则八无例外;否则「先清场再回防」变成一个可刷的漏洞 |
| **威胁事件生成点落在玩家脚下** | **不允许** —— 生成点须按 `SPAWN_AHEAD_DIST` 偏移到玩家**前方**(DC-4 ③);`SPAWN_AHEAD_DIST ≤ 0` 构建期报错 | 二轮 blocking:共位威胁不可读,且玩家无反应时间 |
| **`spawn_anchor = BIOME_REGION`(生态区全域)且 P0** | **P0 不可达** —— 该 `spawn_anchor` 是 P1a 成员;P0 池若引用它,构建期报错(AC-52-42) | 枚举完整性 ≠ P0 可用性 |
| **同一窗口内某档配额未被消费完**(该档 `ΣW_j = 0`) | 空缺**在同一窗口内**按余数顺序补给其他档;四档皆零 ⇒ 本窗口 0 条 | F1 ① 的配额重分配(二轮补:原文未定义配额去向) |
| **`档占比` 之和不能整除 `WINDOW_SIZE`** | 走**最大余数法**;平局 ⇒ 按 **档序**(威胁 < 机会 < 反应 < 灾难)。**不得由实现者自选** | 确定性要求(否则两主机分叉) |
| **`ROLL_INTERVAL` 不整除 `TICKS_PER_DAY`** | **构建期报错** | 否则日边界与子区间边界错位,预算重置点不唯一 |
| **`WINDOW_SIZE ≤ 0` 或 `Σ档占比 ≤ 0`** | **构建期报错** | 前者功能死亡,后者除零 |

## Tuning Knobs

> **全部数值待用户裁定** —— 本 GDD 只交付公式与旋钮,不替用户拍定值。
> **全部数值集中在数据文件**,不得硬编码(见 `coding-standards.md`)。
>
> **格式约定(2026-09-15 二轮修正 —— 兑现 DC-2 的「已改」声明)**:
> - **类型列**:`Fix` 一律标 **`Fix(分子/分母)`** —— 数据文件里写 `num`/`den` 两个整数字段,
>   由 `FixParse` 组装,**不接受浮点字面量**(ADR-006)。
> - **安全范围列**:**不再使用 `> 1` / `(0,1)` / `≈ 0` 这类浮点区间记号**
>   (它们无法在整数域判定,且 `≈` 违反定点域禁近似)。改写成 **`num/den` 的整数约束**
>   或 **`int` 比较式**。原文这四处(`:637/639/645/647/648`)是 DC-2 声称「已改」却未改的残留。

| 旋钮 | 位置 | 类型 | 默认 | 安全范围(整数域可判定) | 作用 / 极端后果 |
